# v0.3.15 Microstructure Forward Data Foundation Report

## Outcome

v0.3.15 establishes an isolated, append-safe, event-time-preserving BTCUSDT USD-M Futures microstructure data pipeline. It captures diff-depth and aggregate-trade events for future preregistered research only. It does not qualify a strategy, create a Direction Engine, inspect the final holdout, or enable execution.

The campaign was frozen before implementation in commit `75a18a562ed6f8ef1b778bfcc21138b1cce8e0cb`, with fixed start `2026-08-31T19:00:00Z`. Collector implementation began in `d3e248c3519fd4777a10ec665f74f8b47d612826`; operational hardening continued in later v0.3.15 commits. The start was never moved in response to collection quality.

## Eligibility source of truth

`quantctl derivatives status` now derives its formal `research_eligibility` from the active v0.3.14 Evidence Epoch. `quantctl forward-evidence status` uses the same epoch calculation. All-time and pre-epoch reliability remains available under `archive_pre_epoch` and is explicitly classified `NOT_FOR_ELIGIBILITY`. Manual, legacy, and backfilled rows do not improve the active gate.

At the delivery snapshot, both commands report `INSUFFICIENT_FORWARD_HISTORY`. Historical outages are preserved for audit but no longer create a second formal eligibility answer.

## Source and protocol verification

The current Binance USD-M Futures documentation was checked before implementation. The frozen routes are:

- Diff depth: `wss://fstream.binance.com/public/stream?streams=btcusdt@depth@100ms`
- Aggregate trade: `wss://fstream.binance.com/market/stream?streams=btcusdt@aggTrade`
- REST depth, bootstrap/resync only: `https://fapi.binance.com/fapi/v1/depth?symbol=BTCUSDT&limit=1000`

Sources: [WebSocket connection and routed paths](https://developers.binance.com/en/docs/products/derivatives-trading-usds-futures/websocket-market-streams/Connect), [2026 routed-stream migration notice](https://developers.binance.com/en/docs/products/derivatives-trading-usds-futures/websocket-market-streams/Important-WebSocket-Change-Notice), and [official local order book procedure](https://developers.binance.com/en/docs/products/derivatives-trading-usds-futures/websocket-market-streams/How-to-manage-a-local-order-book-correctly).

The local book buffers depth events, loads a REST snapshot, discards stale events, requires the first bridge `U <= lastUpdateId <= u`, then requires each new `pu` to equal the preceding `u`. Any gap clears the book, emits a durable gap audit record, and starts a new snapshot synchronization. Reconnect never continues an old sequence.

Aggregate-trade `m=true` is stored as buyer-is-maker and therefore `SELL` aggressor; `m=false` is `BUY` aggressor. Exchange event/transaction timestamps and local receive wall/monotonic timestamps remain separate.

## Storage and mechanical aggregation

Raw data is isolated under `data/forward/BTCUSDT/microstructure/` in UTC-daily SQLite WAL partitions. Primary keys make duplicate writes idempotent. Payload hashes distinguish duplicates from conflicts. Closed partitions receive a SHA-256 manifest after WAL checkpointing.

The collector generates 1-second, 1-minute, and 15-minute causal buckets. Stored mechanical fields include aggressive buy/sell quantity and notional, trade count, book sample count, spread, top-1/top-5/top-20 imbalance, and event OFI. Gap-affected buckets are never counted as complete. These fields are descriptive data infrastructure, not trading signals.

Best-level event OFI is defined for previous `(P_b,Q_b,P_a,Q_a)` and current `(p_b,q_b,p_a,q_a)` as:

`I[p_b>=P_b]q_b - I[p_b<=P_b]Q_b - I[p_a<=P_a]q_a + I[p_a>=P_a]Q_a`.

It uses only the previous and current causally observed book states. It does not emit LONG/SHORT. No hidden iceberg claim is made, and no `absorption_proxy` is emitted in this version.

## Reliability and operations

The microstructure service is an enabled, long-running systemd user service with restart-on-failure, bounded restart bursts, optional inherited network environment, graceful SIGINT shutdown, resynchronization after reconnect, and independent storage. The derivatives and opportunity timers remain active and were not modified by a microstructure failure.

The unified watchdog reports three independent chains: v0.3.14 derivatives epoch, v0.3.13 opportunity/H35 campaign, and v0.3.15 microstructure data campaign. Microstructure health never changes derivatives or H35 eligibility.
