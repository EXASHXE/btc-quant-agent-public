# BTC Quant Agent v0.3.0 数据审计

## 审计结论

研究数据可用于开发集回放，但不能消除策略样本不足问题。规范数据源是 Binance Public Data 的 `BTCUSDT` USD-M 永续合约 1 分钟月度归档，时间统一为 UTC。数据集覆盖 `[2021-01-01, 2026-08-01)`，逻辑 SHA-256 为：

`82d058b2e9e5bfbd20bf36026abec045fb778ddb72582277e0dac00846ae9901`

开发集为 `[2021-01-01, 2026-02-01)`；最终 holdout 为 `[2026-02-01, 2026-08-01)`。本审计允许检查 holdout 的数据质量，但没有运行或查看 holdout 的策略结果。

## 来源与可复现性

- K 线：`https://data.binance.vision/data/futures/um/monthly/klines/BTCUSDT/1m/`
- Funding：`https://data.binance.vision/data/futures/um/monthly/fundingRate/BTCUSDT/`
- Mark price：`https://data.binance.vision/data/futures/um/monthly/markPriceKlines/BTCUSDT/1m/`
- 每个 ZIP 均按同路径 `.CHECKSUM` 中的官方 SHA-256 校验。
- 本地为 67 个按 `year/month` 分区的 Zstandard Parquet 文件；manifest 保存每个分区和 210 个官方源归档的校验和。
- 原始数据约 342 MiB，不纳入 Git；完整 manifest 随 Run 0 产物版本化。

## Funding 与 mark price

共有 6,114 个 funding 结算事件，时间戳无重复，mark price 缺失为 0。Funding 的 `calc_time` 偶有 1–59ms 偏移，使用“包含结算时刻的 UTC 分钟”的官方 1m mark-price 开盘价。

Binance 的月度 mark-price ZIP 在 9 个日期存在整日缺档。构建器只针对这些日期读取并校验 Binance 官方 daily mark-price 归档；没有使用成交价代理或合成 mark price。Funding CSV SHA-256：

## 15m / 1h / 4h 交叉验证

抽样月份为 2021-01、2022-06、2024-03、2026-01、2026-07，共 15 个“月份 × 周期”组合。由规范 1m 聚合出的时间戳和 OHLC 与官方高周期归档全部逐值一致，最大价格绝对误差为 0。

2021-01 有 1 个、2022-06 有 4 个 15m 桶的成交量、quote volume、taker volume 或 trades 与 Binance 官方高周期归档不一致；这些差异向上反映到对应 1h/4h 桶。对相关 5 个日期另取官方 daily 1m 归档，结果与 monthly 1m 逐行一致。因此采用 1m 作为唯一规范事实，并把高周期成交活动差异记为上游聚合异常，不篡改 1m 数据。

审计状态为 `PASS_WITH_SOURCE_ACTIVITY_ANOMALIES`：时间与价格一致性通过，成交活动跨源严格一致性未通过。机器可读报告位于数据目录的 `timeframe_audit.json`。

## 已知限制

- Binance 公共归档是单一交易所数据，不代表全市场价格发现或跨交易所流动性。
- 历史 order book 无可靠官方逐时点归档；本研究禁用该因子。
- OI、账户多空比、taker ratio 与 basis 没有满足全期 point-in-time 要求的本地历史集；Run 0 禁用 derivatives alpha。
- 数据完整不等于策略有效。Run 0 的 13 笔 filled trades 远低于优化门槛。
