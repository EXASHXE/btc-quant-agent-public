## 2. Blocking Finding & Root Cause Analysis

In the previous v0.3.23 implementation, `evaluate_feature_hypotheses` defined the parameter:
```python
def evaluate_feature_hypotheses(
    observations: Sequence[H39Observation],
    horizon: str = "60m",
    allow_unblind: bool = False,
) -> dict[str, FeatureTestResult]:
```
and evaluated the guard as:
```python
if has_post_start and not allow_unblind:
    raise RuntimeError(REFUSED_VALIDATION_NOT_MATURE)
```
Although CLI commands did not expose an unblind flag, passing `allow_unblind=True` at the Python library level permitted bypassing the fail-closed refusal on real post-start fresh forward validation observations (`slot_ms >= 1788520500000`) before sample maturity gates were achieved.

This violated the v0.3.23 strict blindness contract: **v0.3.23 must NOT unblind H39 under any circumstances.** Formal unblind testing is reserved for a future, independent one-shot stage after `H39_READY_FOR_ONE_SHOT_UNBLIND` is reached.

---

## 3. Repair Implementation: Unconditional Fail-Closed Refusal

1. **Parameter Removal**: The `allow_unblind` parameter was completely excised from `evaluate_feature_hypotheses`.
2. **Unconditional Refusal**: Any observation set containing observations with `slot_ms >= H39_VALIDATION_START_MS` unconditionally raises `RuntimeError(REFUSED_VALIDATION_NOT_MATURE)`.
3. **Zero Bypass Vectors**: No environment variables, CLI options, hidden flags, magic tokens, or alternate parameters exist to bypass this check.
4. **Development Evaluation Preserved**: Pre-validation / development observations (`slot_ms < H39_VALIDATION_START_MS`) evaluate normally for research and synthetic math verification.
