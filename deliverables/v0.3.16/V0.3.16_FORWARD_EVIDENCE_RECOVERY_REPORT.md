## 4. Microstructure reliability

每个 daemon process 有唯一 instance、5 秒 heartbeat 和 15 秒 lease。coverage 来自 heartbeat 封闭的 stream segments；crash 后 lease 到期即关闭旧 segments，并记录 `PROCESS_OR_HOST_GAP`。因此 uptime 不再由 open session 无限制延伸到查询时刻。

1s/1m/15m bucket 的 complete 定义为：trade coverage ≥95%、depth coverage ≥95%、depth sequence-valid coverage ≥95%，并且无 explicit gap overlap。事件数量不是 liveness：健康 stream 上真实零成交的 bucket 可以 complete；即使已有 events，只要覆盖不足也必须 incomplete。

`DEPTH_SEQUENCE_GAP`、`DEPTH_BOOTSTRAP_FAILURE`、`DEPTH_RECONNECT`、`TRADE_DISCONNECT`、`PROCESS_OR_HOST_GAP`、`REST_BOOTSTRAP_FAILURE` 分开统计，resync count 只由 depth/resync 类组成。历史 v0.3.15 gap 保留为 legacy `DEPTH_GAP_RESYNC`，不改写。

host clock 每 60 秒通过 Binance server time 测量，offset 为 `server_time - local_request_midpoint`，并保存 RTT 与 quality。raw exchange/receive timestamps 永不修改；adjusted latency 只作诊断。

UTC 日分区在午夜后 1 小时 grace、无 open session 且 WAL checkpoint 后才 finalized。manifest 首次写入 SHA-256 后不允许覆盖；重复计算保持稳定，文件变化会产生 checksum drift。实机已 finalized `microstructure-2026-08-31.sqlite3`，重复 finalization 的 manifest 与 partition digest 均保持不变。
