# Part A — AG-03 producer-contract authority repair

## Existing defect

`SignalProducerContract` uses a frozen dataclass but exposes mutable nested parameter content. `contract_hash` is computed once, while registry lookups return the same live object and replay consumes the current parameter mapping.

The following invariant must become true:

```text
same producer contract identity/hash
        =>
exact same recursively immutable semantic content
```

A caller must not be able to mutate top-level or nested parameter values after construction/registration and have replay continue under the old identity.

## Required behavior

### A1. Deep immutability

Producer contract semantic parameters must be recursively detached from caller-owned mutable aliases and recursively immutable after construction.

Cover at least:

- dict
- nested dict
- list
- tuple containing mutable children
- sets only if currently accepted by the canonical serialization contract; otherwise reject them explicitly

Do not rely only on `@dataclass(frozen=True)`.

Public access must not expose a mutable alias capable of changing authoritative state.

### A2. Hash/content invariant at authority boundaries

At every authority lookup/replay boundary used by formal promotion, verify that the current canonical semantic payload still hashes to the declared `contract_hash`.

At minimum inspect and, if needed, harden:

- `SignalProducerRegistry.register_contract`
- `SignalProducerRegistry.get_contract`
- protocol-bound contract resolution in `economic/replay_bundle.py`
- formal signal replay path

If semantic content and cached identity disagree, fail closed.

### A3. Conflicting registration must fail closed

Registering the same logical contract id/version with different semantic content/hash must not silently replace the authoritative contract.

Define and test the exact rule. Prefer idempotent re-registration of exact same semantics and rejection of conflicting semantics.

Do not introduce a second producer registry.

### A4. Explicit identity/version discipline

If the repair changes canonical serialized semantic payload or existing default contract identities, do not silently keep an old identity with new meaning.

Either:

1. preserve exact semantic hashes where semantics are unchanged by using an immutable representation that canonicalizes identically, or
2. explicitly version/migrate the affected contract identity and make old incompatible authority fail closed for **new promotion**.

Do not mass-edit frozen expected values just to obtain green tests.

### A5. Fresh-process and same-process verification

Permanent regressions must cover both:

- same-process hostile mutation attempts;
- serialization/reload or fresh-registry reconstruction where applicable.

The original Astra attack must no longer be able to change LONG -> NO_TRADE (or any other output) while retaining the original contract/protocol identity.

## Mandatory AG-03 adversarial tests

Convert the Astra finding into permanent tests. Include at least:

1. top-level parameter mutation attempt;
2. nested mapping mutation attempt;
3. nested list mutation attempt;
4. caller-owned source dict mutated after contract construction;
5. object obtained from registry cannot mutate registered authority;
6. conflicting registration under same contract id/version rejected atomically;
7. stale declared hash vs current semantic content rejected;
8. unchanged valid canonical contract still replays deterministically;
9. protocol hash/producer hash cannot remain unchanged while effective signal semantics change.

Do not weaken the test by merely asserting an exception from a convenience wrapper; exercise the actual formal authority path where possible.

# Part B — AG-04 real health GET read-only repair

## Existing defect

`QuantService.health()` constructs `ForwardDerivativeStore`, whose constructor creates parent directories and initializes/migrates SQLite. Therefore a real GET may write filesystem/database state.

The required invariant is:

```text
GET /health
        =>
no filesystem creation
no SQLite creation
no schema migration
no INSERT/UPDATE/DELETE
```

for all stores it inspects.

## Required behavior

### B1. Separate read-only status inspection from writer initialization

Add or use a genuinely read-only forward-store status path.

It must:

- report missing store without creating the directory or DB;
- inspect an existing valid store without migration;
- fail/degrade safely for missing/unsupported schema;
- never call schema preparation/migration;
- never open SQLite in a mode that can create a missing DB;
- not depend on monkeypatching `QuantService.health` in the acceptance test.

Avoid creating a broad new storage abstraction. Keep the repair local and explicit.

### B2. Preserve writer path

Normal collection/write workflows must still be able to initialize `ForwardDerivativeStore` intentionally. Do not globally make the store constructor read-only if doing so breaks explicit writer ownership.

### B3. Permanent real-handler tests

Tests must invoke the actual `/health` handler/service path with only external network/scheduler behavior isolated as necessary.

Cover:

1. forward directory absent before GET -> remains absent after GET;
2. forward DB absent in existing directory -> remains absent;
3. valid populated DB -> response works and DB bytes/data/schema remain unchanged;
4. unsupported/incomplete schema -> health degrades/fails closed without migration;
5. main runtime repository and forward repository both unchanged before/after the GET.

Use storage-level before/after evidence, not only `method == GET`.
