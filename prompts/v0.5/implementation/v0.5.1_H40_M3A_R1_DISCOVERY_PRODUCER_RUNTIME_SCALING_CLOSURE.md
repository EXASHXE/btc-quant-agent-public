# 5. Required optimization design

Implement exact indexed/precomputed scientific state.

## 5.1 Exact causal percentile index

Preferred design:

```text
all reference scalar values are known from non-future source bars
coordinate-compress exact float values
process reference observations in timestamp order
maintain exact frequency counts in a Fenwick/BIT or equivalent order-statistic index
query count(value < x)
query count(value == x)
derive:
(less_count + 0.5 * equal_indicator) / N
```

Important: current percentile tie rule adds exactly `0.5/N` if at least one equal value exists; it does NOT multiply by the number of ties. Preserve this exact behavior.

For `WF1_TRAIN`, state at decision `t` must include only references with `dt < t`.

For `WF1_CALIBRATION`, use the exact frozen full training reference state.

No future observation may influence an earlier state.

Do not use approximate quantiles or floating-point bucketing.

## 5.2 Share candidate-independent state

Regime and opportunity state are source/product/time/partition dependent, not threshold/calibration-configuration dependent.

Cache or precompute them independently of candidate ID.

Raw direction score may be shared only where the exact direction contract/horizon is identical.

Do not share across different D1/D2/D3 variants.

## 5.3 Geometry index

Precompute exact geometry fallback cells for each owner using the current fallback sequence:

```text
L0 = owner + scope + horizon + side
L1 = owner + scope + horizon
L2 = owner + scope
L3 = owner
```

For every cell preserve:

```text
exact member multiset
len >= 30 eligibility
exact current median MFE
exact current median MAE
same first-eligible fallback order
```

`_geometry_pass()` should become O(1) or O(log N) lookup after index construction, not a full record scan.

## 5.4 Sibling configuration reuse

Current registered roster has sibling configurations sharing direction reconstruction.

The producer may compute immutable raw source decisions once per exact:

```text
direction_contract_id
partition
timestamp
product
horizon
source identity
```

and reuse them across configurations before applying configuration-specific calibration/action policy.

Do not reuse configuration-specific fit/action results.
