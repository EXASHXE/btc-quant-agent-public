## 1. Mission

Close the remaining same-type runtime substitution path.

Current production candidate-lock checks:

```python
type(verifier) is H40ProductionDiscoveryEvidenceVerifier
```

This rejects foreign Protocol implementations, subclasses, and proxies.

However an exact-type instance can still be constructed and have instance-level methods replaced. The repository currently demonstrates this pattern in the lifecycle test fixture:

```python
verifier = object.__new__(H40ProductionDiscoveryEvidenceVerifier)
setattr(verifier, "verify_discovery_manifest", ...)
setattr(verifier, "verify_candidate", ...)
setattr(verifier, "verify_wf_fold", ...)
```

Such an object passes the type check but no longer executes the reviewed scientific implementation.

Production candidate-lock must fail closed if an exact-type verifier's scientific behavior or constructor-bound authoritative dependencies have been substituted.

---

## 2. Required invariant

After this repair, production candidate-lock authority must imply:

```text
the actual scientific behavior executed is the reviewed
H40ProductionDiscoveryEvidenceVerifier implementation,
using constructor-bound authoritative dependencies,
not instance-shadowed or forged substitutes
```

The repair must cover at least:

- `verify_discovery_manifest`
- `verify_candidate`
- any internal call path whose instance-level substitution can alter the scientific result;
- constructor-bound dependencies whose replacement can bypass content-addressed evidence or authority lineage.

Do not merely add another class-name, module-name, verifier-id, or duck-typing check.

---

## 3. Preferred repair shape

Prefer the smallest runtime seal that is strong enough.

A valid solution may combine:

1. preventing instance-level shadowing of reviewed verifier methods;
2. preventing replacement of constructor-bound authoritative dependencies after construction;
3. ensuring production lifecycle dispatch reaches reviewed class implementation rather than arbitrary instance attributes;
4. eliminating `object.__new__` + `setattr` exact-type fake-verifier fixtures from production-mode lifecycle tests.

Potential implementation techniques include:

- a slots/frozen-runtime design that disallows arbitrary instance attributes and protects authoritative constructor state;
- direct class-bound dispatch where necessary;
- an explicit runtime integrity assertion implemented by reviewed class-level code;
- internal construction/factory binding if that is the smallest safe design.

Do not choose a technique only because it makes tests easy.

If a truly adequate repair requires changing a frozen lifecycle/governance contract:

```text
STOP
P3B_RUNTIME_BEHAVIOR_SEAL_REQUIRES_GOVERNANCE_AMENDMENT
```

Do not silently amend governance.

---

## 4. Important subtlety: method dispatch alone may be insufficient

If production lifecycle calls the reviewed class method directly but that method later trusts mutable instance collaborators such as a replaced evidence resolver, the authority gap may remain.

Therefore explicitly audit the verifier's authoritative state, including at minimum:

```text
_resolver
_seal
_receipt
_split
```

and any equivalent dependency capable of changing evidence bytes, lineage, or scientific results.

Mutable per-run caches/results may remain mutable where scientifically necessary, but they must not create a route to substitute authority-bearing behavior.
