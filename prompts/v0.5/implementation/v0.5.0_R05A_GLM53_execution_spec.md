# 3. AG-03 — exact implementation design

## 3.1 Root cause

Current code has:

```python
@dataclass(frozen=True)
class SignalProducerContract:
    ...
    parameters: dict[str, Any] = field(default_factory=dict)
    contract_hash: str = ""
```

The dataclass is frozen but the nested dictionary is not. `contract_hash` is computed once in `__post_init__`, while replay later consumes the live `authoritative_contract.parameters` mapping.

Therefore this is currently possible:

```text
construct contract
  -> hash H
register contract
  -> protocol binds H
mutate contract.parameters
  -> effective producer semantics change
  -> H stays cached
  -> protocol stays unchanged
```

This violates authority identity.

## 3.2 Reuse the repository's canonical immutable JSON machinery

Do **not** invent a new deep-freeze implementation.

The repository already contains in:

```text
src/btc_quant_agent/research_contract/canonical.py
```

these accepted helpers:

```python
FrozenDict
freeze_json
thaw_json
canonical_sha256
```

Use them.

Required design:

1. `SignalProducerContract` must detach from caller-owned mutable aliases at construction.
2. `parameters` must become recursively immutable internally.
3. nested dictionaries become `FrozenDict`/`Mapping`;
4. list/tuple-like JSON sequences become immutable tuples internally;
5. unsupported non-JSON values, including sets, must fail closed through the existing canonical JSON rules — do not add a special set serialization;
6. public serialization (`semantic_payload`, `to_dict`) must return ordinary detached JSON-like dict/list values, not expose internal immutable objects as mutable authority aliases.

Preferred implementation shape:

```python
from collections.abc import Mapping
from ..research_contract.canonical import freeze_json, thaw_json

@dataclass(frozen=True)
class SignalProducerContract:
    ...
    parameters: Mapping[str, Any] = field(default_factory=dict)

    def __post_init__(self) -> None:
        frozen = freeze_json(self.parameters)
        if not isinstance(frozen, Mapping):
            raise TypeError("producer contract parameters must be a JSON object")
        object.__setattr__(self, "parameters", frozen)
        computed = canonical_sha256(self.semantic_payload())
        ... existing declared-hash check ...
```

The exact typing may differ if needed for mypy, but the invariant may not.

`semantic_payload()` should produce a detached canonical JSON value, for example using `thaw_json(self.parameters)` instead of exposing nested immutable internals directly.

### Critical compatibility requirement

This repair changes mutability, **not semantic content**.

For every unchanged default producer contract:

```text
pre-R05A contract_hash == post-R05A contract_hash
pre-R05A canonical semantic JSON == post-R05A canonical semantic JSON
```

If the hashes change, treat it as a defect in your implementation. Do not update expected values, versions or protocols merely to make tests green.

## 3.3 Registry integrity checks

Harden `SignalProducerRegistry.register_contract` and `get_contract`.

### register_contract

Before registration:

```text
recomputed = canonical_sha256(contract.semantic_payload())
recomputed must equal contract.contract_hash
```

Otherwise fail closed.

The registry is keyed by `contract_id`, so the exact conflict rule for R05A is:

```text
no existing contract with id
    -> register

existing contract with same id AND exact same canonical semantic payload/hash
    -> idempotent no-op is allowed

existing contract with same id but any different version/content/hash
    -> raise ValueError; do not replace existing authority
```

Do not silently overwrite a contract under an existing ID.

### get_contract

Before returning the stored contract, recompute its semantic hash and verify it still equals the cached `contract_hash`.

If internal content and cached hash disagree, raise/fail closed. Do not return a stale object.

If the caller supplies an expected `contract_hash` and it differs from the valid stored contract, preserve current “not matching” behavior (`None` or the existing documented fail-closed behavior) unless existing tests require an exception. Do not weaken it.

## 3.4 Formal replay boundary

Do not add a second producer registry or duplicate hashing scheme.

Because `replay_bundle.py` resolves the protocol contract through `SignalProducerRegistry.get_contract`, the registry integrity check should become the single ordinary guard.

Inspect both:

```text
_resolve_protocol_producer_contract(...)
validate_formal_replay_input_bundle(...)
```

If they already transitively call hardened `get_contract`, do not add redundant logic just to increase LOC.

However, add a regression proving that a stale/mutated contract cannot survive the actual formal replay path.

# 4. AG-04 — exact implementation design

## 4.1 Root cause

Current health path does:

```python
ForwardDerivativeStore("data/forward/BTCUSDT/derivatives.sqlite3").status(...)
```

Current writer constructor does:

```text
mkdir parent
_initialize()
sqlite connect
schema preparation / CREATE TABLE / ALTER / WAL
```

A GET therefore owns writer initialization.

The required invariant is:

```text
GET /health
  -> may read existing state
  -> must not create directories
  -> must not create SQLite files
  -> must not create -wal / -shm side files
  -> must not migrate schema
  -> must not INSERT/UPDATE/DELETE
```

## 4.2 Preserve the writer constructor

Do not remove initialization from normal `ForwardDerivativeStore(path)` construction. Existing collector/write workflows deliberately rely on it.

Writer behavior stays writer-owned.

## 4.3 Add a narrow read-only inspection path

Preferred design: add a **separate classmethod / factory / explicit inspection entrypoint** in `forward_store.py` that creates a read-only instance without calling `__init__` writer initialization.

Example conceptual API; naming is your choice:

```python
ForwardDerivativeStore.read_status(path, scheduler=..., ...)
```

or:

```python
ForwardDerivativeStore.open_read_only(path).status(...)
```

Requirements:

1. missing path is checked with `Path` before opening SQLite;
2. missing parent directory must not be created;
3. missing database file must not be created;
4. existing DB is opened using SQLite URI `mode=ro` (or an equally strict no-create mechanism), not a normal writable filename connection;
5. enable `PRAGMA query_only=ON` as defense-in-depth if compatible;
6. read-only connection must not call `prepare_schema`, `finish_schema`, CREATE, ALTER, journal-mode mutation or commit writes;
7. existing `status()` query logic should be reused where practical — do not fork/copy hundreds of lines into a second status implementation;
8. existing schema validation may run if it is strictly observational; missing/incompatible schema must degrade/fail closed rather than migrate.

Do not use `immutable=1` as a casual shortcut against an actively written WAL database unless you can prove its correctness for this store; `mode=ro` is preferred. The health endpoint is observational and may return DEGRADED if the store cannot be safely read without mutation.

A small internal `_read_only` flag plus a read-only factory is acceptable if it remains local to this class and the normal constructor remains writer mode.

## 4.4 Suggested connection behavior

Conceptually:

```text
writer instance:
  sqlite3.connect(path)
  existing writer initialization/migrations remain unchanged

read-only inspection instance:
  require file already exists
  sqlite3.connect(file URI with mode=ro, uri=True)
  PRAGMA query_only=ON
  SELECT / PRAGMA inspection only
  no schema preparation
  no writer commit behavior
```

Be portable across Linux CI and normal Windows development paths. Prefer a correctly constructed SQLite file URI from an absolute `Path` rather than manual string concatenation that breaks drive-letter paths.

## 4.5 Missing-store response compatibility

Before editing, record the key set of `ForwardDerivativeStore(...).status()` on a freshly initialized empty store.

The new health read-only missing-store response should preserve the existing public shape as much as practical so API consumers do not break, but it must truthfully report at least:

```text
store_exists = false
health = DEGRADED
sample_count = 0
collection_status = NOT_COLLECTING (or the closest existing truthful state)
```

If preserving every nested zero-valued metric would require duplicating large status logic, prefer a small explicit degraded/missing-store response and add tests for the exact supported contract. Do not create an empty DB merely to preserve old output shape.

## 4.6 Unsupported/incomplete schema

A malformed or legacy-incomplete DB inspected by GET must not be migrated.

Acceptable behavior:

```text
health overall DEGRADED
forward_derivatives.health DEGRADED
stable error/classification showing store is unreadable/incompatible
```

Unacceptable behavior:

```text
ALTER TABLE
CREATE TABLE
schema version write
silent repair
500 caused by an unhandled store-inspection exception if health can safely report degraded status
```

Keep error text concise; do not leak secrets.

## 4.7 Service integration

`QuantService.health()` must use only the new read-only status/inspection path.

Do not instantiate the writer-mode `ForwardDerivativeStore(...)` from `health()`.

External connectivity checking may remain as current behavior. Tests may mock Binance connectivity and scheduler metadata; they may not monkeypatch `QuantService.health()` itself.
