# 3. RG-B02-01 — verify committed lineage before membership

Current problematic pattern in:

```text
src/btc_quant_agent/h40/lifecycle_authority.py
H40LifecycleArtifactStore._get_committed_lineage()
```

is conceptually:

```text
trusted durable head hash
-> open file for hash
-> read raw upstream_receipt_hash
-> treat that upstream hash as committed lineage
-> repeat
```

This is insufficient because a corrupted committed receipt file can advertise an orphan hash as its predecessor.

## Required invariant

Committed-lineage membership is authoritative only after the entire chain from the durable head to genesis has been verified.

A receipt hash must NOT be admitted to lineage merely because another raw JSON object names it in `upstream_receipt_hash`.

## Required implementation behavior

Implement a private lineage verifier/traversal that starts from the authoritative SQLite durable head and verifies every hop before admitting membership.

At minimum verify for every traversed node:

```text
1. expected current hash is valid SHA-256 identity
2. exact content-addressed receipt file for that hash is located
3. envelope is a valid mapping with expected lifecycle envelope structure
4. envelope receipt_sha256 equals expected current hash
5. typed receipt object parses successfully
6. canonical recomputed typed receipt hash equals expected current hash
7. receipt run_authority_id matches requested run
8. receipt source/target semantics are valid for its receipt type
9. upstream_receipt_hash type is valid
10. accepted source->target adjacency is preserved
11. no cycle exists
12. predecessor chain is unique and deterministic
```

For the head node additionally require exact equality with durable-head metadata:

```text
receipt hash == head.head_receipt_hash
receipt target state == head.head_state
receipt upstream hash == head.head_predecessor_receipt_hash
```

Where sufficient information exists, also bind sequence position to the durable head:

```text
head transition_sequence == number of predecessor edges from genesis
```

Do not infer authority from legacy mirror files.

The content-addressed receipt chain is authoritative evidence for lineage only after verification.

## Preferred reuse

Reuse existing receipt/envelope parsing/hash helpers where possible.

Do not create a second inconsistent receipt parser.

Do not call `_cold_restore_authorization()` recursively merely to discover membership if that creates circular semantics or excessive source revalidation.

Membership verification should be structural/cryptographic; cold restore can then perform the existing semantic/source revalidation for the selected member.

## Restore rule

`restore_authorization()` must:

```text
1. load authoritative durable head
2. derive VERIFIED committed lineage from head
3. resolve target receipt
4. require exact target receipt hash membership in verified lineage
5. cold-restore/revalidate the target
```

If any traversed committed receipt is malformed/hash-mismatched/predecessor-inconsistent:

```text
fail closed for restoration
```

even if the requested target receipt itself is valid.

# 4. RG-H01-01 — receipt durability on every commit path

Current problematic pattern in `persist_authorization()`:

```text
new receipt:
    write + file fsync + link + required receipt-directory fsync

existing identical receipt:
    byte compare only
    no required receipt-directory fsync

then durable head commit
```

## Required invariant

Before EVERY authoritative head commit referencing a receipt:

```text
receipt bytes are complete
AND
immutable final receipt exists with exact bytes
AND
authoritative receipt directory durability step succeeds
THEN
SQLite durable-head commit may occur
```

Presence of identical bytes is not proof that a previous directory fsync completed.

## Required implementation behavior

Refactor publication flow so that after the final immutable receipt path is known to contain exactly the expected bytes:

```text
_fsync_dir(receipts_dir, fail_closed=True)
```

or an equivalent stronger fail-closed durability step is executed on the current committing path before `_commit_run_head()`.

This applies to:

```text
new publication
pre-existing identical receipt
FileExistsError from concurrent identical publisher
retry after a prior publication failed at directory fsync
```

The implementation must preserve:

```text
immutable content-addressed receipt files
no different-byte overwrite
no os.replace on authoritative receipt
complete file fsync before initial link
SQLite head as sole lifecycle commit point
orphan receipt has no authority
optional legacy/head mirrors are non-authoritative
```

## Concurrency property

If publisher A has linked the receipt but has not successfully completed authoritative directory durability:

publisher B must not be able to commit the head merely because it sees identical final bytes.

B must itself complete the required authoritative directory durability step before its head transaction.
