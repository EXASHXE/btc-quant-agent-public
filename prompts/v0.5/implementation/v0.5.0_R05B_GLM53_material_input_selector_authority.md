## Why this exists

At current HEAD, `build_formal_replay_input_bundle()` accepts caller-selected `input_references` or caller-selected `observation_open_times_ms`. It validates that referenced rows exist, are available, content-hashed and ordered. `CanonicalRuleSignalProducer.replay_signal()` checks only a minimum lookback and that the supplied rows match the supplied generation contract.

Therefore the system proves:

```text
"these selected rows are genuine"
```

but not:

```text
"these are the complete preregistered rows this producer was required to use"
```

Astra reproduced, under one unchanged protocol/dataset/producer contract, a momentum producer with `lookback_bars=2` where caller selections `[2,3]`, `[0,3]`, and `[0,1,3]` were all rehashed/cold-replayed; the selected window changed LONG to SHORT while remaining formally promotable.

## Required selector semantics

Implement one pure authority function, with one owner only. Suggested names:

```python
resolve_material_input_policy(contract)
select_required_material_candles(contract, candles, signal_timestamp_ms)
```

Do not duplicate selector logic separately in bundle construction and bundle verification. Both must call the same pure reconstruction function; verification must still independently invoke it from the frozen dataset rather than trusting persisted references.

### Supported canonical candidate semantics

For `CANONICAL_RULE_SIGNAL_PRODUCER` candidate contracts:

#### RETURN_SIGN

Required material set = exactly the latest **1** eligible canonical candle.

If contract parameters explicitly declare `lookback_bars`, it must equal 1. A contradictory value must fail closed rather than silently changing selector meaning.

#### MOMENTUM_THRESHOLD

Required material set = exactly the latest **N** eligible contiguous canonical candles, where:

```text
N = int(contract.parameters["lookback_bars"])  if present
N = 1                                            if absent and min_lookback_bars absent
```

`N >= 1` is mandatory.

If only `min_lookback_bars` is present without exact `lookback_bars`, fail closed with an explicit ambiguity error. A minimum is not a complete selector.

If both exist, they must agree or fail closed.

#### PRICE_BREAKOUT

Required material set = exactly latest 1 eligible canonical candle because current rule uses only the terminal close. If `lookback_bars`/`min_lookback_bars` is declared, it must equal 1.

#### FIXED_DIRECTION

This remains synthetic test-only. For a candidate synthetic positive-control contract, require exactly latest 1 eligible candle. Do not relax its existing synthetic-only boundary.

#### RANDOM_MATCHED_OPPORTUNITY

Do not redesign RANDOM_MATCHED benchmark selection in R05B. Existing independent RANDOM benchmark reconstruction remains authoritative. Apply the new exact candidate selector to `CANDIDATE` role; preserve benchmark-role semantics unless an existing test requires a strictly mechanical adaptation.

## Eligible candle definition

A candle is eligible at `signal_timestamp_ms` only when all are true:

```text
closed is True
available_at_ms is not None
available_at_ms <= signal_timestamp_ms
close_time_ms <= signal_timestamp_ms
```

For the reconstructed required window:

- all rows must have the same symbol;
- all rows must have the same interval;
- open times strictly increase;
- adjacent required rows must be contiguous: `next.open_time_ms == previous.close_time_ms + 1`;
- duplicate open times fail closed;
- if fewer than N eligible rows exist, fail closed;
- a gap inside the last-N window fails closed; do not silently step further backward around a missing material row.

The full dataset may contain rows after the decision timestamp; they are simply ineligible. Do not allow their presence to affect the selected pre-decision window.

## Authority reconstruction in bundle construction

Change `build_formal_replay_input_bundle()` so, for candidate entries:

1. resolve the protocol-bound authoritative producer contract exactly as today;
2. reconstruct `expected_candles = select_required_material_candles(...)` from the full `candles` sequence and signal timestamp;
3. build canonical expected `InputReference` objects from those candles;
4. treat caller-provided `input_references`, `observation_open_times_ms`, and `material_input_open_times_ms` only as assertions:
   - if absent, populate from reconstructed expected references;
   - if present, require exact equality with reconstructed references/open-times;
   - omitted row, substituted row, earlier row, extra row, reordering, duplicated row, or changed availability/hash must reject;
5. compute `input_set_sha256` only from the reconstructed canonical references;
6. overwrite generation-contract material-input fields from the reconstructed set, never from caller choice:

```text
material_input_open_times_ms
expected_preimage_sha256
min_lookback_bars   # set to exact required N for compatibility
```

Recommended additional audit fields, generated by the builder and recomputed by validator:

```text
material_input_selector_type = "LATEST_N_CONTIGUOUS_AVAILABLE_CLOSED"
material_input_required_bars = N
material_input_selector_sha256 = canonical_sha256(effective selector policy)
```

Do not accept caller values for these fields unless they exactly match the reconstructed policy.

## Cold verifier requirement — critical

`validate_formal_replay_input_bundle()` must independently repeat selector reconstruction from:

```text
full candles
signal_timestamp_ms
registered producer contract
expected role
```

before calling `producer.replay_signal()`.

It must require the persisted `entry["input_references"]` to exactly equal the independently expected canonical references. Merely checking every persisted reference individually is insufficient.

This is the core security property:

```text
candidate can rehash every outer artifact
        ↓
verifier still reconstructs a different authoritative required set
        ↓
submission fails
```

## Producer-level defense in depth

`CanonicalRuleSignalProducer.replay_signal()` does not possess the full dataset, so it cannot prove latestness. Do not pretend it can.

It should, however, enforce all completeness properties available locally:

- exact required count, not `len >= min_lookback`;
- rule/contract lookback consistency;
- strict ordering;
- same symbol/interval;
- adjacent contiguity for N > 1;
- explicit closed/availability cutoff checks already present;
- persisted generation-contract selector metadata must match the effective policy if present.

The bundle validator remains the authority for "latest required rows from the full frozen dataset".
