## 2. Relevant current authority chain

Current R05C already establishes:

```text
ComparisonContract.funding_interval
→ preregistered comparison hash
→ funding EvidenceReference
→ strict funding evidence bytes
→ authoritative FundingSettlement tuple
→ candidate / passive / random / cold replay
```

The current gap is later in the chain:

```text
candidate_run.identity.funding_evidence_id
        ↓
qualification(required_evidence_ids=caller supplied)
        ↓
attestation.required_evidence_ids
        ↓
registry requires only those ids that qualification declared
```

Therefore if qualification construction omits the funding id, registry cannot infer it independently.

The repair must make the run-bound funding evidence id a mandatory invariant of every current formal qualification.

## 3. Required production changes

### 3.1 `economic/qualification.py` — evaluator boundary

In `evaluate_formal_economic_qualification(...)`, after normalizing `required_evidence_ids`, derive:

```python
funding_id = candidate_run.identity.funding_evidence_id
```

Require:

```python
funding_id in evidence_ids
```

If absent, fail closed with a stable error containing wording equivalent to:

```text
qualification required evidence omits bound funding evidence
```

Do not silently auto-insert the id. Caller omission must be rejected visibly.

Retain existing uniqueness/non-empty validation.

### 3.2 `EconomicQualificationResult.__post_init__()` — object invariant

After tuple-normalizing `required_evidence_ids`, require:

```python
self.run_result.identity.funding_evidence_id in self.required_evidence_ids
```

Reject direct object construction that violates this invariant.

This protects construction paths that bypass `evaluate_formal_economic_qualification()`.

Do not change qualification gate semantics, benchmark semantics, verdict logic, or schema version unless absolutely required. A schema bump should not be necessary for this repair.

### 3.3 `economic/acceptance_verifier.py` — cold persisted verification

In `validate_persisted_qualification_semantics(...)`:

1. obtain persisted `run_identity`;
2. obtain `funding_evidence_id = run_identity.get("funding_evidence_id")`;
3. require it to be a non-empty string;
4. read persisted `semantic.required_evidence_ids`;
5. require the bound funding evidence id to be present.

This must be an independent cold check.

An attacker must not be able to:

```text
remove funding id from required_evidence_ids
→ recompute semantic hash/result id
→ pass cold validation
```

Do not use an externally supplied funding id for this check. Derive it from the persisted run identity.

### 3.4 `ComparisonContract.__post_init__()` — coverage identity invariant

Require exact equality:

```python
funding_interval.coverage_start_ms == data_interval.start_ms
funding_interval.coverage_end_ms == data_interval.end_ms
```

Reject mismatch immediately during comparison construction.

Do not change valid current contract semantics.

### 3.5 `economic/funding_evidence.py` — low-level independent coverage check

At the start of `load_and_validate_funding_evidence(...)`, before accepting the evidence document, require:

```python
expected_identity.coverage_start_ms == expected_start_ms
expected_identity.coverage_end_ms == expected_end_ms
```

Then retain the existing check that the document's coverage equals `expected_start_ms/end_ms`.

The identity coverage and file coverage must both independently bind to the same comparison interval.
