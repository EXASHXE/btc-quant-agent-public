The existing seam is:

```python
class H40LifecycleEvidenceVerifier(Protocol):
```

## 4. Production evidence loading

Implement a production content-addressed evidence loader/resolver.

Preferred new module:

```text
src/btc_quant_agent/h40/discovery_evidence.py
```

or another narrowly named H40 module if existing structure strongly favors it.

Requirements:

1. Caller supplies an approved evidence root, not arbitrary evidence file paths per metric.
2. Every evidence object is addressed by lowercase SHA-256.
3. Resolver maps a digest deterministically to one object under the approved root.
4. Read bytes, parse JSON, require exact accepted schema.
5. Recompute canonical SHA-256 from parsed semantic object and require equality to requested digest.
6. Reject missing, malformed, extra-field, non-finite, wrong-schema, wrong-run, wrong-candidate, wrong-roster, wrong-source/split, or wrong-contract evidence.
7. Path traversal and symlink escape must fail closed.
8. A filename/path alone never establishes authority.
9. Caller summaries, rank fields, winner flags, or precomputed booleans never establish authority.
10. Production verifier recomputes all accepted gates/corrections from lower-level canonical inputs.

Do not reuse `H40SyntheticEvidenceVerifier` internally.

Do not set `synthetic_only=False` on synthetic logic.

The returned values must be derived from accepted raw evidence and accepted correction manifests, not copied from an "adjusted_lcb" summary field.

If the accepted contract requires intermediate corrected p-values or max-stat distributions, recompute them internally from the bound evidence.
