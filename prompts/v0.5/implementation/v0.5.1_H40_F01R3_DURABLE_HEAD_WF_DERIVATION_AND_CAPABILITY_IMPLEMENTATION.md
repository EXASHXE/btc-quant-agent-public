
Do not add a caller nonce.

A content hash property may be derived from the exact canonical fields; do not silently add an extra persisted canonical field unless required by the accepted contract.

## 4.2 One committed head per run

For every:

```text
run_authority_id
```

there is exactly one committed authoritative head.

A receipt existing on disk is NOT enough to be committed history.

Authority is:

```text
committed durable head
+
its unique content-addressed ancestor lineage
```

A sibling receipt may exist physically but is an uncommitted orphan and grants zero transition authority.

## 4.3 Do NOT implement head concurrency as os.replace CAS

Forbidden design:

```text
read head.json
check predecessor
write temp
os.replace(head.json)
```

alone.

Reason:

Two writers can both read the same old head and each replace it. Atomic rename is not compare-and-swap.

## 4.4 Recommended linearizable implementation

Use SQLite for the run-head transaction unless repository constraints make an equivalent stronger mechanism clearly preferable.

Recommended table:

```sql
CREATE TABLE h40_lifecycle_run_heads (
    run_authority_id TEXT PRIMARY KEY,
    head_receipt_hash TEXT NOT NULL,
    head_state TEXT NOT NULL,
    head_predecessor_receipt_hash TEXT,
    transition_sequence INTEGER NOT NULL,
    terminal INTEGER NOT NULL,
    head_json TEXT NOT NULL
)
```

Exact storage placement may follow repository architecture.

Use durability-oriented settings appropriate to the repository; at minimum reason about:

```text
PRAGMA journal_mode=WAL
PRAGMA synchronous=FULL
```

For each head advance:

```text
BEGIN IMMEDIATE

load current head for run_authority_id

verify:
- current terminal == false
- supplied expected predecessor == current head receipt hash
- next sequence == current sequence + 1
- run identity matches
- transition is allowed
- proposed receipt target state matches proposed head state

perform conditional INSERT/UPDATE

COMMIT
```

The transaction/conditional update is the single-winner compare-and-advance authority.

For first committed receipt, define one deterministic initial sequence convention and test it. Recommended:

```text
first committed lifecycle receipt sequence = 0
```

Do not derive authorization from arbitrary filename/key.

## 4.5 Terminal behavior

```text

NOT_TESTABLE
```

This must survive:


# 5. Receipt publication / crash protocol

## 5.1 Content-addressed immutable receipts

Prefer:

```text
artifacts/h40/lifecycle/runs/<run_authority_id>/receipts/<receipt_hash>.json
```

rather than authority-bearing caller keys.

Legacy caller labels may remain only as non-authoritative compatibility metadata if necessary.

## 5.2 Publication order

Before head commit:

1. construct full canonical receipt/evidence envelope bytes in memory;
2. compute content identity;
3. write to a unique temp file in the same filesystem/directory;
4. flush;
5. `fsync(temp_fd)`;
6. close;
7. atomically publish as immutable content-addressed final receipt without overwriting different bytes;
8. `fsync(receipts_directory)`;
9. only then enter the durable-head compare-and-advance transaction;
10. commit head.

Do not use unconditional `os.replace` over an existing immutable receipt.

If final receipt already exists:

- exact identical bytes + complete reverification -> idempotent candidate;
- different bytes -> fail closed.

## 5.3 Commit point

The lifecycle transition becomes committed only when the durable head transaction commits.

Before that point:

```text
receipt may exist
but transition is uncommitted
```

## 5.4 Crash recovery

Implement and test:

```text
C1 crash before temp receipt complete
C2 temp complete but final receipt absent
C3 final receipt durable but head not advanced
C4 head transaction aborted/interrupted
C5 head transaction committed
```

Required meanings:

- C1/C2: previous committed head remains authority;
- C3: receipt is orphan/uncommitted; previous head remains authority;
- C4: SQLite transactional outcome determines old-or-new committed head, never partial logical head;
- C5: new head is authority.

Startup/restore may clean safe temp files but must never silently delete a conflicting immutable receipt.
