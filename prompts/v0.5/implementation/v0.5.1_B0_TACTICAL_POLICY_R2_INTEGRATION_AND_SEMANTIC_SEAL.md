# 6. B0-01 — fix elapsed-time return semantics

Current generic timeframe ROC uses a 12-bar lookback.

This creates:

```text
15m snapshot ROC = 3h
1h snapshot ROC = 12h
4h snapshot ROC = 48h
```

but some code/docs refer to the 1h snapshot ROC as a 1h return/shock.

This ambiguity must be removed.

## Required implementation

Introduce explicit elapsed-time return helpers based on closed bars.

Preferred API shape:

```python
def closed_bar_return(
    candles: Sequence[Candle],
    *,
    horizon_ms: int,
) -> float | None:
    ...
```

or an equivalent typed API.

Requirements:

```text
strict closed-bar only
no forming bar
exact elapsed-time semantics
explicit insufficient-history result
deterministic
```

Add explicit MarketWatch decision features needed immediately:

```text
return_1h
return_4h
return_12h
```

Do not overload one ambiguous `roc` field with multiple time meanings.

Compatibility:

- existing `roc` may remain temporarily only if clearly renamed/documented as a bar-count feature;
- new policy logic that claims “1h return” must use the explicit 1h feature.

Critical regression:

```text
BTC downside shock logic must use true 1h return,
not 12 × 1h bars.
```

Update documentation accordingly.

# 7. B0-02 — close EMA200 config/implementation drift

Current config declares:

```text

```

but slow EMA is not a reliable active snapshot semantic.

B0 must eliminate the configured-but-no-op state.

## Required design

Implement `ema_slow` as an **observational feature only** in B0.

Do not change playbook eligibility/ranking because of EMA200 in B0.

Requirements:

```text
TimeframeSnapshot exposes ema_slow
enough confirmed historical candles are fetched
insufficient history is explicit
no forming-bar influence
config hash binds ema_slow
docs distinguish observational vs policy-active features
```

The scanner should request sufficient bars based on configured periods, not a hard-coded depth that is smaller than `ema_slow`.

Use a bounded deterministic formula such as:

```text
required_bars =
max(
  ema_slow + slope_lookback + warmup_margin,
  ADX/ATR/BB/pivot requirements,
  existing strategy lookbacks
)
```

Choose/document a small explicit warmup margin; do not choose it from outcomes.
