## Required semantics

### 1. Production authority mode must not be caller-selectable

Any public API whose success means "this H40 split is production authoritative" must always enforce production canonical source rules.

Do not allow the caller to pass a policy/mode/flag that disables canonical source checks.

Preferred minimal shape:

```python
H40SplitManifest.materialize_authoritative(
    protocol_identity_hash,
    source_manifest,
    repo_root,
    ...
)

split.assert_authoritative(
    source_manifest,
    repo_root,
)
```

with no public `authority_policy` escape hatch.

Synthetic fixtures may still exercise generic byte/timestamp/split mechanics through separate helpers, but those helpers MUST NOT produce a production-authoritative split and MUST NOT return an object that can be accepted by the production authority verifier.

If `H40AuthorityPolicy` remains for internal/test mechanics, it must not be exported as a production authority control and must not be accepted by production authority APIs.

### 2. Do not fabricate a production BTC source

The accepted protocol/reference currently points `BTCUSDT_USD_M_1H` to:

```text
data/research/BTCUSDT/data_manifest.json
```

and the real environment demonstrates that this object is a legacy 1m manifest, not the exact required H40 1h source artifact.

Therefore current H40 production BTC split-source authority is:

```text
NOT_TESTABLE
```

until a separately authorized protocol/source amendment freezes an exact 1h artifact and lineage.

Do NOT make production authority succeed by writing a new caller-created 1h JSON file at the same canonical locator.

Do NOT treat the historical/legacy reference hash as authority for a different newly created artifact.

Do NOT silently invent a new canonical BTC locator.

P1 may be accepted with production split materialization unavailable because a required source is `NOT_TESTABLE`.

### 3. Canonical source spec must encode authority availability explicitly

Refine canonical source specification so production code can distinguish:

```text
semantic identity is preregistered
vs
exact production artifact authority is established
```

For ETH, if the accepted protocol really freezes and the executing environment reproduces the exact artifact/checksum identity, production verification may remain supported.

For BTC, with the current protocol/reference, production 1h split-input authority must fail closed.

A suitable implementation may add an explicit field/status such as:

```text
production_authority_state = VERIFIED / NOT_TESTABLE
```

or equivalent deterministic semantics. Do not invent a positive current BTC authority identity.

### 4. Preserve all previous authority closures

Do not weaken:

- canonical locator/product/cadence checks;
- protected H39/Final Holdout guards;
- mandatory cold `repo_root` verification;
- file SHA / membership / count verification;
- cold split reconstruction;

### 5. Make P1 tests hermetic

Tests must not require untracked/large local BTC/ETH files to exist.
