## Repair A — Confirmation readiness must not be caller-forgeable

Current P1 exposes `H40ConfirmationGuard(is_confirmation_ready=True)` and arbitrary lifecycle initial states. Remove that authority bypass.

### Required semantics

- During P1/P1R, confirmation outcome access is hard-denied.
- There is no public caller-controlled boolean, enum, constructor parameter, deserialized field, or mutable property that can grant outcome access.
- A future separately authorized task may introduce a content-addressed `H40_CONFIRMATION_READY` attestation/capability. P1R must not invent that future authority now.
- Metadata/timestamp/hash access remains allowed.
- `H40LifecycleStateMachine` construction must not allow arbitrary initialization into `H40_DISCOVERY`, `H40_CANDIDATE_LOCKED`, `H40_WALK_FORWARD_VALIDATED`, `H40_CONFIRMATION_READY`, or `H40_CONFIRMATION_EVALUATED_ONCE` merely from a caller-supplied state.
- P1/P1R may initialize only at an allowed pre-research state (`H40_PREREGISTERED` or `H40_P1_SCAFFOLDED`, choose the simplest repository-consistent contract). Later transitions remain sequential scaffolding, but no constructor shortcut is allowed.

### Mandatory attacks

- constructing an unlocked confirmation guard must be impossible;
- deserializing/forging `is_confirmation_ready=true` must not unlock;
- constructing lifecycle directly at `H40_CONFIRMATION_READY` must fail;
- constructing directly at `H40_CONFIRMATION_EVALUATED_ONCE` must fail;
- metadata access still succeeds;
- outcome access still fails closed.

## Repair B — Protected source authority must be independent of caller labels

A source marked VERIFIED by the caller must still never cause H39 or Final Holdout content to be opened.

### Required semantics

Before any source filesystem operation that could inspect content — including `exists`, `stat` if it follows links, `read_bytes`, parsing, hashing, parquet/CSV open — enforce protected-surface authority independently of `H40SourceStatus`.

At minimum:

- check the original locator/path through `H40ProtectedSurfaceGuard`;
- resolve/canonicalize the candidate path safely and check the resolved path as well where possible, so a benign-looking symlink/relative path cannot trivially target a protected tree;
- reject protected source IDs/locators even if status is forged to VERIFIED;
- a re-hashed serialized manifest must not bypass the protected authority;
- do not open H39/Final Holdout artifacts in tests; use temporary synthetic directories/paths that exercise the guard semantics.

Do not rely solely on substring tests after the file has already been opened.

### Mandatory attacks

- `H40SourceRecord(status=VERIFIED, locator="data/research/h39_validation/...")` fails before read;
- same for Final Holdout;
- serialized/re-hashed manifest with FORBIDDEN→VERIFIED fails;
- relative-path / normalized-path variant fails;
- symlink-like resolved-path attack is covered using synthetic temporary paths without touching actual protected data.

## Repair C — Materialized source and split authority from verified timestamp evidence

Separate *preregistered schedule constants* from *materialized source/split authority*.

Current `H40SplitManifest.build_default()` assumes a continuous hourly calendar. That is not sufficient authority.

### Required semantics

1. A manifest may not claim a source is `VERIFIED` for H40 use merely because expected metadata/hash strings are embedded in code.
2. Materialized VERIFIED source records must be backed by an explicit validation receipt produced from the exact local artifact bytes/timestamps for that run/environment.
3. The validation receipt must bind, as applicable:
   - logical source ID;
   - exact locator;
   - exact byte SHA-256 of the local artifact actually inspected;
   - product and interval/cadence;
   - timestamp field semantics;
   - timestamp count;
   - first/last timestamp;
   - duplicate count;
   - gap count/ranges;
   - timestamp-membership hash;
   - archive/checksum identity when separately available.
4. Historical/report identities may be expected/reference values, but they do not by themselves grant VERIFIED status. Compare actual local receipts against expected identities where appropriate.
5. If exact local artifacts are absent or cannot be parsed under P1 restrictions, record `MISSING`/`NOT_TESTABLE`/`UNVERIFIED` fail-closed. Do not substitute.
6. The authoritative split builder must accept verified timestamp authority and compute membership from the trustworthy BTC/ETH common timestamp intersection required by BASE, applying:
   - 720h lookback reservation;
   - fixed half-open WF/calibration/purge/validation boundaries;
   - confirmation boundaries;
   - complete 24h endpoint constraint;
   - actual gaps/duplicates.
7. Do not shift a boundary to recover sample size.
8. Source gap/membership changes must alter the split hash/counts or fail the build. They cannot be hidden by a synthetic continuous range.
9. A convenience function may still expose the preregistered schedule, but it must be named/typed so it cannot be mistaken for materialized verified split authority.

### Data restrictions

You may inspect unprotected artifact bytes and timestamps only as authorized by P1. Do not parse OHLC/funding/flow values into labels/features/outcomes.

### Mandatory attacks/tests

Use synthetic timestamp-only fixtures when possible:

- source file byte change changes/fails validation receipt;
- wrong product fails;
- wrong cadence/interval fails;
- duplicate timestamp fails or marks source incomplete/NOT_TESTABLE;
- one missing hour is persisted as a gap;
- pooled BTC/ETH intersection drops a timestamp missing from either side;
- split count/hash changes when one valid source timestamp is removed;
- confirmation endpoint constraint removes timestamps without complete 24h future coverage;
- no boundary shifts occur after gaps;
- default/materialized builder cannot return authoritative VERIFIED split from metadata constants alone.

If local repository data needed to reproduce the implementation report are unavailable in the agent environment, do not fake them. Implement the validator/materializer and report the affected source as `NOT_TESTABLE` in the local receipt.
