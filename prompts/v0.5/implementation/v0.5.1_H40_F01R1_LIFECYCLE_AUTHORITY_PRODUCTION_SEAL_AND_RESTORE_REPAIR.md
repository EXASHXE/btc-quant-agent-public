# 3. Repair production source/split authority

Current defect:

Production seal creation accepts independent caller strings:

~~~text

split_manifest_hash
split_attestation_hash
~~~

This is forbidden.

Production authority must derive these identities from typed verified authority objects.

Implement a production factory conceptually like:

~~~text
H40RuntimeSnapshotSeal.from_verified_authority(
    source_manifest=H40SourceManifest,
    split_manifest=H40SplitManifest,
    repo_root=...
)
~~~

Exact naming is flexible; semantics are not.

Mandatory behavior:

1. require typed H40SourceManifest;
2. require typed H40SplitManifest;
3. require non-empty repo_root;
4. invoke existing split_manifest.assert_authoritative(source_manifest, repo_root);
5. require production-canonical attestation;
6. derive source_manifest_hash from source_manifest.manifest_hash;
7. derive split_manifest_hash from split_manifest.split_hash;
8. derive split_attestation_hash from split_manifest.attestation.attestation_hash;
9. bind accepted H40 protocol/source authority;
10. never accept those three hashes independently in production construction.

Hash-only creation is allowed only in an explicitly synthetic/test-only factory.

Do not duplicate source/split validation logic if the accepted P1/P2 path already owns it.
