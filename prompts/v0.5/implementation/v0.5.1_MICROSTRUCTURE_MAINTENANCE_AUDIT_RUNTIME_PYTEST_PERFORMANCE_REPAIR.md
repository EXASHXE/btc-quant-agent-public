## 5. Pytest performance optimization

Optimize from measured durations. Static review already identified likely hotspots in tests/test_microstructure_status_incremental_performance.py:

- P01: 100,000 Python-level SQLite execute calls.
- brute-force reference helper enumerating 1-second buckets across full synthetic days.
- P11-P15 repeatedly finalizing/rebuilding full-day summaries.
- production cold summary construction enumerating 86,400 1-second buckets per finalized day.

Preferred optimizations, in order:

### 5.1 Make the 100k scale test cheap without reducing scale

Keep the explicit >=100,000 raw-gap scale property, but replace Python per-row conn.execute loops with an efficient bulk/streaming insertion method such as executemany with a generator or an equivalent SQLite-side generation technique.

Do not lower the scale below 100k unless a separate explicit 100k acceptance test remains.

### 5.2 Shorten synthetic time horizons where the contract does not require a full day

For semantic equivalence tests, choose campaign/evaluation windows near partition boundaries so 1-second bucket enumeration covers minutes rather than 24-48 hours.

Preserve the property each test is intended to cover:
- partial first day
- cross-midnight gap
- cross-midnight coverage
- finalized + active composition
- cache miss/hit equivalence

Do not keep full-day synthetic history merely because the filename is a daily partition if the asserted semantic can be exercised in a much smaller bounded window.

### 5.3 Remove redundant expensive setup

Where multiple tests independently rebuild identical expensive finalized fixtures, factor bounded fixtures/helpers if isolation and mutation safety remain explicit.

Do not share mutable SQLite files across tests in a way that creates order dependence.

### 5.4 Preserve reference independence

The semantic reference must remain independent of the production optimized implementation.

It is acceptable to optimize the reference algorithm itself if it remains a separate implementation and produces exact expected values.

### 5.5 Do not hide the cost

Do NOT:
- xfail performance tests
- skip the whole new regression file by default
- delete assertions
- reduce integrity coverage
- weaken audit behavior
- change H40 tests/science to make the total look faster

A dedicated explicit scale marker/tier is allowed only if:
- default pytest retains a bounded semantic equivalent;
- the >=100k scale check remains an explicit named acceptance gate;
- the report shows default-suite time AND scale-gate time separately.
