## Mission

Close exactly this blocker:

```text
P1RRR-F1 HIGH — canonical H40 source root is caller-substitutable
```

P1RRR correctly requires cold files and reconstructs the split from them. However, the verifier currently proves only that supplied files match a caller-supplied `H40SourceManifest`; it does not independently prove that the manifest/source records are the preregistered H40 BTC/ETH source authority.

A caller must not be able to create arbitrary local parquet files under an arbitrary root, label them with the canonical BTC/ETH source IDs, create VERIFIED receipts, and thereby obtain an authoritative H40 split.

Do not redesign the split math, confirmation guard, lifecycle, economic kernel, or H40 research protocol.

## Governing invariant

H40 authority requires all three layers:

```text
1. semantic source identity / preregistered provenance
2. exact artifact bytes + timestamp membership
3. exact deterministic split reconstruction
```

P1RRR now enforces layers 2 and 3. P1R4 must enforce layer 1 without weakening 2 or 3.

The original P1 rule is authoritative:

```text
If an exact required artifact is absent:
- do not substitute another source;
- do not loosen PIT semantics;
- do not infer its hash from an old report;
- record MISSING / UNVERIFIED / NOT_TESTABLE as appropriate.
```

## Required semantics

### 1. Define immutable canonical source specifications

For the canonical H40 source IDs used by split authority, independently derive their permitted semantic source specification from the preregistered protocol/reference authority, not from the caller materialized manifest.

At minimum for:

```text
BTCUSDT_USD_M_1H
ETHUSDT_USD_M_1H
```

bind the protocol-authorized fields needed to prevent source substitution, including as applicable:

```text
source_id
product
cadence / interval
source family/type
canonical/preregistered locator or immutable source locator identity
allowed role
origin/provenance identity
reference raw/normalized content identity when the accepted protocol actually freezes one
archive/checksum lineage identity when the accepted protocol freezes one
protocol_identity_hash
```

Use existing BASE/P1 semantics. Do not invent a new market source merely because it is convenient.

### 2. Materialized source authority must prove correspondence to canonical spec

A `VERIFIED` record is not sufficient merely because:

```text
its file exists
+ its receipt matches the file
+ its source_id says BTCUSDT/ETHUSDT
```

Before the record may feed `materialize_authoritative(...)` or `assert_authoritative(...)`, independently verify that it corresponds to the canonical source spec.

A caller-created `H40SourceManifest` must not be able to redefine:

- locator;
- product;
- cadence;
- provenance/source family;
- expected archive/checksum identity;
- protocol role.

### 3. Caller-provided replacement reference manifest must not redefine production authority

`materialize_verified_manifest(..., reference_manifest=...)` may currently accept caller replacement references for convenience/testing.

If retained, a caller replacement reference must NOT be able to redefine canonical production H40 authority.

Acceptable options include:

- make replacement references explicitly non-authoritative/test-only;
- require production authority to compare against an independently reconstructed canonical reference;
- split generic validation from H40 canonical authority materialization;
- another minimal design that preserves testability but makes canonical H40 authority non-caller-defined.

Do not rely on naming something `_private` as an authority boundary.

### 4. Canonical identity vs legacy reference hashes

BASE explicitly says some historical hashes are lineage/reference values and not automatic authorization of unseen bytes.

Therefore:

- do not blindly promote every legacy hash to an authority root;
- where the accepted protocol freezes an exact current artifact/checksum identity, enforce it;
- where no exact current H40 artifact can be reproduced, fail closed as `NOT_TESTABLE` rather than substituting another local file;
- preserve explicit archive/checksum lineage where available;
- if BTC or ETH cannot currently obtain a canonical materialized source under these rules, report that honestly. P1 may be accepted as a safe scaffold with a source state of `NOT_TESTABLE`; do not fabricate success.

### 5. Authoritative split must require canonical source binding

`H40SplitManifest.materialize_authoritative(...)` and `assert_authoritative(...)` must fail unless the supplied BTC and ETH source records pass canonical source-spec verification in addition to the existing mandatory cold artifact verification.

The verifier must remain capable of detecting:

```text
wrong locator
wrong product
wrong cadence
wrong source/provenance identity
wrong expected checksum/archive identity
wrong file bytes
wrong timestamp membership
wrong partition membership
```

### 6. Preserve current cold authority semantics

Do not weaken any P1RRR closure:

- `repo_root` remains mandatory for authority assertion;
- both source artifacts are cold re-read;
- bytes/membership/counts are reproduced;
- split is cold-reconstructed from source timestamp intersection;
- persisted partition rehash attacks still fail;
- caller arrays remain non-authoritative;
- bare `is_authoritative=true` remains non-authoritative;
- confirmation access remains hard-denied;
- H39 / Final Holdout remain protected;
- execution remains disabled.
