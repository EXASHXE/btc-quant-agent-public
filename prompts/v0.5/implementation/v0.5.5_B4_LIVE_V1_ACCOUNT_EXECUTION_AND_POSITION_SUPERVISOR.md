## Exactly-once / retry semantics

Use deterministic clientOrderId derived from intent ID.

On transport uncertainty:

1. query by clientOrderId/order ID;
2. reconcile;
3. only retry if exchange proves order absent.

Never blind-retry placement.

Persist every state transition.

## Protective orders

After entry fill/partial fill where appropriate:

- ensure exchange-side protective stop exists;
- reconcile stop/TP quantities against filled quantity;
- reduce-only;
- idempotent.

Do not rely on LLM process uptime for protective stop.

## Partial fill

Support:

- NEW;
- PARTIALLY_FILLED;
- FILLED;
- CANCELED/EXPIRED/REJECTED.

Stale partial fill is a PositionSupervisor trigger.

Do not assume requested quantity == filled quantity.

## PositionSupervisor

Create deterministic service.

Inputs:

- mark;
- order/fill;
- position;
- unrealized/realized PnL;
- margin;
- stop/TP distance;
- funding;
- OI;
- volatility;
- spread;
- Tactical regime.

Triggers:

```text
POSITION_OPENED
PARTIAL_FILL_STALE
STOP_NEAR
TP_NEAR
REGIME_REVERSAL
OI_SHOCK
FUNDING_SHOCK
VOLATILITY_SPIKE
LIQUIDITY_DETERIORATION
GRID_BOUNDARY_BREACH
ADD_OPPORTUNITY
```

Every trigger:

- deterministic condition;
- cooldown/dedupe;
- source hash/timestamp;
- persisted event.

Only material event builds a PositionCase and calls the existing AnalysisBackend.

## Kill switch

Implement deterministic local kill switch.

At minimum triggers:

- daily loss cap;
- account drawdown cap;
- unreconciled account state beyond timeout;
- repeated order-state conflict;
- wrong environment/credentials;
- mandatory protective order missing beyond grace period.

Kill switch blocks new risk-increasing intent.

Risk-reducing close path may remain separately authorized by deterministic policy,
but LIVE remains blocked in this task.
