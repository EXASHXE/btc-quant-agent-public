## 1. Exact gap to close

The repaired R05C run already binds:

```text
comparison.funding_interval
→ EvidenceReference id/content hash
→ strict funding evidence bytes
→ authoritative FundingSettlement tuple
→ candidate/passive/random/cold replay
```

But the qualification boundary currently allows:

```python
required_evidence_ids=(dataset_id, run_id, benchmark_id)
```

without requiring:

```text
candidate_run.identity.funding_evidence_id
```

`ResearchContractRegistry.record_economic_qualification()` only checks that every id already declared by the attestation/result is supplied. Therefore omission at qualification construction can propagate into a committed P5 decision.

The repair must make the funding evidence id an invariant derived from the bound run, not a caller choice.

---

## 2. Non-negotiable evidence-chain invariant

For every current formal P6 qualification:

```text
funding_id = candidate_run.identity.funding_evidence_id
```

must satisfy:

```text
funding_id in required_evidence_ids
```

at all of these boundaries:

1. qualification construction;
2. `EconomicQualificationResult` object validation;
3. cold persisted qualification validation;
4. registry recording indirectly through the existing generic required-id subset checks.

Do **not** add a mutable registry-side funding map and do not change registry schema/lifecycle semantics.

Once the result/attestation is forced to declare the funding id, existing P5 logic already requires that exact `EvidenceReference` to be included in the submitted `evidence_references` and validates its local content hash/completeness.

---

## 3. Required code changes

### 3.1 `evaluate_formal_economic_qualification()`

After canonicalizing `required_evidence_ids`, require:

```python
candidate_run.identity.funding_evidence_id in evidence_ids
```

Otherwise fail closed with a stable error such as:

```text
qualification required evidence omits bound funding evidence
```

Do not auto-insert the id silently. Caller omission must be visible and rejected.

### 3.2 `EconomicQualificationResult.__post_init__()`

Defense in depth: require

```python
self.run_result.identity.funding_evidence_id in self.required_evidence_ids
```

This protects direct object construction / deserialization-style code paths and ensures the semantic payload can never serialize an accepted qualification that omits its own run's funding root.

### 3.3 `validate_persisted_qualification_semantics()`

From persisted `run_identity`, obtain:

```text
funding_evidence_id
```

Require it to be a non-empty string and require it to be present in persisted:

```text
semantic.required_evidence_ids
```

This check must happen independently during cold validation. A forged artifact that deletes the funding id and recomputes `result_id/result_hash` must still fail.

Do not trust a label or caller-provided separate funding id.

### 3.4 Registry

Prefer **no production changes** to `research_contract/registry.py`.

Reason: after sections 3.1–3.3, the existing generic logic:

```text
attestation.required_evidence_ids
→ expected_ids subset of event_evidence_ids
→ required ids must exist in staged evidence
→ local evidence hash/completeness validation
```

already forces the actual funding `EvidenceReference` into the P5 decision.

If you conclude registry code must change, STOP before editing it and report:

```text
R05CR_ESCALATION_REQUIRED_REGISTRY_AUTHORITY_CHANGE
```

Do not redesign registry authority autonomously.

## 4. Coverage identity closure

### 4.1 `ComparisonContract.__post_init__()`

Require exact equality:

```text
funding_interval.coverage_start_ms == data_interval.start_ms
funding_interval.coverage_end_ms   == data_interval.end_ms
```

Mismatch must fail closed.

This does not change valid current semantics; R05C already requires the evidence document itself to cover the exact comparison interval.

### 4.2 `load_and_validate_funding_evidence()`

Before accepting evidence, independently require:

```text
expected_identity.coverage_start_ms == expected_start_ms
expected_identity.coverage_end_ms   == expected_end_ms
```

Then retain the existing document coverage check.

This prevents the preregistered identity fields from becoming decorative/misleading metadata.

Do not alter event hash normalization or funding arithmetic.
