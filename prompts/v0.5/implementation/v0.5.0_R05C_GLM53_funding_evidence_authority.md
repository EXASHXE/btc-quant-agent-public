## 1. Exact vulnerability to close

At current HEAD, the formal path does this:

```text
caller funding_events
    -> canonical hash
    -> EconomicRunIdentity.funding_event_set_sha256
    -> formal_execution_replay_inputs.funding_events
    -> cold replay reloads the same submitted funding_events
    -> recomputes the same hash
    -> self-consistency passes
```

That proves only:

```text
"the submitted funding list is internally consistent"
```

It does **not** prove:

```text
"this is the preregistered authoritative funding settlement dataset for this comparison interval"
```

Astra successfully demonstrated three candidate families under the same protocol/comparison/candle dataset:

```text
+0.001 funding event
-0.001 funding event
empty funding list
```

All were rehashed and could survive cold verification/promotion in the CASH-only fixture.

The repair must introduce an **independent, preregistered, content-bound funding evidence root**.

Adding another hash of caller-provided `funding_events` is explicitly forbidden.

## 2. Non-negotiable authority model

The final authority graph must be:

```text
preregistered ComparisonContract
    |
    +-- funding model identity
    |
    +-- funding interval/evidence identity
              |
              v
      local COMPLETE EvidenceReference
              |
              v
      strict canonical funding evidence file
              |
              v
      independently reconstructed FundingSettlement tuple
              |
              +--> candidate simulation
              +--> passive benchmark
              +--> RANDOM_MATCHED benchmark
              +--> cold execution replay
```

A runtime/job `funding_events` list may remain only as an **optional assertion/compatibility input** if necessary. It must never be the authority.

If present, it must exactly equal the event tuple independently loaded from the preregistered funding evidence. If absent, the system must derive events from funding evidence itself.

The formal path must not allow:

```text
caller empty list
```

to mean:

```text
there were no funding settlements
```

An empty authoritative event set is valid only when a COMPLETE preregistered funding evidence artifact explicitly covers the whole comparison interval and contains zero events.

## 3. Recommended minimal data model

Prefer this design unless exact code constraints prove it impossible.

### 3.1 Add a funding interval identity to the comparison authority

In `economic/qualification.py`, add a deeply immutable identity analogous to `DataIntervalIdentity`, suggested:

```python
@dataclass(frozen=True)
class FundingIntervalIdentity:
    evidence_id: str
    content_sha256: str
    coverage_start_ms: int
    coverage_end_ms: int
    event_count: int
    event_set_sha256: str
```

Validation requirements:

- non-empty `evidence_id`;
- both hashes are lowercase SHA-256;
- positive increasing coverage interval;
- `event_count >= 0` integer;
- canonical serialization.

Add a required field to `ComparisonContract`, suggested name:

```python
funding_interval: FundingIntervalIdentity
```

It must be included in `ComparisonContract.semantic_payload()`.

This intentionally changes `comparison.contract_hash` and therefore the protocol's preregistered benchmark identity for newly repaired fixtures. Do not try to preserve old comparison hashes by hiding this authority outside the comparison preimage.

Old comparison artifacts that lack the new funding authority must be NOT_TESTABLE for new promotion, not silently upgraded.

Do **not** mutate historical stored files in place.

### 3.2 Funding evidence file

Define one strict canonical funding evidence schema, suggested version `1.0.0`:

```json
{
  "schema_version": "1.0.0",
  "product": "BTCUSDT",
  "coverage_start_ms": 1700000000000,
  "coverage_end_ms": 1700086400000,
  "events": [
    {
      "timestamp_ms": 1700028800000,
      "funding_rate": 0.0001,
      "mark_price": 42000.0
    }
  ]
}
```

Use a stable evidence type, suggested:

```text
FORMAL_FUNDING_SETTLEMENT_DATASET
```

The evidence file itself is the independent preimage. Its raw bytes must match `EvidenceReference.content_sha256`, exactly like other local evidence.

Required strict validation:

- local evidence only for formal promotion;
- `EvidenceCompleteness.COMPLETE` only;
- exact supported schema version;
- exact key set;
- no duplicate JSON keys;
- no NaN/Infinity;
- product equals the sole comparison product;
- coverage exactly equals the comparison data interval unless there is a compelling existing semantic reason to allow a strict superset; if using a superset, document and test the clipping rule explicitly;
- events chronological, strictly increasing timestamps, no duplicates;
- every timestamp lies inside coverage;
- `funding_rate` finite numeric, not bool;
- `mark_price` finite and strictly positive;
- normalize to `FundingSettlement` objects;
- derive `event_count` and `event_set_sha256` from normalized events;
- require those derived values to equal `ComparisonContract.funding_interval`.

Do not infer or fetch exchange funding implicitly during formal replay.

Do not use network calls in the verifier.

### 3.3 Empty funding is evidence, not absence

A zero-event funding file is valid only when:

```text
EvidenceReference.completeness == COMPLETE
coverage covers the required comparison interval
comparison funding_interval.event_count == 0
event_set_sha256 == canonical_sha256([])
```

Missing funding evidence must fail closed even if the caller passes `funding_events=()`.

Partial funding evidence must fail closed.

This is the required distinction:

```text
MISSING funding evidence + []      -> NOT AUTHORIZED / reject
COMPLETE zero-event evidence + []  -> authorized empty set
COMPLETE nonempty evidence + []    -> reject mismatch
```

Put strict funding evidence parsing/validation in one low-level owner, preferably `economic/funding.py`, with pure helpers such as:

```python
FORMAL_FUNDING_EVIDENCE_SCHEMA_VERSION = "1.0.0"
FORMAL_FUNDING_EVIDENCE_TYPE = "FORMAL_FUNDING_SETTLEMENT_DATASET"

load_and_validate_funding_evidence(
    evidence: EvidenceReference,
    *,
    expected_product: str,
    expected_start_ms: int,
    expected_end_ms: int,
    expected_identity: FundingIntervalIdentity,
) -> tuple[FundingSettlement, ...]
```

Do not duplicate independent parsing/coverage logic in `formal_research.py`, `qualification.py`, and `execution_replay.py`.

All formal consumers should call the same strict loader, while each cold-verification boundary must independently invoke it rather than trusting a persisted event list.

If import cycles make this exact location awkward, use a small dedicated module such as:

```text
src/btc_quant_agent/economic/funding_evidence.py
```

but keep one semantic owner.

## 5. Required changes to formal execution

### 5.1 `execute_bound_run`

The formal run must require an authoritative funding evidence reference, suggested signature shape:

```python
execute_bound_run(
    ...,
    funding_evidence: EvidenceReference,
    funding_events: Sequence[FundingSettlement] | None = None,
)
```

Required order:

1. validate protocol/comparison/candle authority as today;
2. validate funding evidence against `comparison.funding_interval`;
3. derive `authoritative_funding_events` from the evidence file;
4. if a compatibility `funding_events` assertion is supplied, require canonical exact equality with the authoritative tuple;
5. simulate using **authoritative_funding_events**, never the caller list;
6. calculate `funding_event_set_sha256` from authoritative events;
7. persist/bind funding evidence id/content hash in `EconomicRunIdentity` or an equivalently authoritative run field;
8. persist enough funding evidence reference information for cold replay, but never let persisted event bytes replace the independent evidence file as the source of truth.

Recommended additions to `EconomicRunIdentity`:

```text
funding_evidence_id
funding_evidence_content_sha256
```

Keep `funding_event_set_sha256` as a useful cross-check, but it becomes a derivative of the authoritative evidence rather than the root.

### 5.2 ReplayInputBundle

Current `funding_input_identity` may remain as an event-set cross-check if useful, but it must not be the only funding authority.

If bundle schema changes are needed, bump schema deliberately and reject legacy bundle versions for new promotion. Do not silently reinterpret old schema `1.0.0` as having funding evidence authority it never carried.

If you can keep bundle schema unchanged because the run/comparison/execution-replay layer owns funding evidence, explain why and add tests proving cold replay still cannot substitute funding.

### 5.3 `formal_execution_replay_inputs`

Persist the funding evidence reference used by the run, suggested key:

```text
funding_evidence
```

You may also retain normalized `funding_events` for audit readability, but cold replay must:

```text
read funding_evidence reference
-> compare evidence identity to preregistered comparison funding_interval
-> verify local bytes/content hash
-> parse authoritative events independently
-> require persisted funding_events (if retained) to exactly equal authoritative events
-> use authoritative events for replay
```

Never do:

```text
persisted funding_events -> reconstruct -> hash against its own run identity
```

as the sole proof.

### 5.4 `verify_execution_replay`

This is critical.

Before constructing the replay engine result, the verifier must independently reload the preregistered funding evidence and derive events.

Attackers may modify all of the following together:

```text
formal_execution_replay_inputs.funding_events
funding_event_set_sha256
ReplayInputBundle.funding_input_identity
candidate result hash
benchmark suite hash
qualification result hash
```

Cold replay must still reject because the event list no longer equals the independently loaded funding evidence bound by the comparison contract.

## 6. Formal job schema

Current `FormalResearchJobSpec` directly carries `funding_events`.

Add an explicit funding evidence reference to the formal job.

Preferred repaired job schema:

```text
funding_evidence
funding_events   # optional assertion only, if retained for compatibility
```

Because the required formal authority changes, bump `FORMAL_JOB_SCHEMA_VERSION` (for example from `1.0.0` to `1.1.0`) if the serialized job shape changes.

Legacy job schema lacking independent funding evidence must fail closed for current formal promotion.

`FormalResearchJobSpec.__post_init__` must apply `_research_path()` protection to funding evidence local paths just as it does for candle evidence:

- no Final Holdout access;
- no H39 protected store access.

`run_formal_job()` must derive the authoritative event tuple from funding evidence before candidate/benchmark execution.

The result evidence chain must include the funding evidence reference:

```python
references = [dataset_evidence, funding_evidence, ...generated run/suite/result evidence...]
```

so a formal P5 decision cannot omit the funding root from required evidence IDs.

## 7. Benchmarks must use the same authoritative funding root

CANDIDATE, PASSIVE_PERPETUAL, and RANDOM_MATCHED must use the same funding evidence-derived event tuple.

`build_formal_benchmark_suite()` may accept the already-derived authoritative event tuple for efficiency, but it must prove the tuple hash equals `candidate_run.identity.funding_event_set_sha256` and that the candidate run is bound to the same preregistered funding evidence identity.

Do not allow benchmark callers to supply a different funding event set and merely rehash it.

CASH naturally has no position funding cashflow, but the candidate/common comparison funding authority still remains part of the formal run identity and evidence chain.

---

## 8. Comparison/protocol binding

`ComparisonContract.funding_interval` must be part of the comparison semantic payload.

Because `protocol.benchmark == comparison.versioned_identity` is already enforced, this makes funding evidence identity preregistered through the protocol benchmark binding.

Do not add a new mutable side registry for funding evidence.

Do not store funding evidence identity only in run/accounting after protocol registration; that would reproduce the current self-binding flaw one level higher.


### T3 — event addition

Authoritative evidence contains one event. Add a second genuine-looking event and rehash. Reject.

### T4 — timestamp substitution

Same rate/mark, altered timestamp. Reject.

### T5 — mark substitution

Same timestamp/rate, altered mark. Reject.

### T6 — funding-rate substitution

Same timestamp/mark, altered rate. Reject.

### T7 — independent zero-event proof

Use a COMPLETE preregistered funding evidence artifact whose coverage equals the comparison interval and whose event list is empty.

Assert:

```text
empty evidence -> authoritative event_count 0 -> formal run can proceed
```

Then prove that removing the evidence reference entirely fails closed even when caller events are empty.

### T8 — incomplete coverage

Evidence coverage begins after comparison start or ends before comparison end. Reject.

### T9 — PARTIAL/MISSING completeness

EvidenceReference completeness PARTIAL or MISSING. Reject.

### T10 — content hash mismatch

Modify funding evidence file bytes after preregistration without changing the EvidenceReference. Reject before simulation.

### T11 — evidence identity swap

Use a different funding evidence file and recompute its valid EvidenceReference, but leave the preregistered comparison unchanged. Reject because evidence id/content hash differ from `comparison.funding_interval`.

### T12 — malformed event chronology

Duplicate timestamp or unsorted timestamps. Reject.

### T13 — nonfinite/invalid numeric data

Reject NaN/Infinity, bool-as-number, zero/negative mark price, malformed rate.

### T14 — out-of-window event

Event outside declared coverage/comparison interval. Reject.

### T15 — persisted execution-replay event forgery

### T16 — candidate/benchmark common funding root

PASSIVE/RANDOM benchmark paths must use the exact authoritative funding set from the candidate evidence root. Attempt a different benchmark funding list and reject.

### T17 — required evidence chain

### T18 — legacy formal job schema

### T19 — protected paths

## 10. Existing tests and fixture migration

This repair necessarily changes comparison authority because funding evidence becomes part of the preregistered comparison identity.

Do not mechanically preserve stale expected comparison hashes.

For positive formal fixtures:

- create a deterministic local funding evidence file;
- usually use a COMPLETE zero-event funding artifact when the fixture is not testing funding economics;
- bind its exact evidence identity/hash/coverage/event-set hash into the comparison before protocol creation;
- ensure protocol benchmark identity is built from the repaired comparison;
- pass the funding evidence reference into formal run/job helpers.

For tests explicitly about funding cashflows, use a nonempty deterministic evidence file.

Do not solve fixture failures by making funding evidence optional.

Do not introduce a global default funding evidence root.
