## Mission

Close exactly this blocker:

```text
P1R-F1 HIGH — authoritative split status is caller-forgeable
```

Do not redesign other H40 subsystems.

The current problem has two equivalent bypasses:

1. `H40SplitManifest.build_materialized(...)` can receive arbitrary non-empty caller timestamp sequences with no verified receipts and returns `is_authoritative=True`.
2. `H40SplitManifest(..., is_authoritative=True)` / `from_dict({..., "is_authoritative": true})` can produce an object whose `assert_authoritative()` succeeds based only on caller-controlled serialized state.

A caller-chosen split must never acquire H40 authority merely by setting a boolean or supplying timestamp arrays.

---

## Required semantics

### 1. Separate pure split calculation from authority materialization

You may keep an internal/pure helper that computes partitions from timestamp sequences, but it MUST NOT produce an object accepted as H40 authoritative solely from caller arrays.

If retained, name/type it clearly as non-authoritative/internal and make downstream authority checks reject it.

### 2. Public authoritative materialization must consume verified source authority

The authoritative entry point must require, at minimum:

- exact H40 protocol identity/hash;
- exact materialized H40 source manifest;
- BTCUSDT 1h candle source record with VERIFIED local validation receipt;
- ETHUSDT 1h candle source record with VERIFIED local validation receipt;
- repository/data root or equivalent context sufficient to cold-check those receipts against actual local bytes/timestamps.

It must independently validate/cold-reconstruct source evidence rather than trusting caller status strings.

### 3. Bind receipts to source records and actual artifacts

Before accepting source evidence, verify receipt fields against the exact source record and inspected artifact, including:

```text
source_id
locator
product
cadence
file_sha256
timestamp_field
timestamp_count
first_timestamp_utc
last_timestamp_utc
duplicate_count
gap_count / gaps
timestamp_membership_hash
archive/checksum identity when present
```

A caller-created `H40SourceValidationReceipt(status=VERIFIED, ...)` must not become authority unless cold validation of the referenced artifact reproduces the same receipt-relevant identity.

### 4. Reconstruct timestamp membership from verified artifacts

The authoritative split's BTC/ETH timestamp sequences must be extracted from the verified artifacts by the validator/materializer, or independently revalidated against the exact receipt membership hashes and counts.

Do not accept arbitrary caller timestamp arrays as authoritative inputs.

The split continues to apply:

- BTC/ETH common timestamp intersection;
- 720h lookback reservation;
- fixed preregistered half-open partitions/purge intervals;
- confirmation boundary;
- 24h complete endpoint requirement;
- real gaps/duplicates;
- no boundary shifting.

### 5. Source root binding

The resulting split must bind the exact canonical hash of the verified source manifest actually consumed.

An arbitrary caller `source_manifest_hash` string must not be able to claim another root.

### 6. Remove caller-controlled authority boolean semantics

`is_authoritative` may remain serialized as a descriptive field only if it is NOT sufficient for authority.

Preferred approaches:

- make direct/default construction always non-authoritative and require a verifier-owned materialization receipt/attestation checked by `assert_authoritative(...)`; or
- replace `assert_authoritative()` with a cold verifier that validates the split against source evidence and protocol identity; or
- use a separate verified split/attestation type whose construction path is not ordinary deserialization and whose verifier cold-reconstructs source/split identity.

Do NOT rely on a private-looking Python constructor name or a boolean alone as a security/authority boundary.

A serialized/rehashed object with `is_authoritative=true` must fail unless independently verified against the source authority.
