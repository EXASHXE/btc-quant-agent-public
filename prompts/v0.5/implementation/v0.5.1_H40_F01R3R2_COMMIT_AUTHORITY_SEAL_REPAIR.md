# 1. Close BLOCKER A — raw durable-head commit must not be production authority

Current defect:

H40LifecycleArtifactStore.advance_run_head() remains public and accepts:

authorization: VerifiedLifecycleAuthorization | None = None

The tests R15/R16/R17 intentionally call it without authorization after writing mock envelopes.

That remains an authority bypass.

## Required production model

The only production path to committed lifecycle state must be:

VerifiedLifecycleAuthorization
-> exact issuing H40LifecycleAuthorityService
-> service.revalidate_authorization()
-> immutable receipt publication
-> private verified head-commit primitive
-> SQLite transactional compare-and-advance

A caller-created typed receipt file is not authority.

## Required API change

Preferred shape:

persist_authorization(
    transition_key: str,
    authorization: VerifiedLifecycleAuthorization,
    *,
    service: H40LifecycleAuthorityService,
) -> Path

Inside persist_authorization:

1. require authorization is VerifiedLifecycleAuthorization;
2. require service is H40LifecycleAuthorityService;
3. call service.revalidate_authorization(authorization);
4. publish exact immutable receipt;
5. parse back / verify exact published envelope;
6. call a private method such as:
   _advance_verified_run_head(authorization=authorization, ...)
7. the private commit primitive must not accept authorization=None.

Do not retain a production public raw-string commit method.

If low-level transaction mechanics require direct unit testing:
- create an explicitly test-only helper/factory;
- gate it with a private construction token;
- do not export it as production authority;
- production H40LifecycleArtifactStore callers must not be able to commit from raw strings.

## Required verified transition checks

Before transactional commit require:

authorization.receipt_hash == published receipt hash
authorization.receipt == parsed typed receipt
authorization.run_authority_id == run ID
authorization.target_state == typed receipt target
authorization.upstream_receipt_hash == typed receipt upstream

For successor transition also require:

authorization.source_state == current_head.head_state
authorization.upstream_receipt_hash == current_head.head_receipt_hash

Enforce the accepted lifecycle adjacency.

At minimum:

H40_P1_SCAFFOLDED -> H40_DISCOVERY
H40_DISCOVERY -> H40_CANDIDATE_LOCKED
H40_CANDIDATE_LOCKED -> H40_WALK_FORWARD_VALIDATED
H40_WALK_FORWARD_VALIDATED -> H40_CONFIRMATION_READY

plus accepted termination rows from the accepted transition matrix.

F02 transition remains prohibited.

Do not infer adjacency only from receipt target type.

## Genesis

Sequence zero must require:
- exact verified authorization;
- null upstream receipt;
- an accepted root/scaffold transition.

Do not permit:
- caller-written Discovery receipt without verified authorization;
- Candidate Lock genesis;
- WF genesis;
- Confirmation genesis;
- arbitrary termination genesis;
- H40_PREREGISTERED -> H40_NO_GO raw storage transition;
- any non-null predecessor at sequence zero.

# 2. Close BLOCKER B — persistence revalidation must not be caller-supplied

Current defect:

persist_authorization(..., revalidate: Callable)

lets the caller define the function that establishes fresh Model-A authority.

A caller can provide:

lambda _: None

and persist a stale cached authorization after source invalidation.

## Required change

Remove arbitrary callable authority from the production persistence API.

Require the typed issuing service:

service: H40LifecycleAuthorityService

and internally call:

service.revalidate_authorization(authorization)

The service's issuer binding must ensure:
- exact issuing service can revalidate;
- foreign lifecycle service fails;
- stale production source truth fails;
- synthetic authorization is accepted only by its exact synthetic issuing service in tests.

Do not accept:
- lambda
- arbitrary Callable
- trusted boolean
- skip_revalidation flag
- verifier callback supplied by caller

as persistence authority.

## Defense in depth

After service revalidation, pass the exact authorization to the private commit primitive.

The commit primitive must reject any mismatch between authorization and persisted receipt.

# 3. Transition-matrix enforcement at durable commit

The durable head must never move to a state not represented by the exact verified authorization.

For each successor require:

current head state == authorization.source_state
current head receipt hash == authorization.upstream_receipt_hash

Then require:

authorization.source_state -> authorization.target_state

belongs to the accepted transition matrix.

Termination source_state must equal current committed head state.

Receipt type and authorization transition must agree.

The storage layer must not allow:
- Discovery -> WF
- WF -> Candidate Lock
- Confirmation Ready -> Confirmation Evaluated Once
- any unlisted transition
even if a caller can construct a typed receipt object.
