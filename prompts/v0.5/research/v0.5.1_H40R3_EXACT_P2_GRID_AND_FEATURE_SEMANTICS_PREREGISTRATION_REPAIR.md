## Why this repair exists

H40-P2 requires exactly 168 complete, immutable configuration identities to be materialized before any H40 label/performance metric is computed.

The accepted BASE/R1/R2 authority freezes:

- exact D1–D5 direction-family names;
- maximum 2 variants per direction family;
- allowed core lookbacks/states;
- four allowed depth-two pairs;
- maximum 12 complete configurations per single-family variant;
- maximum 12 complete configurations per allowed pair;
- global maximum/target of 168 slots;
- legal asset scopes, horizons and confidence thresholds;
- family-level regime/opportunity semantics.

However it does **not** yet uniquely determine the exact 168 rows. In particular it does not uniquely freeze:

- the two exact variants for every direction family;
- which exact lookback/state belongs to each variant;
- the exact 12 end-to-end configurations for each single-family variant;
- the exact 12 end-to-end configurations for each allowed pair;
- exact assignment of asset scope and primary horizon to every slot;
- exact regime and opportunity contract used by every slot;
- exact calibration method and confidence threshold used by every slot;
- exact geometry grouping/fallback identity per slot;
- exact feature parameter values and feature IDs sufficient to reconstruct every slot;
- deterministic slot ordering.

Implementing P2 by choosing these values in code would create new research degrees of freedom after protocol acceptance. P2 therefore correctly fail-closed with:

```text

```

R3 exists only to close that pre-outcome ambiguity.
