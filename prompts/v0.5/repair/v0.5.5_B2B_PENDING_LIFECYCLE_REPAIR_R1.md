# 5. Frozen lifecycle semantics

GridEligibilityStatus currently includes:

ACTIVE
NOT_ACTIVE_PAUSE
PENDING_HORIZON
PENDING_DATA_GAP
RESOLVED

For persistence authority classify:

PROVISIONAL:
- PENDING_HORIZON
- PENDING_DATA_GAP

AUTHORITATIVE_TERMINAL:
- RESOLVED
- NOT_ACTIVE_PAUSE

ACTIVE is not a persistable terminal/provisional result unless existing validation
explicitly permits it; do not introduce new ACTIVE persistence semantics.

## 5.1 Same evaluation ID

If an existing natural key has exactly the same evaluation_id:

return existing ID.

This remains idempotent.

## 5.2 Existing authoritative terminal row

If existing status is RESOLVED or NOT_ACTIVE_PAUSE:

any different evaluation_id under the same natural key must fail closed with
TacticalGridShadowEvaluationConflictError.

No overwrite.

No downgrade to pending.

No terminal-to-terminal replacement.

## 5.3 Existing provisional row

If existing status is PENDING_HORIZON or PENDING_DATA_GAP:

a different evaluation_id is allowed only when the incoming artifact is:

- PENDING_HORIZON;
- PENDING_DATA_GAP;
- RESOLVED.

This supports progressive forward-data arrival.

Examples that MUST be allowed:

PENDING_HORIZON -> newer PENDING_HORIZON
PENDING_DATA_GAP -> newer PENDING_DATA_GAP
PENDING_DATA_GAP -> PENDING_HORIZON
PENDING_HORIZON -> PENDING_DATA_GAP
PENDING_HORIZON -> RESOLVED
PENDING_DATA_GAP -> RESOLVED

Do not require monotonicity between the two pending subtypes; newly observed data
can reveal or repair a coverage gap.

## 5.4 Forbidden provisional transition

Pending -> NOT_ACTIVE_PAUSE is forbidden.

Reason:

GridPlan decision is frozen at decision time. An active source plan cannot later
become a decision-time PAUSE plan.

Fail closed.

## 5.5 Artifact immutability

Do not mutate an existing TacticalGridShadowEvaluationV1 object.

A replacement is a new immutable artifact with a new content-hash evaluation_id.

The database natural-key slot may point from a provisional artifact to a newer
provisional/resolved artifact.

Resolved authority remains immutable.

No schema migration or historical archive table is required for R1 unless a
mechanical SQLite constraint makes the narrow repair impossible.

# 8. Atomic replacement

Replacement of a provisional row must be atomic.

Preferred pattern:

1. read and verify existing row;
2. validate incoming artifact/linkage;
3. conditional UPDATE of the same natural-key row, guarded by the old evaluation_id;
4. update all first-class columns and canonical evaluation_json consistently;
5. if conditional rowcount != 1, re-read;
6. if re-read now equals incoming evaluation_id, return idempotently;
7. otherwise raise conflict.

Do not:

- DELETE then INSERT without an atomic transaction;
- temporarily leave no row;
- silently overwrite a concurrent RESOLVED row;
- use INSERT OR REPLACE in a way that bypasses transition checks.

SQLite transaction semantics must remain fail closed.
