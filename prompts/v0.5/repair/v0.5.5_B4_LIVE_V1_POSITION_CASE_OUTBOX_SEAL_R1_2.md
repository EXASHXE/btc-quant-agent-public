# 2. Single blocker

R1.1 introduced a durable PositionEvent dispatch outbox with:

```text
PENDING
DISPATCHING
DONE
FAILED_CLOSED
```

and lease recovery.

However, the outbox currently persists only the event identity/state.

During every retry, `drain_pending_dispatches()` calls:

```text
fresh_market_case(symbol)
-> position_case_from_event(base_case, event)
```

again.

Therefore the same immutable PositionEvent may materialize a different PositionCase if the
fresh market case changes between attempts.

This violates the seal requirement:

```text
one PositionEvent
-> one immutable PositionCase authority
-> retry reuses that exact case
```

A duplicate `case_id` with a different `case_hash` may then fail closed downstream rather
than cleanly recover.

---

# 3. Required semantics

## 3.1 Freeze before external side effect

Before calling:

`analysis_service.analyze_case(position_case)`

the exact PositionCase authority must already be durable.

Persist at minimum:

```text
event_id
event_hash
position_case_id
position_case_hash
position_case_json
state
lease_token
lease_expires_at_ms
retry_count
```

The persisted JSON must verify against the persisted hash.

The PositionCase must be materialized exactly once per event authority.

## 3.2 Retry rule

If a dispatch row already contains a frozen PositionCase:

- do not call `fresh_market_case()` again for identity materialization;
- deserialize and verify the stored PositionCase;
- use the exact stored case for every retry;
- stored case hash/JSON mismatch => FAILED_CLOSED;
- event-to-case linkage mismatch => FAILED_CLOSED.

## 3.3 First materialization

For a dispatch that has no frozen PositionCase yet:

1. atomically claim the event;
2. load/verify the PositionEvent;
3. obtain the current verified base case once;
4. materialize PositionCase deterministically from that event + base case;
5. persist PositionCase ID/hash/canonical JSON to the dispatch row;
6. commit the durable freeze;
7. only then call external/downstream analysis.

If the process crashes after step 6, restart must use the stored PositionCase.

## 3.4 Crash semantics

Required recoverable windows:

```text
event persisted
-> crash
-> later first materialization allowed

case materialized + persisted
-> crash before analysis
-> retry exact stored case

analysis reserves/saves case
-> crash before DONE
-> retry exact stored case
-> B3 case reservation prevents provider reissue

DONE
-> never dispatched again
```

## 3.5 No mutable fresh-case substitution

Once `position_case_hash` is frozen, a later different fresh market case must not replace,
recompile, or mutate that PositionCase authority.

Fresh market/Tactical data may inform future distinct events, but must not rewrite an already
materialized event case.

# 4. Migration

Current R1.1 SQLite table may exist without PositionCase JSON columns.

Implement a safe additive migration.

Do not DROP valid production-like outbox rows merely to add columns.

Existing PENDING rows without a frozen case remain eligible for one first materialization.

Existing DONE rows must remain DONE and must not be re-dispatched.

If a historical DONE row lacks frozen case payload, preserve DONE authority; do not recreate
or redispatch it.
