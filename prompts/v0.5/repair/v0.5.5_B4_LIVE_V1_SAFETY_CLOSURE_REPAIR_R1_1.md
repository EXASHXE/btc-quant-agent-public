# R1.1-01 — Durable PositionEvent -> PositionCase recovery

Current issue: PositionEvent is persisted before downstream analysis, while `live_position_case_dispatches` is written only after analysis returns. A crash in between can strand a persisted event because source-hash dedupe prevents the original observation from producing the event again.

Required:
- material PositionEvent and dispatch/outbox authority must be durable;
- use explicit PENDING / CLAIMED(or DISPATCHING) / DONE / MANUAL(or FAILED_CLOSED) lifecycle;
- restart must discover unfinished dispatches without requiring original observation replay;
- claim/retry must be atomic and lease/recovery-safe;
- PositionCase identity must be deterministic for the same event;
- use immutable event time/identity, not retry wall-clock time, when deriving PositionCase identity;
- downstream B3 case reservation/idempotency must prevent repeated primary-provider analysis;
- ambiguous recovery becomes explicit MANUAL/FAILED_CLOSED, never silent loss;
- DONE must never dispatch twice.

Required tests:
- crash after event persistence but before analysis -> restart drains it;
- crash after claim -> lease recovery;
- same event -> same PositionCase hash;
- retry after downstream case reservation does not reissue primary provider;
- DONE never repeats;
- no event silently disappears solely due source-hash dedupe.

# R1.1-02 — Protection must use current open position

Current issue: protective reconciliation uses cumulative entry-order `filled_qty`. Historical entry fill is not the same as current open position after stop/TP/manual reduction.

Required before create/resize/recreate protection:
- query authoritative current position for the symbol;
- establish supported position mode and intent-side open quantity;
- if open quantity == 0, do not create a new protection order;
- reconcile/cancel stale protection safely when flat;
- target protection quantity = min(current open position, relevant entry fill);
- never exceed actual current open position;
- position query uncertainty => fail closed / kill switch;
- unsupported or ambiguous position mode => fail closed;
- restart reconciles entry order + current position + protection together.

Required tests:
- filled entry + open position -> protection;
- filled entry + already flat -> no recreated protection;
- partial remaining position -> exact remaining protection;
- position smaller than entry cumulative fill -> use current position;
- position query failure -> fail closed;
- restart after stop-triggered close -> no new stop.
