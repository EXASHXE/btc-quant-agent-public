# 3. Single governance inconsistency

R2.1 correctly removed:

`POST /live-v1/runtime/intents/{intent_id}/execute`

However, `create_app(live_runtime=...)` still enters the general Live V1 block and executes:

```python
app.include_router(create_live_router(live))
```

The accepted B3 Day-1 router contains:

```text
POST /live-v1/scan
GET  /live-v1/cases/{case_id}
POST /live-v1/reviews
```

Therefore the R2.1 runtime regression:

`create_app(live_runtime=...) -> host application routes are read-only`

is not actually satisfied.

Do not solve this by deleting B3 functionality globally.

# 4. Required governance separation

Explicitly separate two surfaces:

## A. B3 Day-1 control-plane mode

This is the already accepted B3 decision/review surface.

It may continue to expose the existing B3 router only when B3 control-plane mode is explicitly
requested independently of the B4 operational runtime.

Preserve B3 semantics; do not expand them.

## B. B4 operational runtime mode

When a `LiveV1Runtime` is injected or `BTC_QUANT_LIVE_V1_RUNTIME_ENABLED=true`:

- host API must not register B3 mutating scan/review routes;
- host API must not register any runtime execution POST/PUT/PATCH/DELETE route;
- existing governed host API remains read-only;
- `/execution/status` may include read-only runtime status;
- `LiveV1Runtime.execute_intent(intent_id)` remains in-process only for local orchestration and
  TESTNET validation;
- runtime lifecycle still starts/stops market/account/reconciliation/outbox/position tasks.

Do not expose an alternative HTTP mutation route.

# 5. Feishu callback exception

The pre-existing B3 Feishu callback is a separately mounted inbound integration surface with its
own verification/signature/approver checks.

Do not treat it as an execution API.

For this repair:

- preserve the accepted Feishu callback behavior;
- do not add order fields or exchange execution authority to it;
- callback still only changes approval state;
- exchange execution remains behind persisted intent + pre-exec authorization;
- no callback value may carry executable quantity, leverage, price, order type, or credential data.

This explicit exception avoids conflating the signed webhook integration with the governed host
Signal API route catalog.

# 6. Suggested implementation

Prefer an explicit mode decision in `create_app()`, for example conceptually:

```text
runtime_mode = live_runtime is not None or BTC_QUANT_LIVE_V1_RUNTIME_ENABLED

    include B3 router

if runtime_mode:
    own LiveV1Runtime lifecycle
    expose only existing read-only host status integration

```

If both legacy B3 enable flag and runtime mode are set, runtime mode must not accidentally restore
the B3 mutating host router.

Document the precedence in code/tests.

Do not rely on AST/catalog blindness.
