# 3. R4-01 BLOCKER — protective placement confirmation must be canonical and verified

## Current defect

Current code converts exchange response identifiers using:

```python
str(raw_stop.get("algoId", raw_stop.get("orderId", "")))
```

Therefore `None` becomes `"None"` and passes the current non-empty string check.

## Required repair

Introduce one strict helper for exchange protective-order identity, e.g.:

`parse_protective_exchange_id(raw_stop) -> str`

It must reject before persistence:

- missing algoId/orderId;
- null;
- bool;
- empty/whitespace;
- literal `"None"` / `"null"`;
- malformed unsupported type;
- conflicting algoId and orderId where both are authoritative but disagree.

Do not use generic `str(...)` as validation.

### Confirmation authority

A successful POST response alone must not automatically mean "verified installed protection".

After placement, either:

1. perform an authoritative query using exact `clientAlgoId` / returned exchange ID and validate the
   complete expected protective contract before marking protection ACTIVE; or
2. persist an explicit `PENDING_CONFIRMATION` state and block new risk until reconciliation proves
   the exact order.

Required exact contract includes at least:

```text
symbol
exit side
STOP_MARKET/order type
positionSide
reduceOnly
trigger price
quantity
exact protective client ID
exact exchange ID once known
owner_key / intent identity
```

Malformed/uncertain confirmation:

```text
-> do not record installed protection
-> trip or retain kill switch
-> enter exact-owner reconciliation
-> return FAILED_CLOSED / blocked state
```

No path may report a filled position as protected if the exchange protective identity cannot be
authoritatively verified.

### Atomicity

Do not leave ownership in a state that looks successfully protected when local persistence fails.

If exchange placement may have occurred but confirmation/persistence is uncertain, preserve enough
owner/client identity to reconcile the exact order after restart. Do not blindly submit another stop.

## Required tests

Using fake clients only:

- `{"algoId": None}` => blocked, kill switch active, no ACTIVE installed stop;
- `{"algoId": ""}` => blocked;
- whitespace ID => blocked;
- bool ID => blocked;
- conflicting IDs => blocked;
- valid ID but authoritative query cannot find order => blocked/reconcile;
- valid ID but wrong symbol/side/stop/qty/reduceOnly => blocked;
- valid exact contract => protection ACTIVE;
- process interruption after remote placement but before local confirmation => restart reconciles exact owner and does not duplicate stop;
- malformed response never results in `protective_stop_id="None"`.

# 5. R4-03 HIGH — lifecycle authority must bind environment and credential namespace

## Current defect

Position lifecycle is keyed by:

`account_id + symbol + position_side`

while the observation model does not carry environment or credential namespace.

## Required repair

Define complete position lifecycle authority:

```text
environment
credential_namespace
account_id
symbol
position_side
```

Carry these fields in `PositionObservationV1` and include them in observation hash.

Persist them in `live_position_lifecycle` and use them for:

- primary/unique identity;
- current_quantity lookup;
- open/close/reopen transition state;
- event authority/cooldown from R4-02;
- runtime polling.

Runtime must populate them from current authoritative account/config/client authority, not caller
free text.

### Migration

Do not silently reinterpret old lifecycle rows as TESTNET authority.

For legacy rows without environment/namespace:
- either migrate only into an explicit legacy/DRY_RUN namespace when provably correct; or
- isolate them so TESTNET cannot inherit them.

### Incompatible DB reuse

If a single DB contains lifecycle/execution authority for a different environment or credential
namespace, runtime must either:
- isolate rows by full authority key; or
- fail closed on incompatible reuse.

It must never silently bind prior DRY_RUN state to current TESTNET state.

## Required tests

- DRY_RUN DEFAULT_ACCOUNT open state does not suppress TESTNET DEFAULT_ACCOUNT POSITION_OPENED;
- TESTNET credential namespace A does not suppress namespace B;
- same complete authority key preserves durable close/reopen across restart;
- wrong environment/namespace lifecycle row ignored or rejected;
- old observation hash cannot be replayed under a new authority;
- account A and B remain isolated;
- runtime poll_positions constructs observation authority from config/account authority.
