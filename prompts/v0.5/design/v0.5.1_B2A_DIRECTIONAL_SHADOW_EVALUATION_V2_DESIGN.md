## 1. Executive Summary & Purpose

The B2A stage implements **Directional ShadowEvaluationV2** and **Outcome Attribution** for the Tactical Policy R2 architecture.

In the Tactical Policy B-line, forward shadow observations capture hypothetical order execution and path outcomes without altering live production systems. Prior to B2A, shadow records stored raw exit reasons and gross metrics in mutable database columns.

B2A establishes a permanent, immutable, content-addressed evaluation record **`TacticalShadowEvaluationV2`** cryptographically bound to the decision-time feature evidence (**`TacticalFeatureEvidenceV2`**), the forward market path, and realized funding rates.

### Core Architectural Invariants:
1. **Separation of Policy and Evaluation:** B2A evaluates outcomes. It does NOT modify tactical decision logic, entry gates, rule scoring, or candidate rankings.
2. **Scientific & Execution Fence:**
   - Zero modifications to H40/H41 research authority (`src/btc_quant_agent/h40/*`).
   - Zero live execution keys, exchange trading endpoints, or order execution pipelines.
3. **Dual-Key Referential Integrity:**
   - Each evaluation references an existing `TacticalFeatureEvidenceV2` record via `feature_evidence_id`.
   - Each evaluation references an existing `market_watch_shadow_records` row via `shadow_record_id`.
   - Natural key: `(shadow_record_id, evaluation_profile_version)`. Re-evaluating the same key with identical content is idempotent; divergent content triggers `TacticalShadowEvaluationConflictError`.
4. **Immutable Content Identity:**
   - `evaluation_id` is a 64-character lowercase SHA-256 hexadecimal digest derived from the deterministic canonical JSON representation of the evaluation payload (excluding `evaluation_id` and persistence timestamp).
5. **Fail-Closed Outcome Attribution:**
   - At evaluation time, `validate_attribution_crosscheck()` enforces strict agreement across symbol, signal timestamp, directional decision, selected playbook, and entry/stop/target barrier parameters between the feature evidence and shadow record.
6. **Descriptive Sample Semantics:**
   - All cohort statistics are strictly sample descriptive metrics. True probability calibration and Bayesian updates are reserved for Stage B4.

## 4. Outcome & Return Accounting

### 4.1 Terminal Status & Event Authority
- `FILLED`: The order matched within the 4-bar limit entry window. Terminal reasons:
  - `TP1`: First profit target hit.
  - `STOP`: Stop loss hit.
  - `TIMEOUT`: Neither target nor stop hit prior to the evaluation horizon end; evaluated at the closing mark of the final horizon bar.
- `NO_FILL`: Order did not fill within the 4-bar entry window. NO_FILL is a valid signal-level outcome (`terminal_status = "NO_FILL"`, `net_r_ex_funding = None`, `funding_status = "NOT_APPLICABLE"`).

### 4.2 Gross R, Friction, & Net R (Ex-Funding)
- $\text{initial\_risk} = |\text{fill\_price} - \text{stop\_loss}|$
- $\text{gross\_r} = \begin{cases} \frac{\text{exit\_price} - \text{fill\_price}}{\text{initial\_risk}} & \text{if LONG} \\ \frac{\text{fill\_price} - \text{exit\_price}}{\text{initial\_risk}} & \text{if SHORT} \end{cases}$
- $\text{friction\_r} = \frac{\text{taker\_fee\_roundturn} + \text{slippage}}{\text{initial\_risk}}$
- $\text{net\_r\_ex\_funding} = \text{gross\_r} - \text{friction\_r}$

### 4.3 Realized Funding Accounting (`TACTICAL_FUNDING_ACCOUNTING_V1`)
- Sourced from Binance public USD-M perpetual funding history (`/fapi/v1/fundingRate`).
- Inclusion boundary: $\text{fill\_time\_ms} < \text{funding\_time\_ms} \le \text{exit\_time\_ms}$.
- Directional cashflow sign:
  - LONG pays positive funding rate: $\text{funding\_pnl\_pct} = -1.0 \times \text{funding\_rate}$.
  - SHORT receives positive funding rate: $\text{funding\_pnl\_pct} = +1.0 \times \text{funding\_rate}$.
- Normalized to R units: $\text{funding\_pnl\_r} = \sum \left(\text{pnl\_pct}_i \times \frac{\text{event\_mark\_price}_i}{\text{initial\_risk}}\right)$.
- Complete funding condition: $\text{net\_r\_after\_funding} = \text{net\_r\_ex\_funding} + \text{funding\_pnl\_r}$.

## 5. Diagnostic Checkpoints (`STANDARD_DIAGNOSTIC_CHECKPOINTS_V1`)

For active positions, checkpoints are recorded at standard intervals ($H \in \{1\text{h}, 2\text{h}, 4\text{h}, 8\text{h}\}$):
- Status: `OBSERVED`, `TERMINATED_BEFORE_CHECKPOINT`, or `NOT_APPLICABLE` (for NO_FILL).
- Measures: `mark_price`, `mark_to_market_gross_r`, `mfe_r_to_checkpoint`, `mae_r_to_checkpoint`, and `barrier_status`.

## 6. Cohort Summary Engine (`TACTICAL_COHORT_SUMMARY_V1`)

Descriptive sample aggregation with strict denominator rules:
- `signal_count`: Total evaluated signals in cohort ($N$).
- `sample_fill_rate`: $\frac{\text{fill\_count}}{\text{signal\_count}}$.
- `sample_tp1_rate_given_fill`: $\frac{\text{tp1\_count}}{\text{resolved\_filled\_count}}$.
- `sample_stop_rate_given_fill`: $\frac{\text{stop\_count}}{\text{resolved\_filled\_count}}$.
- `sample_timeout_rate_given_fill`: $\frac{\text{timeout\_count}}{\text{resolved\_filled\_count}}$.
- `sample_mean_net_r_per_signal_ex_funding`: Treats NO_FILL as $0.0$ R return:
  $$\text{sample\_mean\_net\_r\_per\_signal} = \frac{\sum_{\text{filled}} \text{net\_r\_ex\_funding}}{\text{resolved\_filled\_count} + \text{no\_fill\_count}}$$
- Sample Size Labels (Section 36):
  - $N < 10$: `VERY_LOW_SAMPLE`
  - $10 \le N < 30$: `LOW_SAMPLE`
  - $N \ge 30$: `OBSERVED_SAMPLE`
- Rule Score Buckets: `0–39.999`, `40–59.999`, `60–74.999`, `75–89.999`, `90–100`.
