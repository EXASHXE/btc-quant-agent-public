## 1. Architectural Scope & Purpose

The B1 stage implements the immutable, point-in-time decision record **`TacticalFeatureEvidenceV2`** for the Tactical Policy R2 architecture.

In the Tactical Policy B-line, forward shadow evaluation, cohort backtesting, and rolling calibration require verifiable, tamper-evident audit trails capturing the exact state of the universe, raw market features, derivative metrics, playbook candidates, gate evaluations, and directional/risk plans at the moment each tactical evaluation was rendered.

### Core Invariants:
1. **Scientific Non-Interference:** Strict fence around H40/H41 research authority (`src/btc_quant_agent/h40/*`). Zero shared mutations, zero cross-talk.
2. **Execution Safety Fence:** MarketWatch is an informational scanner and tactical advisory layer with forward shadow evidence. It contains zero private trade execution capabilities, zero order placement endpoints, and zero position mutation APIs.
3. **Immutability & Determinism:**
   - Content identity (`evidence_id`) is a 64-character lowercase SHA-256 hexadecimal digest derived from the canonical JSON representation of the evidence payload.
   - The hash calculation is invariant to dictionary key ordering, whitespace, and system architecture.
   - Database persistence metadata (such as `persisted_at_ms`) is strictly decoupled from the immutable evidence content hash.
4. **Strict Causality Guardrails:**
   - Closed-bar watermarks across all monitored timeframes (15m, 1h, 4h) must be strictly $\le$ `decision_time_ms`.
   - All source receipt timestamps (derivatives, ticker, order book, open interest) must be $\le$ `decision_time_ms`.
   - Any causality violation immediately raises `TacticalCausalityError`.
5. **Fail-Closed Finite Number Validation:**
   - Any occurrence of `NaN`, `+Infinity`, or `-Infinity` anywhere in feature arrays, rule scores, prices, or parameters raises `TacticalEvidenceValidationError`.
6. **Universal Population Coverage:**
   - Every evaluated symbol in a scan cycle receives an immutable `TacticalFeatureEvidenceV2` record persisted to SQLite table `tactical_feature_evidence_v2`.
7. **Referential Integrity & Downstream Immutability:**
   - `market_watch_assessments.feature_evidence_id` points to the corresponding `evidence_id`.
   - `market_watch_shadow_records.feature_evidence_id` strictly requires an existing `evidence_id` in `tactical_feature_evidence_v2` (raises `TacticalEvidenceLinkageError` otherwise).
   - Future lifecycle mutations or terminal outcome resolutions on shadow records NEVER alter the persisted `tactical_feature_evidence_v2` row.

## 3. Schema & Data Model Specifications

### 3.1 Data Structures (`src/btc_quant_agent/market_watch/evidence.py`)

- `SourceProvenanceEvidence`: closed-bar watermarks for 15m, 1h, 4h; auxiliary receipt timestamps.
- `TimeframeFeaturesEvidence`: OHLCV, closed bar timestamps, EMA fast/mid/slow, slopes, ATR, ADX, RSI, ROC, volume Z-scores, BB width, swing pivots.
- `DerivativesFeaturesEvidence`: mark/index prices, funding rate, open interest, OI changes, long/short account ratios, taker ratios, basis, spread, order book imbalance.
- `MarketSnapshotFeaturesEvidence`: composite of 15m, 1h, 4h timeframes, derivatives metrics, price metrics, return observations (1h, 4h, 12h elapsed-time returns).
- `ReferenceUniverseEvidence`: status (`UNIVERSE_COMPLETE` or `UNIVERSE_DEGRADED`), canonical universe list, missing members, incomplete return members, cross-sectional medians, rank.
- `PlaybookCandidateEvidence`: candidate status (`ACTIONABLE`, `WATCH`, `ABSENT`), strategy status (`EXPERIMENTAL`), decision, entry/stop/target/invalidation levels, structural anchor ID, reason/risk codes, breakout parameters.
- `PolicyGateStageTrace`: individual evaluation of gate stage (`CANDIDATE_GATE`, `TREND_GATE`, `EXHAUSTION_GATE`, `VOLATILITY_GATE`, `DERIVATIVES_GATE`, `EXECUTION_GATE`) with pass/fail status and audit reasons.
- `PolicyDecisionTrace`: ordered sequence of gate stage traces, pre-gate decision, final directional decision, and veto reasons.
- `RuleScoreBreakdown`: complete breakdown of rule score components: ADX score, slope score, trend quality, structure quality, entry quality, regime alignment, benchmark penalty, crowding penalty, overextension penalty, low liquidity penalty, total penalty, pre-wait adjustment score, wait adjustment flag, and final rule score.
- `ExhaustionEvidence`: state, EMA distances, swing distances, extension ATRs, reasons.
- `DirectionalRiskPlanEvidence`: stop loss, TP1, TP2, invalidation level, risk-to-reward ratio.
- `GridAdvisoryPlanEvidence`: lower/upper bounds, grid count, spacing, estimated profit.
- `TacticalFeatureEvidenceV2`: top-level root evidence record bundling all components along with semantic identity, config hash, snapshot hash, and computed `evidence_id`.

## 4. SQLite Schema & Storage Benchmark

### Table Definition: `tactical_feature_evidence_v2`
```sql
CREATE TABLE IF NOT EXISTS tactical_feature_evidence_v2 (
    evidence_id TEXT PRIMARY KEY,
    evidence_schema_version TEXT NOT NULL,
    decision_time_ms INTEGER NOT NULL,
    symbol TEXT NOT NULL,
    snapshot_hash TEXT NOT NULL,
    policy_version TEXT NOT NULL,
    config_hash TEXT NOT NULL,
    semantic_identity_hash TEXT,
    signal_identity TEXT,
    setup_key TEXT,
    lifecycle_state TEXT,
    selected_playbook TEXT,
    final_directional_decision TEXT,
    rule_score REAL,
    reference_universe_status TEXT,
    evidence_json TEXT NOT NULL,
    persisted_at_ms INTEGER NOT NULL
);

CREATE INDEX IF NOT EXISTS idx_tactical_feat_ev_natural_key
ON tactical_feature_evidence_v2 (symbol, decision_time_ms, snapshot_hash, policy_version, config_hash);

CREATE INDEX IF NOT EXISTS idx_tactical_feat_ev_time_symbol
ON tactical_feature_evidence_v2 (decision_time_ms, symbol);

CREATE INDEX IF NOT EXISTS idx_tactical_feat_ev_signal_id
ON tactical_feature_evidence_v2 (signal_identity);
```

### Storage Benchmark
- Average payload size in UTF-8 JSON: **13.2 KB** per record (substantially below the 20 KB budget).
- Persistence throughput: 1,000 synthetic records persisted in **0.18s** (~5,500 records/sec).
