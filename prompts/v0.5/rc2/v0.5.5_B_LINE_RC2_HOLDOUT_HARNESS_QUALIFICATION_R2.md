## Required implementation

### A. Normalize Binance metrics archives by event time

In validation harness code:
1. parse `create_time`/event timestamp explicitly;
2. stable-sort by event timestamp;
3. deterministically deduplicate equal timestamps;
4. for hourly series, choose max event timestamp inside each UTC hour bucket;
5. for 15m taker series, choose max event timestamp inside each UTC 15m bucket;
6. never use archive row order as temporal authority.

Add regression for known FILUSDT daily metrics archive:
`FILUSDT-metrics-2026-09-06.zip`.
For the 17h UTC bucket, expected selected observation must be the event-time latest row (17:55, not 17:35).

### B. Permutation invariance

For the same parsed source rows:
- original archive order;
- reverse order;
- at least 5 deterministic permutations.

All must produce identical normalized:
- oi_hist;
- taker_hist;
- gls_hist;
- top_pos_hist;
- top_acc_hist

and identical series SHA256.

### C. Cache authority

Replace anonymous parser-sensitive cache behavior with identity binding.

Cache identity must include at least:
- source URL set + SHA256s;
- parser/normalizer schema version;
- frozen time window;
- symbol roles;
- harness code identity.

On identity mismatch:
- fail closed or rebuild before replay;
- never silently reuse stale parsed data.

Tests:
- same identity => reusable;
- parser identity change => stale cache rejected/rebuilt;
- source digest change => stale cache rejected/rebuilt.
