## 2. Confirm root cause in current code

Current `MicrostructureStore.status()` uses:

```python
cache_key = f"{path.name}:{st.st_mtime_ns}:{st.st_size}"
```

and then appends:

```python
stats_cache[cache_key] = {...}
```

without removing older keys for the same partition.

Therefore every append/change to a live SQLite partition creates a new top-level cache entry while preserving all previous revisions.

Each entry also persists relatively large arrays including:

```text
gap_rows
segments
depth_valid_segments
clocks
latencies
```

so the stale-key leak multiplies serialized payload size.

The hotfix must eliminate revision accumulation first.

---

## 3. Required cache-v2 structure

Replace revision-in-key storage with exactly one top-level cache entry per partition filename.

Preferred serialized structure:

```json
{
  "schema_version": "2.0.0",
  "partitions": {
    "microstructure-YYYY-MM-DD.sqlite3": {
      "mtime_ns": 0,
      "size": 0,
      "stats": {}
    }
  }
}
```

Equivalent strict structure is acceptable if it provides the same invariants.

Required invariant:

```text
top-level partition identity = path.name
freshness identity = mtime_ns + size stored inside the entry
maximum live entries = number of current microstructure-*.sqlite3 files
```

Do NOT use:

```text
path.name:mtime:size
```

as the dictionary key.

---

## 4. Cache hit semantics

For each current:

```text
microstructure-*.sqlite3
```

load only:

```text
cache[path.name]
```

A cache hit is valid only when:

```text
cached.mtime_ns == path.stat().st_mtime_ns
AND
cached.size == path.stat().st_size
AND
cached stats schema is valid
```

Otherwise recompute that partition and overwrite the SAME `path.name` entry.

Never preserve an older revision of the same filename.

---

## 5. Mandatory stale-entry pruning

Before every save construct the exact current partition-name set:

```python
current_names = {
    p.name
    for p in self.root.glob("microstructure-*.sqlite3")
}
```

Persist only entries whose key is in `current_names`.

Therefore cache entries for:
- removed partitions;
- renamed partitions;
- stale legacy revision keys;
- files outside the current store root

must not survive the next save.

Do not infer cache authority from arbitrary paths.

## 6. Legacy / pathological cache handling

Do NOT require parsing a known pathological 693 MB legacy cache just to migrate it.

Add a defensive cache-size guard before `read_text()`.

Suggested implementation policy:

```text
MAX_PARTITION_STATS_CACHE_BYTES = 128 MiB
```

If the cache file exceeds the defensive limit:

```text
treat as cache miss
optionally unlink the cache file
rebuild lazily from SQLite partitions
```

This is derived cache state; correctness must come from SQLite files, never from preserving the cache.

Also:

- legacy unversioned format may be discarded rather than migrated;
- malformed JSON => cache miss;
- wrong schema version => cache miss;
- malformed entry => recompute that partition or discard cache fail-safe.

Do not let a cache parsing failure mark the underlying microstructure data corrupt.

## 7. Preserve status semantics

This repair MUST NOT change the externally visible `MicrostructureStore.status()` result for identical underlying SQLite data and the same `now_ms`, except for irrelevant dictionary ordering/internal cache metadata.

Critical outputs to preserve include:

```text
depth/trade counts
gap/resync counts
coverage and continuity
completeness
latency p50/p95/p99
clock-adjusted latency diagnostics
latest clock measurement
heartbeat/orphan state
integrity state
rolling reliability
```

### Important: do not over-compress latency data in this hotfix

Current code computes global percentiles from the merged latency samples.

Therefore DO NOT replace cached `latencies` with only:

```text
count/min/max/mean
```

because those scalars cannot reconstruct exact p50/p95/p99.

Keep the current bounded latency samples for this hotfix unless you implement an EXACT representation that produces byte-for-byte equivalent percentile results.

The query is already bounded:

```sql
LIMIT 5000
```

per partition.

### Safe clock optimization

Current downstream logic uses only:

```python
latest_clock = max(clocks, key=lambda value: value[0])
```

Therefore cache-v2 SHOULD store only the latest clock measurement for each partition rather than the complete `clock_measurements` sequence, provided tests prove exact status equivalence.

Prefer SQL:

```sql
SELECT measured_at_ms, offset_ms, rtt_ms, quality
FROM clock_measurements
ORDER BY measured_at_ms DESC
LIMIT 1
```

and combine per-partition latest records to derive the same global latest clock.

This reduces cache size without changing semantics.

Do not make broader list-compression changes in the emergency patch unless equivalence is proven.

## 9. Mandatory tests

Add focused tests, preferably in an existing microstructure test file or a new narrowly scoped file such as:

```text
tests/test_microstructure_stats_cache.py
```

At minimum prove:

### C01 one key per partition

Repeatedly mutate the same SQLite partition so mtime/size changes and call `status()`.

After every refresh:

```text
partition cache entry count remains 1
```

for that filename.

### C02 no revision-key leak

Assert no persisted key contains the old:

```text
filename:mtime:size
```

revision-key pattern.

### C03 multiple files bounded

With N partition SQLite files:

```text
cache partition entries <= N
```

and normally exactly N after successful scans.

### C04 deleted partition pruned

Create/cache two partitions, remove one disposable TEST partition, call status/save again, assert deleted filename is removed from cache.

Do not run this deletion test on production data.

### C05 changed file overwrites same entry

Change mtime/size and verify signature/stats are replaced under the same filename.

### C06 legacy cache discarded

Provide old unversioned cache structure and verify it is ignored/rebuilt safely.

### C07 oversized cache not parsed

Create an oversized/sparse TEST cache above the defensive size threshold.

Verify `_load_stats_cache()` treats it as a miss without attempting full JSON parse and status reconstructs from SQLite.

Do not create hundreds of MB of real allocated test data; use a sparse file/truncate or mock stat/read behavior.

### C08 malformed cache harmless

Invalid JSON does not corrupt status; it rebuilds from SQLite.

### C09 cache miss vs cache hit semantic equivalence

For the same synthetic SQLite fixture and fixed `now_ms`:

```text
status_without_cache == status_with_cache
```

for all externally meaningful fields.

### C10 latency percentiles unchanged

Explicitly verify p50/p95/p99 raw and clock-adjusted diagnostics are identical across miss/hit.

### C11 latest clock unchanged

Multiple clock measurements across multiple partitions must produce the same globally latest clock before/after cache-v2.

### C12 bounded repeated growth

Perform many repeated updates/status calls against one partition.

Assert cache size does not grow approximately linearly with revision count.

A reasonable test is:

```text
size_after_many_revisions <= bounded_multiple_of_single_current_entry
```

Do not assert a fragile exact byte size.
