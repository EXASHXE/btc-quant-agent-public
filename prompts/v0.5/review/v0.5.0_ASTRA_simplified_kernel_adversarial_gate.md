This gate MUST NOT:

- enable live execution, testnet execution, paper execution or auto-execution;
- submit/cancel/close any order;
- unblind H39;
- read protected H39 outcome data that the current blindness contract forbids;
- open or inspect Final Holdout outcomes;
- change H39 protocol/freeze artifacts;

- run alpha search, threshold tuning, feature search or model selection;

Temporary hermetic attack scripts and synthetic fixtures are allowed if they do not access protected outcomes and are not committed to the code branch.

If a requested check would require H39 unblind or Final Holdout access, record it as protected/unperformed rather than crossing the boundary.

## 3. Mandatory attack program

For every attack below, identify the exact producer, persisted representation, verifier, independent root and expected failure point. Prefer executable adversarial probes over static reasoning when safe.

### A. PIT and information-set attacks

Attempt at least:

1. unclosed candle accepted as formal evidence;
2. missing `available_at_ms` accepted;
3. availability after decision time accepted;
4. future suffix or future liquidity used in an earlier decision/fill;
5. gap/overlap/instrument/interval substitution while retaining outer hashes;
6. legacy runtime market-data v1 made promotable through an adapter/default/read path;
7. vendor/historical evidence upgraded to forward/PIT authority without valid provenance.

Required property: missing/legacy/ambiguous information must fail closed, not default to promotable current semantics.

### B. Signal producer and input-provenance attacks

Attempt:

1. forged candidate signals with valid-looking IDs;
2. candidate-selected producer contract replacing protocol-selected producer authority;
3. producer contract/hash rewritten together with outer wrappers;
4. incomplete material decision-input set presented as complete;
5. signal set changed while preserving/recomputing outer identities;
6. CANDIDATE decision inputs relabeled as RANDOM or vice versa;
7. identical signal bytes assigned to a different product/horizon/protocol without identity failure.

### C. Candidate execution/accounting attacks

Attempt coherent and incoherent forgeries of:

- fill price;
- fill quantity;
- fees;
- slippage;
- funding;
- trade-event ordering;
- equity curve;
- round-trip attribution;
- terminal equity/PnL;
- pending/completeness/terminal state.

At least one probe must synchronously recompute the outer result hashes after the forged inner payload. A rejection that depends only on a stale outer hash is insufficient.

Verify that qualification consumes cold reconstructed economics rather than submitted PnL/fills/fees/funding.

### D. Execution-causality attacks

Re-attack:

- impossible fills;
- ambiguous LIMIT observable-time/intrabar ordering;
- future-volume liquidity;
- funding/fill same-time ordering;
- terminal pending order ambiguity.

Confirm simplification has not created a convenience route that uses old backtest execution semantics for formal qualification.

### E. RANDOM_MATCHED authority attacks

Attempt:

1. candidate run relabeled as random trial;
2. candidate signals cloned into random;
3. random trial output submitted instead of reconstructed;
4. seed swap;
5. draw swap;
6. direction-template manipulation;
7. opportunity population/sample-count manipulation;
8. trial order/identity manipulation;
9. outer suite/result IDs recomputed after manipulation.

Required property: canonical random experiments must be independently reconstructed from preregistered roots, not trusted from submitted trial outputs.

### F. CASH authority attacks

Attempt:

- traded CASH;
- nonzero fees/funding/turnover/exposure;
- candidate accounting substituted as CASH;
- modified initial capital;
- modified terminal equity;
- recomputed outer benchmark/suite hashes after substitution.

Required property: CASH is independently reconstructed constant-equity/no-activity policy.

### G. Qualification-binding and synchronized-rehash attacks

Try to create a self-consistent forged artifact family by modifying and rehashing multiple layers together:

- run identity/result;
- replay bundle/input hashes;
- benchmark suite;
- qualification result;
- evidence wrapper;
- registry attestation/decision references.

Attack candidate/random role interchange, protocol revision substitution, dataset substitution and result-ID substitution.

The audit must answer:

> What frozen or independently reconstructed root stops an attacker who can rewrite every candidate-owned wrapper consistently?

If the answer is only “the hashes match,” this gate fails.

### H. Registry authority bleed

Attack the separation between:

```text
ResearchRegistry
```

and:

```text
ResearchContractRegistry
```

Try to use operational fields such as:

```text
SUPPORTED_MOVEMENT
VALIDATED_FORWARD
LIVE_ELIGIBLE
qualified_direction_engine_count
```

to create or imply a P5/P6 formal economic decision without cold-verified qualification evidence.

Also inspect CLI/API/service/shadow/forward paths for indirect bridges, not only direct imports.

### I. Legacy diagnostic bypass

R04 newly marks retained historical research/mechanism results:

```text
LEGACY_DIAGNOSTIC_ONLY
NOT_TESTABLE_FOR_NEW_PROMOTION
can_promote=false
```

Attack this boundary:

1. caller supplies forged `classification=QUALIFIED` or `can_promote=true`;
2. nested diagnostic payload omits the marker;
3. raw CSV/Parquet/old artifact is fed into a current formal consumer;
4. pre-R04 historical persisted artifact without the new marker is treated as current authority;
5. legacy `BacktestEngine`, R metrics, old shadow output or mechanism recommendation reaches formal promotion through an adapter;
6. generic `backtest/research/replay` CLI falls back to a legacy engine on malformed/old inputs.

Historical readability is allowed; promotability is not.

### J. Publication, persistence and finalization attacks

Re-attack the retained B09/B10/B11 boundaries:

- concurrent writer race;
- stale generation/CAS;
- temp/rename/fsync uncertainty;
- incomplete SQLite writer finalization;
- WAL/checkpoint ownership;
- schema projection/version mismatch;
- missing version defaulting;
- old readable object inheriting new promotion authority.

No need to redesign publication. The question is whether R01–R04 removed an owner/check or added a bypass.

### K. H39 and Final Holdout isolation

Without reading protected outcomes, prove from reachable code/configuration that:

- R04 did not weaken H39 frozen protocol identity;
- operational H39 diagnostics cannot become formal economic qualification;
- H39 unblind remains a separate explicitly gated one-shot path;
- Final Holdout remains sealed and no ordinary research path reads it;
- future H40 work cannot silently use protected H39/holdout outcomes as development labels.

Any actual protected-outcome read during this audit is itself a gate failure.

### L. Execution activation attacks

Confirm:

- default execution mode is disabled;
- formal research cannot mutate execution config into enabled state;
- diagnostic/API/registry status requests do not place orders;
- no legacy research output can activate execution through `LIVE_ELIGIBLE` or a similar operational state;
- live/testnet/paper interfaces remain separately gated.

Do not perform a real execution test.

### M. API/service/read-only boundary

Re-check retained HTTP GET handlers behaviorally, not just by HTTP verb. In particular verify that a read-only API request does not silently mutate SQLite, promotion state or formal registry state.

### N. Future BTC/ETH multi-horizon identity collision

Without implementing alpha research, construct synthetic identity/preimage cases sufficient to test that explicit variations in:

- BTC vs ETH product;
- 4h / 8h / 12h / 24h horizon;
- protocol revision;
- signal producer contract;

cannot collide or inherit one another's qualification merely because they share feature code or decision cadence.

Do not treat current 1h/BTC defaults in convenience dataclasses as frozen research policy if explicit values are bound into canonical semantics.
