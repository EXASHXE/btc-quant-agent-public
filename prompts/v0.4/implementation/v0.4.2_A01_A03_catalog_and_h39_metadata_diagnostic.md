# PART B — A03 H39 METADATA-ONLY DIAGNOSTIC REPAIR

## 8. A03 exact defect

Current code in:

`src/btc_quant_agent/microstructure_research.py`

method:

`H39ResearchEngine.evaluate_validation_status()`

is marked deprecated/non-authoritative, but it currently scans post-validation-start partitions and calls:

```python
self.build_observations_for_partition(...)
```

That path constructs `H39Observation` / `H39OutcomeRow` and can load future-return/canonical-candle data.

A metadata/status diagnostic must not construct outcomes.

A02 already provides an opt-in test fixture:

`h39_outcome_access_spy`

which fails if metadata-only tests call:

- `load_outcomes_from_opportunity_shadow`
- `get_canonical_1m_candles`
- `build_observations_for_partition`

A03 must make the production diagnostic pass this safety boundary by design.

---

## 9. A03 required semantic behavior

`evaluate_validation_status()` remains:

- deprecated;
- non-authoritative;
- diagnostic-only;
- unable to authorize unblind;
- unable to promote a candidate;
- unable to run formal statistics;
- unable to load outcomes/future returns.

Preserve these output fields and meanings unless a tiny additive field is needed:

```text
deprecated = true
authoritative = false
diagnostic_only = true
readiness_authority = NON_AUTHORITATIVE_DIAGNOSTIC_ONLY
authoritative_unblind_authorization_allowed = false
candidate_promotion_allowed = false
runtime_maximum = OPPORTUNITY_ONLY
execution = DISABLED
```

Do not make this method another implementation of authoritative H39 readiness.

The authoritative readiness gate remains the existing `check_unblind_readiness()` / gatekeeper path under the frozen protocol.

---

## 10. A03 preferred implementation strategy

Replace outcome construction with metadata-only partition/state inspection.

### Allowed information for the deprecated diagnostic

The method may inspect metadata that does not require future outcomes, such as:

- partition filenames
- partition min/max receive/event time metadata
- finalized/integrity metadata if already available without outcome construction
- precomputed eligibility/readiness metadata already stored in blind/metadata tables, if this can be read without labels
- static protocol thresholds and validation-start metadata

### Forbidden information

It must not call or indirectly trigger:

```text
build_observations_for_partition
get_canonical_1m_candles
load_outcomes_from_opportunity_shadow
evaluate_feature_hypotheses
formal H39 statistics
future_close_60m / future_close_240m
return_60m / return_240m
```

Do not solve this by temporarily disabling the A02 spy.

### Conservative behavior is preferred

If the old method cannot reproduce an `eligible_slots_accumulated` or `coverage_ratio_accumulated` value from metadata-only sources without reconstructing outcomes, do NOT invent one.

Preferred choices:

1. derive only from an existing metadata/blind ledger whose rows are already label-free and allowed; or
2. return a clearly typed/explicit metadata-only `UNKNOWN` / `NOT_AUTHORITATIVE` progress field while preserving the method's non-authoritative safety properties.

Do not infer maturity from prices/future labels merely to preserve an old cosmetic field.

The method must never return a value that can be interpreted as authoritative unblind permission.
