## Objective

Make the current economic simulator fail-closed whenever a declared strategy/risk constraint cannot actually be enforced.

The core invariant is:

> No field may appear in a formal `TradePolicy` / risk configuration while being silently ignored by simulation.

A simulated trade may be admitted only when its asset, sizing inputs, market-state inputs, risk budget, pending exposure, actual fill exposure, and drawdown state are all valid under the declared policy.

This stage does **not** restore formal economic qualification.

## Step 2 — Policy validation contract

Every policy/risk field must be one of:

1. **SUPPORTED_AND_ENFORCED** — simulation implements it and tests prove it;
2. **UNSUPPORTED_FAIL_CLOSED** — policy construction or simulation rejects the configuration before trading;
3. **DIAGNOSTIC_ONLY** — only if the public type clearly identifies it as non-binding and no formal policy can rely on it.

No binding-looking field may remain a no-op.

Validate all numeric inputs for finiteness, positivity/range, and compatible combinations before state mutation.

---

## Step 3 — Position sizing enforcement

For the sizing modes that currently exist, enforce explicit semantics.

### FIXED_NOTIONAL
- Convert declared notional to quantity using only causally available order/fill price under the current execution contract.
- Reject zero/non-finite/negative notional.
- Do not exceed risk/gross caps after actual fill.

### RISK_FRACTION
If retained as supported:
- Require a valid stop-distance/risk-per-unit input that is causally available before order submission.
- Reject missing/zero/non-finite stop distance.
- Do not silently fall back to fixed or full allocation.

If the current simulator cannot enforce this cleanly, mark it unsupported and fail closed in this stage.

### VOLATILITY_SCALED
If retained as supported:
- Require a valid PIT ATR/volatility input through an explicit field/source.
- Missing, stale, zero or non-finite ATR must fail closed.
- Do not use future candle range as a substitute.

If a stable contract cannot be implemented minimally, reject this sizing mode rather than inventing a new volatility engine.

Add direct tests for missing ATR and invalid sizing inputs.

## Step 4 — Risk budget enforcement

At minimum enforce, where these fields exist:

- maximum open positions / one-way position permission;
- maximum gross notional / portfolio exposure;
- maximum leverage or equivalent supported exposure cap;
- maximum drawdown stop / entry halt;
- policy risk budget / position size ceiling.

Important invariants:

### No oversubscription through pending orders
P2/P3 introduced pending fills. Multiple pending orders must not each pass the cap independently and later push the portfolio above the declared maximum.

Either:
- reserve risk/exposure for admissible pending orders; or
- reject additional pending orders conservatively.

Document the chosen rule.

### Pre-order and post-fill checks
A pre-order estimate is insufficient. Re-check exposure against the actual filled price/quantity before committing the fill. If the actual fill would violate a hard cap, fail closed according to an explicit deterministic contract.

Do not create impossible partial-fill precision solely to rescue the order unless partial fills are already formally supported.

### Fees / slippage buffer
If fees/slippage affect available capital or the implemented risk cap, use the same configured fee/execution model as the simulation. No duplicate cost source.

## Step 5 — Drawdown halt

Implement the declared drawdown stop using only causal portfolio equity.

Requirements:
- peak equity must be derived from replay state available up to current simulation time;
- reaching/exceeding the configured drawdown threshold prevents new entries;
- existing-position exit logic must still function;
- define whether the halt is sticky for the remainder of the simulation. Prefer a simple sticky halt for this stage unless current policy explicitly specifies another behavior;
- no future equity values may participate.

Required regression: after drawdown halt, a later valid-looking signal cannot create a new position.

---

## Step 6 — Market-state filters

Inspect all declared `MarketStateFilter` fields.

For each supported filter:
- consume only explicitly supplied, timestamp-valid market-state inputs;
- missing required state must fail closed;
- invalid/non-finite values must fail closed;
- do not infer missing regime/spread/volume/volatility from future candles.

If current types declare filters that cannot be reliably supplied to the simulator, reject those policy configurations rather than pretending the filters ran.

Required regressions should include the independent-review cases corresponding to:
- market-state/filter silently ignored;
- missing required market state;
- wrong asset;
- minimum liquidity/volume or spread rule where actually declared.

---

## Step 7 — Signal / re-entry / reversal policy

P2/P3 already enforce basic asset checks and causal fills. In this stage make policy behavior explicit for:
- same-direction repeated signals while a position exists;
- opposite signal while a position exists;
- pending entry plus another signal;
- re-entry after exit;
- close-only vs explicit reversal if such behavior is declared.

Do not allow an implicit reversal path to bypass the ledger or risk checks.

If an option is not supported, fail closed.
