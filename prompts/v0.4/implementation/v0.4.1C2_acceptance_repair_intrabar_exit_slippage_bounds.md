## 1. Why this repair exists

The previous repair correctly closed AR1–AR6 at the structural level, but code review found two remaining correctness blockers and one related fail-open cost path.

### C2-B1 — Intrabar exit trigger is converted into a bar-close market order

Current simulator behavior for SL/TP/trailing is:

1. inspect full bar OHLC at `bar.close_time_ms`;
2. conclude that SL/TP/trailing was touched sometime during the bar;
3. call `_execute_exit(... trigger_timestamp_ms=bar.close_time_ms ...)`;
4. `ExecutionModel.simulate_order()` therefore uses the bar close (or later bar after latency) as market reference.

This is not equivalent to a standing stop/target/trailing order and can create optimistic PnL.

Required regression example:

```text
LONG entry = 100
stop_loss_pct = 5%
next bar: O=100, H=101, L=90, C=100
```

The system must **not** close at ~100 merely because the stop touch is only discovered at bar close. The stop order was economically armed before the touch. Likewise, a TP touch must not be reinterpreted as a discretionary close-at-close order.

### C2-B2 — `max_slippage_bps` is used as an ex-ante risk bound but is not an actual execution bound

`FeeModel.worst_case_price_bound()` treats `max_slippage_bps` as a deterministic cap for `SPREAD_AND_IMPACT`, yet `calculate_slippage_bps()` / `effective_fill_price()` do not clamp actual spread+impact to that cap.

Therefore:

```text
reservation_notional <= gross cap
```

can be true ex ante while the realized fill exceeds the declared bound and breaches the gross cap. This violates the AR3/AR4 contract.

### C2-H1 — Exit spread/cost evidence still fabricates `0.0` spread

Gap exits and intrabar exits currently call `_execute_exit(... current_spread_bps=0.0)`. Reversal exits also fall back to `0.0` when metadata lacks spread. Under `SPREAD_AND_IMPACT`, this silently understates exit cost.

No formal economic result may invent zero spread when the configured execution model requires spread evidence.

## 2. Required contract decisions

### 2.1 Standing conditional exit semantics

Implement an explicit economic contract for stop-loss, take-profit and trailing-stop exits. These exits are **standing conditional orders**, not orders created only after the bar closes.

At minimum:

- SL/TP/trailing must be armed from the causal state available before the bar path that can trigger them.
- Gap stop remains evaluated at bar open with the actual opening price (plus configured adverse execution cost).
- For a non-gap single-touch stop/target within OHLC data, the economic fill reference must not improve merely because the bar later recovers before close.
- Conservative / deterministic handling must be explicit and symmetric for LONG and SHORT.
- `CONSERVATIVE_STOP_FIRST` and `REJECT_AMBIGUOUS` must continue to work.
- Do not reintroduce direct ledger mutation outside the unified execution path.

You may extend `ExecutionModel` with an explicit conditional/trigger execution interface or a clearly typed execution-reference contract. Do not add a general exchange matching engine.

### 2.2 OHLC path ambiguity and event time

With OHLC-only data, exact intrabar trigger time can be unknowable.

Rules:

- Never invent an exact trigger time simply to make ordering convenient.
- If exact ordering relative to another economically material event inside the same bar (e.g. funding settlement) changes cashflow and cannot be determined, the simulation must fail closed / return an explicit `NOT_TESTABLE`-style condition for that run or event rather than choose the favorable path.
- A deterministic conservative scenario is acceptable only if documented and demonstrably non-optimistic.
- Preserve monotonic event ordering and reconstructability.

### 2.3 Slippage bound must be real or not be used as a bound

Choose one coherent contract:

**Preferred:** when `max_slippage_bps` is configured for `SPREAD_AND_IMPACT`, it is a hard execution-model cap and actual slippage is clamped to it. Then `worst_case_price_bound()` is a valid reservation bound.

OR

If you intentionally do not clamp realized slippage, then `worst_case_price_bound()` must not claim a finite bound from `max_slippage_bps`; strict-gross-cap market orders under that model must fail closed ex ante.

Whichever contract is chosen must be reflected consistently in:

- `calculate_slippage_bps()`
- `effective_fill_price()`
- `worst_case_price_bound()`
- risk reservation
- tests
- report

Validate relevant FeeModel parameters as finite and nonnegative where required. Do not allow negative or NaN slippage caps to silently create favorable fills.

### 2.4 Exit spread evidence

Under `SPREAD_AND_IMPACT`:

- do not pass fabricated `0.0` spread for exits;
- use causal spread evidence if available;
- otherwise use an explicitly predeclared adverse bound/scenario that is part of the execution contract;
- if neither exists, fail closed / mark the economic run not testable.

Under `ZERO` or `FIXED_BPS`, missing spread evidence may be irrelevant because that model does not use it; preserve that distinction.

## 3. Mandatory regression tests

Add focused deterministic tests. At minimum:

1. **Long stop recovery bar**
   - entry 100, SL 95;
   - next bar `O=100, H=101, L=90, C=100`;
   - result must not exit near 100 simply because close recovered.

2. **Short stop recovery bar**
   - symmetric case; must not benefit from close recovery.

3. **TP retrace bar**
   - target touched intrabar and close returns to entry;
   - behavior must match declared standing-target contract, not bar-close discretionary execution.

4. **Trailing stop retrace**
   - establish prior peak/trough, then intrabar trailing trigger with recovery;
   - no close-price fabrication.

5. **Gap stop**
   - continue to fill from actual gap-open evidence with adverse configured execution cost.

6. **SL+TP collision**
   - both LONG and SHORT;
   - `CONSERVATIVE_STOP_FIRST` remains adverse;
   - `REJECT_AMBIGUOUS` remains fail-closed.

7. **Funding inside ambiguous trigger bar**
   - if trigger-vs-funding ordering cannot be determined from OHLC, verify explicit fail-closed / not-testable behavior rather than arbitrary ordering.

8. **Slippage-cap enforcement**
   - construct `SPREAD_AND_IMPACT` where raw spread+impact exceeds `max_slippage_bps`;
   - if cap contract chosen, actual effective fill must respect the exact cap and remain within reservation bound.

9. **Gross reservation invariant**
   - for every admitted bounded order, realized fill notional must not exceed the reservation notional used for gross-cap admission (allow tiny floating tolerance only).

10. **Exit spread missing**
    - `SPREAD_AND_IMPACT` with no causal spread and no valid declared bound must not silently execute with zero spread.

11. **Fixed/zero slippage compatibility**
    - ZERO and FIXED_BPS continue to work without unnecessary spread metadata.

12. Preserve all P0–P4 regression suites and run full repository tests.
