# P2 Causal Event Timeline

## Objective

Separate observation, decision, order, fill and settlement time.

Current requirement:

A simulation must never use future information to create fills.

Introduce explicit timestamps:

```
observation_time
decision_time
order_time
fill_time
settlement_time
```

Requirements:

- decision cannot occur before observation
- fill cannot occur before order
- settlement cannot occur before fill
- invalid ordering must fail closed

Equal timestamps must have deterministic ordering.

---

# P3 Execution Semantics

## Objective

Remove optimistic execution assumptions.

Separate:

```
signal
  |
order
  |
fill
  |
position
  |
cashflow
```

A signal is not a trade.

An order is not a fill.

---

## Required Changes

Implement minimal execution model:

- pending order state
- accepted/rejected order
- fill event
- fill price
- filled quantity
- execution timestamp

Do not implement:

- full order book matching
- market impact model
- exchange simulator

# Exit Handling

Fix ambiguous OHLC exits.

When stop and target can both happen inside the same candle:

Do not assume profitable ordering.

Possible acceptable approaches:

1. mark as ambiguous and reject
2. conservative adverse fill
3. configurable scenario mode

Document the choice.
