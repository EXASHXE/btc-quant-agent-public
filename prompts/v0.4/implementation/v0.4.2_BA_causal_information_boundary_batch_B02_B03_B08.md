# PART A — B02 / H3: causal liquidity for opening fills

## 5. Defect

An opening MARKET or marketable-at-open LIMIT fill must not use the current candle's **completed future volume** to determine participation impact/slippage when that volume did not exist at the fill timestamp.

Formal invariant:

> Holding the complete information set available at the fill timestamp fixed, changing only the post-fill bar suffix must not change opening fill/no-fill, execution price, impact/slippage, fee basis, notional, ledger mutation, or downstream state attributable to that fill.

### Mandatory A04 oracle

Load and consume from `tests/goldens/v042_semantic_goldens.json`:

- `D-H3-FUTURE-VOLUME-INVARIANCE`

Also preserve:

- `G09-CAUSAL-EVENT-ORDER`
- `G10-MARKETABLE-LIMIT-AT-OPEN`
- `D-B2-LIMIT-TOUCH-UNRESOLVED` remains closed from B01.

## 6. Required B02 behavior

Opening taker execution may use only:

1. timestamped liquidity/proxy information proven available at or before fill; or
2. an explicit deterministic conservative/adverse scenario already declared/bound in the execution contract when causal observed liquidity is unavailable.

Forbidden as an opening-fill fallback:

- completed current-bar volume;
- later bar volume or later-derived rolling volume;
- current-bar future high/low/close suffix information;
- fabricated spread;
- silent zero impact;
- favorable default;
- invented timestamps that make future data appear causal.

Apply the same canonical liquidity/impact semantics to:

- MARKET BUY/SELL;
- B01 marketable-at-open LIMIT BUY/SELL.

Do not redesign B01 observable-limit/expiry semantics.

Preserve current max-slippage semantics, taker fee classification, risk/notional caps, funding ordering, and no-fabricated-spread rules.

Close-time fills may use information genuinely available at close. Do not overcorrect by banning legitimate close-time data.

# PART B — B03 / H4: closed + PIT availability at formal data boundary

## 7. Defect

The formal economic path can currently treat a candle whose runtime state says `closed=False` as equivalent to a completed candle because the formal serialized candle payload drops or silently defaults the availability state.

That allows identical OHLCV arrays with different information availability to share a formal economic identity.

### Mandatory A04 oracles

Load and consume:

- `D-H4-CLOSED-FALSE-NOT-COMPLETE`
- `PIT-01-CLOSED-POSITIVE`
- `PIT-02-PRODUCT-MISMATCH`
- `PIT-03-INTERVAL-MISMATCH`
- `PIT-04-OVERLAP`
- `PIT-05-GAP`
- `PIT-06-NONFINITE`
- `PIT-07-NOT-YET-AVAILABLE`

## 8. Required B03 behavior

Formal economic input identity must preserve enough state to prove that every candle/input used by the run was available when required.

At minimum the formal boundary must distinguish and validate:

- `closed` state;
- event/open/close interval semantics;
- availability/receipt semantics required by the existing PIT contract;
- product identity;
- interval identity;
- ordering and spacing;
- overlap/gap constraints already required by the frozen contract;
- finite OHLCV values;
- availability relative to signal/decision time.

Required behavior:

- `closed=False` cannot become `COMPLETE` solely because OHLCV matches a closed candle.
- an input not yet available at the relevant decision time must fail closed / typed NOT_TESTABLE according to current contract.
- legacy schemas missing proof of `closed`/availability may remain readable for history, but cannot be silently promoted as formal evidence.
- do not default missing legacy `closed` to `true` for new qualification.
- valid historical closed candles must remain replayable; **do not use current wall-clock freshness** to reject historical replay merely because data is old today.
- do not mutate old evidence files to add fields retroactively.

Prefer one canonical candle/input validation+serialization boundary used by generation and verification rather than separate writer/verifier interpretations.

# PART C — B08: clock-domain and configuration fail-closed behavior

## 9. Scope

B08 belongs in this batch because causal data/execution guarantees are meaningless if service/runtime code confuses clock domains or silently changes configuration.

Inspect current `service.py`, config loaders, time snapshot abstractions, collectors/requesters, and any economic/runtime code that consumes “now”, receipt times, stale/future checks, or default config paths.

## 10. Required clock semantics

Keep distinct concepts distinct:

```text
exchange/event timestamp
receipt timestamp
availability timestamp
wall-clock UTC timestamp
monotonic elapsed time
```

Requirements:

- elapsed timeout/retry/lease/backoff logic must use monotonic time, not wall-clock deltas susceptible to NTP rollback/jump;
- causal/PIT/event comparisons must use the repository's UTC/event/availability timestamps, not monotonic counters;
- local/exchange clock skew must be explicit and bounded by existing policy where one exists;
- stale and impossible-future receipts fail clearly instead of being silently normalized;
- exact candle boundaries must not gain a hidden +/- offset due to local timezone conversion;
- historical replay must use recorded event/availability semantics, not today's wall clock.

Do not invent a new distributed-time subsystem. Collapse ad hoc helpers into the smallest canonical existing abstraction if practical.

## 11. Required configuration semantics

Configuration must fail closed where ambiguity can affect research validity or execution safety.

At minimum:

- an explicitly requested config path that is missing/unreadable/invalid must not silently fall back to defaults;
- unknown/typo top-level sections that could hide intended research/execution settings must fail clearly under the repository's supported schema policy;
- unsafe values must fail validation rather than being coerced into permissive values;
- environment overrides must have deterministic documented precedence and validation;
- default execution remains disabled;
- missing config must never enable network/execution/trading behavior;
- config failure must not reset or rewrite epoch/campaign/registry identity.

Preserve legitimate default behavior only where the current public contract explicitly defines it and where it cannot silently change formal research semantics.
