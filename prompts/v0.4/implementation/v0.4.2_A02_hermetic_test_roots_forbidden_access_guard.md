## 1. Why A02 is first

P7 found that several H39/Forward tests instantiate engines with default store paths. In a populated local checkout, nominally diagnostic/safety tests can traverse real operational stores and may reach paths that construct H39 outcomes. This also explains most of the local full-suite wall time.

Observed P7 timing baseline:

- full suite: `804 passed` in about `483 s`;
- the five slowest tests accounted for about `406 s` / `84%` of wall time;
- the largest offenders were H39/Forward tests that depended on default stores or operational scans.

Green CI on an empty checkout is not proof that tests are hermetic in a populated checkout.

A02 must make that distinction explicit and fail closed.

## 4. Required design

### 4.1 Explicit test-root injection

Refactor affected test factories/helpers so that every stateful component used by H39/Forward tests receives explicit temporary locations instead of inheriting production defaults.

Prefer dependency/path injection at constructors or existing configuration seams.

Do not add global production behavior whose only purpose is to hide tests.

If a small production constructor change is required to support explicit roots, it must:

- preserve existing production behavior outside tests;
- be typed and explicit;
- not change H39/economic semantics;
- avoid environment magic where a normal parameter/config field is sufficient.

Cover at minimum the affected areas identified by P7:

- v0.3.14 Forward watchdog tests;
- v0.3.23 blind-validation / Final-Holdout-safety tests;
- v0.3.25 one-shot/unblind-preregistration/readiness tests;
- v0.3.26 corrected H39 tests if they touch stores;
- report/readiness tests that currently construct engines using defaults.

Search the full test tree for additional default-path instantiations rather than fixing only the named examples.

### 4.2 Clock injection

Tests whose behavior depends on current time, maturity, freshness or epoch state must use an explicit deterministic clock/time snapshot when the code already supports one or can accept one without changing semantics.

Do not globally monkeypatch time in a way that hides clock-domain bugs.

The test API should make clear whether a timestamp represents:

- event/exchange time;
- receipt/availability time;
- wall-clock UTC;
- monotonic elapsed time.

A02 does not repair the broader B08 clock-domain defect; it only removes uncontrolled wall-clock dependence from tests.

### 4.3 Forbidden-access guard

Add a reusable pytest-level guard that causes an immediate, descriptive failure if a test unexpectedly attempts to:

- open/create/connect to forbidden operational SQLite/database/store paths;
- access default Forward/H39 operational roots;
- access Final Holdout paths;
- make external network requests through project exchange clients or common HTTP transport used by the repository;
- invoke live/testnet/order-submission execution transport.

The guard must be narrow enough not to break ordinary Python/package reads or Git operations needed by legitimate tests.

Prefer guarding project persistence/network/execution boundaries over indiscriminately monkeypatching all `open()` calls.

If low-level filesystem interception is needed, scope it to resolved forbidden roots and document the reason.

### 4.4 Explicit opt-in for synthetic stores

Affected tests must construct complete synthetic temporary stores for the states they need, including representative cases such as:

- empty/missing store;
- valid immature state;
- valid mature metadata state;
- gap/integrity state;
- corrupt/incomplete state where already covered by existing tests;
- exactly-once registry state where applicable.

Do not make tests depend on whatever happens to exist in the developer's checkout.

### 4.5 H39 label/outcome access spy

For pre-gate/status/safety tests, add spies/guards that fail if code reaches H39 label/outcome construction or future-return loaders when the test is intended to exercise metadata-only behavior.

This A02 spy is a **test safety boundary**, not the A03 implementation repair itself.

A03 will separately modify the deprecated diagnostic path so it cannot reach those loaders in production code.

For A02, the test infrastructure must make such access observable and fail loudly.
