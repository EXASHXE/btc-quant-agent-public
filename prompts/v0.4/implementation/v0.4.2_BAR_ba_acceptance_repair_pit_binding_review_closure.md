# 1. Why this repair exists

The independent review found four acceptance issues.

## Finding AR-H1 — HIGH: PIT-07 is proven only at helper level, not at formal-run promotion boundary

Current B03 code provides a helper shaped like:

```text
validate_formal_candle_sequence(..., decision_time_ms=...)
```

which can reject:

```text
available_at_ms > decision_time_ms
```

However the formal candidate path currently follows approximately:

```text
execute_bound_run
  -> _validate_protocol_and_runtime
  -> validate_runtime_dataset_binding
  -> validate_formal_candle_sequence
```

without demonstrating that the **actual information consumed to create each decision/signal** was available by the relevant decision timestamp.

Existing tests prove that the helper can reject a future-available candle, but do not yet prove that an end-to-end formal run cannot be promoted while using an unavailable decision input.

Therefore the claim:

```text
B03_H4_CLOSED
```

is not yet fully justified.

## Finding AR-M1 — MEDIUM: do not repair PIT by applying the wrong time comparison

A formal economic dataset contains both:

- information that existed before a signal/decision; and
- future observations legitimately used later to simulate fills, funding, exits, terminal valuation, or benchmark outcomes.

Therefore this repair MUST NOT naively require:

```text
every candle in the entire simulation dataset
available_at_ms <= every signal timestamp
```

That would destroy causal replay semantics by confusing **decision inputs** with **future simulation outcomes**.

The repair must identify the actual proof surface for the signal/decision information set.

## Finding AR-M2 — MEDIUM: B02 behavior is strong, but provenance/report claims are stronger than implementation

The current execution code behaviorally fixes H3 for opening MARKET and marketable-at-open LIMIT fills, but the report states that a unified `CausalLiquidityObservation` protocol exists even though the current interface is still represented by separate fields such as:

```text
causal_liquidity_volume_base
causal_liquidity_available_at_ms
```

The task must either:

- implement a genuinely useful minimal canonical observation object **only if it reduces duplication and improves proof**, or
- keep the existing fields and correct the report language.

Do not create a new type solely to make the report sentence true.

Additionally, when an execution fill actually consumes timestamped causal liquidity, the persisted execution/trade metadata should not omit the exact liquidity quantity that materially affected impact/slippage.

This task may add the **minimum local execution-cost preimage metadata** needed to make the existing B02 evidence truthful, but it must not build the full B04 replay-input bundle or a second replay engine.

## Finding AR-M3 — MEDIUM: independent B-A review evidence and LOC accounting are incomplete

# 4. Allowed repair strategies for PIT decision binding

Choose the smallest strategy that is actually provable from the current repository.

## Strategy A — reuse an existing proof-bearing signal/input binding

Prefer this if the repository already has an artifact that binds:

```text

-> exact input observations
-> content identity
-> availability timestamps
```

If such an artifact exists:

- make `execute_bound_run` or its canonical verifier require it;
- verify the bound input observations against content-hashed evidence;
- verify their availability timestamps are <= the correct decision boundary;
- include the proof identity in formal run identity/accounting where needed;
- reject mismatch/missing/tampered/unavailable proof before formal COMPLETE.

Do not duplicate an existing evidence contract.

## Strategy B — deterministic reconstruction from existing frozen semantics

This is allowed only if the exact decision-input subset can be reconstructed without heuristic inference.

For example, if the frozen protocol unambiguously says that signal `S(t)` uses a precisely defined closed lookback window ending at a specific event-time boundary, and that subset can be selected from the content-hashed dataset deterministically, then:

- reconstruct only that exact subset;
- verify every required observation is closed and available by the decision timestamp;
- bind a canonical digest of the reconstructed decision input set;
- prove a changed unavailable input changes/refuses the formal run.

Do not use vague rules such as “all previous candles probably belong to the signal.”

## Strategy C — fail closed when provenance is insufficient

If the current repository cannot prove which concrete observations produced a formal signal, do **not** invent provenance.

In that case:

- formal economic promotion of that signal/run must fail closed with a typed error / NOT_TESTABLE path consistent with current architecture;
- legacy or exploratory simulations may remain usable outside formal promotion if already allowed;
- do not mark unproven signals COMPLETE merely because their timestamp lies within the dataset interval;
- record that full replay-input provenance is intentionally deferred to B04.

This strategy is scientifically preferable to self-attested or guessed input provenance.
