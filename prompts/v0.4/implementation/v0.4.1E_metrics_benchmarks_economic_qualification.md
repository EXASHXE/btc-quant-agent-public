## 1. Objective

Replace the current diagnostic-only benchmark layer with a formally bound, replayable economic qualification pipeline.

The finished chain must be:

```text
immutable experiment revision
  -> bound input/run identity
  -> causal economic simulation
  -> reconstructable accounting + round-trip attribution
  -> time-valid metrics
  -> preregistered matched benchmarks
  -> immutable comparison contract
  -> deterministic qualification result
  -> content-addressed P5 evidence
  -> legal economic decision transition
```

Formal qualification must be impossible from an arbitrary caller-supplied `SimulationSummary`.

A profitable synthetic test is evidence only that the machinery works. It is not evidence of BTC alpha.

## 2. Known P6 defects to close

At the current baseline:

1. `SimulationSummary` lacks explicit terminal realized/unrealized decomposition and complete exposure/turnover attribution.
2. win/loss reporting can be detached from fully net round-trip economics.
3. Sharpe annualization is hard-coded (`sqrt(35040)`) rather than bound to a declared/verified return cadence.
4. passive BTC uses bespoke spot-like accounting instead of a clearly bound benchmark vehicle/economic contract.
5. random benchmark uses an arbitrary per-candle entry probability, returns only an average plus the last trial curve, and does not match the candidate's preregistered trade/exposure design.
6. `evaluate_economic_qualification()` accepts a caller-provided summary and compares mostly PnL; it is intentionally `NOT_TESTABLE` today.
7. P5 intentionally blocks `ECONOMICALLY_QUALIFIED` because the P6 evidence contract did not yet exist.

P6 must close these without weakening P0–P5 invariants.

## 3. Required accounting/result contract

### 3.1 Reconstructable simulation result

Extend or replace the formal result model so that a run can be reconstructed and reconciled from its ledger/equity evidence.

At minimum provide and validate:

- initial cash;
- final cash;
- final equity;
- realized gross PnL before fees/funding;
- terminal unrealized PnL;
- total fees;
- total funding cashflow;
- slippage as informational attribution only when already embedded in fill price — **never deduct it twice**;
- net PnL and net return;
- final/terminal position quantity, mark, and notional;
- fill count;
- completed round-trip count;
- winning/losing/flat round-trip counts;
- gross wins / gross losses;
- net wins / net losses;
- profit factor with an explicit representation for undefined/infinite cases that remains valid canonical JSON (do not serialize NaN/Infinity);
- max drawdown value and percentage;
- turnover/notional traded;
- time exposure;
- capital/notional exposure statistics sufficient for benchmark matching;
- equity curve with timestamps;
- enough event identifiers to cross-check against `TradeEvent` history.

The primary accounting invariant must hold within a documented floating tolerance:

```text
final_equity - initial_cash
  == realized_gross_pnl
     + terminal_unrealized_pnl
     - total_fees
     + total_funding
```

If the chosen sign convention differs, document it once and enforce an algebraically equivalent identity everywhere.

The last valid equity-curve point must reconcile to `final_equity` under the declared terminal policy.

### 3.2 Round-trip attribution

Create a deterministic round-trip/trade attribution model that works for LONG and SHORT and handles partial reductions.

Each completed round trip must attribute at least:

- entry/exit event ids and timestamps;
- side;
- quantity/notional;
- gross realized PnL;
- allocated entry/exit fees;
- funding attributable while the position was economically open;
- net PnL;
- holding duration;
- MAE/MFE only if derivable causally from the available data without inventing intrabar path; otherwise omit or mark unavailable.

Win/loss classification for economic metrics must be based on **net round-trip PnL after fees and funding**, not gross price movement.

A trade that is gross-positive but net-negative must be a losing trade.

Do not silently merge unrelated reversals or partial reductions into a favorable round trip.

### 3.3 Terminal handling

Formal metrics must obey the protocol's `terminal_policy`.

At minimum distinguish explicitly between:

- terminal flat/forced close using a declared executable rule and costs;
- mark-to-market open position;
- unsupported/incomplete terminal state.

No hidden forced close is allowed.

A candidate and every qualification benchmark must use compatible terminal treatment. If comparability cannot be established, verdict is `NOT_TESTABLE`.

## 4. Time-return and Sharpe contract

Remove hard-coded annualization assumptions.

Introduce an explicit metrics/return contract containing the return sampling rule and annualization semantics.

Requirements:

- return timestamps must be monotonic and reconstructable;
- if a fixed cadence is claimed, verify the actual spacing is compatible with it;
- do not call an arbitrary/irregular equity curve a 15-minute series;
- annualization must derive from an explicit cadence/time unit, not a magic constant;
- if annualized Sharpe is not valid for the available timestamps, represent it as unavailable / not testable rather than fabricate a number;
- candidate and benchmarks must use the same metric sampling contract for formal comparison;
- all persisted metric values must be finite JSON values or explicit null/unavailable states.

Formal qualification should not depend on Sharpe unless the preregistered comparison contract explicitly declares a Sharpe gate and its cadence is valid.

## 5. Immutable run identity and evidence binding

A formal economic run must bind to one exact experiment revision and one exact data/config state.

Create a content-addressed run/result identity that includes at least:

- `experiment_revision_id` and protocol hash;
- input-contract identity;
- dataset/economic-input evidence id/hash;
- exact data interval start/end and observation count;
- signal/input set identity/hash;
- funding-event set identity/hash when applicable;
- product/instrument scope;
- initial capital;
- economic policy identity/hash;
- cost model identity/hash;
- execution model identity/hash;
- benchmark/comparison contract identity/hash;
- terminal policy;
- metrics contract identity/hash;
- code revision;
- completeness/testability state.

Do not let two runs with materially different semantics share one formal result identity.

Do not make generated timestamps part of semantic/content identity unless they are economically meaningful.

## 6. ComparisonContract — preregister before qualification

Implement a deeply immutable, canonical/content-addressed comparison contract.

It must define, not infer after seeing results:

- product / benchmark vehicle;
- initial capital;
- data interval identity;
- candidate policy/cost/execution/funding identities;
- metrics contract;
- terminal handling;
- required vs descriptive benchmarks;
- randomization unit;
- seed and number of trials;
- required direction-count / trade-count / holding / exposure matching rules;
- tolerance for any matched statistic;
- all economic hurdles and pass/fail operators;
- whether passive BTC is mandatory, descriptive, or not applicable;
- random-baseline pass criterion (for example a preregistered percentile/quantile rule — **do not invent a universal default**);
- evidence/completeness requirements;
- result schema version.

The `ExperimentMetadata.benchmark` field must be a concrete `VersionedIdentity` bound to this comparison contract for formal qualification. A protocol that still uses `P6_PENDING` is diagnostic-only and cannot be economically qualified.

Changing any comparison rule must create a new benchmark identity and therefore a new experiment revision; never overwrite the old protocol semantics.

## 7. Benchmark semantics

### 7.1 Cash benchmark

Cash/no-trade may remain a required baseline when the comparison contract says so.

It must use the same interval, initial capital, metric timestamps, and terminal accounting conventions.

### 7.2 Passive BTC / beta benchmark

Do not silently compare a BTCUSDT perpetual candidate against bespoke spot accounting as if they were the same vehicle.

For a formal BTCUSDT linear-perpetual comparison, prefer a passive long benchmark implemented with the same economic engine/cost/funding/terminal semantics where applicable.

If a spot-equivalent BTC benchmark is intentionally retained, its vehicle difference must be explicit in the comparison contract. It must be descriptive-only unless the preregistered contract explicitly permits it as a required cross-vehicle hurdle.

Terminal fees/costs must be reflected consistently in both final equity and the final equity-curve point.

### 7.3 Random matched benchmark

Replace the current arbitrary 5%-per-candle random entry baseline for formal qualification.

The preregistered randomization procedure must use only eligible causal opportunity timestamps and match the declared candidate design as closely as the contract requires. At minimum support matching rules for:

- number of entries/trades;
- LONG/SHORT direction counts or declared direction distribution;
- same sizing/risk policy;
- same exit policy;
- same fee/execution/funding model;
- same data interval;
- holding/exposure constraints specified by the contract.

Do not force exact exposure matching if the chosen stochastic procedure cannot guarantee it. Instead validate the contract's declared tolerance; a failed comparability check makes that trial/qualification `NOT_TESTABLE`, not silently acceptable.

Persist **every trial result**, seed/trial id, matching diagnostics, and aggregate distribution. Never return only a mean while attaching the last trial's equity curve.

Randomization must be deterministic for the same preregistered seed + inputs.

No random baseline may use H39/holdout labels or future information unavailable to the candidate at the corresponding decision time.

## 8. EconomicQualificationResult

Create an immutable canonical qualification result that binds:

- experiment revision;
- run identity/result evidence;
- comparison-contract identity;
- benchmark result identities;
- metric values;
- per-gate observed value, operator, hurdle, pass/fail/testability;
- random trial distribution and matching diagnostics where required;
- terminal/completeness status;
- overall verdict: `QUALIFIED`, `REJECTED`, or `NOT_TESTABLE`;
- explicit reason codes;
- code revision/schema version.

The result must be deterministic from the bound evidence and comparison contract.

`NOT_TESTABLE` must be used for missing/incomparable/incomplete evidence and must not be converted to `REJECTED` merely for convenience.

Economic and statistical qualification remain separate. Do not require H39/FWL globally.

## 9. P5 lifecycle integration

P5 currently intentionally rejects `ECONOMICALLY_QUALIFIED`. P6 may open that transition only through a fail-closed, evidence-bound path.

Requirements:

1. Current status must already be `STATISTICALLY_QUALIFIED`.
2. Direct arbitrary `update_decision_status(... ECONOMICALLY_QUALIFIED ...)` must **not** become an easy bypass.
3. Add a dedicated economic-decision path or equivalent fail-closed mechanism that validates:
   - exact experiment revision;
   - concrete benchmark `VersionedIdentity` (not `P6_PENDING`);
   - COMPLETE local/content-hashed economic qualification evidence;
   - result schema/type;
   - result verdict;
   - bound run/comparison/benchmark identities;
   - protocol/code/product/terminal consistency;
   - required evidence ids are all registered and content-valid.
4. `QUALIFIED` may append `STATISTICALLY_QUALIFIED -> ECONOMICALLY_QUALIFIED`.
5. `REJECTED` may append `STATISTICALLY_QUALIFIED -> REJECTED` with the economic result as evidence.
6. `NOT_TESTABLE` must not manufacture a lifecycle promotion/rejection; persist/register diagnostic evidence only and leave status unchanged.
7. Invalid/tampered/incomplete/stale evidence must leave registry memory, generation, event chain, and committed bytes unchanged.
8. Preserve P5 stale-writer, append-only, hash-chain, atomic-write, and Final Holdout isolation invariants.

Avoid circular module dependencies. If the registry needs a generic evidence attestation/typed contract rather than importing economic implementation code, design that boundary explicitly and test it.

## 10. Legacy diagnostic API

The old `BenchmarkEngine.evaluate_economic_qualification(strategy_summary, ...)` must not remain a hidden formal bypass.

Choose one:

- keep it explicitly diagnostic-only and unable to produce/register formal qualification; or
- replace it with a formal API that requires bound run evidence + ComparisonContract + experiment revision.

Arbitrary manually constructed `SimulationSummary` objects must never be enough to reach `ECONOMICALLY_QUALIFIED`.

## 11. Mandatory regression tests

Add focused deterministic tests covering at least:

1. **Accounting identity** — LONG/SHORT, profits/losses, fees, funding, partial close, terminal open/flat.
2. **Net winner correctness** — gross-positive but fee/funding-negative round trip is classified losing.
3. **Terminal reconciliation** — final curve point equals final equity under the declared terminal policy.
4. **No double slippage charge** — slippage embedded in fill price is not deducted again.
5. **Sharpe cadence** — 15m valid spacing may annualize according to contract; irregular/arbitrary spacing cannot impersonate 15m.
6. **Undefined metrics** — zero-volatility/zero-loss cases serialize without NaN/Infinity.
7. **Passive benchmark accounting** — terminal fee/funding/vehicle semantics reconcile.
8. **Random trial preservation** — every trial is returned/persisted; aggregate cannot pair mean metrics with a last-trial curve.
9. **Random determinism** — same seed/input/contract => same trials and result hash.
10. **Matched benchmark** — required trade/direction/exposure matching is verified; failed tolerance => `NOT_TESTABLE`.
11. **Comparison preregistration** — changing hurdle/seed/trial count/required benchmark/terminal rule changes contract hash and protocol revision.
12. **`P6_PENDING` gate** — cannot formally qualify.
13. **Manual-summary bypass** — caller-created summary cannot qualify.
14. **Evidence tamper** — changed result/benchmark/input bytes are rejected before lifecycle change.
15. **Lifecycle success** — only valid `STATISTICALLY_QUALIFIED + QUALIFIED evidence` reaches `ECONOMICALLY_QUALIFIED`.
16. **Lifecycle rejection** — valid failed economic evidence reaches `REJECTED` where contract says failure.
17. **NOT_TESTABLE lifecycle** — status remains unchanged.
18. **Atomic failure/stale writer** — no partial decision/evidence persistence.
19. **P0–P5 preservation** — all prior economic/registry/holdout regression suites still pass.
20. **Repeatability** — identical semantic inputs/configs produce identical formal hashes/results apart from explicitly non-semantic audit timestamps.

Map relevant old observations from `reviews/v0.4/v040_review_checks.py` into repaired expectations rather than keeping stale old-defect assertions as the acceptance source.
