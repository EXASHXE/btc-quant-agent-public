## 3. Remaining defect

`ExperimentMetadata.signal_producer_contract` is currently optional.

When it is `None`, the B04 builder still has a compatibility path roughly equivalent to:

```text
protocol.signal_producer_contract = None
        ↓
candidate declares producer_contract_id
        ↓
registry lookup accepts the contract
        ↓
bundle can be built
```

The verifier also only enforces equality if `_resolve_protocol_producer_contract(expected_protocol)` returns a contract. Therefore:

```text
expected_protocol exists
but
expected_protocol.signal_producer_contract is None
```

can skip the authoritative protocol-contract equality check.

Persisted verification similarly permits `run_identity.signal_producer_contract` to be absent if the artifact was built through this compatibility path.

This violates the required authority chain:

```text
frozen/versioned protocol
        ↓
authoritative signal producer contract
        ↓
verified replay bundle
        ↓
formal signal candidate
```

Formal candidate authority must never be:

```text
candidate chooses any registered contract
```

## 4. Required semantic repair

### 4.1 Formal non-empty signal runs require a protocol-bound producer contract

For every formal run with `signals != ()`:

```text
protocol.signal_producer_contract MUST be present
```

If absent:

```text
FAIL CLOSED / NOT_TESTABLE
```

Do not infer a contract from:

- `generation_contract.rule`
- `producer_contract_id`
- `producer_identity`
- feature id
- registry defaults
- legacy bindings
- signal payload

### 4.2 Builder must reject missing protocol contract

In `build_formal_replay_input_bundle(...)` or the nearest canonical construction boundary:

```text
if signals are non-empty
and protocol-bound producer contract cannot be resolved
→ reject
```

The existing fallback where a caller-provided registered `producer_contract_id` is accepted when the protocol has no bound contract must not authorize formal candidate runs.

### 4.3 Verifier must independently reject missing protocol contract

`validate_formal_replay_input_bundle(..., expected_protocol=...)` must not rely on the builder having done the right thing.

If:

```text
bundle.decision_inputs non-empty
and expected_protocol is supplied
and expected_protocol has no resolvable signal producer contract
```

then reject.

Do not silently skip the contract check when `proto_contract is None`.

### 4.4 `execute_bound_run` must fail closed before economic qualification

A formal run with non-empty signals must not reach successful COMPLETE qualification if the protocol lacks a producer contract.

The failure should happen before the result can be treated as formally qualified evidence.

### 4.5 Persisted run identity must require producer contract for signal-based COMPLETE runs

For persisted validation:

```text
COMPLETE
+ non-empty signal set
→ run_identity.signal_producer_contract REQUIRED
```

If absent, reject even when:

- ReplayInputBundle exists
- bundle hashes are valid
- dataset evidence is valid
- decision bindings are valid
- bundle producer contract is a known registry contract

The authority must come from the frozen run/protocol identity, not from the bundle itself.

### 4.6 Preserve legitimate zero-signal runs

Do not break legitimate:

```text
CASH / zero-signal / no-signal COMPLETE controls
```

A run whose signal set is genuinely empty may continue without `signal_producer_contract`, provided this matches current canonical semantics.
