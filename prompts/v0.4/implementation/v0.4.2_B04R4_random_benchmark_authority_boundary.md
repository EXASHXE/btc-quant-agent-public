# v0.4.2 B04R4 — Random Benchmark Authority Boundary Acceptance Repair

Repository: `EXASHXE/btc-quant-agent`  
Branch: `v0.4`

## 0. Purpose

This is a **very narrow acceptance repair** after independent review of B04R3.

Do **not** redesign B04. Do **not** start B05/B06/B07. Do **not** change alpha logic, randomization semantics, strategy parameters, economic hurdles, H39, Final Holdout, live/testnet execution, persistence architecture, REST, or SQLite work.

B04R3 correctly closed the generic “protocol has no producer contract” path for ordinary candidates, but one authority bypass remains:

> `CANONICAL_RANDOM_BENCHMARK_V1` is exempted from protocol producer-contract matching inside generic replay-bundle construction/verification and persisted verification. Because the same generic `execute_bound_run` / `EconomicRunResult` path is also used for candidate runs, a candidate can potentially submit a random-benchmark producer bundle while the protocol is bound to a different candidate producer contract.

The B04R3 task explicitly required:

> Preserve RANDOM_MATCHED only where it is clearly benchmark-specific and cannot authorize the candidate strategy. Do not use the random benchmark exemption as a generic escape hatch.

Current implementation does not yet prove that boundary.

Goal: make candidate-vs-benchmark authority explicit and fail-closed, while preserving the existing RANDOM_MATCHED benchmark workflow and leaving B06 random-draw reconstruction untouched.

## 3. Exact remaining defect

Current `build_formal_replay_input_bundle(...)` contains logic equivalent to:

```text
if declared_contract_id == CANONICAL_RANDOM_BENCHMARK_V1:
    accept random benchmark contract
elif protocol-bound producer exists:
    enforce protocol contract
```

Current `validate_formal_replay_input_bundle(...)` similarly skips protocol-contract equality for:

```text
CANONICAL_RANDOM_BENCHMARK_V1
```

Persisted verification also skips candidate run-identity producer-contract equality when a decision entry uses the random benchmark contract.

This exemption is currently keyed only by **contract identity**, not by an independently bound benchmark/candidate role.

Therefore a formal candidate can potentially have:

```text
protocol.signal_producer_contract = CANONICAL_RETURN_SIGN_V1
run_identity.signal_producer_contract = CANONICAL_RETURN_SIGN_V1

but ReplayInputBundle.decision_inputs[*].producer_contract_id = CANONICAL_RANDOM_BENCHMARK_V1
```

and pass the generic random exception.

Because `RandomBenchmarkSignalProducer` obtains direction/strength from its benchmark generation material rather than the protocol candidate producer contract, this is an authority escape hatch if such an artifact can be treated as candidate evidence.

This violates:

```text
candidate protocol
    -> exact candidate producer contract
    -> exact candidate ReplayInputBundle
    -> candidate EconomicRunResult
```

## 4. Required semantic boundary

There must be a canonical distinction between:

```text
CANDIDATE
```

and:

```text
RANDOM_BENCHMARK
```

The distinction must be bound strongly enough that a random-benchmark run/bundle cannot later be accepted as candidate evidence.

A generic special case based only on:

```text
producer_contract_id == CANONICAL_RANDOM_BENCHMARK_V1
```

is not sufficient.

---

## 5. Candidate authority rule

For every non-empty **candidate** run:

```text
ReplayInputBundle producer contract
== protocol.signal_producer_contract
== run_identity.signal_producer_contract
```

both contract ID and contract hash must match exactly.

No exception for `CANONICAL_RANDOM_BENCHMARK_V1` is allowed in candidate mode.

If a candidate protocol is bound to `CANONICAL_RETURN_SIGN_V1`, then a random-benchmark bundle must be rejected even though the random contract is registered and internally valid.

---

## 6. Random benchmark rule

The RANDOM_MATCHED benchmark flow may continue to use:

```text
CANONICAL_RANDOM_BENCHMARK_V1
```

but only under an explicitly benchmark-specific authority context that cannot be mistaken for candidate evidence.

Do not redesign random-draw semantics. Do not implement B06 seed/draw reconstruction in this task.

The repair must ensure the system can answer, from canonical persisted semantics:

```text
Is this run candidate evidence or a random benchmark trial?
```

The answer must not depend only on which producer contract happened to appear in the bundle.

---

## 7. Recommended minimal design

Prefer the smallest explicit role binding, for example a versioned enum/field such as:

```text
run_role = CANDIDATE | RANDOM_BENCHMARK
```

or an equivalent existing canonical concept if the repository already has one.

If implemented, the role should be bound into the relevant semantic identity, ideally `EconomicRunIdentity` and therefore `run_id`.

Recommended rules:

### CANDIDATE

```text
run_role = CANDIDATE
protocol.signal_producer_contract required for non-empty signals
bundle producer contract must exactly match protocol/run identity
CANONICAL_RANDOM_BENCHMARK_V1 cannot bypass this
```

### RANDOM_BENCHMARK

```text
run_role = RANDOM_BENCHMARK
producer contract must be exactly CANONICAL_RANDOM_BENCHMARK_V1
run must only be consumed by benchmark construction
must not satisfy candidate-run validation
```

Do not mechanically implement this exact field name if an existing repository identity is cleaner. The invariant matters more than naming.

## 8. Candidate consumer must reject benchmark runs

The candidate boundary used by:

```text
build_formal_benchmark_suite(... candidate_run=...)
evaluate_formal_economic_qualification(... candidate_run=...)
```

or their shared `_validate_candidate_run_binding(...)` path must reject an `EconomicRunResult` whose canonical role is RANDOM_BENCHMARK.

This is essential.

Otherwise an attacker can simply request benchmark mode, obtain a valid random-producer `EconomicRunResult`, and then reuse it as candidate evidence.

## 9. Persisted verifier

`validate_persisted_decision_input_bindings(...)` must enforce role-specific producer authority.

For candidate COMPLETE signal runs:

```text
run role = CANDIDATE
run_identity.signal_producer_contract required
bundle producer contract must match run_identity.signal_producer_contract
```

Do not retain a generic persisted exception:

```text
if producer_contract_id == CANONICAL_RANDOM_BENCHMARK_V1:
    continue
```

unless the persisted run is independently identified as RANDOM_BENCHMARK.

For random benchmark runs:

```text
role = RANDOM_BENCHMARK
bundle producer contract = CANONICAL_RANDOM_BENCHMARK_V1
```

Any other producer contract must reject.

---

## 10. Generic builder/verifier API boundary

`build_formal_replay_input_bundle(...)` and `validate_formal_replay_input_bundle(...)` must not infer benchmark authority solely from bundle content.

The authority context must come from outside the untrusted bundle, e.g.:

```text
expected run role / caller semantic context / canonical run identity
```

A bundle cannot self-declare itself a benchmark and thereby escape candidate protocol matching.

Do not trust:

```text
producer_contract_id
producer_identity
generation_contract.rule
```

as sufficient proof of benchmark role.
