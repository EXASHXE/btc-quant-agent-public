## MarketEventV1 (exact semantic contract)

Envelope JSON canonical UTF-8, schema_version `market-event-v1`. Required fields and meanings:
- `symbol` = `BTCUSDT` uppercase, product `BINANCE_USDT_M_PERP`, `channel` ∈ `{last_kline_1m,mark_price,agg_trade,depth_delta,depth_snapshot,funding_settled,health}`.
- `provider_event_ms`: original source E if present, otherwise null with explicit why; `provider_transaction_ms`: original source T if present, else null; `observed_wall_utc_ms`: wall clock on receiver ingress; `observed_monotonic_ns`: monotonic ingress order within process only; `available_at_ms`: the **no-earlier-than receiver ingress wall time** of record, not merely bar close/provider E; deterministic replay must preserve recorded value unchanged. Wall time can jump, so if monotonic ordering and wall timestamp contradict, gate `CLOCK_UNCERTAIN`.
- `source_stream_id`, `connection_epoch`, `source_sequence` (integer where provider supplies; otherwise null), `payload_sha256`, `payload` (public provider fields only), `quality` ∈ `{VERIFIED,DEGRADED,UNKNOWN,INVALID}`; `reason_codes` string array; `raw_source_manifest_sha256` of immutable raw append segment. Public-only source IDs; never API keys or account data. Dedupe key `sha256(symbol,channel,epoch,provider-id-or-raw-sha)`; duplicates remain observable counters but do not count twice.
- **BookIntegrityV1** optional `book`: `snapshot_update_id`, `first_update_id`, `final_update_id`, `previous_final_update_id` when provider supplies, `continuous` boolean, `best_bid`, `best_ask`, `observed_depth_levels`, `stale_age_ms`, `quality`, `reason_codes`. Futures depth sequence based on provider's official snapshot + differential update rules; no claim of a valid book if gap, crossed spread or clock uncertainty. Depth snapshot is **not** an execution order or a promise of queue fill.
- Bars: `bar_open_ms`, `bar_close_ms`, `closed` as provider-observed; signal decisions only on closed and recorded-as-available bars. Derived windows have own `feature_known_at_ms = max(input.available_at_ms)`, `decision_at_ms >= feature_known_at_ms`. Missing data does NOT permit forward fill or interpolation and must become `NO_DATA/UNKNOWN`.
- Signed funding source: only **settled official realized** rates with known settlement + observed timestamps may accrue. Estimated next-rate Mark stream must be labeled `ESTIMATED_NOT_SETTLED` and forbidden from realized cash journal.
- Replayer identity: raw immutable segment hash + adapter source SHA + market-event-v1 schema identity + feature/config registry hash + receiver-clock provenance. **Historical data acquired after the fact cannot be represented as originally available_at**. On replay always use stored arrival times.

Concrete public official docs: https://developers.binance.com/en/docs/products/derivatives-trading-usds-futures/Introduction and https://developers.binance.com/en/docs/products/derivatives-trading-usds-futures/websocket-market-streams/Live-Subscribing-Unsubscribing-to-streams .
