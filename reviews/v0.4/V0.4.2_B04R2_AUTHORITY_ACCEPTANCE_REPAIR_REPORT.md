# V0.4.2 B04R2 Acceptance Repair Report — Authoritative Producer Binding & Economic Metadata Provenance Closure

## 1. Executive Summary

This report documents the completion of **v0.4.2 B04R2 Authority Acceptance Repair** on branch `v0.4` of repository `EXASHXE/btc-quant-agent`.
The repair resolves all three critical findings raised during independent review of B04R:

1. **A1 (BLOCKER) — Authoritative Producer Binding via Protocol**:
   Eliminated opportunistic and candidate-selected producer contracts. Authoritative producer contracts (`SignalProducerContract`) are now strictly bound at the protocol definition layer via `ExperimentMetadata.signal_producer_contract`. The contract identity and canonical hash are cryptographically locked into `protocol_hash` and `experiment_revision_id`, and stamped into `EconomicRunIdentity.signal_producer_contract`. Any candidate attempting to declare an unregistered contract, a mismatched contract, or swap contracts is rejected fail-closed.
2. **A2 (BLOCKER) — Economic Dynamic Inputs Provenance Closure & Circular Attestation Elimination**:
   Eliminated circular self-attestation where candidate signals backfilled execution and metadata parameters into `generation_contract`. Replay now derives signal parameters strictly from `authoritative_contract.parameters`. Every dynamic economic input has an unambiguous, single-owner provenance hierarchy: signal-generation inputs are producer-derived from immutable preimages, while execution-time inputs are bound to causal market data.
3. **A3 (HIGH) — Evidence-Stripping Bypass Fail-Closed Repair in Persisted Verifier**:
   Repaired the persisted accounting verifier in `acceptance_verifier.py`. The requirement for formal replay bundle evidence is now derived strictly from immutable run semantics (`run_identity.completeness == "COMPLETE"` and non-empty signal set), rather than the presence of evidence fields in accounting. Any candidate run that strips `formal_decision_input_bindings`, `formal_decision_input_set_sha256`, or `replay_input_bundle_sha256` fails closed immediately with `ValueError`. Legitimate CASH / 0-signal runs are preserved without false rejections.

All 980 tests pass across the full test suite (13 new adversarial/positive-control tests added). Local and remote CI matrices across Python 3.11, Python 3.12, and Python 3.13 are 100% green.

## 3. Finding A1 (BLOCKER) — Authoritative Producer Binding via Protocol

### 3.1 Root Cause
In B04/B04R, producer contracts were verified against a registry, but the candidate or bundle builder still chose or implied which contract to use (`declared_producer`, `declared_contract_id`). If absent, it could fall back to auto-selecting contracts based on candidate rule strings. This created an attack vector where an adversary could swap out the intended contract for another valid registered contract (e.g. substituting a loose momentum threshold contract for a strict return sign contract) without violating registry membership.

### 3.2 Technical Repair
1. **Protocol Binding (`ExperimentMetadata.signal_producer_contract`)**:
   - `signal_producer_contract: VersionedIdentity | Any | None = None` is defined directly on `ExperimentMetadata` (`src/btc_quant_agent/research_contract/models.py`).
   - When present, `signal_producer_contract` is included in `ExperimentMetadata.semantic_payload()`.
   - As a consequence, `signal_producer_contract.contract_id` and canonical `contract_hash` are immutably hashed into `protocol_hash` and `experiment_revision_id`. Any alteration of the contract definition changes the experiment revision ID.
2. **Run Identity Stamping (`EconomicRunIdentity.signal_producer_contract`)**:
   - `EconomicRunIdentity` (`src/btc_quant_agent/economic/qualification.py`) includes `signal_producer_contract: VersionedIdentity | None = None`.
   - In `execute_bound_run`, the protocol's authoritative contract identity is resolved and stamped into the run identity:
     ```python
     spc = protocol.signal_producer_contract
     spc_identity = spc if isinstance(spc, VersionedIdentity) else spc.to_versioned_identity()
     ```
   - Serialized in `EconomicRunIdentity.to_dict()` and part of `run_id`.
3. **Bundle Build & Verification Enforcement**:
   - In `build_formal_replay_input_bundle` (`src/btc_quant_agent/economic/replay_bundle.py`):
     - Resolves `authoritative_contract` from `protocol.signal_producer_contract`.
     - Candidate market-derived signals are strictly enforced against `authoritative_contract`.
     - Exemption is strictly scoped to `CANONICAL_RANDOM_BENCHMARK_V1` benchmark runs.
     - Unverified fallback to `FIXED_DIRECTION` or auto-selecting registered contracts is strictly prohibited and raises `ValueError`.
   - In `validate_formal_replay_input_bundle`:
     - Checks contract ID existence in the registry.
     - Verifies contract hash matches authoritative contract in registry.
     - Verifies contract matches protocol-bound authoritative contract.
   - In `validate_persisted_decision_input_bindings` (`src/btc_quant_agent/economic/acceptance_verifier.py`):
     - Cross-validates `run_identity.signal_producer_contract` against bundle entries (skipping random benchmarks). Mismatches fail closed.

## 4. Finding A2 (BLOCKER) — Economic Dynamic Inputs Provenance Closure & Circular Attestation Elimination

### 4.1 Root Cause
In B04/B04R, circular self-attestation existed where candidate signals supplied their own execution parameters (`strength`, `horizon_ms`, `confidence_interval`, `spread_bps`, `liquidity_volume_base`, etc.) and backfilled them into `generation_contract` during bundle construction. The verifier then replayed using those backfilled parameters, confirming only that the candidate matched its own self-attestation.

### 4.2 Technical Repair & Dynamic Inputs Taxonomy
All parameter backfilling into `generation_contract` from candidate signal payloads has been removed. Replay derives parameters strictly from authoritative sources.

The authoritative provenance hierarchy for all dynamic economic inputs is structured as follows:

| Dynamic Input | Provenance Owner | Authority Source | Derived vs Causal | Tampering / Mismatch Policy |
|---|---|---|---|---|
| `direction` | Signal Producer | Empirical rule evaluated over material candle preimages | Producer-derived | Fails closed (`ValueError` on mismatch) |
| `strength` | Authoritative Contract | `contract.parameters.get("strength", 1.0)` | Producer-derived | Fails closed (`ValueError` if candidate diverges) |
| `horizon_ms` | Authoritative Contract | `contract.parameters.get("horizon_ms", 3_600_000)` | Producer-derived | Fails closed (`ValueError` if candidate diverges) |
| `confidence_interval` | Authoritative Contract | `contract.parameters.get("confidence_interval")` | Producer-derived | Fails closed (`ValueError` if candidate diverges) |
| `metadata` (economic) | Authoritative Contract | `contract.parameters.get("metadata", {})` | Producer-derived | Fails closed (`ValueError` if candidate diverges) |
| `material_input_open_times_ms` | Dataset Evidence | Dataset candle open times verified with $t_{available} \le t_{signal}$ | Preimage boundary | Fails closed (`ValueError` on unavailable/missing candle) |
| `expected_preimage_sha256` | Dataset Evidence | `canonical_sha256` of canonical candle payloads | Preimage boundary | Fails closed (`ValueError` on hash mismatch) |
| `execution_price` | Execution Model | Open price of execution candle at event timestamp | Causal Market Input | Fails closed (must match verified candle series) |
| `spread_bps` | Cost Model | Protocol `cost_model.parameters["spread_bps"]` (or verified order book depth) | Causal Market Input | Fails closed (`ValueError` on divergence) |
| `liquidity_volume_base` | Market Snapshot | Verified depth snapshot at event timestamp (or protocol model constraints) | Causal Market Input | Fails closed (`ValueError` on divergence) |
| `funding_rate` / settlement | Funding Model | Formal funding settlement stream bound to runtime market data | Causal Market Input | Fails closed (`ValueError` on settlement mismatch) |

In `CanonicalRuleSignalProducer.replay_signal` (`src/btc_quant_agent/economic/signal_producer.py`):
```python
rule_name = authoritative_contract.rule
strength = float(authoritative_contract.parameters.get("strength", 1.0))
horizon_ms = int(authoritative_contract.parameters.get("horizon_ms", 3_600_000))
confidence_interval = authoritative_contract.parameters.get("confidence_interval")
metadata = dict(authoritative_contract.parameters.get("metadata", {}))
```
Candidate signals attempting to self-attest or overwrite any of these fields are rejected immediately upon comparison with the replayed signal in `validate_formal_replay_input_bundle`.

## 5. Finding A3 (HIGH) — Evidence-Stripping Bypass Fail-Closed Repair

### 5.1 Root Cause
In `src/btc_quant_agent/economic/acceptance_verifier.py`, the persisted accounting verifier contained the following logic:
```python
if "formal_decision_input_bindings" in accounting:
    # validate bindings and replay bundle
```
If an adversarial candidate generated profitable trades without valid signal provenance and simply stripped `formal_decision_input_bindings` and `formal_decision_input_set_sha256` from the persisted accounting JSON, the check evaluated to `False` and skipped bundle validation completely, allowing an unverified run to pass acceptance.

### 5.2 Technical Repair
1. **Deriving Completeness from Run Semantics**:
   The requirement for formal evidence is derived from the immutable run identity and accounting completeness:
   ```python
   is_complete = run_identity.get("completeness") == "COMPLETE"
   has_signals = run_identity.get("signal_set_sha256") != canonical_sha256([])
   requires_formal_bundle = is_complete and has_signals
   ```
2. **Fail-Closed Evidence Check**:
   If `requires_formal_bundle` is True:
   - The absence of `formal_replay_input_bundle` in accounting raises `ValueError("persisted accounting for COMPLETE run requires formal_replay_input_bundle")`.
   - The absence of `formal_decision_input_bindings` or `formal_decision_input_set_sha256` raises `ValueError`.
   - The absence of `replay_input_bundle_sha256` in `run_identity` raises `ValueError`.
3. **Preservation of Legitimate CASH / 0-Signal Runs**:
   For runs where no signals were generated (e.g. CASH baseline where `signal_set_sha256 == canonical_sha256([])`), `has_signals` is `False`. The accounting dictionary has empty bindings `[]`. Using `has_legacy = bool(accounting.get("formal_decision_input_bindings"))` allows valid 0-signal runs to pass without false-positive failures.
