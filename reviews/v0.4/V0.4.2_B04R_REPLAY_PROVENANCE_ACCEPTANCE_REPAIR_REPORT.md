## 3. Detailed Technical Repairs

### 3.1 R1: Authoritative Producer Contracts & Prohibition of Unverified Fallbacks
**Problem**: In B04, the generation contract was declared directly by the caller/runner inside `decision_inputs` (`generation_contract={"rule": "FIXED_DIRECTION", ...}`). If unspecified, it silently fell back to `FIXED_DIRECTION`. Furthermore, `CanonicalRuleSignalProducer` permitted `FIXED_DIRECTION`, allowing market candidate signals to bypass empirical rule generation.

**Repair Implementation**:
1. **`SignalProducerContract` Dataclass**:
   - Defined in `src/btc_quant_agent/economic/signal_producer.py`.
   - Immutable fields: `contract_id`, `producer_identity`, `producer_version`, `rule`, `lookback_bars`, `input_requirements`, `parameters`, `semantic_version`.
   - Canonical hash: `canonical_sha256(semantic_payload())`.
2. **Authoritative Registry (`SignalProducerRegistry`)**:
   - Standard contracts registered:
     - `CANONICAL_RETURN_SIGN_V1`
     - `CANONICAL_MOMENTUM_THRESHOLD_V1`
     - `CANONICAL_PRICE_BREAKOUT_V1`
     - `CANONICAL_RANDOM_BENCHMARK_V1`
     - `SYNTHETIC_FIXED_DIRECTION_V1`
3. **Prohibition of `FIXED_DIRECTION` for Candidate Signals**:
   - In `CanonicalRuleSignalProducer`: explicitly raises `ValueError("FIXED_DIRECTION is forbidden in CanonicalRuleSignalProducer")`.
   - In `build_formal_replay_input_bundle`: raises `ValueError` if `CANONICAL_RULE_SIGNAL_PRODUCER` attempts to declare `FIXED_DIRECTION` or if an unverified fallback is attempted.
4. **Synthetic Isolation**:
   - `SyntheticFixedSignalProducer` handles `SYNTHETIC_FIXED_DIRECTION_V1` strictly for synthetic/fixture testing. Requires lookback validation against dataset candles ($t_{available} \le t_{signal}$).

### 3.2 R2: Complete Economic Signal Semantic Payload Verification
**Problem**: B04's replay engine checked only scalar attributes (`direction`, `strength`, `timestamp_ms`, `asset`, `horizon_ms`). Any corruption or tampering with `confidence_interval` or economic execution metadata (`spread_bps`, `liquidity_volume_base`, etc.) bypassed verification.

**Repair Implementation**:
1. **`canonical_signal_semantic_payload`**:
   - Defined in `src/btc_quant_agent/economic/signal.py`.
   - Extracts all canonical fields: `signal_id`, `experiment_id`, `timestamp_ms`, `asset`, `direction`, `strength`, `confidence_interval` (as list), `horizon_ms`, and `economic_metadata` containing sorted key-value pairs of:
     - `spread_bps`
     - `liquidity_volume_base`
     - `liquidity_available_at_ms`
     - `volume_usdt`
     - `regime`
     - `atr`
2. **Full Replay Verification in `validate_formal_replay_input_bundle`**:
   - Verifies exact equality between `canonical_signal_semantic_payload(replayed_signal)` and `canonical_signal_semantic_payload(formal_signal)`. Any divergence raises `ValueError` detailing mismatched keys.

### 3.3 R3: Top-Down Authority & Direct Run Identity Binding
**Problem**: `EconomicRunIdentity` did not directly bind the SHA-256 of `ReplayInputBundle`. Verification occurred through ad-hoc accounting checks, leaving ambiguity as to whether the bundle or legacy decision input bindings held primary authority.

**Repair Implementation**:
1. **Direct Field on `EconomicRunIdentity`**:
   - Added `replay_input_bundle_sha256: str | None = None` to `EconomicRunIdentity`.
   - Serialized in `to_dict()`.
   - In `execute_bound_run`: binds `replay_input_bundle_sha256 = bundle_payload["bundle_sha256"]`.
2. **Unidirectional Top-Down Hierarchy**:
   - Enforced in `validate_persisted_decision_input_bindings`:
     1. Candidate claiming `completeness="COMPLETE"` requires both `formal_replay_input_bundle` and `run_identity.replay_input_bundle_sha256`.
     2. Verifies `run_identity.replay_input_bundle_sha256 == bundle["bundle_sha256"]`.
     3. Validates full run identity metadata against bundle (`experiment_revision_id`, `protocol_hash`, `dataset_evidence_id`, `dataset_content_sha256`, `input_contract_identity`, `signal_set_sha256`).
     4. Runs deterministic replay verification on the bundle.
     5. Projects `expected_legacy_bindings = bundle_obj.legacy_decision_bindings()`.
     6. Verifies legacy bindings in accounting match the bundle projection exactly. Legacy bindings alone have zero authority to grant qualification.
