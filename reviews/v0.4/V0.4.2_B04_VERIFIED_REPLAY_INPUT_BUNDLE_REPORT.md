## 1. Executive Summary

This report documents the implementation of **v0.4.2 B-AR2 + B04** on branch `v0.4` of `EXASHXE/btc-quant-agent`.
The core defect addressed is the **self-attested decision-input provenance gap** in the prior B-AR system, where `material_input_scope="EXACT_COMPLETE_SET"` was merely a caller declaration rather than a proven causal relationship.

This implementation permanently closes the gap by introducing:
1. `FORMAL_REPLAY_INPUT_BUNDLE_V1` (`ReplayInputBundle` schema version `1.0.0`): a versioned, content-bound replay contract binding protocol identity, dataset hash, input contract, signal set hash, per-signal input preimages with canonical row content hashes, B02 causal execution inputs, and funding identity.
2. Deterministic Signal Replay Engine (`SignalProducer` protocol and `SignalProducerRegistry`): Mode A (replay verification) for `CanonicalRuleSignalProducer` and `RandomBenchmarkSignalProducer`; Mode B (unregistered/non-replayable) fails closed (`NOT_TESTABLE`).
3. Complete convergence of legacy `formal_decision_input_*` hooks into a projected compatibility view of the bundle. Legacy caller declarations alone are strictly prevented from authorizing formal `COMPLETE` status.

## 3. Defect Analysis & Architecture

### 3.1 The Prior Defect (B-AR2)
Under B-AR, the verifier inspected `formal_decision_input_bindings` and verified that referenced candles existed in the dataset, were closed, and had `available_at_ms <= signal_timestamp_ms`. However, the assertion that these candles constituted the `EXACT_COMPLETE_SET` of inputs was solely self-attested by the caller/producer. The verifier had no independent proof that the signal was generated exclusively from those candles rather than unstated, future, or external inputs.

### 3.2 Chosen Design: Replay-Input Bundle (`FORMAL_REPLAY_INPUT_BUNDLE_V1`)
To convert self-attestation into cryptographic and operational certainty, we established:
- **`InputReference`**: Exact content-bound reference to each canonical input candle (`source_type`, `dataset_evidence_id`, `open_time_ms`, `close_time_ms`, `available_at_ms`, `row_content_sha256`).
- **`DecisionInputEntry`**: Per-signal proven input preimage, `producer_identity`, `producer_version`, `input_references`, `generation_contract`, and `verified_scope="VERIFIED_BY_REPLAY"`.
- **`ReplayInputBundle`**: Immutable top-level bundle binding protocol identity, dataset evidence and content hash, input contract identity, signal set hash, decision inputs, B02 causal execution inputs, and funding input identity.
- **`bundle_sha256`**: Canonical hash of the exact material replay inputs (`canonical_sha256(semantic_payload)`).

### 3.3 Signal Producers Discovered & Replay Semantics
1. **`CanonicalRuleSignalProducer`** (`v1.0.0`):
   - Replays deterministic research/rule signals (`FIXED_DIRECTION`, `MOMENTUM_THRESHOLD`, `PRICE_BREAKOUT`, `RETURN_SIGN`).
   - Verifies lookback sufficiency, strictly increasing chronological candle order, candle closed state, and availability $t_{available} \le t_{signal}$.
   - Verifies `expected_preimage_sha256` and input open times against the generation contract.
   - Computes replayed `InformationSignal` and verifies exact equality against candidate signal (direction, strength, timestamp, asset, horizon).
2. **`RandomBenchmarkSignalProducer`** (`v1.0.0`):
   - Replays deterministic P6 random benchmark trial opportunity signals from opportunity decision inputs and sampling contract.
3. **Unregistered / Non-replayable Producers**:
   - Any signal claiming an unregistered producer or unreplayable logic fails closed (`NOT_TESTABLE` / `ValueError`).

## 4. Formal Boundary Convergence & Legacy Absorption

- **`execute_bound_run()`**:
  - Non-empty signals require a verified `ReplayInputBundle`. Missing bundle fails closed (`ValueError`, T3).
  - Supplying legacy `decision_input_bindings` without a verified replay bundle is rejected immediately (`ValueError`, T4).
  - Validates protocol, dataset, input contract, candle row hashes, availability, producer registration, and deterministic signal replay before simulation begins.
  - Extracts B02 `causal_execution_inputs` post-simulation and binds them into the finalized bundle in accounting metadata.
- **`acceptance_verifier.py`**:
  - `validate_persisted_decision_input_bindings()` re-verifies the persisted `formal_replay_input_bundle` against the dataset candles.
  - Candidates claiming `completeness="COMPLETE"` with non-empty signals that lack a verified replay bundle fail closed (T4).
  - Legacy `formal_decision_input_bindings` is retained strictly as a projected compatibility view (`ReplayInputBundle.legacy_decision_bindings()`), ensuring existing tools can inspect legacy fields without granting them independent authority.

---

## 5. Causality Invariants

1. **Exact Preimage Completeness**: Proven by 1:1 signal-to-entry mapping and exact `expected_preimage_sha256` matching the SHA-256 of `[_runtime_candle_payload(c) for c in input_candles]`.
2. **Availability Verification**: Proven against underlying canonical candle metadata: $t_{available} \le t_{signal}$. Asserted availability timestamps in bundle references are checked against actual candle availability.
3. **Future Timeline Invariance**: Candles occurring strictly after the signal timestamp are legal for simulation and PnL calculation, but forbidden from signal input preimages. Changing future price/volume data does not alter signal bundle identity or verification status (verified in T11).
4. **B02 Cost Provenance Integration**: Actual execution preimages (`liquidity_evidence`, `causal_liquidity_volume_base`, `causal_liquidity_available_at_ms`, `declared_max_slippage_bps`) are preserved in `causal_execution_inputs` within the finalized bundle.
5. **No Wall-Clock Dependency**: Historical replay verification and execution rely solely on deterministic timestamps (verified in T15).

## 7. Scope & Boundary Discipline

- **Why this is B04 and not premature B05**:
  B04 strictly bounds signal input provenance, deterministic signal replay, and local B02 liquidity cost preimages. It does NOT implement full simulation trade event comparison, fill price reconstruction, or execution-order replay verifiers (which belongs to B05).
- **Random Benchmark & B06 Boundary**:
  B04 uses `RandomBenchmarkSignalProducer` to verify that each random benchmark trial binds its drawn opportunities deterministically. It does NOT implement full random draw seed reconstruction (B06).
- **CASH & B07 Boundary**:
  CASH benchmark verification remains untouched; full CASH curve reconstruction is left to B07.
