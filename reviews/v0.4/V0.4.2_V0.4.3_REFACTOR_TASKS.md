## 1. Rules applying to every work package

- One package = one bounded purpose and independently reviewable commit/push. If the expected diff crosses unrelated semantics or exceeds what can be adversarially reviewed in one sitting, split it at a typed interface. Never combine a changed algorithm, schema migration, file move and CLI deletion in one commit.
- Before starting: fetch exact branch HEAD, inspect dirty state, confirm dependencies' accepted commits and applicable frozen hashes. Do not assume this planning SHA is still the branch tip.
- Deliver: implementation summary, changed semantic identities, fixture/evidence comparison, exact test commands/results, LOC/import/command deltas, rollback instructions, commit SHA, exact-head CI link and independent review verdict. The implementer cannot self-certify a semantic stage.
- Each commit must pass its named tests plus Ruff/mypy/compile checks and the repository's exact-head Python 3.11/3.12/3.13 CI before acceptance. Early intermediate repair commits may remain `REPAIR_REQUIRED`; green CI alone is not kernel GO. Later fast lanes do not replace the full stage gate.
- Run tests only in an isolated checkout or with A02's operational-root guard until H5 is closed. All synthetic databases, registries and Git fixtures must have explicit temporary paths. No real H39 labels, Final Holdout, public exchange request or execution transport in tests.
- Rollback is a normal code revert or per-consumer adapter switch. Never roll back a registry generation, erase a decision, reset a campaign, mutate a frozen database, or clear H39 consumed state. New artifacts remain preserved even if their code path is rolled back.
- No task enables live/testnet/paper/auto execution, buys data, searches parameters, unblinds H39 or accesses Final Holdout. F02 prepares a future research contract; actual experiment execution needs its own scoped authorization.
- No slow test is deleted without an explicit invariant/fault-detection replacement accepted by independent review. No blanket xfail/skip, reduced significance threshold or smaller formal randomization budget to make CI faster.

Role codes (planning labels requested by the prompt): **Flash** = Gemini 3.8 Flash for mechanical work only; **Sol** = GPT-5.6 Sol High for semantic implementation; **Astra** = Astra/GPT-6 High/Max for architecture, research and independent acceptance. A reviewer must be a distinct review pass, not a renamed implementation summary.

## 3. Phase A — preservation and safe characterization

- Rollback: revert new inventory tooling/docs only.
- Impact: +small tooling/catalog, zero source deletion; prevents false LOC accounting. Flash performs enumeration, Astra judges archival boundaries.

### A02 — Make tests hermetic before another populated-checkout full run

- Scope: H39/forward test factories, explicit store-root and clock injection, test guard against operational roots, uncontrolled network and execution clients; no hypothesis/evaluator changes.
- Acceptance: H5 test callers cannot open default `data/forward`, `data/research/h39_validation`, holdout or `var/quant.db`; seeded temporary schemas cover missing/corrupt/mature/immature states. “No unblind” assertions spy on label-loader calls, not only output strings.
- Tests: affected v0.3.14/.23/.25/.26 suites plus authorized synthetic one-shot; run full suite only in the isolated environment. Record before/after durations and node-ID union.
- Rollback: revert fixture changes in an isolated checkout only; do not resume unguarded local full tests.
- Impact: likely largest runtime improvement; no test removal; source LOC may grow slightly for injectable paths.

### A03 — Close H5 without changing the frozen experiment

- Scope: `H39ResearchEngine.evaluate_validation_status` and its diagnostic adapter; no `evaluate_feature_hypotheses`, frozen constants, protocol files or real ledger operations.
- Acceptance: post-start metadata requests never call `build_observations_for_partition`, canonical future-price retrieval or outcome/statistical loaders. Deprecation/diagnostic-only markers and no-promotion behavior remain explicit; authoritative readiness remains separate.
- Tests: spies raise if a pre-gate diagnostic reaches any outcome loader, including a synthetic partition with post-start timestamps; authorized mock one-shot still works.
- Rollback: return an explicit diagnostic refusal if metadata-only implementation fails; never restore an unsafe fallback in a deployed health surface.

### A04 — Freeze correct semantic goldens and enumerate known bad cases

## 4. Phase B — bounded correctness packages

### B01 — Causal LIMIT fills and expiry/funding ambiguity

- Files: `economic/execution_model.py`, narrow simulator event adapter if needed; relevant P2/P3 tests.
- Contract: at-open marketability is observable; full-bar through/touch is not a timestamp. Unknown touch cannot fill after an unknowable expiry or confer early funding exposure. Both sides and touch/through branches share one policy.
- Acceptance: B2 one-millisecond-TIF probe refuses/NOT_TESTABLE; paired identical-OHLC paths cannot imply an invented ordering. Positive opening-gap case, same-time funding and entry-bar exit goldens pass. Version changed execution semantics.
- Rollback: disable unsupported ambiguous LIMIT formal replay; retain prior artifacts as historical. Do not revert to a falsely early fill merely to preserve output.
- Impact: small rewrite, initially similar LOC; eliminates duplicated four-branch time logic.

### B02 — Opening-fill liquidity availability

- Files: ExecutionModel/FeeModel liquidity inputs and passive adapter; no new market-data source.
- Contract: completed future volume cannot affect an opening fill; separately timestamped past liquidity or declared adverse scenario is required. Close-time data remains legal at close.
- Acceptance: H3 suffix perturbations invariant at open; long/short, missing spread, cap, volume-zero, passive and exit positive controls. Never fabricate spread=0.
- Rollback: fall back only to a preregistered adverse scenario or refuse unsupported input, not future volume.
- Impact: tens/hundreds of lines plus tests; no change to fee/funding economic sign.

### B03 — Closed/PIT formal dataset contract

- Files: runtime candle schema/decoder and formal runtime validation; shared quality adapter if needed.
- Contract: preserve/reject closed and availability state, product/interval/spacing/nonfinite violations; historical data is not rejected merely for being old.
- Acceptance: H4 `closed=False` no longer becomes COMPLETE or serializes as equivalent to closed=True. Versioned old-schema reader cannot silently promote incomplete legacy inputs. Existing canonical valid historical fixtures replay.
- Rollback: old schema stays read-only; refuse new formal promotion if decoder incomplete.
- Impact: source grows for explicit types/validation; one canonical data validation boundary replaces ad hoc checks later.

### B04 — Persist and verify complete replay-input preimages

- Files: P6 artifact schema/identity, policy/model/signal/funding decoders and run generator; use B03 verified dataset.
- Output: immutable replay bundle containing every model and ordered signal/funding/availability/opportunity reference required to reproduce the run, with schema and supported implementation identity.
