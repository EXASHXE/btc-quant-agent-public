## 1. Scope and provisional verdict

The P6 implementation replaces diagnostic-only performance comparison with a
content-addressed formal pipeline:

```text
concrete experiment revision
  -> exact dataset/signal/funding/runtime identities
  -> causal ledger replay
  -> reconciled terminal accounting and FIFO round trips
  -> cadence-validated metrics
  -> preregistered cash/passive-perpetual/random-matched benchmarks
  -> deterministic gates and verdict
  -> local content-hashed P5 evidence
  -> dedicated atomic economic lifecycle decision
```

The old `BenchmarkEngine.evaluate_economic_qualification()` remains available only as a
legacy diagnostic. It always reports `diagnostic_only=True`,
`qualification_evaluated=False`, and `NOT_TESTABLE`; a caller-created
`SimulationSummary` cannot drive a registry transition.

No H39 labels, Final Holdout, production Forward raw data, alpha/parameter search,
live/testnet path, or trading eligibility was read or changed. The passing synthetic
fixture proves that the machinery can reconcile, compare, persist, and transition. It
is **not evidence of BTC alpha** and is not a recommendation to trade.

## 2. Formal contracts implemented

### 2.1 Reconstructable accounting and round trips

`economic/metrics.py` owns the formal result contract. `summarize_ledger()` replays the
immutable `TradeEvent` sequence through `Portfolio.from_events()` and reports initial
cash, final cash/equity, realized gross PnL, terminal unrealized PnL, fees, funding,
slippage attribution, net PnL/return, terminal quantity/mark/notional, fills, FIFO
round trips, net win/loss counts and amounts, drawdown, turnover, time exposure,
time-weighted notional exposure, event ids, and the timestamped equity curve.

The enforced identity is:

```text
final_equity - initial_cash
  == realized_gross_pnl
     + terminal_unrealized_pnl
     - total_fees
     + total_funding
```

`final_cash` is independently reconciled to realized cashflows, and the last curve point
must be at the declared interval end and equal final equity. Slippage is calculated from
fill price versus reference price for attribution only. Since it is already embedded in
the fill price, it is never deducted again.

FIFO lot attribution supports LONG, SHORT, multiple entry lots, and partial reductions.
Entry fees and accrued funding are allocated pro rata as a lot is reduced; each close
allocates its own exit fee. Outcome classification and profit factor use net round-trip
PnL after both fees and funding. Gross-positive/net-negative trades are losses.

Profit factor uses a finite value plus `FINITE`, or JSON `null` plus the explicit
`INFINITE`/`UNDEFINED` state. Sharpe and every other persisted metric follow the same
finite-or-null rule; canonical serialization rejects NaN and Infinity.

### 2.2 Terminal and return cadence

Formal results distinguish `MARK_TO_MARKET_OPEN` from `REQUIRE_FLAT`. An open terminal
position is valid only under mark-to-market treatment. The same state under
`REQUIRE_FLAT`, or a run with pending orders, is incomplete and therefore cannot be
qualified. There is no hidden candidate forced close.

`ReturnMetricsContract` binds the sampling rule, cadence in milliseconds, spacing
tolerance, annualization rule, and per-period risk-free rate. It verifies strictly
increasing timestamps and every observed spacing before annualization. Irregular data,
insufficient observations, nonpositive equity, and zero variance produce a null Sharpe
with an explicit status. The previous `sqrt(35040)` constant has been removed from the
simulator and legacy benchmark code.

### 2.3 Immutable comparison and run identities

`ComparisonContract` is frozen and canonical/content-addressed. It binds product scope,
perpetual benchmark vehicle, capital, exact dataset interval/evidence, candidate policy,
cost/execution/funding models, metrics and terminal contracts, required versus
descriptive benchmarks, the randomization unit and full eligible-opportunity-set hash,
seed/trial count, matching tolerances, every hurdle/operator, evidence requirements, and
result schema. A change to a hurdle, seed, trial count, benchmark role, terminal rule, or
eligible opportunity pool changes the comparison hash and concrete protocol revision.

`EconomicRunIdentity` additionally binds the exact experiment revision/protocol hash,
input contract, dataset evidence/hash and interval, signal-set hash, funding-event-set
hash, policy/cost/execution/funding identities, product/capital, comparison and metrics
hashes, terminal policy, code revision, and completeness. Audit generation timestamps do
not participate in semantic result ids.

Formal P6 supports one linear-contract product per run, consistent with the explicit
scope exclusion for generic multi-asset/cross-margin simulation. Candle inputs cannot mix
instruments.

### 2.4 Benchmark semantics

- Cash uses the candidate's exact metric timestamps, interval, capital, and terminal
  accounting contract.
- Passive BTC is `BTCUSDT_LINEAR_PERPETUAL`, entered and, when required, exited through
  the same execution/fee engine. It receives the same funding events and terminal rule;
  its final fee is reflected in both final equity and the final curve point. Unsupported
  vehicles or unexecutable entry/exit states are explicitly incomparable.
- Random matched uses only the content-bound eligible causal opportunity pool. For each
  preregistered trial it derives and persists a deterministic trial seed, samples the
  exact candidate entry count, preserves candidate LONG/SHORT counts, uses the same
  policy/sizing/exits/costs/execution/funding/interval/terminal rules, and checks declared
  holding, time-exposure, and average-notional tolerances. Every individual accounting
  result, curve, seed, run id, and diagnostic is retained. A failed match makes the
  random benchmark incomparable and formal qualification `NOT_TESTABLE`.

No universal random percentile is invented. A random-quantile gate exists only when the
contract declares its quantile and operator.

### 2.5 Deterministic qualification and P5 lifecycle

`EconomicQualificationResult` embeds the exact comparison payload, bound run artifact,
benchmark suite, metric values, every gate's observation/operator/hurdle/testability and
pass result, explicit reason codes, product/terminal/code identities, and required
evidence ids. Its semantic hash excludes only the audit generation timestamp.

`EconomicDecisionAttestation` is the dependency-safe boundary in
`research_contract/models.py`; the research-contract package never imports the economic
implementation. `ResearchContractRegistry.record_economic_qualification()` independently
verifies the attestation against local content-hashed JSON bytes, the concrete protocol,
comparison hash, embedded run/suite identities, candidate and benchmark accounting,
required benchmark comparability, gate/verdict consistency, exact run and suite evidence,
dataset hash, evidence types/completeness, and P6 provenance.

The dedicated path requires current status `STATISTICALLY_QUALIFIED`:

- `QUALIFIED` appends `STATISTICALLY_QUALIFIED -> ECONOMICALLY_QUALIFIED`;
- `REJECTED` appends `STATISTICALLY_QUALIFIED -> REJECTED`;
- `NOT_TESTABLE` atomically registers diagnostic evidence without a decision event or
  status change.

The ordinary `update_decision_status(... ECONOMICALLY_QUALIFIED ...)` API remains blocked.
All validation uses staged copies and the existing generation compare-and-swap,
hash-chained event log, fsynced temporary file, atomic replace, and directory fsync.
Tamper, incomplete evidence, invalid provenance, injected write failure, or a stale writer
leaves memory, generation, event chain, and committed bytes unchanged.

## 6. Qualification boundary

P6 economic qualification is a local research-governance decision tied to one immutable
protocol, dataset, run, and comparison contract. It does not unblind H39, authorize Final
Holdout access, establish live/testnet eligibility, or prove that any strategy has alpha.
No P7 independent repair review may begin until the final local gates, pushed commit, and
exact-HEAD remote CI evidence in this report are complete.
