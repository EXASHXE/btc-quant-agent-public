## B05 — execution authority and exact equality

`economic/execution_replay.py` is orchestration, not another simulator. It reconstructs existing `TradePolicy`, `FeeModel`, `ExecutionModel`, `FundingModel` and `FundingSettlement` objects and invokes the existing `execute_bound_run` / `EconomicSimulationEngine` path.

Authority flow:

1. The actual registry supplies its frozen `ExperimentMetadata` and verified dataset evidence. The in-memory candidate consumer supplies the actual protocol and comparison contract. Registry comparison/protocol binding and artifact identity checks remain in place.
2. New `formal_execution_replay_inputs` stores exact protocol, dataset reference, policy/cost/execution/funding model preimages and funding event inputs. Model contents are checked against frozen identities by the existing runtime validator; these are not inferred from submitted trade events. The execution model's fee preimage is recorded separately from the engine fee preimage.
3. Runtime candles are decoded and checked against dataset evidence, product and comparison interval by existing validators. B04 persisted decision-input/bundle validation runs before execution. Signals come from the verified bundle's signal preimages, never from the submitted execution ledger.
4. Funding inputs retain timestamp order, including existing stable order for equal timestamps. Their canonical hash must equal the run input identity and the B04 bundle funding identity. Nonempty funding cannot use the bundle's historical empty-input `None` representation.
5. Canonical execution recomputes order/fill behavior, B02 causal liquidity use, fees, funding, quantities, terminal handling, portfolio state and metrics. No submitted fill price, quantity, fee, funding amount, PnL or equity point is fed into execution replay.
6. `require_replay_equality` compares the canonical hashes of **entire** semantic payloads. This is exact canonical equality, not a tolerance or an ad-hoc subset. Outer identity, embedded identity, ordered events and metadata, all accounting, equity/exposure metrics, completeness, bundle identities and role/producer authority are covered.

Protocol audit creation time/metadata in the new replay context is normalized to a fixed epoch/empty metadata. It is not an economic input. Existing protocol identity semantics are unchanged; inconsistent submitted replay context still fails whole-payload equality.

Acceptance integration is at the existing chokepoints:

- `_validate_candidate_run_binding` requires canonical candidate replay, preserving B04R5 role and external producer checks.
- `evaluate_formal_economic_qualification` verifies reconstructed benchmarks before calculating qualification gates.
- `validate_persisted_qualification_semantics` requires candidate execution and benchmark reconstruction on reloaded evidence.
- `ResearchContractRegistry._validate_economic_attestation` passes the actual frozen protocol into that persisted verifier, before any registry decision/generation mutation.

The optional recorded-protocol fallback is for the standalone helper's diagnostic use. Actual in-memory qualification and registry promotion pass external protocol authority; it does not create a second promotion path.

## B06 — complete random experiment reconstruction

The existing `_random_matched_benchmark` remains the only owner of random generation. New distribution provenance records schema `1.0.0`, algorithm identity `PYTHON_MT19937_RANDRANGE63_SAMPLE_SHUFFLE_TIMESTAMP_ID_V1`, randomization unit, ordered opportunity preimages/material metadata, opportunity hash, verified candidate result ID, direction template and sample size. The distribution stores master seed, contiguous trial IDs, derived trial seeds/count, complete trial accounting and diagnostics as before.

The frozen `ComparisonContract` binds seed, trial budget, matching rules and opportunity-set hash. Acceptance verifies the opportunity preimage against that frozen hash, then calls the same generator with the **B05-reconstructed candidate**, canonical engine, verified candles and funding inputs:

1. Sort opportunities by `(timestamp_ms, opportunity_id)`; reject duplicate IDs/out-of-interval opportunities.
2. Derive each trial seed with `random.Random(master_seed).randrange(0, 2**63)` in trial-ID order.
3. Use `random.Random(trial_seed).sample` at the verified candidate opening count.
4. Sort selected opportunities by `(timestamp_ms, opportunity_id)` and shuffle a copy of the verified candidate opening-direction template with that same trial RNG.
5. Rebuild exact random signals and their decision preimages, B04 bundle and explicit `RANDOM_BENCHMARK` / `CANONICAL_RANDOM_BENCHMARK_V1` authority.
6. Execute each trial through the same `execute_bound_run` engine used by B05. Apply the same exact canonical equality mechanism to the complete reconstructed distribution, including each trial, bundle, accounting, result ID, seed/order, diagnostics, comparability and aggregate.

There is no verifier-local PRNG, sampling algorithm, execution arithmetic or shadow portfolio. Correct labels cannot authorize a different draw/execution. Candidate-cloned and post-hoc signals can be valid standalone random-role runs and still fail the reconstructed experiment equality.

The new tie rule removes incidental selected-list order. A04 G08B was characterization-only, not a frozen semantic endorsement; its golden is not rewritten. Equal-timestamp opportunities in reversed insertion order produce identical complete distributions under the new versioned provenance. No historical evidence is migrated or silently promoted under the new algorithm.

## B07 — independent no-trade CASH

`_cash_benchmark` no longer accepts the candidate run. Its equity/metric grid comes directly from verified canonical candle close timestamps; initial capital, interval, terminal policy and metrics contract come from the comparison. It uses the existing no-event `summarize_ledger` primitive with a zero notional grid.

Acceptance reconstructs the entire `FormalBenchmarkResult` and requires exact equality: `CASH`, `USDT_CASH_NO_TRADE`, constant initial equity, zero events/orders/fills/fees/funding/position/exposure/turnover, canonical grid, supported terminal treatment, no populated random seed/trial/run-result fields, and canonical diagnostics/comparability. The final product mark supplied to the existing metrics primitive does not create exposure in a zero-position cash ledger.

Neither candidate trade/funding events nor candidate equity timestamps are CASH inputs. A CASH-labelled copy of a coherent traded candidate passes old ledger arithmetic but fails independent CASH equality, including through actual registry promotion.
