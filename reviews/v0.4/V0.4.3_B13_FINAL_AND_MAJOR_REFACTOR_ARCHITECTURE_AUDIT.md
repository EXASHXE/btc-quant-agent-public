1. **Evidence stripping + trades:** B05's empty-signal case installs an empty run's formal fields into traded accounting; canonical execution still yields no trades and rejects the submission.

## 7. Architectural findings and choice of refactor size

### What actually needs convergence

1. **Formal-looking entrypoints still choose legacy economics.** `cli.main` selects the old `BacktestEngine`/`run_full_suite`; `tools/run_formal_research.py` imports `research.run_full_suite`; `QuantService.update_shadow` delegates to `shadow.update_shadow`, which calls old signal resolution. P6 rejection protects formal promotion, but a researcher must currently know which route not to use. C-lite must make the safe route explicit and default for new jobs.
2. **Acceptance checks are valuable; orchestration is tangled.** Candidate replay can be repeated during binding, qualification, benchmark verification and registry promotion. `validate_persisted_qualification_semantics` calls candidate replay and subsequently `verify_benchmark_replay`, which replays the candidate again. Reduce duplicate work within one verified request, not verification obligations. Keep an immutable, full-key verification result; never cache by submitted result ID alone.
3. **H39 is both a frozen scientific instrument and a report factory.** The four `generate_all_v0322/23/24/25_deliverables` definitions total 2,062 lines. Separating those is a better first cut than splitting the 841-line exactly-once evaluator transaction into arbitrary helpers. Readiness, input checks, baseline ATR, inference and consumed-state ownership remain protected.
4. **Application construction has side effects unrelated to the command.** `cli.main:440` constructs the general service before almost every non-registry command, including research/data commands; `api.py` constructs the app at import; signal GET routes expire records; health constructs a forward store and makes a network check. These are coupling/observability design problems, not newly demonstrated P6 promotion bypasses. Move construction behind explicit handlers and separate status snapshots from mutation/recovery.
5. **Historical helpers distort the dependency direction.** Data loading imports resampling and funding types from the old backtester. Extract those leaf meanings, then archive the historical runner dependency cluster together. Do not make every old private helper a permanent core API.
6. **Shared infrastructure already exists.** B09–B12 supplied the publisher, owner guards, schema projections and REST coordinator. Reimplementing them under new namespaces would add risk with little reduction. Consolidate caller policy and typing, not another abstraction stack.

### Strategy comparison

Estimates refer to active maintenance surface, not deletion of archive evidence.

| Strategy | Scientific regression risk | Reduction / test burden | History, iteration and migration |
| --- | --- | --- | --- |
| Minimal cleanup | Low immediate risk, leaves wrong-default consumer choice | Roughly 0–5%; same semantic integration burden | Best short-term stability, but future hypotheses keep needing bespoke wiring; insufficient here. |
| **Bounded semantic convergence + archival** | Moderate and localized behind frozen replay/reader tests | Roughly 22–27% active LOC; retain oracles, add adapter/packaging tests | Preserves interpretable history, makes new alpha workflow obvious; two reviewable rounds. **Chosen.** |
| Broad modular reorganization | Higher import/serialization/path regression risk | Many changed files; little extra semantic reduction over chosen option | Costly shim/migration work and test churn; defer namespace-only changes. |
| Partial subsystem rewrite | High for simulator/H39/registry, lower for a thin CLI dispatcher | New characterization and differential tests; unclear net LOC | A CLI dispatch rewrite may be bounded inside D-lite; rewriting economics is unjustified after B13. |
| Repository-wide rewrite | Very high; weakest independent historical reference | Largest apparent source reduction, highest validation burden | Risks losing frozen schema interpretation and repeating P7 defects; reject. |

The scientific distinction is **one active economic meaning, multiple independent tests**, not “one function computes and validates everything.” A new generic plugin framework, distributed scheduler, universal repository or statistical DSL is unnecessary for a personal low-frequency BTC research system.

## 15. Compressed implementation plan

### Round C-lite — one supported economic path for new consumers

**Objective:** an explicit PIT sample → registered producer → canonical execution → benchmark reconstruction → qualification workflow that new research/backtest/shadow callers cannot accidentally bypass.

**Included paths:** `economic/{qualification,execution_replay,acceptance_verifier,signal_producer,replay_bundle}.py`, extracted value-contract types as necessary; `research_contract/{models,registry}.py` only for dependency/typed acceptance boundary; `data/{binance_archive,funding}.py` and new leaf resample/funding adapters; `backtest.py`, `shadow.py`, `service.py`, minimal `cli.py` dispatch; a small new `research/jobs.py` facade; compatibility shims and corresponding tests. **Excluded:** H39 statistical/freeze/consumed-state redesign, archive mass moves, broad CLI/API replacement, operational database migration, protocol/config/cost changes, alpha search and all execution activation. No second simulator or general strategy plugin architecture.

**Sequence:**

1. Record exact immutable kernel comparison and input/output rejection goldens; explicitly label old runner outputs as legacy.
2. Extract `resample` and versioned funding decoding/types out of backtest; isolate producer contract value type to break the model/implementation cycle while preserving hashes.
3. Introduce one formal workflow facade over existing replay/build/verify functions; separate P6 value types from orchestration only where necessary. Preserve the independent accounting/gate verifier. Optimize repeated replay only with cold-path and mutation-key tests.
4. Add an explicit new research/replay CLI path consuming frozen protocol, dataset proof, producer and execution policies. Ambiguous old command usage refuses or requires an explicit archive engine; no silent reinterpretation.
5. Route new shadow records through the same canonical execution contract and explicit time/evidence availability. Keep old records/old-engine replay in compatibility. Do not run any actual campaign.
6. Verify no new research/backtest/shadow path imports old trade resolution or can qualify with a diagnostic summary; preserve runtime opportunity-only gating and execution disabled.

**Authority after cutover:** existing EconomicSimulationEngine/ExecutionModel/Portfolio + formal replay and independent P5/P6 validation. Compatibility understands legacy inputs/results but cannot confer qualification.
