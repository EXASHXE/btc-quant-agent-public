## 1. Executive verdict

The three C2 findings are closed within the economic kernel and deterministic
economic tests:

- Intrabar stop-loss, take-profit, and trailing-stop touches are executed as
  pre-armed conditional orders. A later bar close can no longer replace the
  standing trigger price.
- `max_slippage_bps` is now a hard realized-execution cap as well as the bound
  used for ex-ante gross reservation.
- Spread-sensitive exits no longer manufacture `0.0` spread. They use causal
  spread evidence where the event supplies it, otherwise the declared all-in
  adverse cap scenario, and fail closed if neither is available.

This repair does not perform P5/P6 work and does not change the formal economic
qualification from `NOT_TESTABLE`.

## 2. Explicit contracts

### 2.1 Standing conditional exits and OHLC time

SL and TP orders are armed at the position's confirmed entry fill. A trailing
stop is initially armed at entry and re-armed at each prior close after its
causally known peak/trough is updated. The simulator evaluates a full bar only
when the applicable order was armed no later than that bar's open.

For a gap condition, trigger time and reference price are both known: the fill
uses the actual bar open plus adverse configured execution cost. For a non-gap
OHLC touch, the economic reference is the already-declared stop/target level,
not the later close. Exact intrabar time is not reconstructed. The ledger uses
the bar close as the latest observable accounting timestamp and persists:

- `standing_order_armed_ms`;
- `trigger_observation_timestamp_ms`;
- `trigger_time_semantics=INTRABAR_UNKNOWN`;
- `ref_price`.

This separates a known order-arm time, an unknown intrabar trigger time, and the
time at which completed OHLC evidence becomes observable while retaining a
monotonic, replayable event sequence.

Adverse selection is symmetric. A LONG uses the lowest touched adverse stop; a
SHORT uses the highest. If an adverse stop and TP both touch, `REJECT_AMBIGUOUS`
raises `AmbiguousExitRejectionError`; `CONSERVATIVE_STOP_FIRST` selects the
adverse stop. Trailing levels use only the prior causal peak/trough, never an
unorderable same-bar newly established extreme.

If a nonzero funding cashflow occurs after bar open and no later than bar close
in a bar containing an unknown-time conditional trigger, trigger-versus-funding
order can change cashflow. The simulator raises `AmbiguousExitRejectionError`
before applying the funding or exit rather than choosing an arbitrary ordering.
Funding exactly at bar open retains the established deterministic
funding-before-fill tie-break.

All gap and intrabar exits traverse
`ExecutionModel.simulate_conditional_market_fill`; reversal and max-holding
exits continue through `ExecutionModel.simulate_order`. `Portfolio.apply_trade`
remains only the atomic ledger commit.

### 2.2 Slippage and reservation bound

For `SPREAD_AND_IMPACT`, realized slippage is:

```text
min(half_spread_bps + modeled_impact_bps, max_slippage_bps)
```

when causal spread is supplied and a cap exists. If spread is absent but a cap
exists, the cap itself is the explicitly declared adverse all-in scenario. If
both spread and the cap are absent, execution fails closed.

Conditional fills always use the all-in cap scenario under
`SPREAD_AND_IMPACT`: exact trigger-time liquidity is not present in OHLC data,
so completed trigger-bar volume is not allowed to make the cost cheaper. An
unbounded spread-and-impact model therefore cannot execute a standing
conditional from OHLC alone.

`worst_case_price_bound` uses the same hard cap. Consequently, for each admitted
market entry:

```text
quantity * realized_fill_price <= reservation_notional
```

up to floating-point tolerance. The reservation is persisted on the entry
`TradeEvent` for reconstruction. The execution request also carries it as
`max_fill_notional`. If the causal market reference moves before a delayed
fill, the model reduces filled base quantity instead of exceeding the admitted
notional; it records requested quantity and whether the cap applied. This
preserves the price move, books the accepted fill, and enforces the invariant
without fabricating a favorable price.

Maker/taker fee rates, fixed slippage, impact coefficient, and optional maximum
slippage are validated as finite and nonnegative. Fixed and capped adverse
slippage must also remain below 10,000 bps so a SELL fill cannot become
nonpositive.

### 2.3 Spread evidence

`current_spread_bps` is optional at the API boundary rather than defaulting to a
fabricated number. The modes behave as follows:

| Slippage mode | Missing spread behavior |
| --- | --- |
| `ZERO` | Spread is not used. |
| `FIXED_BPS` | Spread is not used. |
| `SPREAD_AND_IMPACT` with a valid cap | Execute the declared cap scenario and persist `spread_evidence=DECLARED_MAX_SLIPPAGE_SCENARIO`. |
| `SPREAD_AND_IMPACT` without a cap | Require causal spread for a discretionary market fill; reject an OHLC conditional because trigger-time impact is still unbounded. |

A reversal signal's own `spread_bps` metadata is causal exit evidence and is
passed through. Missing reversal, gap, intrabar, and max-holding spread is never
replaced by `0.0` or `1.0`.
