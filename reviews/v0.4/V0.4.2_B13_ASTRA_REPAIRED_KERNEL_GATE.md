## 3. Cross-Layer Composition Attack Results

The following composite attack scenarios were verified to confirm that combinations of local bypasses cannot defeat end-to-end qualification authority:

1. **Evidence Stripping + Empty Signal Identity + Nonempty Ledger**:
   - *Attack*: Strip formal decision inputs, set signal set identity to empty `[]`, but submit a forged nonempty trade ledger.
   - *Result*: **REJECTED**. Replay against the empty signal set produces zero trades; `require_replay_equality()` detects mismatch against the nonempty ledger and raises `ValueError: economic execution canonical replay mismatch`.
2. **RANDOM_BENCHMARK Artifact Relabelled into Candidate Role**:
   - *Attack*: Take a valid random benchmark artifact, update outer identity role to `CANDIDATE`, and submit for promotion.
   - *Result*: **REJECTED**. Outer identity differs from embedded identity, raising `ValueError`. If embedded identity is synchronized, `_validate_candidate_run_binding()` rejects the random producer contract against the protocol's required candidate contract.
3. **Synchronized Candidate Producer / Bundle / Replay-Context Rewrite**:
   - *Attack*: Rewrite candidate producer identity to an arbitrary registered contract and forge matching bundle fields.
   - *Result*: **REJECTED**. Acceptance checks protocol authority: producer contract must match `protocol.signal_producer_contract`. Mismatches raise `ValueError: candidate producer contract ... differs from protocol authority`.
4. **Candidate + Benchmark + Qualification Fully Rehashed Together**:
   - *Attack*: Forged entry price (1.0), recompute ledger, recompute curves, recompute benchmark suite, update gates, and recalculate all artifact hashes.
   - *Result*: **REJECTED ATOMICALLY**. `validate_persisted_qualification_semantics()` re-runs canonical execution from raw inputs, raising `EvidenceValidationError: semantic replay mismatch`. Registry generation does not increment and file bytes remain unaltered.
5. **Correct Random Draw with Execution Tampering**:
   - *Attack*: Replay the correct opportunity set and seeds, but tamper with fee or slippage accounting in the resulting trial.
   - *Result*: **REJECTED**. `verify_benchmark_replay()` executes canonical simulation for each trial and requires bitwise canonical equality with the trial accounting. Mismatches raise `ValueError: random experiment canonical replay mismatch`.
6. **Stale Publisher / Finalizer Competition**:
   - *Attack*: Two concurrent finalizers read the same partition and manifest digest, then attempt finalization concurrently.
   - *Result*: **SERIALIZED / ONE STALE**. Exactly one finalizer commits; the second detects digest change under the advisory lock and raises `PublicationConflict`. Subsequent mutations on the stale instance fail closed.
7. **Partial SQLite Migration Followed by Active Mutation**:
   - *Attack*: Manually alter an active store to drop a required column while setting version to 1, or drop an adapter column on version 1.
   - *Result*: **REJECTED**. Store instantiation and mutator methods validate column presence, raising `SQLiteSchemaError: NOT_TESTABLE` before any write.
8. **Concurrent Retryable REST Failures**:
   - *Attack*: Multiple concurrent workers query the same origin while receiving 429 / 503 responses.
   - *Result*: **COORDINATED BACKOFF**. Shared `RestCoordinator` publishes cooldown across callers; second caller respects backoff rather than sending immediate traffic, preventing retry storms.
9. **Crash / Directory Fsync Uncertainty at Cutover**:
   - *Attack*: Inject directory fsync failure immediately after `os.replace` commits new bytes.
   - *Result*: **EXPLICIT UNCERTAINTY**. `PublicationUncertain` is raised. The new bytes are physically on disk; subsequent reopening or idempotent retry recognizes the committed state without creating duplicate generations.

## 6. Residual Limitations & Explicit Non-Claims

The `GO` verdict attests that the research and economic qualification kernel is causally correct, reproducible, durable, and resilient against evidence forgery within its declared specifications. It does **not** make the following claims:

1. **OHLC Simulation vs. Tick Truth**: The simulator models execution at OHLC bar boundaries with explicit causality rules (e.g. failing closed on ambiguous intrabar touches). It is not a continuous-time tick matching engine or order-book queue simulator.
2. **Liquidation & Margin Mechanics**: No continuous margin engine or liquidation cascade realism is implemented or claimed.
3. **Market Impact**: Slippage and market impact are parametric models (`SPREAD_AND_IMPACT`, fixed bps), not empirical exchange order book reactions.
4. **Local vs. Distributed Durability**: File locking (`publication_lock`) and atomic replacement provide local single-node filesystem guarantees, not distributed consensus (Raft/Paxos).
5. **POSIX-Oriented File Locking**: `publication.py` utilizes `fcntl.flock`, which requires POSIX/Linux filesystem semantics (Linux native or WSL2). On Windows native Python without POSIX emulation, `fcntl` is unavailable.
6. **SQLite Type Rigor**: SQLite schema compatibility verifies declared column projections, existence, and version markers; it is not a formal proof of universal SQL type coercion.
7. **Urllib Socket Worker Quarantine**: In rare OS DNS hang scenarios, a daemon worker thread may outlive caller deadlines, although caller timeouts and retry amplification remain strictly bounded.
8. **M6 Verifier Performance**: Replaying dense event ledgers against bars remains $O(N \cdot M)$ in event/bar scans; this is an accepted performance residual and does not compromise audit integrity.
