## Old defects and reproduction

At baseline `381e6f0`, the v0.4 contract had four directly reproducible failure modes:

1. `FeatureDefinition.input_requirements`, feature/evaluation parameters, and metadata
   retained caller-owned lists/dicts. Mutating a source object after construction changed
   a nominally frozen experiment.
2. `experiment_id` was the registry key, so `allow_update=True` could replace feature,
   target, policy, or cost semantics under the same identity.
3. `update_decision_status()` accepted arbitrary status jumps and replaced the current
   experiment object. It recorded neither the prior status nor immutable evidence.
4. `save()` wrote directly to the committed file and had no generation, state hash,
   lock, compare-and-swap check, event chain, or recoverable pre-replace boundary.

Consequently a result could not be bound to a unique semantic protocol, concurrent
writers could lose updates, and an interrupted write could destroy the only registry
copy.

## Protocol identity contract

`ExperimentMetadata` is now the immutable protocol definition. Its semantic payload
binds:

- human experiment family and name;
- versioned/content-hashed input contract;
- feature formula, input requirements, parameters, and bounds;
- prediction target, horizon, and calculation rule;
- evaluation method, statistical test, FWER rule, threshold, and parameters;
- versioned/content-hashed economic policy, cost model, and execution model;
- a versioned benchmark identity or the literal `P6_PENDING` placeholder;
- product/instrument scope;
- implementation/code revision; and
- terminal/data-completeness policy.

`VersionedIdentity` requires a non-empty logical id, version, and lowercase 64-character
SHA-256 digest. Nested JSON collections are copied recursively: objects become
`FrozenDict`, and arrays become tuples. Caller mutation cannot alter the protocol, and
exposed nested mappings cannot be assigned through.

The caller-supplied `experiment_id` is only the human family id. The registry key is:

```text
protocol_hash = SHA256(UTF8(canonical_semantic_json))
experiment_revision_id = experiment_family + "@" + protocol_hash
```

### Canonical serialization

Canonical semantic JSON uses:

- string-only object keys;
- recursive enum-to-value normalization;
- list and tuple equivalence as JSON arrays;
- UTF-8 with `ensure_ascii=False`;
- lexicographically sorted object keys;
- separators `,` and `:` with no insignificant whitespace; and
- `allow_nan=False`, rejecting NaN and infinities.

`created_at_utc` and free-form audit `metadata` are explicitly non-semantic. They are
persisted but excluded from `protocol_hash`. Equivalent mappings with different insertion
orders hash identically. Changing any semantic field changes both `protocol_hash` and
`experiment_revision_id`.

Exact semantic duplicate registration is idempotent: it preserves the first audit record,
does not append another event, and does not advance the generation. Changed semantics in
the same family create a new revision. `allow_update=True` is explicitly rejected, and all
prior revisions remain readable.

## Decision lifecycle

Status is no longer stored in or rewritten on the protocol. It is reconstructed from a
global append-only, SHA-256-linked `DecisionEvent` sequence. Every event binds revision
id, previous/new status, UTC decision time, evidence ids, reason, actor, source, optional
statistical/economic result ids, sequence, and prior-event hash.

| Previous | Legal next state(s) |
|---|---|
| `PROPOSED` | `REGISTERED` |
| `REGISTERED` | `STATISTICALLY_QUALIFIED`, `REJECTED`, `FROZEN_ARCHIVE` |
| `STATISTICALLY_QUALIFIED` | `ECONOMICALLY_QUALIFIED`*, `REJECTED`, `FROZEN_ARCHIVE` |
| `ECONOMICALLY_QUALIFIED` | `FROZEN_ARCHIVE` |
| `REJECTED` | `FROZEN_ARCHIVE` |
| `FROZEN_ARCHIVE` | none |

`*` The structural edge is reserved for P6, but P5 unconditionally rejects it. A loaded
P5 file containing `ECONOMICALLY_QUALIFIED` is treated as corrupt. There is no thaw or
backward transition.

Registration appends exactly one `PROPOSED -> REGISTERED` event. Every later decision
requires complete immutable evidence plus non-empty reason, actor, and source. Validation
is performed on staged copies; any invalid transition or evidence leaves memory,
generation, events, and committed bytes unchanged.

## Evidence binding

`EvidenceReference` binds:

- evidence type and logical id;
- SHA-256 content digest;
- observed/generated UTC time;
- producing protocol/revision and code revision;
- completeness marker;
- optional path/URI; and
- recursively immutable metadata.

Its identity is `<logical-id>@SHA256(canonical reference payload)`. A complete local
reference is re-hashed when registered and whenever it is used in a decision; missing or
tampered content fails closed. A decision can reference an existing evidence id or stage a
new reference atomically with the event. Duplicate evidence ids and unbound optional
result ids are rejected.

`PROHIBITED` references can be recorded without opening their local path, allowing sealed
H39/holdout lineage to be represented without loading prohibited content. They cannot be
used to justify a decision. `PARTIAL`, `MISSING`, and `PROHIBITED` evidence are all rejected
at decision time.

## Atomic persistence and concurrency

The committed JSON envelope has an exact schema containing `schema_version`, positive
`generation`, complete `payload`, and `content_hash`. The hash covers schema version,
generation, all protocol/evidence records, and the complete event chain.

Each local commit performs:

```text
acquire same-registry advisory lock
-> read and fully validate committed state
-> compare committed generation with writer's loaded generation
-> serialize complete generation N+1 state
-> create temp file in the registry directory
-> write, flush, and fsync temp file
-> injected pre-replace boundary (tests)
-> atomic os.replace(temp, committed)
-> fsync parent directory
-> publish staged state in memory
```

If writer B commits `N+1` after writer A loaded `N`, A's later commit raises
`StaleRegistryError`; B's bytes remain unchanged. A failure before `os.replace` removes the
temporary file, keeps the previous file byte-for-byte intact, and does not publish staged
protocols/evidence/events in memory.

Load rejects invalid JSON/UTF-8, non-finite JSON constants, wrong envelope or record
schemas, unsupported schema, non-positive/non-integer generation, state-hash mismatch,
protocol/evidence identity mismatch, non-contiguous or duplicated events, broken hash
chains, illegal transitions, unknown references, and incomplete decision evidence. There
is no empty-registry fallback for an existing corrupt file.

## API migration

The intentional v0.4 API changes are:

- construct `ExperimentMetadata` with versioned identities plus name, execution model,
  product scope, code revision, and terminal policy;
- use `experiment_revision_id`, not the family id, for exact retrieval and decisions;
- query lifecycle with `get_status()` / `decision_events()`;
- provide evidence, reason, actor, and source to `update_decision_status()`; and
- receive an immutable `DecisionEvent` rather than a rewritten protocol object.

The existing v0.4 research-kernel test was migrated. Repository search found no production
call sites depending on the old mutable-status API.
