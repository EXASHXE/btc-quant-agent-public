# v0.4.2–v0.4.3 major refactor blueprint

Planning baseline: `908c7e06023d1e577005ed59f0e790e87e3d2ca2`, 2026-09-10. This document proposes future work; none of the refactor is implemented here. The [P7 audit](V0.4.1G_P7_ASTRA_STAGE_FINAL_AUDIT.md) is **REPAIR_REQUIRED**. Task IDs below refer to [the actionable breakdown](V0.4.2_V0.4.3_REFACTOR_TASKS.md).

## 1. Decision and migration strategy

Use **in-place semantic convergence**, followed by **modular extraction around frozen interfaces** and **strangler-style archival of historical paths**. Allow a bounded rewrite of the LIMIT time-resolution branch and persisted replay verifier because their current semantics are defective. Do not rewrite the repository, the cash ledger, the H39 experiment or every test.

The target is one executable meaning for each formal economic concept, not merely smaller files. A filename move is not a simplification unless it also removes a dependency, duplicated behavior, runtime entrypoint or active maintenance obligation.

Order:

1. Inventory/freeze evidence contracts and make tests safe to run in populated checkouts.
2. Characterize correct behavior; encode P7 defects as explicit expected rejections, not golden “correct” outputs.
3. Repair H39 diagnostic isolation, LIMIT timing, open-fill liquidity, data availability and formal candidate/benchmark replay.
4. Independent acceptance before granting the next baseline a GO.
5. Converge semantic ownership, then cut over one consumer at a time.
6. Archive obsolete runners behind a reproducible compatibility boundary.
7. Shorten feedback with hermetic fixtures and a coverage-enabled exact-head matrix.
8. Resume one bounded research hypothesis family, only after the stage gate.

Do not convert “same output” into a reason to retain known bugs. Correctness repairs create a new versioned semantic contract with explicit changed goldens; subsequent extraction commits require equivalence to that corrected contract. Historical reports remain historical, not silently restated using the new engine.

## 2. Non-negotiable contracts

| Domain | Invariants / prohibited shortcut |
| --- | --- |
| PIT | Distinct event/receipt/availability/decision timestamps; immutable input hashes; closed/complete data rules; no future suffix can affect a prior decision/fill |
| Causal execution | Orders only fill when the declared evidence supports price and time; unresolved OHLC ordering stays unresolved; funding before equal-time fills; no fallback ideal prices |
| Accounting | Linear-perpetual realized/unrealized PnL; fees/slippage/funding exactly once; legal atomic ledger; explicit terminal treatment; no undocumented margin/liquidation support |
| Qualification | Verified preimages → supported deterministic execution → metrics → same-contract benchmarks → preregistered hurdles → append-only decision; no arbitrary summary promotion |
| Statistics | Hypothesis/target/unit/seed/budget/correction immutable; preserve HAC/overlap/null construction appropriate to each experiment; H39 FWL/conditional inference is not imposed on every future hypothesis |
| Governance | Revisions rather than overwrite; failed/stopped work remains discoverable; no automatic resurrection of rejected families; registries are local audit controls, not proof against an administrator rewriting all storage/history |
| Blind experiment | H39 metadata-only readiness, fixed denominator and maturity, no labels before authorization, frozen snapshots and exactly-once execution; Final Holdout sealed |
| Operations | Every attempt and gap remains recorded; no campaign reset to hide a gap; read-only status must not quietly become a writer/finalizer; execution disabled |

## 6. Proposed packages, interfaces and dependencies

```text

  contracts/             # market/time/signal/policy/evidence identities, canonical bytes
  data/                  # PIT validation, archive inputs, public collection, durable stores
  features/              # pure feature/opportunity generation; no orders or registry writes
  economics/             # fills, reservations, ledger, funding, metrics, one replay loop

    lifecycle/           # base epochs and explicit campaign scheduling

  cli/                   # thin typed command handlers and explicit offline/operational modes

  v03/                   # historical runners, schemas, original outputs/locks/catalog
```

This is a target responsibility tree, not a mandate to create every directory immediately. Increase module count where splitting a 742-line loop clarifies invariants; cap dependency cycles rather than rewarding fewer files.

Dependency direction:

```text
contracts ← data / features / economics
data + features → immutable signals and replay inputs
contracts + data + economics → qualification
data + qualification → forward orchestration
forward metadata + registry projection → diagnostics / CLI
explicit reviewed plan → execution_boundary (currently always disabled)
archive → versioned read-only adapters; core -X-> archive
```

`contracts` may define a verifier protocol but must not import a concrete simulator. The application wires qualification verification into P5 promotion. Feature code cannot import execution or write registry decisions. Diagnostics cannot import an outcome loader as a convenience. H39 statistics remain behind their frozen authorization capability, not a method callable by a generic health endpoint.

## 7. Test and CI redesign based on measured cost

Baseline: 804 cases in 483.46 s; top five consume 406.34 s (84%). The slowest three alone consume 341.22 s. Inspection shows unisolated default Forward paths in safety/status tests. The immediate opportunity is **hermeticity**, not weakening H39 statistics or lowering trial counts.

1. H5 first: all test paths and clocks explicit; fail on access to operational/holdout roots, uncontrolled network or real execution transports. Preserve authorized synthetic one-shot tests.
2. Separate fixture construction from behavior assertions. A test asserting three constant safety-policy fields does not need repeated scanning/hashing of actual Forward partitions. Use one minimal synthetic schema and a spy proving that outcome loaders are not called.
3. Share immutable seed data at module/session scope only where each test gets an isolated mutable copy. SQLite backup can copy a seeded fixture; do not share mutable registry/consumption state.
4. Preserve independent negative cases: changed dataset, hash, model, terminal, funding and order chronology detect distinct faults even when they share setup. Use parameterization for setup reuse, not reduction of tested dimensions.
5. Measure core replay separately: current verifier prefix reconstruction should become one ordered sweep after exact same-time semantics are frozen. Assert scaling on small dense synthetic sequences without importing historical data.

| Lane | Contents | Trigger | Initial target, not measured achievement |
| --- | --- | --- | --- |
| T0 | Ruff, mypy, compile, canonical identity/type/serialization tests | Every edit/precommit | 5–15 s; profile startup separately |
| T1 | Pure ledger, policy, fill, funding, PIT and metrics tests | Every PR/push | 10–30 s |
| T2 | P5 CAS/crash tests, candidate/benchmark forgery regressions, golden end-to-end replay | Every semantic change; mandatory before package acceptance | 20–60 s |
| T3 | Hermetic H39 integration, historical compatibility and calibrated statistical tests | Relevant changes and full gate; scheduled isolated runs | 30–120 s after fixture isolation |
| T4 | Union of all scientific cases, all three Python versions, coverage, import/schema compatibility and negative safety guards | Every release/stage and exact-head final acceptance | Full pytest 90–180 s and coverage 120–240 s as provisional budgets |

Targets are plausible because only 77.12 s lies outside the top five at baseline; they require replacing default-store work with equivalent synthetic fault detection, not deleting those tests. Tiers may overlap setup and should not be summed as a runtime promise. If the measured gates remain slower after safe changes, report it and retain rigor.

CI migration: first collect identical node IDs and coverage from plain and traced runs; then run **one coverage-enabled full union per Python version**, not plain+coverage twice. Exact-head full scientific gate remains mandatory. Path-based selection may accelerate PR feedback only; it never replaces T4. Dependencies and immutable fixture manifests may be cached with full keys. Source hashes, attestations, maturity state and qualification verdicts must always be checked afresh.

Archive lane: keep all old regression cases until fault-detection mapping and environment reproducibility are proven. Release validation includes archive schema/reader compatibility and representative pinned reconstruction; scheduled archive jobs may own expensive historical reproductions only under an explicit test-to-invariant mapping. “Archive” is not a mechanism for silently losing tests.

## 8. Minimum durable process architecture

Measured declaration: 6 service units / 5 timers. One service is a continuous WebSocket microstructure recorder; five are oneshots. No claim is made about which are installed/running.

| Responsibility | Target operating mode | Boundary |
| --- | --- | --- |
| Base BTCUSDT PIT data | One collector/supervisor with explicit cadence and bounded requester; persists every attempt | Lifetime independent of any alpha family; no background alpha evaluation |
| H39 diff-depth + aggTrade | Keep isolated recorder and heartbeat/clock monitoring while frozen collection obligations apply | No campaign reset, clock rewrite or stopping just to reduce process count |
| H39 blind accumulation | Dedicated scheduled batch, immutable finalized sources, one-shot state separate | Must honor maturity, coverage, input contract and frozen sample; do not make it an auto-unblind worker |
| Health/freshness | Metadata-only scheduled task owned by supervisor; optional read-only endpoint | Reading status does not finalize partitions or compute future outcomes |
| OPPORTUNITY_ONLY | Campaign-scoped scheduled observation/resolution, not always-on trading process | Terminal H35/H36/H38-era obligations remain terminal; explicit successor registry decides what can collect |
| API/status UI | Off by default, optional read-only on demand | No independent scheduler or market truth; mutation routes migrated separately |
| Offline replay/research | Explicit batch jobs with dataset/protocol/revision refs | Not a persistent daemon; rejects sealed inputs without authorization |
| Historical campaigns | No active scheduler | Archive compatibility runner and immutable evidence replace execution |

Target persistent processes are **one base supervisor plus one H39 recorder when necessary**, with three to five scheduled responsibilities; this can increase the number of persistent processes from the current one-daemon declaration while reducing operational coupling. Do not sell a false “six daemons to two” reduction. A supervisor consolidates scheduling/health and transport budgets, not database ownership across independent frozen experiments. Keep systemd if it is sufficient; no Kubernetes or queue infrastructure is required.

Use single-writer ownership per store, bounded queues and process-level finalization locks. The heartbeat thread does not justify a second independent owner of the same scientific state. Separate disposable operational caches from authoritative immutable evidence.
