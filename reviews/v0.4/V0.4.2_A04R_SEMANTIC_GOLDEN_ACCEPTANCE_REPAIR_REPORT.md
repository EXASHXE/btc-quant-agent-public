## 2. Review Findings & Implemented Repairs

- **Repair**:
  - Changed G06 vehicle input in [`tests/goldens/v042_semantic_goldens.json`](file:///tests/goldens/v042_semantic_goldens.json) to `USDT_CASH_NO_TRADE`.
  - Added explicit test assertions in `test_g06_cash_is_exact_no_trade_and_current_diagnostic_control_agrees`:
    ```python
    assert case["inputs"]["vehicle"] == "USDT_CASH_NO_TRADE"
    assert case["inputs"]["vehicle"] != "USD_CASH_NO_TRADE"
    assert "USD_CASH_NO_TRADE" not in str(case["inputs"])
    ```
  - Reversion or typo back to `USD_CASH_NO_TRADE` will fail the targeted test suite.

### R2 (HIGH) — B05 Consumer-Map Consistency
- **Issue**: The A04 report specified that B05 must consume `G07-PASSIVE-SIMPLE-ZERO-COST`, but `consumer_map["B05"]` in the machine-readable JSON omitted G07.
- **Repair**:
  - Added `G07-PASSIVE-SIMPLE-ZERO-COST` to `consumer_map["B05"]` in [`tests/goldens/v042_semantic_goldens.json`](file:///tests/goldens/v042_semantic_goldens.json).
  - Enhanced `test_b01_b07_consumer_map_references_existing_exact_cases` in [`tests/test_v042_a04_semantic_goldens.py`](file:///tests/test_v042_a04_semantic_goldens.py) to assert exact dictionary equality against authoritative `EXPECTED_CONSUMER_MAP`, and specifically asserted G07 membership in B05.

### R3 (MEDIUM) — Causal Event-Order Contract Clarification
- **Issue**: Previous wording implied a universal relationship `order <= funding <= fill`, suggesting funding must always exist between an order and its fill.
- **Repair**:
  - Updated `event_order_contract` in [`tests/goldens/v042_semantic_goldens.json`](file:///tests/goldens/v042_semantic_goldens.json) and [`reviews/v0.4/V0.4.2_A04_SEMANTIC_GOLDENS_REPORT.md`](file:///reviews/v0.4/V0.4.2_A04_SEMANTIC_GOLDENS_REPORT.md) to define the base lifecycle:
    $$\text{market\_observation\_availability} \le \text{signal\_observation} \le \text{decision} \le \text{order} \le \text{fill} \le \text{terminal}$$
  - Clarified that funding follows explicit timestamps, tie-breaks via `FUNDING_BEFORE_FILL` when equal ($t_{funding} = t_{fill}$), and lifecycles without funding omit the funding event entirely.
  - Added positive controls in `test_causal_order_and_limit_contrast_do_not_invent_intrabar_order`:
    - **Case A**: Clean lifecycle with no funding event (`MARKET_AVAILABLE` through `TERMINAL`).
    - **Case B**: Preserved equal-time funding and fill with `FUNDING_BEFORE_FILL`.

### R4 (HARDENING) — Random Draw Equal-Timestamp Hardening & Ambiguity Characterization
- **Issue**: G08 only contained distinct-timestamp opportunities. The behavior when multiple opportunities share identical `timestamp_ms` was uncharacterized.
- **Investigation of Production Behavior**:
  - In `_random_matched_benchmark` (`src/btc_quant_agent/economic/qualification.py:1384-1405`):
    - Input opportunities are stably sorted by `(timestamp_ms, opportunity_id)`.
    - `rng.sample(...)` randomly draws $k$ items.
    - Post-sample sorting uses `selected.sort(key=lambda item: item.timestamp_ms)`.
  - Because Python's `sort()` is stable and only keys on `timestamp_ms`, equal-timestamp opportunities retain whatever order `rng.sample` produced them in.
  - In trial 2 of seed `20260910`, `rng.sample` draws `opp-a2` then `opp-a1`. Sorting only on `timestamp_ms` leaves `['opp-a2', 'opp-a1']`.
  - Conversely, deterministic post-sample tie-breaking `(timestamp_ms, opportunity_id)` yields `['opp-a1', 'opp-a2']`.
- **Repair**:
  - Added `G08B-RANDOM-EQUAL-TIMESTAMPS-AMBIGUITY` as `CHARACTERIZATION_ONLY` (not inventing unapproved production rules in A04R).
  - Extended independent helper `preregistered_random_draws` with `post_sample_tie_break_by_id: bool = False`.
  - In `test_g08b_random_equal_timestamp_hardening_and_ambiguity_characterization`:
    - Verified pre-sample preimage ordering `(timestamp_ms, opportunity_id)`.
    - Verified current CPython stdlib draw output (`['opp-a2', 'opp-a1']` in trial 2) without production calls.
    - Verified deterministic tie-break behavior (`['opp-a1', 'opp-a2']`).
    - Confirmed the exact gap is documented for B06 implementation.
