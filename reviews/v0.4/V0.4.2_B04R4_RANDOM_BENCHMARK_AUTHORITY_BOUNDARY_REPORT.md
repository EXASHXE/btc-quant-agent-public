# V0.4.2 B04R4 Acceptance Repair Report — Random Benchmark Authority Boundary

## 1. Executive Summary

This report documents the completion of **v0.4.2 B04R4 Random Benchmark Authority Boundary Acceptance Repair** on branch `v0.4` of repository `EXASHXE/btc-quant-agent`.

The repair establishes an explicit canonical boundary between `CANDIDATE` and `RANDOM_BENCHMARK` authority, completely eliminating the generic, role-unaware `CANONICAL_RANDOM_BENCHMARK_V1` exemption across bundle construction, bundle verification, runtime execution (`execute_bound_run`), persisted verification (`validate_persisted_decision_input_bindings`), and candidate consumers (`_validate_candidate_run_binding`, `build_formal_benchmark_suite`, and `evaluate_formal_economic_qualification`).

Under B04R4:
1. **Explicit Authority Roles**: Introduced `EconomicRunRole` (`CANDIDATE`, `RANDOM_BENCHMARK`) in `btc_quant_agent.economic`.
2. **Zero Exemption in Candidate Context**: In candidate authority context, candidate decision inputs must strictly match the protocol-bound candidate producer contract (e.g. `CANONICAL_RETURN_SIGN_V1`). Any attempt to substitute `CANONICAL_RANDOM_BENCHMARK_V1` into a candidate run fails closed at all layers.
3. **Strict Benchmark Role Enforcement**: In benchmark authority context, only `CANONICAL_RANDOM_BENCHMARK_V1` is accepted; non-random contracts are rejected.
4. **Persisted Role Binding**: `run_role` is persisted in `EconomicRunIdentity` and strictly enforced by `validate_persisted_decision_input_bindings`.
5. **Anti-Replay / Non-Substitution**: A random benchmark trial artifact cannot be passed or substituted as candidate evidence in formal qualification.
6. **Legitimate Benchmark Preservation**: The actual `RANDOM_MATCHED` benchmark path (`_random_matched_benchmark`) continues to function deterministically under explicit benchmark authority role.
7. **Legitimate Zero-Signal Run Preservation**: Legitimate zero-signal runs (e.g. CASH baseline where `signal_set_sha256 == canonical_sha256([])`) continue to pass without false rejections.

All 996 tests pass across the full test suite (9 new comprehensive adversarial and positive control tests added for T1–T9). Local validation and remote CI across Python 3.11, 3.12, and 3.13 are 100% green.

## 3. Root Cause Analysis of Generic Random Exemption

In B04R3 and earlier implementations, the system enforced candidate producer contracts against protocol authority, but granted a blanket, role-unaware exemption to `CANONICAL_RANDOM_BENCHMARK_V1`:

1. **Replay Bundle Builder Bypass**:
   In `build_formal_replay_input_bundle`, the code had:
   ```python
   if declared_contract_id == "CANONICAL_RANDOM_BENCHMARK_V1":
       contract = SignalProducerRegistry.get_contract(declared_contract_id)
   ```
   This allowed a candidate bundle builder invocation to supply `CANONICAL_RANDOM_BENCHMARK_V1` and bypass the protocol-bound candidate contract.
2. **Replay Bundle Verifier Exemption**:
   In `validate_formal_replay_input_bundle`, the equality check was guarded by:
   ```python
   if expected_protocol is not None and contract.contract_id != "CANONICAL_RANDOM_BENCHMARK_V1":
   ```
   Any bundle containing `CANONICAL_RANDOM_BENCHMARK_V1` was silently excused from matching `expected_protocol.signal_producer_contract`.
3. **Persisted Verifier Exemption**:
   In `validate_persisted_decision_input_bindings`, the verifier contained:
   ```python
   if producer_contract_id == "CANONICAL_RANDOM_BENCHMARK_V1":
       continue
   ```
   An attacker-crafted candidate run claiming COMPLETE could embed random benchmark inputs and escape contract binding against `run_identity.signal_producer_contract`.
4. **Missing Role Disambiguation at Consumer Chokepoints**:
   `EconomicRunIdentity` did not record whether a run was executed under candidate authority or random benchmark trial authority, allowing trial artifacts to potentially be presented where candidate evidence was demanded.

## 4. Candidate vs. Benchmark Authority Model

### 4.1 Canonical Role Enum (`src/btc_quant_agent/economic/qualification.py`)
```python
class EconomicRunRole(StrEnum):
    CANDIDATE = "CANDIDATE"
    RANDOM_BENCHMARK = "RANDOM_BENCHMARK"
```
Re-exported in `src/btc_quant_agent/economic/__init__.py`.

### 4.2 Replay Bundle Builder (`src/btc_quant_agent/economic/replay_bundle.py`)
- Accepts `authority_role: EconomicRunRole | str = "CANDIDATE"`.
- When `authority_role == "CANDIDATE"`:
  - Requires `protocol.signal_producer_contract`.
  - Generic random exemption removed; declared random contracts fail closed against candidate protocol.
- When `authority_role == "RANDOM_BENCHMARK"`:
  - Enforces `CANONICAL_RANDOM_BENCHMARK_V1`.
  - Rejects non-random producer contracts.
- Self-validation passes `expected_role=clean_role` to `validate_formal_replay_input_bundle`.

### 4.3 Independent Verifier (`src/btc_quant_agent/economic/replay_bundle.py`)
- Accepts `expected_role: EconomicRunRole | str = "CANDIDATE"`.
- When `expected_role == "CANDIDATE"`:
  - Strictly enforces `contract.contract_id == proto_contract.contract_id` and `contract.contract_hash == proto_contract.contract_hash`.
  - Zero random exemption; random producer contract in candidate context is rejected.
- When `expected_role == "RANDOM_BENCHMARK"`:
  - Enforces `contract.contract_id == "CANONICAL_RANDOM_BENCHMARK_V1"`.

### 4.4 Runtime Execution (`src/btc_quant_agent/economic/qualification.py`)
- `execute_bound_run` accepts `run_role: EconomicRunRole | str = EconomicRunRole.CANDIDATE`.
- For `CANDIDATE`: validates `protocol.signal_producer_contract` is present when signals exist, passes `expected_role=EconomicRunRole.CANDIDATE` to bundle verifier, stamps `spc_identity` from protocol contract, and sets `identity.run_role = EconomicRunRole.CANDIDATE`.
- For `RANDOM_BENCHMARK`: binds `spc_identity = CANONICAL_RANDOM_BENCHMARK_V1`, passes `expected_role=EconomicRunRole.RANDOM_BENCHMARK` to bundle verifier, and stamps `identity.run_role = EconomicRunRole.RANDOM_BENCHMARK`.

### 4.5 Persisted Verifier (`src/btc_quant_agent/economic/acceptance_verifier.py`)
- `validate_persisted_decision_input_bindings` reads `run_identity.get("run_role", "CANDIDATE")`.
- In `CANDIDATE` mode: removed `if producer_contract_id == "CANONICAL_RANDOM_BENCHMARK_V1": continue`. Every decision input entry must match `run_identity.signal_producer_contract`.
- In `RANDOM_BENCHMARK` mode: requires all decision inputs to use `CANONICAL_RANDOM_BENCHMARK_V1`.
- Passes `expected_role=run_role` to `validate_formal_replay_input_bundle`.

### 4.6 Consumer Rejection of Non-Candidate Roles (`src/btc_quant_agent/economic/qualification.py`)
In `_validate_candidate_run_binding`:
```python
if getattr(candidate_run.identity, "run_role", None) != EconomicRunRole.CANDIDATE:
    raise ValueError(
        f"candidate run cannot have role {getattr(candidate_run.identity, 'run_role', None)}; "
        "benchmark trial cannot authorize candidate economic qualification"
    )
```
This single funnel protects both `build_formal_benchmark_suite` and `evaluate_formal_economic_qualification`.
