## 2. Executive summary

Do not freeze this HEAD as an accepted formal qualification baseline. Preserve it as an auditable repair baseline.

The cash ledger and immutable P5 registry are materially stronger than v0.4.0. The latest passive provenance repair really reconstructs its declared passive policy, models and funding payload. Nevertheless, the end-to-end qualification boundary still confuses **a self-consistent account of trades** with **trades reproducible from the declared strategy and available market evidence**.

Independent synthetic probes found:

- A candidate entry at **1.0**, against candles whose lowest price is **99.5**, passes accounting replay and reaches `ECONOMICALLY_QUALIFIED`. Recomputed return changes from **0.05% to 9.95%**, crossing a preregistered 5% hurdle. All artifact hashes are recomputed; no hash collision or registry-file edit is involved.
- A supposedly no-trade cash benchmark containing two trade events passes registry acceptance.
- Four random benchmark trials can all be replaced with the candidate's identical trade path while retaining the expected per-trial seeds and model identities. Registry acceptance still succeeds.
- A limit order expiring one millisecond after bar open is filled at that open using a low observed somewhere in the following 15 minutes.
- A market fill stamped at bar open changes from 100.02 to 100.0101 solely when that bar's future total volume changes.
- Input candles marked `closed=False` are accepted as a formal `COMPLETE` run; serialization drops the closed flag.

These are acceptance/control failures, not evidence of profitable strategies. Existing green tests do not cover these attacks.

## 4. New findings by severity

### B1 — BLOCKER: candidate replay validates the story, not its execution

**Paths:** `economic/qualification.py:898` (`execute_bound_run`), `:1037` (evaluation); `economic/acceptance_verifier.py:357` (`verify_formal_accounting`), `:1046` (persisted semantics); `research_contract/registry.py:614` (promotion validation).

**Failure:** run identity contains `signal_set_sha256`, but persisted candidate evidence does not contain the signal-set preimage or replayable policy/model bundle. The verifier accepts supplied TradeEvents, reconstructs Portfolio state, and compares derived metrics. It never checks those events against the execution model, available input, signal set or risk policy. Rehashing coherent forged events defeats content-only checks without altering the preregistered contract.

**Observed attack:** use the existing eight-bar zero-cost fixture; keep the real candidate identity; rebuild its legal ledger with its OPEN_LONG price changed from 100 to 1; rebuild curve, drawdown, attribution and all artifact hashes. With CASH required and a fixed 5% return hurdle, genuine return is 0.0005, forged return is 0.0995, and `record_economic_qualification` produces `ECONOMICALLY_QUALIFIED`. The statistical predecessor is explicitly a synthetic fixture; no real alpha attestation is claimed.

**Consequence:** arbitrary coherent execution prices, costs, quantities, funding cashflows or omitted policy decisions can be certified. P0/P1 ledger integrity does not prevent fabricated alpha.

**Minimal repair boundary:** version a replay-input bundle with canonical signal, funding, policy, fee, execution, dataset and availability preimages. Reconstruct from verified content, execute the supported policy through the canonical kernel, and compare the complete event stream and summary before accepting the result. Verify that the runtime implementation is the supported implementation, not merely an object with matching parameter attributes. Preserve old artifacts read-only; artifacts lacking required provenance cannot acquire new qualification. No rewrite of Portfolio or historical results is needed.

**Required adversarial regression:** the exact 1-versus-99.5 case must fail after all hashes/curves/gates are correctly rebuilt. Also alter fee, funding, risk cap, signal direction/time and terminal handling one at a time while conserving cash. Include a genuinely correct nonzero-cost/funding run that still promotes.

### B2 — BLOCKER: LIMIT fills still backdate full-bar extremes and defeat expiry

**Paths:** `economic/execution_model.py:456` onward, four long/short through/touch branches; simulator pending/admission and funding processing consume the resulting fill timestamp.

**Observed attack:** a bar opens at 100, low=90, high=110, closes at 100, interval `[1800000000000,1800000900000]`. BUY LIMIT 95 submitted at open, TIF=1 ms, is filled at **1800000000000**. The low only proves that a touch occurred somewhere in the whole bar, possibly after expiry. The ordinary API produces this; forged evidence is unnecessary.

**Consequence:** a future touch becomes an already-held position. Funding, holding time, stop/target ordering and qualification can be wrong. Existing tests reject an order arriving *inside* a bar or expiring *before* a later bar; neither closes this counterexample.

**Minimal repair boundary:** distinguish an observable marketable-at-open limit from an unknown intrabar touch. An unknown touch cannot authorize an opening timestamp. Use a declared conservative/ambiguous result or lower-resolution evidence; reject/not-testable when expiry, funding or another material event lies inside the unresolved window. Merely moving every fill to close is insufficient if expiry precedes close. Apply the same rule to both sides and exact-touch/through cases.

**Required adversarial regression:** construct two tick paths with identical OHLC but touches before versus after expiry/funding; the OHLC path must not invent one ordering. Test opening-gap marketability, all four branches, same-time funding, entry-bar exits and notional caps.

### H1 — HIGH: random benchmark seeds are checked, random draws are not

**Paths:** `_random_matched_benchmark` in `qualification.py:1363`; `acceptance_verifier.py:1132` onward.

**Observed attack:** replace every random trial ledger with the candidate's ledger, preserve each original trial's declared identity and expected seed, recompute its run ID and matching diagnostics. Four entry timestamps become `[1800000000000]` instead of the generated `[1800005400000,1800004500000,1800004500000,1800005400000]`. P5 promotion still accepts the suite.

**Consequence:** a chosen null distribution can replace the preregistered random distribution, changing relative-return gates. An opportunity-set hash with no verified preimage is not a replayable sampling procedure.

**Minimal repair boundary:** persist the ordered eligible-opportunity preimage and versioned draw rule, including metadata and stable tie ordering; reconstruct trial seeds, selections, shuffled directions, signals and executions. Matching is a secondary comparison, not proof of random selection. Do not alter the frozen seed, number of trials, tolerance or randomization unit as a repair convenience.

**Required regression:** cloned trials and a different opportunity set under the same declared hash must fail even with valid ledgers and matching metrics; correct draw sequence, duplicate timestamps and both directions must replay identically across Python 3.11–3.13.

### H2 — HIGH: cash benchmark is not required to remain cash

**Paths:** `acceptance_verifier.py:1087` cash branch; `_cash_benchmark` in `qualification.py:1269`.

**Observed attack:** replace the cash record's accounting with the genuine candidate accounting, retain `USDT_CASH_NO_TRADE` and `comparable=True`, and rehash/rebuild the result. It now contains two trade events, but is accepted by the registry as a formal cash benchmark.

**Consequence:** excess-return-versus-cash is not necessarily excess return versus a no-trade portfolio. A losing traded path could make this hurdle easier; the probe used the genuine positive path solely to establish policy substitution.

**Minimal repair boundary:** independently reconstruct the no-trade baseline from initial capital and expected timestamps; require no events/positions/orders, zero fee/funding/turnover/exposure/PnL, constant equity, exact benchmark kind/vehicle and null random identifiers. Reuse metric arithmetic, not candidate accounting.

**Required regression:** positive and negative traded “cash”, a funding-only cashflow, changed timestamps and nonzero exposure must fail after full rehash; constant cash remains valid for both supported terminal policies.

### H3 — HIGH: open-price impact uses future completed-bar volume

**Paths:** `execution_model.py:353`–`:370`; `fee_model.py:120` participation impact. The conditional-exit repair explicitly avoids this dependency; MARKET does not.

**Observed attack:** keep price, signal, timestamps, quantity=1 and causal spread=2 bps unchanged. With SPREAD_AND_IMPACT, coefficient=0.01 and cap=100 bps, future bar volume 100 gives an opening fill 100.02; volume 10,000 gives 100.0101. Both fills are timestamped at bar open.

**Consequence:** a strategy's costs and admission/exposure depend on information unavailable at execution. A bounded cost is not necessarily a causal cost.

**Minimal repair boundary:** pass a separately timestamped already-available liquidity observation, or use the declared adverse cap when it is unavailable. Do not use completed-bar volume for an earlier fill. The zero-volume availability/rejection check needs the same explicit scenario treatment. Keep legitimate close-time information usable at close.

**Required regression:** suffix-volume perturbations cannot change an already-observed opening fill; causal prior-volume perturbations may. Test long/short, passive entry, cap, missing spread and close-time fills.

### H4 — HIGH: formal candle binding erases closed/availability state

**Paths:** `acceptance_verifier.py:26` canonical runtime candles and `:215` reconstruction; `qualification.py:1141` runtime validation; compare `data/quality.py:25`.

**Observed attack:** replace every synthetic input candle with `closed=False`. `execute_bound_run` still returns `COMPLETE`; the persisted ten-field candle payload has no closed flag and reconstruction defaults to `closed=True`.

**Consequence:** identical price arrays can represent different information-availability states while sharing formal economic identity. The declared `closed_btcusdt_15m` requirement is not enforced at this boundary.

**Minimal repair boundary:** version the data/PIT boundary to validate and preserve closed/availability semantics, uniform interval and supported spacing rules. Explicitly reject an unfinished bar for a completed-bar replay; do not silently coerce it. Bind availability provenance to the input contract, not just a caller-supplied label. Do not require current wall-clock freshness for legitimate historical replay.

**Required regression:** open/incomplete candles, interval mismatch, overlapping/gapped intervals, nonfinite values and unavailable signal inputs must fail with typed reasons; valid historical closed candles still pass. Existing schema stays readable but cannot be silently upgraded into formal evidence.

### H5 — HIGH: deprecated blind diagnostic constructs outcomes; tests use default stores

**Paths:** `microstructure_research.py:2440` (`evaluate_validation_status`) calls `build_observations_for_partition` at `:2491` for post-start partitions. The latter reads canonical candles through future horizons and constructs `H39OutcomeRow.return_60m/return_240m` at `:2307` onward. `tests/test_v0323_blind_validation.py:704` and `tests/test_v0325_one_shot_unblind_preregistration.py:405` instantiate the engine with default paths. The report-generation and several readiness tests likewise use default store paths.

**Failure scenario:** an innocently named status/safety regression running in a populated checkout traverses fresh Forward partitions and invokes outcome construction before any one-shot authorization. The diagnostic returns only counts and explicitly cannot promote candidates; that protection is real, but does not make its internal data path label-free. Filesystem and wall-clock dependence also make CI on an empty checkout unrepresentative of local behavior.

**Observed boundary:** the existing full test run executed those default-path callers; they took 156.47 and 98.99 seconds respectively. Their output exposed no labels or formal statistical result. This audit did not instrument file accesses in advance, so it cannot quantify which underlying values were read and will not claim zero access or rerun that path locally. The pre-gate outcome-construction call is independently visible in source.

**Consequence:** the blind-data separation is weaker than the safety test names imply. Running tests or health tooling should not create an avenue for premature outcome inspection, modify operational caches, or depend on current experiment maturity.

**Minimal repair boundary:** make deprecated diagnostics metadata-only or a refusal; make every test provide explicit temporary stores and a fixed clock, and prohibit default operational roots/network access in test mode. Keep formal H39 evaluation, frozen coefficients/thresholds and one-shot gatekeeper unchanged. Review this as a boundary repair, not permission to alter the experiment or inspect its outcomes.

**Required regression:** install spies that raise on canonical future-candle/outcome/statistical loaders and on operational-root opens; every pre-unblind status/readiness/safety test must pass without calling them. Verify the deprecated route cannot authorize anything. Retain the full synthetic authorized one-shot test separately, and run the exact-head CI in a fresh isolated checkout.
