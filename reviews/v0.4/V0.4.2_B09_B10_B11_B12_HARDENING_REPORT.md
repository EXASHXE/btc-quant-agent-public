## B09 — one durable publisher

Root cause: the registry already had the strongest same-directory atomic writer, including file and directory fsync. Other active manifest/economic JSON writers used direct writes or weaker atomic replacement. The registry also lacked explicit in-memory reconciliation when replacement succeeded but directory fsync failed.

`publication.py` consolidates that primitive:

```text
serialize caller-owned bytes
-> same-directory temp write
-> flush
-> fsync(temp file)
-> atomic os.replace
-> fsync(parent directory)
```

Serialization remains with the owning module: existing canonical economic JSON plus newline, data-manifest UTF-8/indent/sort settings, finalized-manifest settings, backup-manifest settings and export CSV bytes are preserved. JSON schemas are unchanged.

Ownership is a canonical-target advisory file lock, reentrant within the owning thread. Aliases/symlinks normalize with `os.path.realpath`. The generic policy is serialized publication, not an implicit target read/CAS. Stores with a frozen digest/generation add their explicit CAS under that same lock. A stale explicit digest raises `PublicationConflict` before temp publication.

| Injected boundary | Observed result |
| --- | --- |
| Partial temp write | OSError; previous committed bytes identical; temp removed. |
| Before temp flush | OSError; previous committed bytes identical; temp removed. |
| Temp file fsync | OSError; previous committed bytes identical. |
| After file fsync / before replace | OSError; previous committed bytes identical. |
| Replace failure | OSError; previous committed bytes identical. |
| Replace succeeded / directory fsync failed | `PublicationUncertain`; complete new bytes visible, no durability-success or rollback claim. |
| Two owners with the same expected absent generation | Exactly one commit; the other conflicts; complete JSON only. |
| Truncated registry / orphan temp | Truncated authority rejected; orphan is never loaded as committed state. |
| Path normalization | No extra final-target `Path.stat` probe; existing write-boundary hermetic rejection preserved. |

The directory-fsync case cannot truthfully restore the old target: atomic replacement has already occurred. It surfaces uncertainty and requires authoritative reread rather than blind retry. Registry and microstructure owners reconcile their cached state on that explicit exception.

Migrated active callers: registry, economic qualification/suite/run JSON writer, data manifest, microstructure finalized manifest and advisory stats cache, forward export CSV/manifest, and blind-ledger backup manifest. Advisory-cache failures remain advisory, never authoritative success. Historical archive download/report writers are not swept.

This primitive does **not** make SQLite/WAL or a two-file export transaction atomic.

## B10 — finalization and mutation ownership

Already correct: the research registry had generation CAS, whole-state validation and append-only hash-chained decision events; duplicate registration was idempotent. These semantics are retained, not replaced.

Missing repairs:

- Microstructure mutations/finalization now share the finalized-manifest target lock and cached digest. Staleness is checked before mutation. Cross-partition mutators validate mutable schemas before writes/checkpoints; sealed partitions are never migrated by a writer.
- Successful finalization requires a non-busy WAL checkpoint before hashing the partition and publishing its manifest. Existing UTC eligibility/grace and open-session exclusion remain unchanged.
- Reopening loads the committed digest. Repeating an already sealed finalization produces no duplicate manifest transition. Post-cutover uncertainty refreshes the owner digest before rethrowing.
- Forward exports lock both canonical CSV and manifest targets in sorted order. Targets must differ. CSV bytes are immutable even when another owner chooses a different manifest path; existing manifests must exactly match current data/metadata and the CSV must exist and match. Changed rows, missing CSV or corrupt manifests fail before overwrite. New generations use fresh artifact paths.
- Blind-ledger source registration and slot ingestion use native `BEGIN IMMEDIATE` to serialize read/check/write ownership. Finalized source hashes cannot be overwritten or downgraded to mutable. No blind outcomes or historical rows are rewritten.

State transitions:

```text
current mutable owner
-> lock + digest/generation/schema validation
-> native SQLite mutation/checkpoint as applicable
-> durable authoritative manifest/registry cutover
-> sealed/current generation

pre-cutover failure -> old committed authority remains
post-cutover uncertainty -> reread one complete committed generation + explicit error
stale owner -> reject before mutation
reopen/retry committed result -> idempotent or explicitly immutable
```

| Attack | Outcome |
| --- | --- |
| Two microstructure finalizers start from the same manifest | One successful transition; one stale rejection. |
| Stale append / heartbeat after another owner finalizes | Conflict before SQLite bytes change. |
| Repeat finalization after reopening | Same manifest bytes; one sealed partition; no duplicate output. |
| Crash before publishing a second partition | Old manifest authoritative; clean retry adds only the second partition. |
| Directory failure after cutover | Reopen and same-owner retry both see exactly one committed result. |
| Busy WAL / open session | Refused or excluded; no sealed manifest claimed. |
| Registry postcommit directory failure | In-memory/reopened generation and append-only event prefix agree; retry does not append again. |
| Two blind source finalizers with different hashes | One commit; competing hash rejected after serialized authority check. |
| Finalized blind source set to mutable | Explicit rejection; finalized flag stays true. |
| Two exports, same CSV / different manifest paths | One commit; incompatible CSV owner rejected. |

Heartbeat availability remains distinct from schema validity: the existing advisory contract skips an unavailable/locked connection without writing; an actual malformed schema is not treated as valid.

Export failure before the first manifest can leave a complete uncommitted CSV orphan. The manifest is the export commit surface; an orphan is not formal authority. Retry can publish the same bytes, but cannot silently overwrite a different existing CSV. No cross-file atomicity is claimed.

## B11 — explicit SQLite boundary

Root cause: active stores had implicit positional inserts and `SELECT *`; adjacent-partition UNION views could silently align different physical orders. Legacy ALTER adapters existed but version/required-column agreement was not consistently enforced.

`sqlite_schema.py` declares canonical column tuples/projections, required-column checks and a monotonic `PRAGMA user_version` boundary:

| Schema condition | Policy / evidence |
| --- | --- |
| Version 0, empty/new store | Create declared tables, verify columns, mark version 1. |
| Version 0, supported core schema | Apply only the owner's existing optional-column ALTER adapter; preserve rows; verify then mark 1. |
| Forward legacy collection_runs | Four telemetry/trigger extensions; neutral `LEGACY_UNKNOWN`, NULL, `{}`, NULL defaults. |
| Opportunity legacy observations | Existing trigger-source adapter retained. |
| Microstructure legacy sessions | Only `sessions.instance_id` and `sessions.last_heartbeat_ms` are optional; same-named core columns in other tables remain required. |
| Blind-ledger legacy input contract | Existing nullable input-contract column adapter; no outcomes or formal eligibility manufactured. |
| Version 1, complete schema | Named reads/writes in declared order. |
| Reordered physical columns / unknown extra column | Explicit projection remains correct; extra column safely ignored. |
| Missing required core column, version 0 or 1 | Explicit `SQLiteSchemaError` / NOT_TESTABLE. |
| Version 1 missing an adapter column | Partial migration rejected; no self-healing/relabeling. |
| Unsupported marker (-1, 2, 99) | Explicit schema error; marker not rewritten. |
| URI/localhost/encoded/symlink forbidden paths | Existing hermetic tests remain unchanged and pass. |

Boundaries cover Repository, ForwardDerivativeStore, OpportunityForwardStore, MicrostructureStore, blind-ledger connections and read-only microstructure partition loading. Adjacent sources validate each source schema and project the same canonical columns before UNION. One-shot/frozen ledger reads use explicit projections too; no unblind workflow was executed.

Compatibility adapters do not rewrite sealed research outcomes. JSON durability, native SQLite transactions, integrity checks and WAL checkpointing remain separate concerns. Column existence/order compatibility is asserted; this is not a new ORM or universal SQL type-coercion framework.

## B12 — one coordinated bounded urllib requester

Root cause: derivative collection retried locally with independent linear sleeps; other active GET/diagnostic paths had no shared retry/rate-limit ownership or overall deadline, and response reads were unbounded.

`data/rest.py` owns policy, scheduling and caller deadlines; existing urllib remains the only transport. Production integrates Binance public GETs, network diagnostics and forward network checks. Existing private one-shot `_get` remains the transport seam, preserving mocked tests; active production GET callers route through `_request`.

Default compatibility policy derives from existing DataConfig timeout T:

- per-attempt socket timeout <= T and remaining overall budget;
- overall deadline 3*T + 2 seconds, measured monotonically;
- maximum 3 attempts;
- exponential base 0.1 seconds, cap 1.0 second;
- shared minimum origin start interval 0.05 seconds;
- diagnostics declare one attempt with their existing 5/10-second bound;
- all six RequestPolicy fields required; invalid/nonfinite/bool/range values, missing or misspelled config fail closed.

Origin ownership is shared across clients. Cooldown is published before transport-lock release, and queued callers check it after acquiring ownership. Thus 429/backoff and start spacing are not independent per-caller retry loops.

| Mocked fault | Outcome |
| --- | --- |
| Repeated 500/503 / raised network timeout | Exactly 3 attempts; bounded 0.1/0.2 backoffs; explicit final error. |
| Overall deadline shorter than remaining retries | Stops before another attempt. |
| 429 numeric Retry-After | Bounded wait, then positive success. |
| HTTP-date Retry-After / absurd positive wait | Converted/capped at declared maximum. |
| NaN, negative or malformed Retry-After | Rejected; bounded fallback, no unbounded sleep. |
| 400/401/403, schema error, certificate verification error | One attempt; no retry storm. |
| Wall-clock rollback | Monotonic elapsed budget/backoff unchanged. |
| Concurrent callers after 429 | Shared cooldown and minimum start spacing respected. |
| Cancellation during backoff | Prompt explicit `RequestCancelled`; no extra request. |
| Slow/uncooperative DNS/open/read | Caller deadline fires; one origin transport retained/quarantined; no worker amplification. |
| Mocked urllib JSON / malformed / >2 MiB body | Positive decode, or nonretryable schema/size error, one call. |
| Missing/typo/invalid policy | TypeError/ValueError before transport. |

Selected 429/5xx/network transient conditions alone are retryable; auth/config/schema/certificate errors are not blindly retried. HTTP Retry-After uses wall time only to interpret an HTTP date. UTC event/receipt/availability timestamps and the existing B08 collection clock boundary are unchanged; monotonic time accounts only for elapsed budgets/backoff.

urllib can outlive its socket timeout during DNS/open/read. A daemon Future wrapper bounds the caller; the origin transport lock remains held until a late transport exits. Later callers expire/cancel rather than launch competing transports. Cancellation does not claim to forcibly terminate an uncooperative OS/DNS operation; GET-only quarantine bounds amplification and shutdown does not join that daemon indefinitely. No second HTTP stack, queue or execution pathway was added.

All requester tests use synthetic/mocked transport only.
