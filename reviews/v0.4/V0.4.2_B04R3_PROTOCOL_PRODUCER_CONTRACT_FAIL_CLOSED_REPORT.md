# V0.4.2 B04R3 Acceptance Repair Report — Protocol Producer Contract Fail-Closed

## 1. Executive Summary

This report documents the completion of **v0.4.2 B04R3 Protocol Producer Contract Fail-Closed Acceptance Repair** on branch `v0.4` of repository `EXASHXE/btc-quant-agent`.

The repair closes the remaining contract authority vulnerability identified in B04R2:
In B04R2, while a protocol-bound producer contract was strictly verified when present, the absence of `protocol.signal_producer_contract` allowed candidate runs to supply, discover, or synthesize an authoritative contract from the registry without protocol authorization. The verifier silently skipped contract enforcement if `proto_contract is None`, `execute_bound_run` did not require protocol contract authority before qualification, and persisted artifact verification did not require `signal_producer_contract` in `run_identity`.

Under B04R3:
1. **Mandatory Protocol Producer Contract for Formal Non-Empty Signal Runs**: Formal economic qualification of any candidate with non-empty signals strictly requires `protocol.signal_producer_contract`. If missing, the run fails closed at all layers.
2. **Builder Fail-Closed Enforcement**: `build_formal_replay_input_bundle` rejects candidate runs when `authoritative_contract is None`. Candidate choice, registry fallback, and feature heuristics cannot substitute for missing protocol authority.
3. **Independent Verifier Fail-Closed Enforcement**: `validate_formal_replay_input_bundle` independently rejects bundles with decision inputs if `expected_protocol` lacks `signal_producer_contract`.
4. **Early Runtime Fail-Closed in `execute_bound_run`**: `execute_bound_run` rejects runs with non-empty signals immediately if `protocol.signal_producer_contract is None`, prior to simulated execution or accounting.
5. **Persisted Run-Identity Requirement**: `validate_persisted_decision_input_bindings` strictly requires `signal_producer_contract` in `run_identity` for all COMPLETE runs with non-empty signals. Valid bundles cannot backfill missing run authority.
6. **Legitimate Zero-Signal Run Preservation**: Legitimate zero-signal runs (e.g. CASH baseline where `signal_set_sha256 == canonical_sha256([])`) continue to pass without false rejections.

All 987 tests pass across the full test suite (7 new adversarial and positive control tests added for T1–T7). Local validation and remote CI across Python 3.11, 3.12, and 3.13 are 100% green.

## 3. Root Cause Analysis

In B04R2, the system enforced that *if* the protocol declared a producer contract, the replay bundle's decision inputs had to match that contract. However, the converse requirement was not fail-closed:

1. **Unchecked Verifier Bypass**:
   In `validate_formal_replay_input_bundle`, the check was guarded by:
   ```python
   proto_contract = _resolve_protocol_producer_contract(expected_protocol)
   if proto_contract is not None:
       if contract.contract_id != proto_contract.contract_id:
           ...
   ```
   If `proto_contract is None`, the check was silently bypassed. An attacker could craft or synthesize a bundle referencing a valid registry contract and present it alongside a protocol lacking `signal_producer_contract`.
2. **Candidate Fallback in Bundle Builder**:
   In `build_formal_replay_input_bundle`, when `authoritative_contract is None`, fallback code still accepted candidate-supplied contract IDs or attempted heuristics based on candidate producer identity or feature definitions, allowing a candidate to choose its own contract without protocol authorization.
3. **Permissive Runtime Qualification**:
   In `execute_bound_run`, formal execution enforced that `replay_input_bundle` must be provided when `signals` was non-empty, but did not check `protocol.signal_producer_contract is not None`. This allowed a candidate lacking protocol authority to execute simulated trades and obtain `ResultCompleteness.COMPLETE`.
4. **Missing Persisted Run-Identity Assertion**:
   In `validate_persisted_decision_input_bindings`, persisted artifact verification validated bundle hash integrity and cross-binding, but did not strictly require `signal_producer_contract` in `run_identity` for COMPLETE runs with signals.

## 4. Exact Fail-Closed Boundaries Added

### 4.1 Builder Fail-Closed (`src/btc_quant_agent/economic/replay_bundle.py`)
- In `build_formal_replay_input_bundle`:
  ```python
  if signals and authoritative_contract is None:
      raise ValueError(
          "formal replay input bundle with signals requires protocol-bound signal_producer_contract; "
          "candidate cannot authorize its own signal producer contract"
      )
  ```
- In the item processing loop:
  If `authoritative_contract is None`:
  ```python
  if declared_contract_id:
      raise ValueError(
          f"bundle producer contract {declared_contract_id} cannot be authorized by candidate; "
          "protocol.signal_producer_contract is strictly required for formal signal runs"
      )
  raise ValueError(
      f"decision input entry for {signal_id} lacks authoritative protocol-bound producer contract; "
      "protocol.signal_producer_contract is strictly required for formal signal runs"
  )
  ```
  All heuristic fallbacks to `FIXED_DIRECTION` or feature definition lookups have been permanently removed.

### 4.2 Verifier Fail-Closed (`src/btc_quant_agent/economic/replay_bundle.py`)
- In `validate_formal_replay_input_bundle`:
  For all non-benchmark entries when `expected_protocol` is supplied:
  ```python
  if expected_protocol is not None and contract.contract_id != "CANONICAL_RANDOM_BENCHMARK_V1":
      proto_contract = _resolve_protocol_producer_contract(expected_protocol)
      if proto_contract is None:
          raise ValueError(
              f"expected protocol {getattr(expected_protocol, 'experiment_id', 'unknown')} "
              f"lacks required signal_producer_contract for non-empty decision inputs"
          )
      if contract.contract_id != proto_contract.contract_id:
          raise ValueError(...)
      if contract.contract_hash != proto_contract.contract_hash:
          raise ValueError(...)
  ```
  The verifier independently fails closed even if the bundle bypassed the builder.

### 4.3 Runtime Qualification Fail-Closed (`src/btc_quant_agent/economic/qualification.py`)
- In `execute_bound_run`:
  Evaluated before simulation, accounting, or benchmark generation:
  ```python
  if signals:
      if protocol.signal_producer_contract is None:
          raise ValueError(
              "formal run with signals requires protocol.signal_producer_contract; "
              "missing protocol contract cannot authorize formal economic qualification"
          )
      if replay_input_bundle is None:
          raise ValueError(
              "formal economic qualification with non-empty signals requires formal replay_input_bundle; "
              "unverified execution is strictly prohibited (Mode B: NOT_TESTABLE)"
          )
  ```
  A formal candidate with signals cannot produce simulated outcomes without protocol authority.

### 4.4 Persisted Verifier Fail-Closed (`src/btc_quant_agent/economic/acceptance_verifier.py`)
- In `validate_persisted_decision_input_bindings`:
  For `is_complete and has_signals`:
  ```python
  if run_identity.get("signal_producer_contract") is None:
      raise ValueError(
          "persisted candidate claims COMPLETE with signals but lacks signal_producer_contract in run_identity"
      )
  ```
  And inside the entry verification loop, cross-validates against `identity_spc`:
  ```python
  if identity_spc is None or entry.get("producer_contract_id") != identity_spc.contract_id:
      raise ValueError(
          f"bundle producer contract {entry.get('producer_contract_id')} does not match "
          f"run_identity signal_producer_contract {getattr(identity_spc, 'contract_id', None)}"
      )
  ```
  A valid bundle cannot backfill authority into a run identity that lacks it.

### 4.5 Random Benchmark Boundary
Entries where `producer_contract_id == "CANONICAL_RANDOM_BENCHMARK_V1"` are strictly exempt from candidate protocol contract matching, preserving comparative random benchmark evaluation without creating a candidate loophole.
