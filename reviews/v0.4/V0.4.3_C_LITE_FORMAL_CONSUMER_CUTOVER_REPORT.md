## Supported inputs and routing

Supported invocation:

```text
quantctl backtest --job JOB.json --output NEW_FORMAL_ROOT
quantctl research --job JOB.json --output NEW_FORMAL_ROOT
quantctl replay --job JOB.json --output NEW_FORMAL_ROOT
python tools/run_formal_research.py --job JOB.json --output NEW_FORMAL_ROOT
```

Optional `--registry EXISTING_P5.json --record-decision` requests the accepted P5 commit phase. None of these commands constructs the operational service/default SQLite database or activates execution.

Job schema `1.0.0` requires all of: `schema_version`, `protocol_path`, `comparison`, `dataset_evidence`, `engine`, `candles`, `signals`, `decision_inputs`, `eligible_opportunities`, `funding_events`, `observed_at_utc`. The engine specifies policy, fee, execution and funding inputs, checked against frozen canonical authority. The timestamp must be timezone-aware. JSON duplicates/nonfinite constants fail closed. Each candle must explicitly carry `closed` and `available_at_ms`; compatibility defaults cannot supply formal PIT proof.

`protocol_path` is relative to the job file when not absolute. Evidence paths retain P5/P6 cwd-relative semantics and are not silently rebased, which would change evidence identity. If CLI `--config` is supplied, its loading/failure semantics remain enforced; it does not substitute economic job authority.
