## Finding R05C-F1 — P5 required-evidence closure is not enforced

Severity: **MEDIUM acceptance blocker**.

The R05C prompt explicitly requires that a formal qualification/registry decision cannot omit the funding evidence root from `required_evidence_ids`.

Current code does not enforce that invariant at the qualification authority boundary:

- `evaluate_formal_economic_qualification()` only requires that `required_evidence_ids` is non-empty and unique. It does **not** require `candidate_run.identity.funding_evidence_id` to be present.
- `EconomicQualificationResult.__post_init__()` likewise checks only non-empty/unique evidence ids.
- `validate_persisted_qualification_semantics()` cold-replays funding correctly, but does not require `semantic.required_evidence_ids` to contain the run's funding evidence id.
- `ResearchContractRegistry.record_economic_qualification()` generically requires only the ids that the attestation/result already declares. It does not derive the missing funding id itself.

Consequently, a direct caller can construct an otherwise valid qualification while omitting the funding evidence id from `required_evidence_ids`, publish the result, and ask P5 to record only the declared dataset/run/benchmark/result evidence. During the initial decision the embedded funding reference can still be read and cold-replayed, so economics are not forged; however the committed P5 evidence chain does not explicitly retain/register the funding authority required by the repaired contract.

This is not a resurrection of sign-swap PnL forgery, but it violates the R05C authority contract and weakens atomic traceability/reproducibility. R05C cannot be accepted until omission/replacement is fail-closed.

### Minimal required repair

Do **not** redesign the registry. Enforce the invariant upstream and in cold verification:

```text
funding_id = candidate_run.identity.funding_evidence_id
funding_id MUST be in required_evidence_ids
```

Required defense-in-depth locations:

1. `evaluate_formal_economic_qualification()`;
2. `EconomicQualificationResult.__post_init__()`;
3. `validate_persisted_qualification_semantics()` using persisted `run_identity.funding_evidence_id`.

Once the funding id is mandatory in the result/attestation, the existing generic registry subset checks automatically require the actual funding `EvidenceReference` in `evidence_references`; no registry schema/lifecycle redesign is needed.

## Finding R05C-F2 — FundingIntervalIdentity coverage fields are not cross-bound

Severity: **LOW**, fix in the same companion repair.

`FundingIntervalIdentity` contains `coverage_start_ms` / `coverage_end_ms`, and those fields participate in the preregistered comparison hash. However `ComparisonContract.__post_init__()` does not require them to equal `data_interval.start_ms/end_ms`, and `load_and_validate_funding_evidence()` validates document coverage against separately supplied expected start/end without checking `expected_identity.coverage_*`.

The evidence file is still safely checked against the actual comparison data interval, so this is not a funding substitution bypass. But it allows a misleading preregistered identity whose declared coverage fields disagree with the coverage actually enforced.

Repair both boundaries:

```text
comparison.funding_interval.coverage_start_ms == comparison.data_interval.start_ms
comparison.funding_interval.coverage_end_ms   == comparison.data_interval.end_ms
```

and assert the same in the low-level loader before reading/accepting events.
