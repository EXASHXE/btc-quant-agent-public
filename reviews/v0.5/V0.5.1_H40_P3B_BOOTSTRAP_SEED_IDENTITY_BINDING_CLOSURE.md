# V0.5.1 H40 P3B — Bootstrap Seed Identity Binding Closure

## Status

```text
H40_P3B_BOOTSTRAP_SEED_IDENTITY_BINDING_CLOSURE
PRE_OUTCOME
NO_REAL_H40_OUTCOMES_ACCESSED
```

This document closes a valid-family implementation ambiguity in the already accepted R2 bootstrap seed rule.

R2 §3.3 freezes:

```python
seed_preimage = canonical_json([
    protocol_id,
    candidate_id,
    partition_id,
    metric_id,
])
```

but did not bind the abstract names `protocol_id` and `candidate_id` to one exact repository identity.

Because multiple plausible hashes now exist, implementation must not choose implicitly.

---

## 1. Accepted identity mapping

For every H40 bootstrap/randomization seed derived under the R2 convention:

```text
protocol_id =
protocol_authority_hash
```

Specifically for current H40 V1 R3:

```text
protocol_id =
a83f8fc7a5ca7109fb8cd7fed114d87c3b2c968b5145c11cada203aa5111d1ce
```

The implementation MUST obtain this through the accepted protocol-authority computation/verification path, not from an arbitrary caller string.

For every structural candidate:

```text
candidate_id =
structural_configuration_hash
```

The implementation MUST derive/verify that value from the accepted sealed configuration/roster identity.

---

## 2. Explicitly forbidden alternative identities

The following MUST NOT be substituted into the R2 seed preimage:

```text
H40ProtocolIdentity.protocol_hash
config_id
slot_hash
slot_index
structural_ledger_hash
runtime_authority_snapshot_hash
materialized_run_authority_hash
run_authority_id
source_manifest_hash
split_manifest_hash
Git commit SHA
filesystem path
caller label
```

Rationale:

- `protocol_hash` is an earlier protocol identity object and does not bind the full cumulative accepted protocol-authority chain.
- `config_id` contains a different historical/configuration payload and is not the later accepted canonical structural candidate identity.
- slot/run/runtime/source/split identities describe placement or runtime authority, not the scientific candidate itself.

A bootstrap seed for the same accepted structural candidate and same accepted scientific partition/metric must not change merely because runtime materialization or run identity changes.


The only governing Discovery metric IDs are exactly:

```text

```

For the accepted RANDOM_MATCHED procedure, where that procedure invokes the same R2 seed convention:

```text
metric_id =
"RANDOM_MATCHED"
```

No lowercase, aliases, enum repr strings, or human-readable labels are permitted.

## 4. Exact seed derivation

Preserve R2 exactly:

```python
seed_preimage = canonical_json([
    protocol_id,
    candidate_id,
    partition_id,
    metric_id,
]).encode("utf-8")

digest = hashlib.sha256(seed_preimage).digest()
raw_u64 = int.from_bytes(digest[:8], byteorder="big", signed=False)
seed = raw_u64 % (2**63 - 1)

rng = np.random.Generator(np.random.PCG64(seed))
```

## 7. Mandatory implementation invariants

Production P3B tests must prove:

1. `protocol_id == compute_protocol_authority_hash()`.
2. `candidate_id == structural_configuration_hash`.
3. same candidate/partition/metric produces the same seed across different run-authority IDs.
4. changing only slot index cannot change the candidate seed if structural candidate identity is unchanged.
5. `protocol_hash` substitution changes the preimage and is rejected.
6. `config_id` substitution changes the preimage and is rejected.
7. runtime/source/split hashes cannot enter the preimage.
8. PRECISION and NET_EXPECTANCY use distinct seeds because metric_id differs.
9. another structural candidate uses a distinct seed.
10. seed metadata persists the exact policy ID/hash and four preimage values.
