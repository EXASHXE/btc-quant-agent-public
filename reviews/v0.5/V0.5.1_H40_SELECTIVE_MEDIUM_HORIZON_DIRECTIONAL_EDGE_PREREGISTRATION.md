## 1. Research question, action space, and non-claims

### 1.1 Question

> Does there exist a PIT-safe, preregistered conditional subset of BTCUSDT and/or
> ETHUSDT perpetual decision opportunities for which abstention-first directional
> decisions achieve stable out-of-sample directional precision and positive
> cost-adjusted expectancy, without forcing a prediction at every timestamp?

The only admissible actions are:

```text
LONG
SHORT
NO_TRADE
```

`NO_TRADE` is the default. H40 is not a continuous LONG/SHORT classifier. A row
that is unavailable, causally ambiguous, outside the locked scope, below any gate,
or unsupported by the selected evidence produces `NO_TRADE` with a reason code.

### 1.2 Fixed funnel

```text
Regime
  -> Opportunity
  -> Direction evidence
  -> Expected excursion / MAE-MFE / cost-adjusted geometry
  -> Confidence / calibration gate
  -> LONG / SHORT / NO_TRADE
```

Each arrow is an explicit contract boundary. Magnitude evidence, including TP/BR
style evidence, can open the opportunity gate but cannot supply direction unless a
separately enumerated directional family does so.

### 1.3 Non-claims

This preregistration makes no claim of alpha, profitability, execution readiness,
or deployability. It does not authorize model implementation, paper/testnet/live
trading, order placement, H39 unblinding, Final Holdout access, or CI execution.

| Dimension | Preregistered scope |
| --- | --- |
| Products | BTCUSDT linear perpetual; ETHUSDT linear perpetual |
| Decision cadence | One UTC-aligned decision opportunity per product per hour |
| Primary horizons | 4h, 8h, 12h |
| Diagnostic horizon | 24h only |
| Candidate asset scopes | `BTC_ONLY`, `ETH_ONLY`, or `POOLED_BTC_ETH` |
| Actions | LONG, SHORT, NO_TRADE |

Asset scope and exactly one primary economic horizon must be part of every full
configuration and locked candidate identity. A deterministic multi-horizon rule is
permitted only if it is one of the enumerated configurations before discovery; it
cannot select the best realized horizon. The 24h result cannot select, rescue, or
promote a candidate that fails all primary horizons.

For a pooled candidate, simultaneous BTC and ETH opportunities remain separate
decision rows and are clustered together by UTC outcome block for inference. No
price, feature, or outcome is forward-filled across assets.

## 3. Observable-time convention and labels

### 3.1 Decision boundary

For an hourly boundary `t`:

- the decision timestamp is `t`;
- all feature rows must have `available_at_ms <= t`;
- candle-derived features may use only candles whose `close_time_ms < t` and
  `closed == true`;
- the reference price `P0(t)` is the linear-perpetual 1h candle open at `t`;
- that opening value may be used only as an event observable at `t`, never in a
  feature claimed to exist before `t`;
- an order is submitted no earlier than `t`, and canonical replay applies its own
  latency, fill, fee, slippage, and funding rules.

If the reference bar is missing, duplicated, not closed when later used as a
historical record, has no trustworthy timestamp, or has a product mismatch, the
row is ineligible and cannot be imputed.

### 3.2 Deterministic statistical labels

For `h` in `{4, 8, 12, 24}` hours, let `Ch(t)` be the close of the last hourly bar
in `[t, t+h)`. Define:

```text
r_h(t) = log(Ch(t) / P0(t))
```

The frozen analytical round-trip friction proxy is:

```text
c_rt = 2 * taker_fee_rate + 2 * fixed_slippage_bps / 10_000
```

using the exact fee/slippage parameters from the candidate's versioned canonical
comparison contract. With the frozen kernel defaults this is `0.0012` (12 bps),
before funding. If the future comparison contract differs, the formula, inputs,
and identity must be locked before any candidate outcome and the default value may
not be silently retained.

The three-class statistical label is:

```text
LONG_LABEL     if r_h(t) >  +c_rt
SHORT_LABEL    if r_h(t) <  -c_rt
NEUTRAL_LABEL  otherwise
```

Exactly zero is `NEUTRAL_LABEL`. Statistical directional precision counts a LONG
decision correct only on `LONG_LABEL`, and a SHORT decision correct only on
`SHORT_LABEL`; neutral outcomes are not silently dropped from accepted-trade
precision. Raw-return-sign precision is a secondary diagnostic.

Missing any endpoint bar makes that `(t, product, h)` label unavailable. It is not
zero, neutral, or interpolated. All overlapping labels are retained but handled as
dependent observations under Section 9.

### 3.3 Excursion and geometry labels

For each horizon, using all complete hourly bars in `[t, t+h)`:

```text
MFE_LONG  = max(high / P0 - 1)
MAE_LONG  = max(1 - low / P0)
MFE_SHORT = max(1 - low / P0)
MAE_SHORT = max(high / P0 - 1)
```

Directional correctness is defined by Section 3.2, not by whether either intrabar
extreme was touched. Primary economic evaluation uses a fixed-horizon market exit
at the locked horizon. H40 V1 does not select a favorable exit after observing the
path and does not use MFE as realized PnL. If a later candidate proposes stops or
targets, that requires a new protocol version and conservative canonical ordering;
it is not in this search budget.

The geometry gate is fitted only on allowed training/calibration data. For the
proposed side it requires both:

```text
estimated median MFE >= 1.5 * c_rt
estimated median MFE / max(estimated median MAE, c_rt) >= 1.25
```

The estimates, grouping rule, fallback rule, and sample count are configuration
fields. Fewer than 30 training observations in the applicable estimation cell
causes `NO_TRADE`; cells may be pooled only by a preregistered hierarchy.

### 3.4 Economic target

The economic target is net round-trip return and USDT PnL reconstructed by the
frozen v0.5 canonical execution/accounting kernel. It includes the locked policy,
actual canonical fills, fees, slippage, settlement-timestamp funding, evidence
identities, and accounting verification. H40 must not implement a second PnL
calculator.

The `c_rt` proxy is allowed for fast screening only. It is explicitly diagnostic
until canonical replay. Future funding is never treated as known at decision time;
settled funding enters only canonical economic replay from authoritative evidence.

## 5. Separate semantic owners

Every full candidate configuration must persist the output and reason code of each
owner below. An opaque end-to-end score is prohibited.

### 5.1 Regime owner

Regime classifies state and cannot emit direction. Allowed families are:

1. `R_VOL_RANGE_V1`: trailing 24h realized volatility and true-range percentile,
   using only prior closed bars;
2. `R_TREND_RANGE_V1`: trailing efficiency/trend-strength state over an enumerated
   24h, 72h, or 168h window;
3. `R_LIQ_ACTIVITY_V1`: quote-volume/activity percentile where complete;
4. `R_CROSS_ASSET_V1`: synchronized BTC/ETH volatility and trend state;
5. `R_FUNDING_CROWDING_V1`: last-settled funding/crowding state where an admissible
   source exists.

Rolling percentiles are fitted on the current training partition only, lagged one
decision, and then frozen for the following calibration/validation interval.
Allowed percentile cutoffs are `{0.20, 0.40, 0.60, 0.80}`. A configuration uses at
most one primary regime family and one binary conjunction; absent data fails to
`NO_TRADE` rather than selecting another regime.

### 5.2 Opportunity owner

Opportunity means sufficient potential movement after costs, not known direction.
Allowed families are:

1. `O_RANGE_EXPANSION_V1`: lagged realized range/volatility state;
2. `O_COMPRESSION_RELEASE_V1`: a 24h or 72h compression state followed by a
   last-closed-bar expansion;
3. `O_BREAKOUT_DISTANCE_V1`: absolute distance from a prior 24h, 72h, or 168h
   range boundary;
4. `O_EXPECTED_EXCURSION_V1`: training-only conditional magnitude estimate;
5. `O_TPBR_MAGNITUDE_V1`: only an unprotected, independently versioned TP/BR-style
   magnitude flag, with its historical side discarded.

Output is `NONE`, `WATCH`, or `ELIGIBLE`, with numeric boundaries in the full
configuration. Only `ELIGIBLE` proceeds. TP/BR cannot supply side, confidence, or
labels.

### 5.3 Direction owner

The bounded hypothesis families are:

| ID | Hypothesis | Maximum variants | Allowed core lookbacks / states |
| --- | --- | ---: | --- |
| `D1_TREND_CONTINUATION` | Lagged own-asset return/trend continues | 2 | 4h, 8h, 12h, 24h |
| `D2_BREAKOUT_CONTINUATION` | A last-closed-bar range break continues | 2 | prior 24h, 72h, or 168h range |
| `D3_FAILED_MOVE_REVERSAL` | A completed break-and-close-back reverses | 2 | prior 24h or 72h range |
| `D4_BTC_ETH_CONFIRM_DIVERGE` | Synchronized cross-asset confirmation or lagged divergence contains direction | 2 | 4h, 8h, or 12h relative/confirming state |
| `D5_FUNDING_DIRECTION_INTERACTION` | Last-settled crowding interacts with an independently directional D1/D2/D3 signal | 2 | training quantiles 0.10 or 0.20; source must be admissible |

Funding by itself is not directional. D5 must name its base directional family and
whether the frozen hypothesis is continuation or crowding reversal. If the source
gate fails, D5 is `NOT_TESTABLE`, not replaced.

### 5.4 Geometry owner

The geometry owner applies the fixed rules in Section 3.3. It estimates magnitude
and adverse excursion separately from direction and emits `PASS`, `FAIL`, or
`INSUFFICIENT_CELL_N`. It cannot choose an exit from realized future paths.

### 5.5 Confidence/calibration owner

The owner receives direction evidence only after the earlier gates. Each full
configuration chooses exactly one of:

- logistic/Platt calibration; or
- isotonic calibration, allowed only with at least 200 calibration observations
  and at least 40 in each predicted side.

Calibration is fitted only on the dedicated calibration interval. Allowed action
thresholds are exactly `q in {0.55, 0.60, 0.65}`:

```text
LONG  if p_up >= q and every prior gate passes
SHORT if p_up <= 1 - q and every prior gate passes
NO_TRADE otherwise
```

A monotonic non-probabilistic score may be used only if its fixed action cutoff is
an enumerated configuration and it is not described as probability. No threshold
may be adjusted to manufacture a target abstention rate.

Probabilistic candidates additionally require adaptive-bin expected calibration
error `<= 0.05` (minimum 20 observations per bin) and positive Brier skill versus
the calibration base-rate predictor before candidate lock. Undefined calibration
is a failure, not a pass.

## 6. Finite search budget

The unit counted is a complete end-to-end configuration: asset scope, primary
horizon, regime rule, opportunity rule, direction variant, geometry estimator,
calibration method, confidence threshold, and every numeric hyperparameter.

1. At most five direction families are allowed.
2. At most two variants per family are allowed.
3. At most 12 complete configurations per single-family variant are allowed:
   `5 * 2 * 12 = 120`.
4. Direction-family combinations have maximum depth two and are limited to these
   four pairs: `D1+D4`, `D1+D5`, `D2+D4`, and `D3+D5`.
5. Each allowed pair has at most 12 complete configurations: `4 * 12 = 48`.
6. The total H40 V1 search budget is therefore at most **168 complete
   configurations** across all assets and primary horizons, not 168 per asset,
   fold, or horizon.
7. Asset scope and horizon alternatives consume slots. Diagnostic 24h calculations
   consume no selection slot because they cannot select or rescue a candidate.
8. The configuration ledger, including rejected and failed rows, is append-only and
   content-hashed before the first label metric is computed.
9. Dropping a family or configuration does not replenish the budget. A failed
   family cannot be replaced. Any new feature family, pairing, grid point, or deeper
   combination requires `H40_PROTOCOL_V2` and cannot reuse V1 confirmation.
10. Only one primary locked candidate may enter the H40 confirmation holdout.

No unrestricted feature mining, automated feature generation, Bayesian search,
random hyperparameter search, or outcome-driven grid expansion is allowed.

## 7. Baselines and nulls

The following comparisons are mandatory when applicable:

1. `CASH / NO_TRADE`: zero activity and constant equity;
2. passive same-product perpetual exposure under matching frozen cost/funding
   semantics, descriptive rather than a mandatory directional hurdle;
3. `RANDOM_MATCHED` under the frozen kernel, matched on eligible opportunity set,
   trade count, side count, horizon/holding time, product scope, and deterministic
   preregistered seeds;
4. a 50/50 conditional-direction null;
5. an empirical training-only base-rate null evaluated at the candidate's locked
   LONG/SHORT mix;
6. simple frozen canonical momentum/return-sign rules where contract-compatible.

The operative directional null is:

```text
p0 = max(0.50, precision of the empirical base-rate null at the locked side mix)
```

No benchmark may use confirmation outcomes to set its distribution or matching
rules. H40 is not considered supported merely because it beats an intentionally
weak benchmark.

## 8. Chronological split and sealing

### 8.1 Base eligible timestamp set

The common base set is the sorted intersection of trustworthy BTC and ETH hourly
reference timestamps. A uniform maximum feature lookback of 720 hours and the 24h
diagnostic endpoint are reserved. Under the currently documented coverage, base
decision timestamps begin at `2021-01-31T00:00:00Z`; the last possible timestamp is
the latest `t` whose complete `[t,t+24h)` bars end before
`2026-02-01T00:00:00Z`.

Before outcomes, the next authorized task must write an immutable split manifest
containing exact timestamp arrays/counts after gaps, hashes, and exclusion reason
counts. A discrepancy from documented coverage is recorded and removed; boundaries
are not moved to improve results.

### 8.2 Walk-forward schedule

The design is expanding-window, with a dedicated roughly three-month calibration
window and a 24h purge between train/calibration and calibration/evaluation.

| Fold | Training interval (half-open) | Purge | Calibration interval (half-open) | Purge | Validation interval (half-open) |
| --- | --- | --- | --- | --- | --- |
| WF1 | 2021-01-31 to 2022-10-31 | 2022-10-31 to 2022-11-01 | 2022-11-01 to 2023-01-31 | 2023-01-31 to 2023-02-01 | 2023-02-01 to 2023-07-31 |
| WF2 | 2021-01-31 to 2023-04-30 | 2023-04-30 to 2023-05-01 | 2023-05-01 to 2023-07-31 | 2023-07-31 to 2023-08-01 | 2023-08-01 to 2024-01-31 |
| WF3 | 2021-01-31 to 2023-10-31 | 2023-10-31 to 2023-11-01 | 2023-11-01 to 2024-01-31 | 2024-01-31 to 2024-02-01 | 2024-02-01 to 2024-07-31 |
| WF4 | 2021-01-31 to 2024-04-30 | 2024-04-30 to 2024-05-01 | 2024-05-01 to 2024-07-31 | 2024-07-31 to 2024-08-01 | 2024-08-01 to 2025-01-31 |

The final day before each next evaluation interval is excluded so no 24h label can
cross the boundary. Shorter primary horizons use the same conservative 24h purge.
Cross-asset rows use the same UTC fold; an asset-specific missing row does not shift
the other asset's boundary.

Feature/model parameters may be re-estimated on each fold's training data and the
calibrator refitted on its calibration interval only if that refit algorithm was
locked before WF1. Hyperparameters, thresholds, feature semantics, scope, and
horizon do not change between folds.

### 8.3 H40 confirmation holdout

The H40 confirmation partition is:

```text
all base-eligible decision timestamps t such that
2025-02-01T00:00:00Z <= t
and the complete 24h endpoint is earlier than 2026-02-01T00:00:00Z
```

The intervening `2025-01-31` UTC day is purged. Before any H40 label or candidate
metric is computed, the exact confirmation timestamp list and source hashes must be
sealed in the split manifest. H40 processes must deny candidate-level reads of its
future price columns until `H40_CONFIRMATION_READY` is committed.

After walk-forward validation, the locked fitting algorithm may perform one final
mechanical refit using only pre-confirmation data; this does not permit changing
semantics or hyperparameters. Confirmation is evaluated exactly once. Its outcomes
cannot tune, recalibrate, repair, rank, or spawn a successor. Any successor protocol
requires a newly accumulated confirmation interval.

If the exact artifacts cannot support these boundaries, the affected scope is
`NOT_TESTABLE`; it is not assigned a later favorable interval.

## 9. Dependence and multiple testing

### 9.1 Overlap-aware uncertainty

Hourly 4h/8h/12h/24h outcomes are never treated as IID. The primary uncertainty
method is a UTC-aligned moving-block bootstrap with seven-day (168-hour) blocks,
10,000 resamples, and seed derived as SHA-256 of
`protocol_id || candidate_id || partition_id || metric_id`. Resampling keeps BTC
and ETH rows in the same block.

Newey-West/HAC estimates with maximum lag 24 hours are a required secondary check.
For trade-count gates:

```text
n_eff = min(
  accepted trade count,
  number of distinct occupied UTC 24h outcome blocks,
  HAC effective sample size clipped to [1, accepted trade count]
)
```

The formula and autocorrelation truncation at lag 24 are frozen. Undefined or
non-positive effective size fails closed.

### 9.2 Family-wise selection control

- Within each direction family, configurations are compared by a block-resampled
  max-statistic; Holm-adjusted one-sided p-values are also persisted.
- The best surviving representative of each of the five families is then subject
  to Holm control at family-wise alpha `0.05`.
- Combination configurations form a sixth family for correction; the four allowed
  pairs are corrected together.
- The candidate-selection score is lexicographic: pass every hard gate, then highest
  adjusted lower confidence bound on net expectancy, then highest adjusted lower
  confidence bound on precision, then lower complexity, then lexicographic ID.
- Fold aggregation is pooled by timestamp block plus a table of all four folds. The
  best fold is never selected or separately advertised as proof.
- Confirmation has two co-primary tests, precision and net expectancy. Each must
  pass a one-sided alpha `0.025`; no optional stopping or repeated look is allowed.

## 10. Metrics

### 10.1 Primary selection metrics

Every candidate/fold and the pooled result must report:

- coverage: accepted LONG or SHORT decisions divided by all base-eligible decisions;
- accepted trade count and `n_eff`;
- conditional directional precision;
- LONG precision and SHORT precision separately;
- cost-adjusted net expectancy per trade in return units and USDT;
- gross and net profit factor when both gains and losses exist;
- MFE and MAE median, quartiles, 90th and 95th percentiles by side;
- canonical maximum drawdown and worst 20-consecutive-trade net sequence;
- calibration ECE, Brier score, and Brier skill for probabilistic candidates;
- all four walk-forward fold values and regime/product contributions.

Overall classification accuracy is forbidden as a selection metric.

### 10.2 Secondary diagnostics

Secondary diagnostics are raw forward-return distributions, opportunity hit rate,
regime-conditional results, asset/horizon contribution, turnover, exposure time,
abstention reason counts, passive comparison, and the 24h diagnostic. They cannot
override any failed primary gate.

## 11. Low-frequency objective and sample floors

The operational objective is approximately **2-5 accepted opportunities per week
across the intended active scope**. It is evaluated after thresholds are locked;
thresholds may not be moved to land in that band.

Scientific/economic qualification and operational suitability are separate:

- scientific coverage must be at least `0.25%` of base-eligible rows and at most
  `10%`; this only excludes near-zero and non-selective systems;
- candidate lock requires at least 120 training `n_eff`, 40 calibration accepted
  trades, calibration `n_eff >= 32`, and at least 15 calibration trades per emitted
  side;
- pooled walk-forward validation requires at least 160 raw trades, `n_eff >= 120`,
  and side-specific `n_eff >= 40`;
- confirmation requires at least 100 raw trades, `n_eff >= 80`, and side-specific
  `n_eff >= 25`;
- a candidate outside 2-5/week is marked `OPERATIONALLY_UNSUITABLE` even if it has a
  scientific result. It is not retuned;
- a candidate below a sample floor is `NOT_TESTABLE`, never a high-precision pass on
  a handful of observations.

The floors are chosen so a roughly one-year confirmation at the operating objective
can contain about 104-260 raw opportunities while retaining a conservative minimum
after temporal clustering.

| Ready -> `H40-CONFIRMATION_EVALUATED_ONCE` | H40 confirmation, exactly once | Complete immutable result, whether pass or fail | Never | Confirmation result hash, consumed nonce, access/audit log |
| Evaluated -> `ECONOMIC_REPLAY_CANDIDATE` | Same locked confirmation decisions | All confirmation statistical gates; this transition authorizes exactly one canonical economic replay | No | Confirmation result and exact replay-input commitment; canonical artifacts are appended by the replay |

After `H40-CANDIDATE_LOCKED`, any change to scope, feature formula, availability
rule, gate order, threshold, horizon, label, confidence/calibration, policy, cost
assumption, or abstention behavior creates a new candidate identity. It cannot use
the consumed H40 V1 confirmation.

`ECONOMIC_REPLAY_CANDIDATE` is not a GO marker. Final H40 support requires the
canonical replay and benchmark requirements in Section 13.2; its canonical run,
benchmark suite, qualification evidence, and attestation are then immutable
artifacts whether the result passes or fails.

## 13. Numeric GO / NO-GO gates

These thresholds were chosen from null behavior, the frozen default 12 bps
round-trip proxy, dependence-aware sample requirements, and a conservative risk
budget, without reading H40 candidate outcomes.

### 13.1 Walk-forward gate

To become `H40-WALK_FORWARD_VALIDATED`, all must hold:

1. Section 11 coverage and sample floors pass.
2. At least three of four folds have positive proxy-net expectancy, and no fold has
   proxy-net expectancy below `-0.0012` (-12 bps) per accepted trade.
3. Pooled conditional precision is at least `p0 + 0.05` and at least `0.58`.
4. LONG and SHORT precision are each at least `0.54` with the side sample floors.
5. The 95% moving-block lower bound for precision is greater than `p0` after the
   Section 9 selection correction.
6. Proxy-net expectancy is at least `+0.0005` (+5 bps) per accepted trade and its
   corrected 95% moving-block lower bound is greater than zero.
7. Net profit factor is at least `1.20`, and its 90% moving-block lower bound is
   greater than `1.00`.
8. Probabilistic calibration meets Section 5.5 in pooled validation; calibration
   cannot be rescued by dropping a fold.
9. A `POOLED_BTC_ETH` candidate has nonnegative net expectancy in each asset, each
   asset has `n_eff >= 30`, and neither asset supplies more than 80% of accepted
   trades. A locked single-asset candidate is exempt, because narrow scope is part
   of its identity.
10. All four fold rows, including failures, remain published in the immutable
    result. The 24h diagnostic is ignored by the gate.

### 13.2 Confirmation and final economic gate

To obtain final H40 GO after its one permitted confirmation evaluation and the
authorized canonical replay, all must hold:

1. Section 11 confirmation coverage and sample floors pass.
2. Conditional precision is at least `p0 + 0.05` and at least `0.58`; LONG and SHORT
   precision are each at least `0.54`.
3. The one-sided 97.5% moving-block lower bound for precision is greater than `p0`.
4. Proxy-net expectancy is at least `+0.0005` per accepted trade and its one-sided
   97.5% moving-block lower bound is greater than zero.
5. Profit factor is at least `1.20` and its 90% block lower bound is greater than
   `1.00`.
6. Under the locked canonical policy, maximum drawdown is no more than `10%` of
   initial equity, the worst 20-consecutive-trade sequence loses no more than `5%`
   of initial equity, and the canonical drawdown halt is never reached.
7. For pooled scope, each asset has nonnegative canonical net expectancy and
   `n_eff >= 25`; neither asset supplies more than 80% of trades. A single-asset
   identity is assessed only on its preregistered asset.
8. The candidate remains positive under frozen canonical fees, adverse slippage,
   authoritative funding settlements, and fixed-horizon exits; accounting and
   evidence verification pass cold replay.
9. Canonical net PnL exceeds CASH and the 95th percentile of `RANDOM_MATCHED`.
   Passive exposure is reported but is not a mandatory hurdle.
10. There is no post-confirmation retuning, exclusion, horizon switch, side removal,
    or asset narrowing.

Failure of any item is `H40_NO_GO`. Missing authoritative funding, insufficient
coverage, undefined uncertainty, or inadequate sample size is `NOT_TESTABLE`, not a
relaxed pass. The confirmation decision is never made from 24h diagnostics.

## 14. Reproducibility contract

Every enumerated configuration and locked candidate must persist, in canonical
content-addressed form:

- protocol/preregistration ID and document hash;
- frozen kernel SHA and implementation code SHA;
- raw, normalized, feature, funding, and evidence identities and SHA-256 hashes;
- retrieval time, exchange timestamp semantics, gaps, field coverage, and source
  role;
- exact base-eligible timestamps, split boundaries, purges, exclusions, and split
  manifest hash;
- full 168-slot configuration ledger, family/variant/config IDs, and unused/failed
  slot reasons;
- regime, opportunity, direction, geometry, confidence, label, policy, cost,
  funding, and producer-contract identities;
- exact hyperparameters, estimator type, fitting hierarchy, primary horizon, asset
  scope, and action thresholds;
- training/calibration/validation lineage and all mechanical-refit boundaries;
- deterministic seeds and derivation rules;
- row-level action, confidence, stage outputs, and reason-coded abstention without
  protected data leakage;
- coverage, side counts, fold metrics, block-bootstrap samples or sufficient
  reconstructable statistics, HAC output, adjusted p-values, and effective counts;
- immutable candidate-lock record and timestamp;
- confirmation readiness attestation, one-shot nonce, access log, and consumed
  result identity;
- canonical replay input bundle, ledger, accounting summary, funding evidence,
  benchmark suite, qualification gates, and attestation when reached.

The artifact graph must prove that candidate identity and all decision semantics
existed before its confirmation result was observable. Outer self-hashes without
independently authoritative source identities are insufficient.
