## 2. Why Option B is accepted

Option A would require interpreting the existing legacy BTC/ETH pair split attestation as something it does not represent.

That would violate the already accepted rule:

```text
hash integrity != evidence truth
```

The existing production split authority requires both BTC and ETH canonical production verification. Because BTC is intentionally NOT_TESTABLE, it cannot truthfully attest the current 18-row ETH-only REGISTERED universe.

The F01R2 amendment instead introduces a distinct authority object:

```text
H40_RUNTIME_SOURCE_SPLIT_ATTESTATION_V1
```

This object binds:

- the accepted reference source identity;
- the accepted reference split/calendar identity;
- the accepted RuntimeAuthoritySnapshot;
- the complete 168-slot structural ledger;
- the exact sealed REGISTERED roster;
- the exact 18/150 counts;
- the roster-derived active required source union;
- cold evidence for every and only active required source;
- the unavailable/NOT_TESTABLE source set;
- the runtime-scoped split reconstructed from active verified sources.

This is a truthful authority model for partial source availability.

## 8. Separation of identity from production availability

The amendment correctly distinguishes:

```text
canonical source identity
!=
production VERIFIED state
```

An unavailable source must still be checked as the same preregistered source identity, but that check must not promote its production authority.

This separation is required to prevent:

```text
local file exists
-> accidental VERIFIED promotion
```

The implementation must therefore add an identity-only canonical source verifier rather than weaken or reinterpret the existing production VERIFIED assertion.

- horizon truncation rules.

The runtime-scoped split may recompute availability-dependent:

- counts;

- first/last timestamps;
- timestamp membership hashes;

from the intersection of exactly the active verified source set.

For the current 18-row runtime universe that active set is ETH-only.

The legacy BTC/ETH pair attestation is not valid authority for this run.
