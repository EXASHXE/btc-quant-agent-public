## 1. RG-B02-01 is accepted

Exact current implementation:

```text
src/btc_quant_agent/h40/lifecycle_authority.py
H40LifecycleArtifactStore._get_committed_lineage()
H40LifecycleArtifactStore.restore_authorization()
```

Current lineage construction:

```text
durable head receipt hash
-> find receipt file
-> parse JSON
-> read receipt.upstream_receipt_hash
-> repeat
```

The traversal records each advertised hash as committed lineage membership before proving that the loaded receipt bytes are canonically bound to that content hash and accepted predecessor relationship.

The current implementation therefore separates:

```text
membership derivation
```

from:

```text
cryptographic/semantic verification of the chain establishing that membership
```

in an unsafe order.

A corrupted committed descendant can advertise a valid orphan receipt hash as its predecessor. The target orphan can then satisfy the subsequent target-membership test, while cold restoration verifies only the requested orphan and its own ancestors rather than the corrupted descendant that falsely admitted it.

This violates the accepted persistence/replay V2 rule:

```text
only current committed head / unique verified ancestor lineage has authority
orphans confer no authority
malformed or hash-mismatched lineage fails closed
```

The defect does NOT mean SQLite single-head CAS is broken.

The correct scope is:

```text
committed-lineage membership verification
```

not redesign of durable-head semantics.

### Required correction

Before any hash is treated as a member of committed lineage, verify the full chain from the trusted durable head backward.

At each hop require at minimum:

```text
file/content address == expected current receipt hash
envelope receipt_sha256 == expected current receipt hash
canonical recomputed typed receipt hash == expected current receipt hash
run_authority_id consistency
receipt source/target schema consistency
upstream/predecessor relationship consistency
accepted transition adjacency
head receipt state == durable head state
head predecessor == durable head predecessor
no cycles
unique predecessor chain
```

Only after successful full-chain verification may `restore_authorization()` accept a target as a committed member.

Do not introduce a new public authority surface.

Do not weaken cold source-truth revalidation.

## 2. RG-H01-01 is accepted

Exact current implementation:

```text
H40LifecycleArtifactStore.persist_authorization()
```

Current behavior:

```text
if final receipt does not exist:
    write temp
    fsync file
    hard-link final
    fsync receipt directory fail-closed

if final receipt already exists with identical bytes:
    verify bytes
    skip authoritative receipt-directory fsync

then:
    commit SQLite durable head
```

The existing-file branch assumes that presence of identical bytes proves prior durable publication.

That assumption is invalid for the accepted protocol because the existing file may have come from:

```text
a prior publication whose required directory fsync failed
or
a concurrent publisher that linked the file but has not completed required directory fsync
```

Therefore a retry or concurrent identical publisher may advance the authoritative SQLite head before the required receipt-directory durability boundary is satisfied.

This violates the accepted ordering:

```text
complete receipt bytes
-> immutable final publication
-> authoritative receipt-directory durability
-> durable SQLite head commit
```

### Required correction

Every path that may advance the durable head for a receipt must first establish authoritative receipt-directory durability.

For an existing identical receipt:

```text
verify exact bytes
then perform fail-closed _fsync_dir(receipts_dir, fail_closed=True)
then and only then allow head commit
```

The implementation may use an equivalent stronger mechanism, but:

- existing bytes are not sufficient proof of prior durable publication;
- retries after fsync failure must remain fail-closed while fsync continues failing;
- concurrent identical publishers must not allow head commit before at least the current committing path successfully completes the required directory durability step;
- content-addressed immutable no-overwrite semantics remain unchanged;
- SQLite durable run head remains the sole lifecycle commit point.

No canonical semantic amendment is required because this is implementation conformance to already accepted persistence V2.
