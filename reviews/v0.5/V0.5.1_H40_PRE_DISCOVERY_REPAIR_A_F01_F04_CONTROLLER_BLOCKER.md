## Blocker B01 — synthetic controller registry is reachable from production construction

File:

```text
src/btc_quant_agent/h40/lifecycle_authority.py
```

The implementation defines process-global synthetic registries:

```text
_SYNTHETIC_CONTROLLER_REGISTRY
_SYNTHETIC_GRANT_REGISTRY
```

`H40LifecycleAuthorityService.synthetic_for_tests()` inserts synthetic controller authority into
`_SYNTHETIC_CONTROLLER_REGISTRY`.

However, `H40LifecycleAuthorityService.production()` contains a production-side fallback that,
when no controller object is supplied and the accepted controller hash is present in that
synthetic registry, reads the synthetic registry and injects that controller into the production
service.

That creates a direct reachability edge:

```text
synthetic_for_tests()
  -> _SYNTHETIC_CONTROLLER_REGISTRY
  -> production()
  -> production service controller authority
```

This conflicts with the accepted Repair A requirement that synthetic/test authority remain a
strictly separate authority domain and must not be promotable into production via test-only
state, registry state, labels, hashes, serialization, or restore paths.

The fact that the currently committed production accepted hash is `None` prevents immediate real
Discovery, but it does not close the implementation defect. Repair A is defining the authority
boundary that will later be activated by republication, so the dormant cross-domain path must be
removed before acceptance.

### Required minimal repair

`H40LifecycleAuthorityService.production()` must never consult:

```text
_SYNTHETIC_CONTROLLER_REGISTRY
_SYNTHETIC_GRANT_REGISTRY
```

Production construction may continue to allow `controller_authority=None`, as frozen by the
contract, but later production Discovery must fail closed until an explicit/current production
controller authority is supplied and validated against the accepted production hash.

Synthetic registries may be retained only inside explicitly synthetic/test-only paths whose
`synthetic_only` domain cannot be consumed by production services.

No lifecycle child object, root hash, governance hash, scientific identity, or Repair B semantic
change is required for this repair.

## Blocker B02 — mandatory adversarial test is absent

The Repair A execution prompt explicitly required an adversarial test proving:

```text
synthetic authority cannot cross into production
```

The new Repair A test module contains 48 numbered tests, but no test exercises the concrete
cross-domain scenario above.

A required regression must:

1. create/register a synthetic controller via the synthetic path;
2. configure test-local accepted hashes to the same content addresses;
3. construct a production service **without** passing the controller explicitly;
4. prove production construction does not read the synthetic registry;
5. prove production Discovery still fails without explicit/current production controller
   authority;
6. prove the synthetic service still functions only within the synthetic domain.

This must be tested without changing committed production constants away from `None`.
