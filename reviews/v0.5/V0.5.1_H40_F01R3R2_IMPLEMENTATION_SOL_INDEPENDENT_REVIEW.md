## 1. Repairs accepted

### 1.1 Typed service revalidation is now internal to persistence

`persist_authorization()` now requires:

```python
service: H40LifecycleAuthorityService
```

and internally calls:

```python
service.revalidate_authorization(authorization)
```

The arbitrary caller-supplied revalidation callable was removed.

A foreign issuing service fails issuer validation.

This closes the R1 persistence callback bypass.

### 1.2 Durable transition adjacency is now checked

The durable commit path now binds receipt type to source/target semantics and checks:

```text
authorization.source_state
authorization.target_state
current committed head state
current committed head receipt hash
accepted transition set
```

The accepted transition set matches the relevant executable rows of the frozen transition matrix and explicitly excludes F02.

### 1.3 Genesis is now restricted

Sequence zero requires:

```text
H40_P1_SCAFFOLDED -> H40_DISCOVERY
null predecessor
```

Candidate Lock, WF, Confirmation Ready and termination cannot become arbitrary genesis transitions.

### 1.4 Empty legacy head_hash now fails closed

Authoritative reads reject an empty head-hash storage integrity column.

This closes the permissive legacy migration hole.

## 2. F01R3R2-SOL-01 — BLOCKER — public head-commit API still bypasses accepted persistence authority

The accepted persistence model is:

```text
VerifiedLifecycleAuthorization
-> exact issuing H40LifecycleAuthorityService
-> service.revalidate_authorization()
-> immutable receipt publication
-> internal durable-head commit
```

The implementation still exposes:

```python
H40LifecycleArtifactStore.advance_run_head(...)
```

as a public method.

It supports two bypass forms.

### 2.1 Public TEST_COMMIT_TOKEN bypass

The implementation defines:

```python
_TEST_COMMIT_TOKEN = object()
TEST_COMMIT_TOKEN = _TEST_COMMIT_TOKEN
```

and exports `TEST_COMMIT_TOKEN` through:

```text
src/btc_quant_agent/h40/__init__.py
lifecycle_authority.__all__
```

Therefore production callers can explicitly import the token and call:

```python
store.advance_run_head(..., _test_token=TEST_COMMIT_TOKEN)
```

without a `VerifiedLifecycleAuthorization`.

This is not test-only isolation. It is a public capability.

The R30-R45 tests themselves import the exported token.

### 2.2 Public stale-authorization bypass

Even without the token, the public method accepts:

```python
authorization: VerifiedLifecycleAuthorization | None
```

A caller holding a previously valid but now stale cached authorization may call `advance_run_head(..., authorization=stale_authorization)` directly.

That path verifies object/receipt identity but does not call:

```python
service.revalidate_authorization(...)
```

Therefore it can bypass the accepted Model-A requirement that every production transition consumption reverify current root source truth.

If an exact receipt envelope already exists as an orphan or is otherwise present, the public method can commit it without the typed issuing-service revalidation required by V2.

This violates:

```text
only_the_accepted_implementation_verifier_may_atomically_construct_and_persist_authorization_after_recomputation
```

and:

```text
every_production_transition_issue_revalidation_and_consumption_must_recursively_reverify_root runtime/source truth
```

## 3. Required closure

There must be one public production persistence authority surface only:

```python
persist_authorization(
    transition_key,
    authorization,
    *,
    service,
)
```

The durable-head commit primitive must be private/internal and callable only from that already-revalidated persistence flow.

Required changes:

1. remove public/exported `TEST_COMMIT_TOKEN`;
2. remove it from `btc_quant_agent.h40.__init__` and `__all__`;
3. remove or privatize public `advance_run_head()`;
4. remove the optional-authorization/raw-string production API;
5. keep a private internal commit method that requires a non-null verified authorization;
6. call that private method only after `service.revalidate_authorization()` and immutable receipt publication;
7. update concurrency/head-integrity tests to use real synthetic `VerifiedLifecycleAuthorization` objects through `persist_authorization()`;
8. for storage-corruption tests that need direct DB setup, mutate SQLite directly rather than exposing production commit authority;
9. no public test token may grant commit capability.

A module-private low-level test helper is still undesirable if it can become a de facto production API. Prefer testing the real persistence path.
