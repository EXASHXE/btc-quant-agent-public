## 1. Close R3R3-SOL-10: Direction Owner Remains Authoritative After Calibration

The direction owner's proposed side is the sole source of side; the calibrator is a **confidence gate only** and may never flip the proposed side.

```text
proposed_side = sign(raw_score)
```

Exact action rule:

```text
if proposed_side == +1:
    LONG only if p_up >= q
    else NO_TRADE

if proposed_side == -1:
    SHORT only if p_up <= 1 - q
    else NO_TRADE

if proposed_side == 0:
    NO_TRADE
```

Explicit consequences (binding):

- `raw_score < 0` can **never** emit LONG even if `p_up >= q` (an unrestricted intercept/base-rate shift cannot create a LONG from a bearish direction score).
- `raw_score > 0` can **never** emit SHORT even if `p_up <= 1 - q`.
- Platt `a >= 0` remains binding (R3R3).
- Isotonic remains monotone nondecreasing (R3R3).
- D4/D5 secondary confirm/veto filters continue to suppress only; they never change side.
- No new threshold or slot is created.

This clause **supersedes** any earlier wording that could be read as permitting calibration to emit the opposite side.

## 2. Close R3R3-SOL-11: Exact Isotonic Prediction Map

Preserve the R3R2 PAVA fit and tie pooling. The evaluation map is frozen exactly as a **clipped left-step function**.

Let the fitted isotonic calibration have sorted distinct calibration score support:

```text
x_1 < x_2 < ... < x_m
```

with monotone fitted block values:

```text
p_1 <= p_2 <= ... <= p_m
```

For any query raw score `x`:

```text
if x <= x_1:
    p_up = p_1
elif x >= x_m:
    p_up = p_m
else:
    i = max{k : x_k <= x}
    p_up = p_i
```

- Prediction is a **clipped left-step function**: no interpolation, no extrapolation slope, no nearest-neighbor choice, no library-default behavior, no out-of-range failure.
- Tie handling remains: identical calibration raw scores are one pooled support value before PAVA prediction.
- Degenerate cases: no support / one-class target / otherwise invalid fit → fail closed.
- An isotonic map may be constant, but the direction-owner rule (Section 1) prevents it from reversing side.

## 3. Close R3R3-SOL-12: Exact Adaptive-Bin ECE

One deterministic equal-frequency adaptive-bin ECE algorithm.

Population is exactly the already-frozen binary `probability_diagnostic_population` (R3R3 Section 6).

For `N` rows:

```text
if N < 20:
    ECE undefined -> calibration gate fails closed

B = min(10, floor(N / 20))
```

Sort rows ascending by the deterministic tuple:

```text
(p_up, decision_t, product)
```

where product canonical order is `BTCUSDT < ETHUSDT`, and `(decision_t, product)` is unique within a candidate evaluation population.

Create `B` contiguous equal-frequency bins using exact integer boundaries:

```text
start_b = floor(b * N / B)
end_b   = floor((b + 1) * N / B)
for b = 0..B-1
```

so every row is assigned exactly once and bin sizes differ by at most one. Since `B <= floor(N/20)`, every bin has at least 20 observations.

**Tie policy:** equal `p_up` values may be split across adjacent bins only according to the deterministic `(decision_t, product)` secondary key. No implementation-selected tie merge is allowed.

For each bin:

```text
conf_b = mean(p_up)
acc_b  = mean(y)
```

and:

```text
ECE = sum_b (n_b / N) * abs(acc_b - conf_b)
```

Hard gate remains exactly:

```text
ECE <= 0.05
```

No alternate bin count, fixed-width bins, quantile-library call, tie-group merge, or optimized binning is allowed. No calibration threshold may be tuned from ECE.

## 7. Close R3R3-SOL-16: Exact Mandatory RANDOM_MATCHED Baseline

### 7.1 Evaluation universe

For the locked candidate on an authorized evaluation partition, define the per-product randomization universe:

```text
U_product = rows for that product that pass:
  source/runtime authority
  PIT/availability
  regime gate
  opportunity gate
```

Direction feature, secondary direction filter, calibration threshold, realized return, and label are **not** conditions for entering the randomization universe. No interpolation or synthetic row creation.

### 7.2 Exact matching target

From the locked candidate's actual accepted decisions on that partition record, for each product:

```text
N_product_LONG
N_product_SHORT
N_product = N_product_LONG + N_product_SHORT
```

Every random replicate must match these counts exactly. Candidate horizon/holding time and scope are already fixed by identity and remain identical.

### 7.3 Sampling algorithm

For each product independently within each replicate:

1. If `|U_product| < N_product`, the benchmark is `NOT_TESTABLE` and the final GO gate cannot pass.
2. Sample exactly `N_product` distinct rows uniformly **without replacement** from `U_product`.
3. Generate a random permutation of the sampled rows using the frozen RNG.
4. Assign LONG to the first `N_product_LONG` rows and SHORT to the remaining `N_product_SHORT` rows.

This exactly matches product count and side count while randomizing timing and side placement without outcome information.

For pooled scope, BTC and ETH are sampled as separate product strata, preserving exact candidate product counts. The resulting joint random decision set is evaluated as one replicate.

### 7.4 Replicates and seed

Exactly:

```text
M = 10000
```

Use:

```text
seed_preimage = canonical_json([
    protocol_id,
    candidate_id,
    partition_id,
    "RANDOM_MATCHED",
])
```

SHA-256 first 8 bytes big-endian unsigned, modulo `(2**63 - 1)`, then NumPy `PCG64`, preserving the existing R2 seed convention. Use one generator sequentially across replicates/products in canonical order:

```text
replicate 0..9999
  BTCUSDT first if present
  ETHUSDT second if present
```

No replicate-specific new seed selection.

### 7.5 Economic evaluation and 95th percentile

Each sampled random decision uses:

- the same locked product;
- same primary horizon / fixed-horizon exit;
- same canonical policy/cost/funding/accounting semantics as the candidate;
- no favorable exit/path selection.

Let each replicate produce canonical net PnL. Sort the 10,000 replicate net PnLs ascending. The benchmark upper 95th percentile is:

```text
sorted_net_pnl[9499]
```

using the already-frozen nearest-rank convention.

Final BASE requirement remains:

```text
candidate canonical net PnL > RANDOM_MATCHED upper-95th percentile
```

Strict `>` equality fails the hurdle.

No outcome-aware matching, resampling until favorable composition, alternative random benchmark, or seed retry is authorized.
