## Production path

`H40ProductionDiscoveryEvidenceProducer.produce()` requires exact typed accepted implementation/controller authority, V3 receipt, run, production seal and split, plus canonical repo/evidence roots. It compares every receipt/run lineage field, reconstructs the grant identity, verifies the complete roster metadata against the frozen ledger, binds the attestation roster hash, and cold verifies the production seal at entry and before final publication. Invalid receipt binding and unsafe source locators fail before cold source reads. Synthetic authority and V2 receipts are rejected.

The producer reads the attested ETH source bytes and reuses the verifier’s economic adapter and causal scientific functions. Base membership is derived from the source/split universe. The source support stays `[2021-01-01, 2023-02-01)`, and reserve hours before January 31 cannot enter base membership. All 18 ETH D1–D3 slots are represented, including fit-invalid markers. Training has null probability/action/net fields. Calibration uses the frozen fit, geometry, side-preserving action, and proxy-return helpers. The producer supplies no ranking, winner, Candidate Lock, WF verifier, or CLI.

Each candidate has complete training/calibration rows, six hard-gate inputs with coverage audit, two metric inputs (accepted seed/start sampler and current NumPy binding, or an exact fit-invalid marker), and a result-input object. The correction manifest binds all 18 entries and the same fixed six family universes for both metrics. The final typed Discovery evidence is written only after its dependencies, using an unconditional write that also works under `python -O`.

## Canonical store and runtime integrity

Canonical JSON is encoded once; its SHA-256 is `canonical_sha256(exact object)`. Objects are written to `<approved_root>/<digest[:2]>/<digest>.json`. The real approved directory is protected against normal reassignment/deletion and bound by device/inode. Every directory component is opened without following symlinks. Temp bytes are fsynced, published with atomic no-replace rename, and directory metadata is fsynced. Existing exact canonical bytes are idempotent; conflicts, noncanonical/duplicate-key bytes, symlinks, escapes and protected/Confirmation roots fail closed.

Root/shard namespace identities are checked around publication. A concurrent shard move causes rejection and rollback of only the writer’s own inode, without deleting a preexisting colliding object. Failure cleanup is tested. As with any local store, directory ownership/permissions must prevent arbitrary external modification after a successful write; the downstream resolver independently validates content hashes. The no-replace rename uses Linux `renameat2`; lack of that primitive fails closed instead of using an overwriting fallback.

Independent code review identified two issues before release: final publication under an assert, and moved-shard publication. Both were reproduced by failing tests, fixed, and checked by passing optimized-interpreter and namespace-race regressions. Final read-only review found no remaining material issue.
