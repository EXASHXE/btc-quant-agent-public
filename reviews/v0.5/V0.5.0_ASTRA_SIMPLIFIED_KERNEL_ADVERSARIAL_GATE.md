## Findings

### AG-01 — HIGH: funding source substitution survives cold replay and formal promotion

Affected code: `economic/qualification.py:950` (`execute_bound_run`, funding input hashing around 1038/1126), `economic/execution_replay.py:56` (`verify_execution_replay`, input reconstruction around 92–115), `formal_research.py:229` (`run_formal_job`).

The comparison binds the funding **model**, but not an independent funding **event dataset**. The run computes `funding_event_set_sha256` from caller-supplied events; the replay bundle hashes the same events; the cold verifier reloads those events from `formal_execution_replay_inputs` and checks their agreement with the candidate-owned hash. None of these is an independently frozen funding source. A candidate can rewrite the event input and have the canonical engine regenerate the entire accounting/result/evidence family consistently.

Executable probe: `test_funding_source_root_substitution[False]`. It uses the normal `CANONICAL_RETURN_SIGN_V1` producer, a frozen CASH comparison, a single unchanged candle dataset, unchanged signals, and separate registries registered with the same protocol before each candidate submission. It submits a positive funding rate, the sign-reversed rate, and no events. All three are cold-verified, appended, and remain `ECONOMICALLY_QUALIFIED` after constructing a new registry object from disk.

|---|---:|---:|---|
| `+0.001` at the fixed synthetic settlement | -0.9901960784313726 | 3.911764705881069 | ECONOMICALLY_QUALIFIED |
| `-0.001`, same timestamp and mark | +0.9901960784313726 | 5.892156862744741 | ECONOMICALLY_QUALIFIED |
| empty event list | 0 | 4.901960784312905 | ECONOMICALLY_QUALIFIED |

Final probe's common protocol hash: `e89904b02792c519e24e9c87e6f57694307301bf96231d9355b97d0a09fa7584`; common comparison hash: `7bbe6402396828e48ddbb61f4ede8b9ada34fcd7f3e3b58093de985e06d178d0`. Protocol, comparison, dataset and hurdle are unchanged across the three cases. The existing synthetic fixture's permissive hurdle was not tuned; this proves unauthorized economic input substitution, not an optimized profitability result.

Scope qualification: the additional nonzero-cost fixture with required RANDOM_MATCHED cold-replayed the substituted funding but stayed `NOT_TESTABLE` because its strict matching constraint was incomparable in every case. It did **not** promote, and is not counted as a successful full-random promotion attack. The CASH-only canonical protocol already demonstrates a reachable formal promotion bypass. Existing B05 tests forge submitted funding cashflows without replacing the underlying replay event root; they correctly reject that narrower attack.

Minimum repair: bind an independently content-hashed funding dataset/coverage declaration into preregistered authority, validate its source and exact event set during cold replay, and distinguish an independently proven no-settlement interval from a caller's empty list. Do not repair this by adding another candidate-owned hash. Regression: keep protocol/comparison/candle roots fixed; sign swap, event deletion/addition and mark/timestamp substitution plus full rehash must fail atomically. **A full 3-version gate is required after repair**, because authority preimages and replay acceptance change.

### AG-02 — HIGH: material-input selection is not reconstructed from the producer contract

Affected code: `economic/signal_producer.py:222` (`CanonicalRuleSignalProducer.replay_signal`, minimum-count and declared-preimage checks around 255–292), `economic/replay_bundle.py:171` and `:415` (candidate-nominated reference normalization/validation).

The producer validates a minimum lookback count and compares references to the candidate's own `material_input_open_times_ms` and `expected_preimage_sha256`. It has no independent selector proving which eligible historical rows constitute the complete input window for this decision. Hashing a selected subset proves its bytes, not that the subset is the preregistered material input set.

Executable probe: `test_canonical_input_window_is_caller_selected`. Before registration, it fixes one synthetic dataset and a momentum producer with `lookback_bars=2`. The first synthetic candle has a deliberately different open, so input selection has a visible consequence. All rows remain closed and available, and the full dataset is contiguous. At the same decision timestamp, with unchanged protocol/comparison/dataset/producer:

| Candidate-nominated indices | Direction | Net PnL USDT | Persisted status |
|---|---|---:|---|
| `[2,3]` | LONG | +4.807692307691468 | ECONOMICALLY_QUALIFIED |
| `[0,3]` (omits intervening material history) | SHORT | -4.807692307691468 | ECONOMICALLY_QUALIFIED |
| `[0,1,3]` with declared minimum still 2 | SHORT | -4.807692307691468 | ECONOMICALLY_QUALIFIED |

Common protocol hash: `ed80c00f3ad4bd5032b5da5a1918dd8c77dd43a1b969a50bc075a644e367280b`. Every outer artifact and evidence identity is freshly generated and valid; a newly loaded registry accepts each family.

The defect is the absence of a bound selection rule, not a universal requirement that every producer must use the latest two bars. A valid non-contiguous or variable-length selector is possible, but its semantics must itself be preregistered and replayed. As implemented, the contract permits candidate-controlled selection to change the trading direction while still claiming complete reconstruction.

Minimum repair: give the supported producer/input contract a deterministic material-input selector (including lookback, alignment/cadence, availability cutoff and any allowed gaps), reconstruct its required references from the frozen dataset and decision time, and reject omissions/substitutions/extra rows unless the selector explicitly permits them. Fail closed for contracts whose input completeness cannot be verified. Regression: the three fully rehashed cases above must not all inherit the same formal authority. **Full 3-version gate required.**

### AG-03 — HIGH: registered producer parameters are mutable under an unchanged hash

Affected code: `economic/signal_producer.py:30` (`SignalProducerContract`), `:133`/`:137` (`register_contract`/`get_contract`), and `:222` (`replay_signal`).

`@dataclass(frozen=True)` does not freeze the `parameters` dictionary. The contract computes `contract_hash` only at construction, and the registry stores/returns the same object. Lookups compare the cached hash; they do not check that current parameters still hash to it. A protocol represented by an immutable `VersionedIdentity` therefore continues to identify the old contract while execution uses changed parameters.

Executable probe: `test_registered_contract_parameters_mutate_without_identity_change`. It uses the built-in `CANONICAL_MOMENTUM_THRESHOLD_V1`, freezes its versioned identity into a protocol, and obtains the public parameter mapping from the registry. It then adds `threshold_return_bps=10000.0` without replacing the producer, registry, cached hash, code, or frozen protocol. This deterministic hostile mutation changes the signal from LONG to NO_TRADE; both submissions are recorded as `ECONOMICALLY_QUALIFIED` and survive registry reload in the same process. The probe asserts:

```text
contract.contract_hash == old_hash
canonical_sha256(contract.semantic_payload()) != old_hash
protocol hash unchanged
signal direction: 1 -> 0
net PnL: 4.901960784312905 -> 0
```

Common protocol hash in the final run: `b57b8a50f81ba4b70d54b0014e2a0cef51b5b9dd79f00013481b75ce2c25c205`.

Threat scope: this is a public in-process object/alias mutation, not proof that a JSON-only caller can mutate Python globals. No arbitrary replacement of verifier code is needed. Cold verification in the same service process trusts the altered registry object, so a replay call is not sufficient isolation. The probe restores the dictionary afterward. It does not claim acceptance after restarting into an unmodified producer registry.

Minimum repair: recursively copy/freeze contract parameters, reject mutable aliases and conflicting registrations under the same identity, and validate current semantic content against the declared hash at the authority boundary. Add nested-dictionary/list mutation and stale-hash regressions, with both same-process and fresh-process replay checks. **Full 3-version gate required** because producer authority and acceptance behavior change.

### AG-04 — MEDIUM: real GET `/health` initializes the forward evidence database

Affected code: `api.py:48`, `service.py:118`/`:137`, `data/forward_store.py:131`/`:154`; coverage gap in `tests/test_v050_r02_orchestration_guards.py` (`_setup_test_app_r02r` replaces `QuantService.health`).

Executable probe: `test_real_health_get_creates_forward_sqlite`. In a new temporary working directory it creates the API's configured runtime database, confirms the separate forward database does not exist, and invokes the actual `/health` endpoint with the real service/store implementation. Only network, scheduler checks and operational metadata location are isolated. The endpoint returns `OK` and creates `data/forward/BTCUSDT/derivatives.sqlite3`, including `collection_runs` and `derivative_snapshots` tables. This write occurs during the request, after app construction.

The existing all-six-routes test spies on the main Repository but replaces health, so it cannot detect this second database. The constructor also owns schema initialization/migration for existing stores. The report's assertion that retained GET requests have no storage side effects is therefore false.

This is an operational behavior/acceptance defect, not merely documentation or maintainability. No formal promotion, protected-outcome read or order submission was observed. Minimum repair: provide a read-only status opener, report a missing store without creating it, and test real health against both missing and populated forward stores while denying writes on all connections. Include this regression in the repair's final matrix.

### What stops an attacker who rewrites every candidate-owned wrapper?

For candle/economic-policy/fee/execution-model/comparison/opportunity/seed/hurdle substitutions, the existing registered protocol, comparison and dataset bindings plus canonical reconstruction provide an external check. Submitted trial/ledger hashes alone do not confer authority, and the negative probes verify that rejection is semantic rather than merely a stale outer checksum.

There is no equivalent independent stop for AG-01's funding event source or AG-02's exact material-input selector. AG-03 undermines the immutability of the registered producer content itself. Those are the reasons for BLOCKED despite a single registry writer and a working replay engine.
