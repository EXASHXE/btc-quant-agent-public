## Corrections

### R03A-F1 — `legacy_directional_role` is not an unused mechanical field
Severity: MEDIUM inventory error.

The active `configs/research_registry.json` still persists `legacy_directional_role: REJECTED` for retained opportunity components such as `trend_pullback_opportunity` and `breakout_retest_opportunity`. This field records an important distinction: movement/opportunity evidence remains reusable while the old directional interpretation was rejected.

Disposition:

```text
SIMP-02: SEMANTIC_CUT_REQUIRES_SOL
```

Do not remove it in R03B.

### R03A-F2 — legacy runtime market-data v1 is fail-closed, not a safe diagnostic adapter candidate
Severity: HIGH classification error, no code impact because R03A was read-only.

`economic/acceptance_verifier.py::_candles_from_accounting()` explicitly rejects schema `1.0.0` with `legacy runtime market data lacks formal availability proof`. That fail-closed behavior protects the availability/PIT and schema boundaries repaired under H4/B11.

Turning v1 into `READABLE_DIAGNOSTIC_ONLY` changes verifier behavior and cannot be classified as a mechanical cleanup.

Disposition:

```text
SIMP-03: KEEP_SECURITY_BOUNDARY
```

No R03 implementation may broaden v1 readability inside formal acceptance without a separate semantic/adversarial design and review.

### R03A-F3 — legacy BenchmarkEngine is not literally unreachable
Severity: MEDIUM inventory precision error.

`economic/benchmarks.py` appears to be a legacy diagnostic benchmark implementation and code search finds no current direct callers, but `economic/__init__.py` still imports and exports `BenchmarkEngine` and `BenchmarkResult`. Therefore the inventory statement `zero production callers` is too strong: the symbols remain part of the package surface.

Disposition:

```text
SIMP-01: SAFE_MECHANICAL_CANDIDATE only after exact-HEAD reachability preflight
```

A bounded removal may delete the legacy implementation and its package exports if there are no active production/CLI/formal/persistence consumers beyond the export shim. The canonical `FormalBenchmarkSuite`/`build_formal_benchmark_suite` path must remain unchanged.

### R03A-F4 — NO_TRADE compatibility is only partially demonstrated
Severity: LOW design precision issue.

An empty signal set correctly produces a no-trade economic replay, but this is not identical to an explicit per-decision `NO_TRADE`/abstention prediction class with calibrated probabilities. The future research layer may need an explicit abstention representation, but this is not a reason to alter the current economic kernel now.

Disposition: defer to the future research-program design after the simplified-kernel gate.
