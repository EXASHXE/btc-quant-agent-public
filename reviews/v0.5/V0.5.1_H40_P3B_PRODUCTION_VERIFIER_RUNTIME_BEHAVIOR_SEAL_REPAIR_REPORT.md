## Root cause and repair scope

An exact-type check alone allowed a `H40ProductionDiscoveryEvidenceVerifier` made with `object.__new__` to shadow instance scientific methods and replace constructor-bound evidence authority. The prior lifecycle fixture used this pattern. The code repair introduced a constructor binding, write-once fields, exact class-bound production dispatch, and scientific result binding; lifecycle governance fixtures were moved to explicit synthetic mode or normal constructor-backed production objects. The later E402 repair changed only three test import comments.

## Exact runtime mechanism

`H40ProductionDiscoveryEvidenceVerifier` and `H40DiscoveryEvidenceResolver` use `__slots__`, so ordinary instances have no instance `__dict__` for method shadows. Their `__setattr__` guards use `hasattr(self, field)` for the specific write-once fields: verifier `_resolver`, `_seal`, `_receipt`, `_split`, and resolver `_root`. There is no `_initialized` sentinel. Normal scientific cache fields `_manifest_hash`, `_evidence_hash`, `_verified`, `_dependencies`, and `_entries_by_id` remain mutable while verification runs.

After the normal constructor completes, the private `WeakKeyDictionary` `_VERIFIER_BINDINGS` records this exact nine-item binding, in order:

1. resolver object (`self._resolver`);
2. resolver `_root` (`self._resolver._root`);
3. runtime seal object (`self._seal`);
4. seal `authority_context_hash`;
5. seal transitive context binding from `_seal_context_binding(self._seal)`;
6. Discovery receipt object (`self._receipt`);
7. receipt `receipt_sha256`;
8. split object (`self._split`);
9. `canonical_sha256(self._split.to_dict())`.

The transitive seal binding includes object identities and canonical hashes of its source manifest, split manifest, and runtime attestation contexts, plus the seal's repository-root context. Runtime integrity compares the current objects and values with the constructor binding, including the resolver's `_root`; direct `object.__setattr__` tampering cannot silently redirect evidence loading. An `object.__new__` or partially initialized verifier has no completed binding and fails integrity before candidate-lock science.

For production candidate lock, lifecycle authority first requires the exact concrete verifier type, then calls the saved class implementation of `assert_runtime_integrity`, `verify_discovery_manifest`, and `verify_candidate` from `_VERIFIER_METHODS`. Integrity also compares current verifier and resolver class methods with their saved mappings. Instance method replacement therefore cannot confer production authority, and class method replacement is detected. Synthetic mode remains explicitly separate and uses its own instance methods.

`_VERIFIER_RESULTS` binds the canonical scientific result state after manifest verification. `verify_candidate` checks it before consuming candidate results, so a mutated cache cannot select a candidate, while the normal scientific algorithm can still update its caches before binding.
