## 6. Non-blocking backlog findings

### 6.1 Account authority configurability — future execution backlog

Current `ExecutionConfig` does not expose a first-class `account_authority_id` field.

`ExecutionEnvironmentAuthority.from_config()` therefore normally falls back to environment-scoped labels:

```text
BINANCE_TESTNET_DEFAULT
BINANCE_LIVE_DEFAULT
```

This is sufficient for the current research-disabled branch because no signed capability can be reached.

It is NOT sufficient as final multi-account/subaccount production execution authority.

Before any future TESTNET/LIVE signed authority is accepted, require an explicitly configured non-secret stable account/subaccount authority ID and tests proving same-environment cross-account isolation.

Disposition:

```text
DEFERRED_FUTURE_EXECUTION_BLOCKER
NOT_H40_RESEARCH_BLOCKER
```

### 6.2 P05 plan status centralization — maintenance backlog

The shared preflight does not itself own every plan kind/status validation; some status checks remain in service methods.

Under current policy this cannot enable signed exchange capability.

Before future execution authorization, consolidate exact plan-kind/status semantics into the authoritative preflight or prove equivalent complete coverage.

Disposition:

```text
DEFERRED_FUTURE_EXECUTION_HARDENING
NOT_H40_RESEARCH_BLOCKER
```
