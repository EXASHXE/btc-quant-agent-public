## AG-03 — ACCEPTED

The producer-contract repair closes the demonstrated Astra mutable-preimage attack without changing default producer semantics or identities.

Accepted properties:

- `SignalProducerContract.parameters` is recursively detached/frozen through the existing canonical `freeze_json` machinery.
- `semantic_payload()`/`to_dict()` thaw into detached plain JSON and therefore do not leak a mutable alias back into authority.
- `register_contract()` recomputes the semantic hash, accepts exact duplicate semantics idempotently, and rejects conflicting content under an existing contract id.
- `get_contract()` recomputes the semantic hash and fails closed if stored semantic content no longer matches `contract_hash`.
- replay uses the frozen parameters; metadata is thawed before leaving the producer boundary.
- all five pre-R05A default contract hashes are explicitly frozen in regressions and preserved.
- permanent tests cover caller alias mutation, top-level/nested mapping mutation, nested sequence mutation, detached serialization, conflict registration, stale-preimage lookup, same-process Astra LONG→NO_TRADE mutation, round-trip reconstruction and fresh-process default registry hashes.

No producer identity/schema version migration was introduced because canonical semantic payloads are unchanged.

## AG-04 — PARTIAL; one MEDIUM remains

The primary defect is fixed for normal stable stores:

- `/health` no longer constructs writer-mode `ForwardDerivativeStore`.
- missing parent/store remains absent.
- normal checkpointed populated DB is inspected without schema migration.
- unsupported schema degrades rather than migrating.
- writer-mode construction remains unchanged.

However, the claimed invariant "GET creates no WAL/SHM sidecar" is not complete for a WAL crash/recovery state.

Current read-only `_connect()` logic is:

```text
non-empty <db>-wal exists
    -> sqlite URI ?mode=ro
otherwise
    -> ?immutable=1
```

If a non-empty WAL exists but `<db>-shm` is absent, SQLite `mode=ro` is allowed to create the missing SHM file when the containing directory is writable. This is documented SQLite WAL behavior and independently reproduced during this review. Therefore a health GET can still mutate filesystem state by creating `derivatives.sqlite3-shm` in a crash-leftover WAL state.

The implementation comment currently predicts that this condition will fail closed, but that prediction is not generally true.

The permanent AG-04 suite does not cover this state. Its populated-store helper intentionally closes all writer connections and asserts no sidecars remain before GET, so the active/crash WAL branch is untested.

### Required narrow repair

Before any SQLite read-only connection is opened:

1. inspect `<db>-wal` and `<db>-shm` state;
2. if WAL is non-empty and SHM is absent, return an explicit degraded/fail-closed status without opening SQLite;
3. do not use `immutable=1` to silently ignore a non-empty WAL, because that could report stale main-DB state;
4. when WAL+SHM already exist, a `mode=ro` inspection may be retained if tests prove no new filesystem member is created; preserve existing sidecars rather than manufacturing recovery state;
5. add permanent real `/health` regression covering a non-empty crash-leftover WAL with no SHM and assert before/after directory membership and hashes are identical.

This is a bounded AG-04 repair only. Do not touch AG-01/AG-02.
