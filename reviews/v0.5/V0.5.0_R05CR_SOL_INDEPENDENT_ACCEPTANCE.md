## 2. R05C-F1 evidence-chain closure — ACCEPTED

The bound run's `funding_evidence_id` is now mandatory at three independent layers:

1. `evaluate_formal_economic_qualification()` rejects caller omission;
2. `EconomicQualificationResult.__post_init__()` rejects direct-object omission;
3. `validate_persisted_qualification_semantics()` reconstructs the funding id from persisted `run_identity` and rejects a rehashed qualification whose `required_evidence_ids` omits that id.

The implementation deliberately does not auto-insert the id: omission is visible and fail-closed.

The existing P5 registry boundary remains generic. Once the funding id is mandatory in the result/attestation, `record_economic_qualification()` already requires every declared required id to be present in submitted `evidence_references`, validates completeness/local content hashes, and commits atomically. No registry production modification is necessary.

`EvidenceReference.evidence_id` is itself content-addressed over the complete identity payload including evidence type, logical id, content SHA-256, path/provenance, completeness and metadata. Therefore an unrelated/different-content EvidenceReference cannot normally substitute for the required funding evidence under the same id without a cryptographic collision.

Permanent tests T21-T26 cover evaluator omission, direct result omission, persisted full-rehash omission, registry atomic omission, unrelated COMPLETE evidence replacement, and valid-chain positive control.

## 3. R05C-F2 coverage identity closure — ACCEPTED
