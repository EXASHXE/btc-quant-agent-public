## Blocking finding — Discovery provenance contract hash is not reproducible

Repair Contract Freeze R1 publishes:

```text
H40_DISCOVERY_PROVENANCE_CONTRACT_V1

claimed contract_hash =
9a5a71101875829aff2959c93391648dbfd94ab26fd55ed31b720610fa7be81b
```

The controller prompt requires this value to be independently recomputed from the exact
canonical contract object represented by the R1 JSON and explicitly requires BLOCK if
the JSON/report canonical identity is inconsistent.

The exact R1 JSON object contains a `provenance_contract` object composed of:

```text
schema_id
source_value_extraction_contract
prefit_reconstruction_contract
contract_hash
```

Using the repository canonical serialization rule:

```text
sort_keys = true
separators = (",", ":")
ensure_ascii = false
allow_nan = false
SHA-256 over UTF-8 canonical JSON
```

the controller independently hashed the represented provenance preimage with the
self-reported `contract_hash` excluded.

Diagnostic recomputation:

```text
represented_preimage_sha256 =
31fc3930e44149e6b3af54ddd3b11c630f95cbbd3f152b3d0d5e614690dcf7ae

published_contract_hash =
9a5a71101875829aff2959c93391648dbfd94ab26fd55ed31b720610fa7be81b

MATCH = NO
```

The diagnostic `31fc3930...` value is **not accepted as a replacement authority** by
this review. It is evidence that the published R1 identity cannot be reproduced from the
canonical object presently represented in R1 JSON.

Plausible alternate readings of the represented object were also checked, including the
object with the reported hash included, the two nested contracts without the schema
wrapper, each nested contract independently, and a schema-plus-contract-ID projection.
None reproduced `9a5a7110...`.

## Minimal docs-only repair required

Do not rewrite or delete the historical R1 artifacts.

Create a superseding docs-only Repair Contract revision/amendment that:

1. publishes the **exact canonical preimage object** for
   `H40_DISCOVERY_PROVENANCE_CONTRACT_V1`;
2. states unambiguously whether the hash preimage contains only:
   `schema_id`, `source_value_extraction_contract`, and
   `prefit_reconstruction_contract`, or another exact frozen field set;
3. recomputes the provenance contract hash from that exact published preimage using the
   repository canonical JSON algorithm;
4. publishes one identical provenance hash in both the human-readable contract and its
   machine-readable JSON;
5. includes a deterministic replay/check proving
   `canonical_sha256(exact_published_preimage) == published_contract_hash`;
6. preserves all already-frozen F01/F02/F03/F04 semantics unless an additional explicit
   controller review proves a separate ambiguity;
7. explicitly preserves the three frozen scientific identities above;
8. keeps H40 P3, H40 Discovery, protected outcomes, and execution fail-closed.

The superseding artifact should use a new version/path rather than editing R1 history.
After that exact docs commit exists, rerun an independent Controller Contract Acceptance
review. Only a PASS review may create an acceptance commit and proceed to Lifecycle V5
hash materialization.
