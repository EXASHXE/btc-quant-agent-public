2. `materialize_authoritative(...)` requires a source manifest plus `repo_root`, cold-extracts BTC/ETH timestamps from referenced artifacts, computes the common membership, builds the split, and binds source file SHA-256, timestamp-membership hashes/counts, source-manifest hash, protocol identity, and split hash into `H40SplitAttestation`.

## Remaining finding

### P1RR-F1 HIGH — offline caller-forgeable source receipt + attestation chain

`H40SplitManifest.assert_authoritative(...)` still accepts `repo_root=None`.

When `repo_root` is omitted, the verifier checks only semantic/hash consistency among:

- the caller-supplied `H40SourceManifest`;
- caller-supplied `H40SourceValidationReceipt` objects marked `VERIFIED`;
- caller-supplied split partitions / `is_authoritative=True`;
- caller-created `H40SplitAttestation` and its self-hash.

All of those values are publicly constructible. `H40SplitAttestation.create()` uses an ordinary unkeyed canonical SHA-256; it proves payload consistency, not provenance or authority.

A caller can therefore construct a fully self-consistent fake chain without any artifact cold validation:

```text
forged VERIFIED BTC receipt
forged VERIFIED ETH receipt
        ↓
forged H40SourceManifest
        ↓
caller-chosen split with is_authoritative=True
        ↓
H40SplitAttestation.create(...matching hashes...)
        ↓
assert_authoritative(source_manifest=forged_manifest, repo_root=None)
```

The current `assert_authoritative()` path performs no cold byte/timestamp validation when `repo_root` is `None`, so this chain can satisfy all remaining checks.

This violates the governing P1RR requirement:

> A caller-created `H40SourceValidationReceipt(status=VERIFIED, ...)` must not become authority unless cold validation of the referenced artifact reproduces the same receipt-relevant identity.

## Required repair

Keep the repair narrow.

1. Any public authority assertion must require cold verification context. `repo_root` must not be optional for an authority-accepting path.
2. A persisted attestation may be deserialized for transport/audit, but it must not be sufficient to grant H40 split authority offline.
3. `assert_authoritative(...)` must independently cold-validate the exact BTC/ETH artifacts and reproduce the receipt-relevant identity before success.
4. Prefer additionally cold-reconstructing the split membership from the validated artifacts and comparing the reconstructed partition/split hash, rather than trusting persisted partitions alone.
5. Caller-created VERIFIED receipts, source manifests, and attestation hashes must fail if no matching artifact bytes/timestamps are available.
6. Do not redesign the protocol, source inventory, split schedule, guards, lifecycle, economic kernel, H39, or execution.

## Required attacks

At minimum add tests proving:

- `assert_authoritative(source_manifest=forged_manifest)` without `repo_root` is impossible / fails closed;
- a completely self-consistent forged VERIFIED receipts + source manifest + split + attestation chain cannot pass without cold artifacts;
- forged receipts plus unrelated local artifact bytes fail;
- cold verification of the valid synthetic positive chain still passes;
- round-trip serialized valid split requires the same cold source bytes/timestamps to regain authority;
- changing one source byte or timestamp after serialization makes the round-trip assertion fail.
