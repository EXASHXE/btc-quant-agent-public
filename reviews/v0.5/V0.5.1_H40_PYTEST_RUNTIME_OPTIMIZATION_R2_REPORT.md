## Test-only cache and fresh state

The default governance helper now uses a cached tuple of fixed hourly timestamp strings, a cached serialized accepted search-space ledger template, and a cached immutable roster tuple. Each calendar request receives a **new list**. Each ledger request is deserialized into a **new ledger and slots**. A `cached_calendar=False` mode runs the original uncached calendar and roster materialization; A00 and A05 explicitly use it. The helper still invokes `materialize_runtime_source_split_authority` on each setup. Production source validation, timestamp extraction, split construction, attestation checks, runtime-seal verification, transition revalidation, and cold restore still execute.

Fresh per test: `cold_state`, monkeypatch closures, source/split/attestation objects, runtime seal and private context, lifecycle service, persistent store, evidence root, resolver, production/synthetic verifier, and scientific caches. The new isolation test constructs two real verifiers and resolvers, mutates evidence bytes in one root, and confirms the other root is unchanged. No verifier or seal instance is shared by the cache.

The new full-versus-cached equivalence test asserts exact source-manifest, split-manifest, runtime-attestation, snapshot, roster, run-authority ID, and Discovery receipt hashes, registered/not-testable counts, and roster entries. It also asserts fresh source/split/attestation/seal/cold-state objects, fresh calendar lists, independently mutable ledger copies, and cold source-disappearance rejection in cached mode. Both new tests passed. Existing R35 and R24 retain source-mutation failure coverage.
