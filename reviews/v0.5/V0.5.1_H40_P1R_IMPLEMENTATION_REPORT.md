## 3. Detailed Finding Closures & Architecture Repairs

### 3.1 Repair A — Closure of P1-F1 (HIGH): Unforgeable Confirmation Readiness

**Vulnerability**: `H40ConfirmationGuard` previously accepted `is_confirmation_ready=True` in its constructor, and `H40LifecycleStateMachine` allowed arbitrary initial states including `H40_CONFIRMATION_READY`.

**Repair Implemented**:
1. **Removed Constructor Parameter**: `H40ConfirmationGuard` has no caller-controlled parameters (`__init__` takes no readiness arguments). `is_ready` is a fixed property returning `False`. `assert_outcomes_accessible()` unconditionally raises `H40GuardError` with `H40ReasonCode.CONFIRMATION_NOT_READY`.
2. **Hard-Denied Confirmation Access**: Metadata/timestamp/manifest inspection remains accessible via `assert_metadata_accessible()`, while outcome/return/price data access is permanently blocked during P1/P1R.
3. **Restricted Lifecycle Construction**: `H40LifecycleStateMachine` enforces `ALLOWED_INITIAL_STATES = frozenset({H40LifecycleState.H40_PREREGISTERED, H40LifecycleState.H40_P1_SCAFFOLDED})`. Any attempt to instantiate directly at confirmation states (`H40_CONFIRMATION_READY`, `H40_CONFIRMATION_EVALUATED_ONCE`) raises `H40GuardError` (`CONFIRMATION_NOT_READY`). Direct instantiation at post-scaffold states (`H40_DISCOVERY`, `H40_CANDIDATE_LOCKED`, etc.) raises `NOT_TESTABLE`.
4. **Mandatory Attacks Tested**:
   - `test_confirmation_guard_unlocked_construction_impossible`: Confirms constructor accepts no unlock flags and outcome access fails closed.
   - `test_confirmation_guard_forging_readiness_fails`: Confirms attribute monkeypatching/assignment fails and outcomes remain locked.
   - `test_lifecycle_cannot_construct_at_confirmation_ready`: Confirms direct initialization fails with `CONFIRMATION_NOT_READY`.
   - `test_lifecycle_cannot_construct_at_confirmation_evaluated_once`: Confirms direct initialization fails with `CONFIRMATION_NOT_READY`.
   - `test_lifecycle_cannot_construct_at_post_scaffold_states`: Confirms post-scaffold initialization attempts fail with `NOT_TESTABLE`.

### 3.2 Repair B — Closure of P1-F2 (HIGH): Independent Protected Source Authority

**Vulnerability**: `H40SourceManifest` previously checked source status before opening files, allowing a caller to construct an `H40SourceRecord(status=VERIFIED, locator=...)` pointing to H39 or Final Holdout paths, bypassing default `FORBIDDEN` records.

**Repair Implemented**:
1. **Universal Path Authority Guard**: Added `H40ProtectedSurfaceGuard.assert_path_allowed(locator, source_id, repo_root)`. It evaluates:
   - Logical `source_id` against `FORBIDDEN_SOURCE_IDS` (`{"h39", "final_holdout"}`).
   - Raw locator string against `FORBIDDEN_LOCATORS` (`{"h39", "final_holdout"}`).
   - Normalized path (`os.path.normpath`) preventing relative path traversal (`../`).
   - Resolved symlink target (`Path.resolve()`) preventing symlink alias attacks.
2. **Source Record Invariant**: `H40SourceRecord.__post_init__()` validates every source record through `assert_path_allowed()` regardless of the caller-supplied `status`, unless status is explicitly `FORBIDDEN`. Furthermore, any record claiming `VERIFIED` status without an explicit valid receipt is rejected with `SOURCE_UNVERIFIED`.
3. **Pre-Filesystem Check in Validators**: `validate_source_artifact()` calls `assert_path_allowed()` before executing `exists()`, `stat()`, `read_bytes()`, or parquet schema inspections.
4. **Mandatory Attacks Tested**:
   - `test_protected_source_relabel_attack_fails_before_read`: Attempting to create an H39 source with `status=VERIFIED` or validating it fails before any read.
   - `test_final_holdout_relabel_attack_fails_before_read`: Attempting to create a Final Holdout source with `status=VERIFIED` or validating it fails before any read.
   - `test_serialized_manifest_relabel_forbidden_to_verified_fails`: Deserializing a tampered manifest JSON with `FORBIDDEN -> VERIFIED` raises `PROTECTED_SURFACE_DENIED`.
   - `test_protected_surface_normalized_and_relative_path_attack`: Non-canonical paths and traversal patterns (`data/research/../h39_validation/`) fail closed.
   - `test_protected_surface_symlink_attack_synthetic_temp_path`: Synthetic symlinks with benign names pointing to forbidden directories are detected via `resolve()` and blocked.

### 3.3 Repair C — Closure of P1-F3 (MEDIUM): Materialized Source & Split Authority

**Vulnerability**: Split partitions were derived from an assumed continuous calendar without verifying local source files or timestamp continuity. Embedded metadata strings granted `VERIFIED` status without evidence binding.

**Repair Implemented**:
1. **Explicit Validation Receipts (`H40SourceValidationReceipt`)**:
   - Binds: `source_id`, `locator`, `file_sha256`, `product`, `cadence`, `timestamp_field`, `timestamp_count`, `first_timestamp_utc`, `last_timestamp_utc`, `duplicate_count`, `gap_count`, `gaps`, `membership_sha256`, and archive identity.
   - Validation inspects actual local bytes and timestamps without reading price/OHLC/outcome columns.
   - Local artifacts `data/research/cross_asset_1h/ETHUSDT.parquet` (SHA `563a1a4d...`, 44,568 rows) and `data/research/v0.3.19_official_derivatives/hourly_inputs.parquet` (SHA `77a8ad63...`, 44,568 rows) verified against preregistration.
2. **Separation of Schedule from Authority**:
   - `H40SplitManifest.build_preregistered_schedule()` creates a reference split with `is_authoritative=False`. Calling `assert_authoritative()` fails closed with `SOURCE_UNVERIFIED`.
   - `H40SplitManifest.build_materialized()` produces an authoritative split (`is_authoritative=True`) strictly requiring validated BTC and ETH timestamp sequences.
3. **Materialized Intersection & Exclusion Accounting**:
   - Computes common intersection of trustworthy BTC and ETH hourly timestamps.
   - Enforces 720h feature lookback reservation (`[2021-01-01, 2021-01-31)`).
   - Enforces 24h future coverage horizon truncation on confirmation holdout without shifting partition boundaries.
   - Partitions use fixed half-open UTC boundaries `[start_utc, end_utc)`.
   - Gaps and missing hours decrement partition counts and alter `timestamps_sha256` and `split_hash` without boundary expansion.
4. **Mandatory Attacks Tested**:
   - `test_source_validation_receipt_detects_hash_tampering`: Byte tampering records `SOURCE_HASH_MISMATCH` and `NOT_TESTABLE`.
   - `test_source_validation_receipt_detects_missing_file`: Missing file records `SOURCE_MISSING`.
   - `test_source_validation_receipt_detects_wrong_product`: Product mismatch records `PRODUCT_MISMATCH`.
   - `test_source_validation_receipt_detects_wrong_cadence`: Non-1h intervals record `INTERVAL_MISMATCH`.
   - `test_source_validation_receipt_detects_duplicate_timestamps`: Duplicate timestamps record `DUPLICATE_TIMESTAMP`.
   - `test_source_validation_receipt_persists_gaps`: Missing hours are recorded in receipt `gaps`.
   - `test_materialized_split_authoritative_with_full_timestamps`: Authoritative split passes `assert_authoritative()`.
   - `test_pooled_btc_eth_intersection_drops_missing_timestamps`: Missing hour in ETH is dropped from pooled intersection.
   - `test_split_count_and_hash_changes_when_timestamp_removed`: Dropping one hour changes partition counts, manifest hash, and records `SOURCE_GAP`.
   - `test_confirmation_endpoint_constraint_removes_uncovered_timestamps`: 23 hours lacking 24h future coverage recorded as `HORIZON_TRUNCATED`.
   - `test_no_boundary_shifts_occur_after_gaps`: Partition counts drop after gaps but start/end boundaries remain fixed.
   - `test_builder_cannot_return_authoritative_split_from_constants_alone`: `build_default()` / schedule cannot pass `assert_authoritative()`.
