## Finding R1-SOL-01 — MEDIUM — Direction-family authority conflict

R1 Section 5 states that all BASE protocol invariants are preserved, but then renames/reassigns D2–D5 inconsistently with BASE Section 5.3.

BASE authoritative families are exactly:

```text
D1_TREND_CONTINUATION
D2_BREAKOUT_CONTINUATION
D3_FAILED_MOVE_REVERSAL
D4_BTC_ETH_CONFIRM_DIVERGE
D5_FUNDING_DIRECTION_INTERACTION
```

R1 instead summarizes D2–D5 as Mean Reversion / Breakout / Funding Pressure / Cross-Asset Imbalance. Because downstream consumers are instructed to treat BASE + AMENDMENT as one authority pair, this is not harmless prose: an implementation could follow the wrong family semantics.

Required closure: a second pre-outcome amendment must explicitly restore the exact BASE identifiers, names, meanings, variant limits and allowed pairings, and state that any conflicting R1 Section 5 shorthand is superseded.

## Finding R1-SOL-02 — MEDIUM — HAC lag unit conflicts with BASE

BASE Section 9.1 preregisters Newey-West/HAC with a maximum lag of 24 **hours**. R1 Section 2 constructs a sequence indexed only by accepted trades and then sets `K=min(24,N-1)`. Under the intended 2–5 opportunities/week, 24 accepted-trade lags can span many weeks and therefore does not implement a 24-hour lag.

This can materially change `n_eff`, which directly controls candidate-lock, walk-forward and confirmation sample-floor gates.

Required closure: define HAC autocovariance by actual UTC entry-time separation, with lags `k=1..24` hours. A deterministic acceptable construction is:

```text
mean(z) = sum_i z_i / N

gamma_0 = (1/N) * sum_i (z_i-mean)^2

gamma_k = (1/N) * sum_{(i,j): t_j-t_i = k hours}
          (z_i-mean)(z_j-mean),  k=1..24
```

then use the preregistered Bartlett weights over the 24 hourly lags. Simultaneous BTC/ETH observations remain separate observations; same-timestamp cross-asset dependence is handled by the joint UTC block bootstrap and the occupied-day floor rather than pretending that a trade index is an hour.

All empty-lag, zero-variance, non-finite and non-positive-VIF behavior must remain fail-closed and deterministic.

## Finding R1-SOL-03 — MEDIUM — Bootstrap exactness remains ambiguous

R1 Section 3.5 simultaneously uses one-based order-statistic notation such as `v_(500)` and says the exact convention is a zero-indexed rank `floor(10000*alpha)`. Those are different array elements. R1 also defines the Holm adjustment algebra but not the exact marginal one-sided bootstrap p-value construction, and its seed preimage concatenation does not specify unambiguous encoding/delimiters or integer byte order.

Because the amendment was explicitly intended to make bootstrap results independently reproducible, these freedoms must be removed before any metric is computed.

Required closure:

1. Use one exact empirical quantile convention. Recommended nearest-rank:
   `r=max(1,ceil(alpha*M))`, one-based order statistic `v_(r)`; a zero-based implementation uses index `r-1`. Thus at M=10000, 95% LCB=`v_(500)`, 97.5% LCB=`v_(250)`, 90% LCB=`v_(1000)`.
2. Define upper critical quantiles analogously with `r=ceil((1-alpha)*M)`.
3. Define marginal one-sided bootstrap p-values before Holm, including null centering and the finite-M `+1` correction. For a metric with null `theta0`, use observed `T_obs=theta_hat-theta0`, centered bootstrap `T_m=theta_hat_m-theta_hat`, and `p=(1+sum I[T_m>=T_obs])/(M+1)`. Precision uses `theta0=p0`; net expectancy uses `theta0=0`.
4. Make bootstrap seed preimage unambiguous, preferably `canonical_json([protocol_id,candidate_id,partition_id,metric_id]).encode("utf-8")`; convert the first 8 digest bytes as unsigned big-endian before the stated modulus; instantiate `numpy.random.Generator(numpy.random.PCG64(seed))` explicitly.

## R1 items accepted

The following R1 changes are accepted and must not be reopened by the narrow repair:

- first candidate selection/lock is restricted to WF1 training + WF1 calibration;
- all 168 configurations are committed before the first H40 label/metric;
- WF1 validation, later folds and confirmation cannot influence the first lock;
- runner-up promotion after validation failure is forbidden;
- later fold refits are mechanical only and cannot change candidate identity;
- empirical directional null uses training-only label base rates and candidate side mix;
- original 168-slot search budget, 12 bps proxy, horizons, action space, one-shot confirmation, H39/Final-Holdout protection and execution-disabled boundary remain intact.

The next amendment should also express the confirmation training interval using an exact half-open timestamp interval, not an inclusive natural-language date, to eliminate a final date-boundary ambiguity.
