## 2. Implemented Architecture & Semantic Seal

### 2.1 Evidence Data Model (`src/btc_quant_agent/market_watch/evidence.py`)
- Defines immutable, frozen dataclasses capturing the complete state of a decision:
  - `SourceProvenanceEvidence`: closed-bar watermarks for 15m, 1h, 4h; auxiliary receipt timestamps.
  - `TimeframeFeaturesEvidence`: bar metrics, moving averages, slopes, ATR, ADX, RSI, ROC, volume Z-scores, BB width, swing points.
  - `DerivativesFeaturesEvidence`: mark/index prices, funding rate, open interest, long/short ratios, basis, spread, order book imbalance.
  - `MarketSnapshotFeaturesEvidence`: bundles 15m, 1h, 4h timeframes, derivatives metrics, price metrics, return observations (1h, 4h, 12h elapsed-time returns).
  - `ReferenceUniverseEvidence`: universe status (`UNIVERSE_COMPLETE` or `UNIVERSE_DEGRADED`), canonical universe list, missing members, incomplete return members, cross-sectional medians, rank.
  - `PlaybookCandidateEvidence`: candidate status, strategy status, decision, entry/stop/target/invalidation levels, structural anchor ID, reason/risk codes, breakout parameters.
  - `PolicyGateStageTrace` & `PolicyDecisionTrace`: explicit stage-by-stage gate evaluation trace.
  - `RuleScoreBreakdown`: complete decomposition of rule score components, penalties, and adjustments.
  - `ExhaustionEvidence`, `DirectionalRiskPlanEvidence`, `GridAdvisoryPlanEvidence`.
  - `TacticalFeatureEvidenceV2`: root evidence container bundling all sub-components, semantic identity, config hash, snapshot hash, and 64-char SHA-256 `evidence_id`.

### 2.2 Canonical Serialization & Content Identity
- `canonical_evidence_payload(evidence)` extracts a canonical dict representation excluding `evidence_id`.
- `canonical_json_dump(payload)` formats deterministic, sorted-key, compact UTF-8 JSON (`separators=(",", ":")`).
- `compute_evidence_id(payload_or_evidence)` computes the 64-character lowercase SHA-256 hexadecimal digest.
- `canonical_evidence_json(evidence)` produces the canonical JSON including `evidence_id`.
- `deserialize_tactical_feature_evidence(json_str)` reconstructs the frozen dataclass hierarchy.

### 2.3 Fail-Closed Validation & Causality Guardrails
- `validate_tactical_feature_evidence(evidence)` enforces:
  - No `NaN`, `+Infinity`, or `-Infinity` anywhere in numeric fields (raises `TacticalEvidenceValidationError`).
  - Closed-bar watermarks $\le$ `decision_time_ms` (raises `TacticalCausalityError`).
  - Source receipt timestamps $\le$ `decision_time_ms` (raises `TacticalCausalityError`).
  - Strict policy version equality to `TACTICAL_POLICY_R2_B0`.
  - Schema version equality to `TACTICAL_FEATURE_EVIDENCE_V2`.

### 2.4 State Store & Scanner Integration (`state.py`, `scanner.py`)
- SQLite table `tactical_feature_evidence_v2` created with natural key index `(symbol, decision_time_ms, snapshot_hash, policy_version, config_hash)`.
- `save_symbol_state`:
  - Detects natural key collisions: saving identical `evidence_id` is idempotent; saving conflicting `evidence_id` raises `TacticalEvidenceConflictError`.
  - Persists `evidence_json` and decoupled `persisted_at_ms`.
- `record_shadow_observation`:
  - Validates `feature_evidence_id` exists in `tactical_feature_evidence_v2` (raises `TacticalEvidenceLinkageError` if missing).
  - Resolving or updating shadow records strictly preserves immutability of `tactical_feature_evidence_v2`.
- `MarketWatchScanner`:
  - Builds return observations (1h, 4h, 12h elapsed-time returns).
  - Collects gate decision traces and candidate records.
  - Assembles and validates `TacticalFeatureEvidenceV2` for every target symbol.
  - Links evidence ID to assessment and shadow record.
