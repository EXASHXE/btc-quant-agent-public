## 3. Detailed Component Verification

### 3.1 Immutable Evaluation Identity & Storage
- **Identity Scheme:** Content-addressed 64-character lowercase SHA-256 derived from deterministic canonical JSON representation of the evaluation payload (excluding `evaluation_id` and `persisted_at_ms`).
- **Database Table:** `tactical_shadow_evaluations_v2` with primary key `evaluation_id` and unique natural key index on `(shadow_record_id, evaluation_profile_version)`.
- **Conflict Enforcement:** Attempting to insert a divergent evaluation with differing payload under an existing natural key immediately raises `TacticalShadowEvaluationConflictError`. Re-evaluating with identical payload is strictly idempotent.

### 3.2 Attribution Cross-Checking
- Implemented `validate_attribution_crosscheck()` enforcing fail-closed agreement between `TacticalFeatureEvidenceV2` and `market_watch_shadow_records`:
  - Symbol match
  - Decision timestamp match
  - Final directional decision match (`LONG` / `SHORT`)
  - Selected playbook match
  - Limit entry price, stop loss, and profit targets with scale-safe comparison math.isclose(a, b, rel_tol=1e-12, abs_tol=1e-12)
  - Discrepancies raise `TacticalShadowAttributionConflictError`.

### 3.3 Directional Playbook Profiles & Checkpoints
- Implemented `get_playbook_evaluation_profile()`:
  - `TREND_PULLBACK`: 12h horizon (48 bars 15m), checkpoints at 4h, 8h, 12h, 24h.
  - `BREAKOUT_RETEST`: 12h horizon (48 bars 15m), checkpoints at 4h, 8h, 12h, 24h.
  - `FAILED_BREAKOUT`: 8h horizon (32 bars 15m), checkpoints at 4h, 8h, 12h, 24h.
  - `FAILED_BREAKDOWN`: 8h horizon (32 bars 15m), checkpoints at 4h, 8h, 12h, 24h.
  - `VOLATILITY_EXPANSION`: 8h horizon (32 bars 15m), checkpoints at 4h, 8h, 12h, 24h.
- Evaluates mark price, mark-to-market gross R, MFE R, MAE R, and barrier status at each checkpoint.

### 3.4 Terminal Event & NO_FILL Semantics
- Evaluates `TP1`, `STOP`, and `TIMEOUT` conditional on order fill.
- Evaluates `NO_FILL` when order limit price is not touched within the 4-bar entry window:
  - `terminal_status = "NO_FILL"`
  - `fill_price = None`, `net_r_ex_funding = None`, `net_r_after_funding = None`
  - `funding_status = "NOT_APPLICABLE"`
  - Diagnostic checkpoints recorded with status `"NOT_APPLICABLE"`
  - Included as valid denominator count in signal-level cohort calculations.

### 3.5 Realized Funding Accounting
- Added `funding_rate_history()` to `BinancePublicClient` targeting public endpoint `/fapi/v1/fundingRate`.
- Causal boundary matching: $\text{fill\_time\_ms} < \text{funding\_time\_ms} \le \text{exit\_time\_ms}$.
- Signed cashflows: LONG pays positive rate; SHORT receives positive rate.
- Normalized into R units based on initial trade risk.

### 3.6 Cohort Summary & Stratification Engine
- Implemented `compute_tactical_cohort_summary_v1()` outputting descriptive statistics only:
  - `sample_fill_rate`
  - `sample_tp1_rate_given_fill`, `sample_stop_rate_given_fill`, `sample_timeout_rate_given_fill`
  - `sample_mean_net_r_per_signal_ex_funding` (treating NO_FILL as 0.0 R)
  - Small sample size labels: `VERY_LOW_SAMPLE` ($N < 10$), `LOW_SAMPLE` ($10 \le N < 30$), `OBSERVED_SAMPLE` ($N \ge 30$).
  - Stratification supported across: playbook, direction, playbook $\times$ direction, 1h regime, 4h regime, entry quality, derivatives regime, benchmark context, reference universe status, and 5 Rule Score buckets (`RULE_SCORE_BUCKETS_V1`).
