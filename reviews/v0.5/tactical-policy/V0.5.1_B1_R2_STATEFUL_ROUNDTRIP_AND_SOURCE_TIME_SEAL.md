## 1. Executive Summary & Defect Closures

The B1-R2 repair contract closes critical semantic-authority defects discovered during Controller review of B1-R1. The fixes guarantee exact stateful round-trip fidelity, correct Binance funding timestamp semantics, strict read-path validation, and database row-key referential integrity.

### Defect 1: PolicyStateInputEvidence Canonical Round-Trip
- **Defect:** `PolicyStateInputEvidence` serialized dictionary contains exact `previous_*` fields, but deserialization in B1-R1 used `from_prev_state` which expects un-prefixed runtime state dictionary keys (`setup`, `lifecycle_state`, etc.). This caused all `previous_*` fields to be dropped on deserialization and reset to defaults.
- **Root Cause:** Conflation of runtime state converter (`from_prev_state`) with canonical serialized dictionary deserializer.
- **Repair:**
  - Added `@classmethod def from_dict(cls, data: Mapping[str, Any] | None) -> PolicyStateInputEvidence:` reading exact `previous_*` keys.
  - Retained `from_prev_state` strictly for mapping raw runtime store state to input evidence.
  - In `deserialize_tactical_feature_evidence`, instantiated `PolicyStateInputEvidence.from_dict(data.get("policy_state_before"))`.
- **Proof:** `test_b1_r2_stateful_round_trip` and `test_b1_r2_stateful_db_round_trip` prove byte-equivalent canonical evidence and identical evidence ID for non-default state continuity.

### Defect 2: Binance Premium Index Source-Time Semantics
- **Defect:** B1-R1 erroneously assumed Binance `premium["time"]` represented the upcoming scheduled funding timestamp, classifying it as future schedule time.
- **Root Cause:** Failure to distinguish observation timestamp from settlement schedule timestamp in the Binance `/fapi/v1/premiumIndex` API payload.
- **Repair:**
  - `premium["time"]` is frozen as `PREMIUM_INDEX_EVENT_TIME` (`premium_index_time_ms`), representing the timestamp of the mark/index price observation. Invariant: `premium_index_time_ms <= decision_time_ms`.
  - `premium["nextFundingTime"]` is frozen as `KNOWN_FUTURE_SCHEDULE_TIME` (`next_funding_time_ms`), representing the scheduled settlement slot. Permitted: `next_funding_time_ms > decision_time_ms`.
  - `funding_time_ms` is documented and preserved strictly as a compatibility alias of `premium_index_time_ms` (`funding_time_ms <= decision_time_ms`).
  - Extended `DerivativesSnapshot`, `HistoricalDerivativeStore`, `BinancePublicClient`, `DerivativesMetrics`, `SourceProvenanceEvidence`, and `DerivativesFeaturesEvidence` with explicit `premium_index_time_ms` and `next_funding_time_ms`.
  - Validator enforces `funding_time_ms == premium_index_time_ms` when both are present and rejects `premium_index_time_ms > decision_time_ms` with `TacticalCausalityError`.
- **Proof:** `test_b1_r2_binance_premium_index_time_semantics` and `test_b1_r2_causality_tests_a_b_c` verify correct parsing, future schedule acceptance, and event timestamp causality enforcement.

### Defect 3: Read-Path Full Semantic Validation
- **Defect:** Read path previously only checked SHA-256 identity hash, allowing syntactically valid but semantically or PIT-invalid payloads to pass deserialization without validation.
- **Root Cause:** Deserializer did not invoke `validate_tactical_feature_evidence`.
- **Repair:** `deserialize_tactical_feature_evidence` now executes both `verify_tactical_evidence_identity(evidence)` and `validate_tactical_feature_evidence(evidence)` when `verify_identity=True`.
- **Proof:** Full validation rejects invalid schema versions, out-of-bounds timestamps, NaN/Inf numbers, and contradictory timestamp semantics on read.

### Defect 4: DB Row-Key / Embedded Evidence-ID Consistency
- **Defect:** Primary-key column in `tactical_feature_evidence_v2` was not compared against the internal `evidence_id` inside `evidence_json`.
- **Root Cause:** Query selected only `evidence_json`.
- **Repair:**
  - `get_tactical_feature_evidence` and `list_tactical_feature_evidence` updated to `SELECT evidence_id, evidence_json`.
  - Deserialization asserts `row["evidence_id"] == deserialized.evidence_id`, raising `TacticalEvidenceIdentityError` on any mismatch.
- **Proof:** `test_b1_r2_row_key_embedded_id_corruption` verifies row-key corruption is detected and fails closed.

### Defect 5: PolicyState + Identity Tampering Rejection
- **Defect:** Need to verify that any modification of `policy_state_before` in database or canonical JSON breaks evidence identity.
- **Repair:** Deserialization and query methods fail closed with `TacticalEvidenceIdentityError` if `policy_state_before` is modified without recomputing `evidence_id`.
- **Proof:** `test_b1_r2_policystate_identity_corruption` passes.
