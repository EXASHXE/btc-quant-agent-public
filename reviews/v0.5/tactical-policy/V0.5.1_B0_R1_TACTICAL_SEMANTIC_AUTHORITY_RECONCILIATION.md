## 2. Reconciled Semantic Authorities

### 2.1 Benchmark Volatility Shock (Strict Fail-Closed)
- In `src/btc_quant_agent/market_watch/context.py`, completely eliminated fallback from `return_1h` to `tf_1h.roc` for both BTC and ETH.
- When `return_1h is None`, explicit audit reason codes `BTC_RETURN_1H_UNAVAILABLE` and `ETH_RETURN_1H_UNAVAILABLE` are recorded.
- Shock conditions cannot fire when `return_1h is None`, strictly preventing legacy 12-hour bar-count ROC from triggering 1-hour volatility shocks.

### 2.2 Relative Strength Return Extraction (No ROC Fallback)
- In `src/btc_quant_agent/market_watch/ranking.py`, removed legacy fallback from `return_1h`, `return_4h`, `return_12h` to `tf_1h.roc`, `tf_4h.roc`, `tf_15m.roc`.
- Missing returns strictly preserve `None`.
- Reference universe members with missing returns are recorded in `incomplete_return_members`.

### 2.3 Reference Universe Degradation (`TACTICAL_RS_UNIVERSE_V1`)
- In `ranking.py`, universe status degrades to `UNIVERSE_DEGRADED` if any member of the canonical 8-symbol reference universe is missing from snapshots OR has incomplete returns (`return_1h`, `return_4h`, or `return_12h` is `None`).
- When degraded:
  - `incomplete_return_members` lists degraded members.
  - Cross-sectional median returns are neutralized (`None`).
  - Cross-sectional percentile rank is disabled (`rank = 0`).
  - BTC and ETH pairwise relative returns continue independently.

### 2.4 RelativePerformance Domain Model
- In `src/btc_quant_agent/market_watch/domain.py`:
  - Deprecated legacy field `perf_15m` is initialized to `None` and is strictly never populated from `perf_1h`.
  - Added field `incomplete_return_members: tuple[str, ...] = ()`.
  - Added canonical dictionary serializer `as_dict()` exposing all canonical B0 fields without `perf_15m`.

### 2.5 DerivativesRegime Price Horizon Reconciliation
- In `src/btc_quant_agent/market_watch/scanner.py`, reorganized `collect_symbol_snapshot` so that confirmed closed-bar returns (`r1h, r4h, r12h`) are computed before calling `evaluate_derivatives_regime`.
- Passed true `price_change_1h_pct=r1h` instead of legacy `tf_1h.roc`.
- In `src/btc_quant_agent/market_watch/derivatives.py`:
  - Updated signature to `price_change_1h_pct: float | None`.
  - When `price_change_1h_pct is None`:
    - Sharp deleveraging (`oi_1h <= -0.04` or `oi_4h <= -0.07`) yields `DerivativesRegime.DELEVERAGING` (never upgraded to `LONG_LIQUIDATION`).
    - Crowding checks without price yield `LONG_CROWDING` or `SHORT_CROWDING`.
    - Price-dependent states (`HEALTHY_LONG_BUILD`, `HEALTHY_SHORT_BUILD`, `SHORT_COVERING`, `LONG_LIQUIDATION`) are strictly prevented from firing.
    - Otherwise defaults safely to `DerivativesRegime.NEUTRAL`.

### 2.6 Entry Quality Multi-Bar Extension
- In `src/btc_quant_agent/market_watch/entry_quality.py`, replaced ambiguous `tf.roc` with explicit `tf.roc_12bars` in `multi_bar_extension_atr` calculation.

### 2.7 Code vs Documentation Alignment
- Documented actual implementation behavior of `select_playbook_candidate` in `playbooks.py`: candidates are selected strictly by frozen precedence order (`TREND_PULLBACK > BREAKOUT_RETEST > FAILED_BREAKOUT > FAILED_BREAKDOWN > VOLATILITY_EXPANSION`), without promoting `ACTIONABLE` over earlier `WATCH` candidates.
- Clarified that `ReturnAvailability` has exactly 3 enum values: `AVAILABLE`, `INSUFFICIENT_HISTORY`, `MISSING_HORIZON_ANCHOR` (removed references to non-existent `UNFORMED_SERIES`).
