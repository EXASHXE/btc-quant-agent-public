## 1. Executive Summary & Defect Closures

The B1-R1 repair contract seals the semantic, cryptographic, and point-in-time (PIT) evidence authority of `TacticalFeatureEvidenceV2`. All defects identified in the Controller review of B1 have been addressed and proved by tests.

### Exact Defect Closures
1. **Deep Immutability**: All fields in `TacticalFeatureEvidenceV2` and nested structures are frozen dataclasses with tuples for collections. No mutable `dict`, `list`, or `set` is reachable. `DecisionConfigEvidence` stores configuration as an immutable `canonical_json` string and returns detached copies via `.to_dict()`.
2. **Cryptographic Identity Verification**: 
   - `evidence_id` format is verified with `^[0-9a-f]{64}$`.
   - `verify_tactical_evidence_identity(evidence)` asserts that `evidence_id == compute_evidence_id(evidence)`.
   - The builder pipeline follows: provisional -> validate -> hash -> final -> validate -> verify identity -> return.
   - Persistence layer verifies identity before SQLite insertion.
   - Read path (`get_tactical_feature_evidence`, `list_tactical_feature_evidence`) verifies identity upon deserialization, failing closed with `TacticalEvidenceIdentityError` on tampered records.
3. **Canonical Non-Finite Float Rejection**:
   - `canonical_json_dump` enforces `allow_nan=False`, converting `ValueError` into `TacticalEvidenceValidationError`.
   - `_assert_finite_number` pre-checks all numeric primitives recursively.
4. **Full Config Self-Containment & Hash Reproducibility**:
   - `DecisionConfigEvidence` captures the complete 23-key payload used in `market_watch_config_hash_payload`.
   - `compute_market_watch_config_hash_from_payload` is added to reproduce `config_hash` directly from stored evidence config.
   - Regression proof guarantees unchanged hashes: default `27f7d4c835a36330`, custom `bc35d7240d77cea0`.
5. **Playbook-Input Feature Completeness**:
   - `TimeframeFeaturesEvidence` includes `latest_closed_bar` (`ClosedBarEvidence` capturing open/high/low/close/volume/quote_volume/trades), `is_volatility_expanded`, and `has_prior_compression_window`.
   - `DerivativesFeaturesEvidence` includes `risk_codes` and `reasons`.
6. **Pre-Decision Policy State Evidence**:
   - Captured in `PolicyStateInputEvidence` (previous setup, breakout state, levels, timestamps, lifecycle state, signal ID, setup key) and attached as `policy_state_before`.
7. **Point-In-Time (PIT) & Causality Invariants**:
   - All source event timestamps (closed-bar watermarks, receipt timestamps, past derivatives events, collection timestamps) must satisfy $\le \text{decision\_time\_ms}$.
   - Scheduled future timestamps (specifically `funding_time_ms`) are explicitly verified as permitted to exceed decision time.
   - Return observation spans must satisfy: $\text{horizon\_ms} == (\text{latest\_close\_time\_ms} - \text{anchor\_close\_time\_ms})$, with anchor $\le$ latest $\le$ decision time. Unavailable returns require null value and anchor.
8. **Schema & Policy Authority Invariants**:
   - Schema version (`TACTICAL_FEATURE_EVIDENCE_V2`), policy version (`TACTICAL_POLICY_R2_B0`), rule score semantics (`RULE_SCORE_V1`), and semantic identity fields are verified in `validate_tactical_feature_evidence`.
   - Candidate set completeness: exactly the 5 active playbooks (`ACTIVE_PLAYBOOKS`), strictly excluding `RANGE_MEAN_REVERSION` (which remains `RESERVED_INACTIVE_PLAYBOOKS`).
9. **Natural-Key Uniqueness & Concurrency**:
   - Unique index `idx_tactical_feat_ev_natural_key` on `(symbol, decision_time_ms, policy_version, config_hash)`.
   - Idempotent re-save of identical evidence succeeds.
   - Divergent evidence for the same natural key raises `TacticalEvidenceConflictError`.
   - Store startup (`_init_db`) runs an integrity query detecting existing conflicting natural keys and fails closed (`B1_R1_EXISTING_EVIDENCE_CONFLICT`).
10. **Atomic Persistence Rollback**:
    - Mid-transaction failure between evidence persistence and assessment persistence rolls back atomically in SQLite, leaving 0 orphaned rows.
11. **Full Population Proof**:
    - Population proof passes for `LONG`, `SHORT`, `WAIT` (with candidate setup), and `WAIT` + `NO_TRADE`.
    - In `TacticalFeatureEvidenceV2`, `selected_playbook` is normalized to `None` when no active trade is selected.
12. **Documentation & Semantic Reconciliation**:
    - Reconciled documentation to reflect exact implemented fields and validated behaviors without aspirational claims.
