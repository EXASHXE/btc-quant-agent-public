## 1. Executive Summary & Root Cause Analysis

B2A-R2 closes the exit event uncertainty to funding settlement causality gap in Stage B2A.

### Root Cause
While B2A previously modeled entry uncertainty through `fill_interval_start_ms`, `fill_interval_end_ms`, and `fill_time_resolution`, terminal TP1/STOP outcomes used only point timestamp `exit_time_ms` (which was typically the close timestamp of the proving candle). A candle close timestamp is not an exact execution timestamp. Consequently, verifying `funding_time_ms <= exit_time_ms` was insufficient to prove that the position was still open at funding settlement.

### Sealed Architectural Invariants

1. **Terminal Uncertainty Interval:**
   - Added additive fields to `market_watch_shadow_records` and `TacticalShadowEvaluationV2`:
     - `exit_interval_start_ms: int | None`
     - `exit_interval_end_ms: int | None`
     - `exit_time_resolution: str | None`
   - Taxonomy:
     - `ONE_MINUTE_TERMINAL_INTERVAL`: For terminal TP1/STOP proven from a 1m candle (`exit_interval_start_ms = c1.open_time_ms`, `exit_interval_end_ms = c1.close_time_ms`, `exit_time_ms = c1.close_time_ms`).
     - `FIFTEEN_MINUTE_FALLBACK_INTERVAL`: For TP1/STOP proven only from a 15m candle (`exit_interval_start_ms = c.open_time_ms`, `exit_interval_end_ms = c.close_time_ms`, `exit_time_ms = c.close_time_ms`).
     - `HORIZON_TIMEOUT_BOUNDARY`: For TIMEOUT terminating at the preregistered deterministic horizon (`exit_interval_start_ms = evaluation_end_ms`, `exit_interval_end_ms = evaluation_end_ms`, `exit_time_ms = evaluation_end_ms`).

2. **Funding Settlement Causality Classification:**
   - A funding settlement is evaluated against both entry and exit uncertainty intervals:
     - **Before proven entry (`funding_time_ms < fill_interval_start_ms`):** Excluded as `NOT APPLICABLE`.
     - **Ambiguous entry boundary (`fill_interval_start_ms <= funding_time_ms <= fill_interval_end_ms`):** Classified as `AMBIGUOUS_FILL_BOUNDARY`. Authoritative funding PnL is unavailable.
     - **Proven holding interval (`funding_time_ms > fill_interval_end_ms and funding_time_ms < exit_interval_start_ms`):** The position is provably open throughout the timestamp. Settled authoritatively.
     - **Ambiguous exit boundary (`exit_interval_start_ms <= funding_time_ms <= exit_interval_end_ms`):** Classified as `AMBIGUOUS_EXIT_BOUNDARY`. No authoritative realized funding may be assigned.
     - **After exit (`funding_time_ms > exit_interval_end_ms`):** Excluded as `NOT APPLICABLE`.

3. **Ambiguity Precedence:**
   - If an evaluation contains multiple funding settlements and ANY relevant settlement is `AMBIGUOUS_FILL_BOUNDARY` or `AMBIGUOUS_EXIT_BOUNDARY`, aggregate authoritative funding PnL remains unavailable (`funding_pnl_r = None`, `funding_cash_total = None`, `net_r_after_funding = None`). Partial summation is strictly forbidden.

4. **Embedded Identity Protection on Authoritative Reads:**
   - Updated `get_shadow_evaluation`, `get_shadow_evaluation_by_shadow_id`, and `list_shadow_evaluations` in `MarketWatchStateStore` to require `evaluation_id` embedded in `evaluation_json`, raising `TacticalShadowEvaluationIdentityError` on any missing or tampered identity.

5. **Self-Contained Evaluation Artifacts:**
   - Updated `TacticalShadowEvaluationV2` validator to enforce strict consistency:
     - For `NO_FILL`: `exit_interval_start_ms`, `exit_interval_end_ms`, `exit_time_resolution` must all be `None`.
     - For `FILLED`: all three fields are required; `exit_time_resolution` must adhere to the taxonomy; `exit_interval_start_ms <= exit_interval_end_ms`; `exit_time_ms` must be within `[exit_interval_start_ms, exit_interval_end_ms]`.
     - For `TIMEOUT`: `exit_interval_start_ms == exit_interval_end_ms == evaluation_end_ms` and `exit_time_resolution == HORIZON_TIMEOUT_BOUNDARY`.
     - For `TP1` / `STOP`: `exit_time_ms == exit_interval_end_ms`.
