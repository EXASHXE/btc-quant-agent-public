## 3. Root Cause Analysis

Profiling of `quantctl forward-evidence health` over 24 production SQLite partitions (~45 GB total) identified four compounding $O(\text{history})$ hot paths executed every 15 minutes:

1. **`finalized_full_hash_every_health` (P0-A)**:
   `MicrostructureStore.partition_integrity_audit()` recomputed SHA-256 over all 24 finalized SQLite partitions by streaming all ~45 GB from disk on every health invocation because cache-v2 only stored operational statistics without cryptographic attestation fingerprints.
2. **`active_quick_check_every_health` (P0-B)**:
   `MicrostructureStore.status()` executed `PRAGMA quick_check` unconditionally on the active database every 15 minutes, performing full B-tree page verification during active capture, despite the partition already being validated via normal query operations and finalization already enforcing integrity.
3. **`full_history_bucket_materialization` (P0-C)**:
   `MicrostructureStore.status()` constructed a global Python set of candidate bucket timestamps (`bucket_candidates: set[tuple[int, int]]`) spanning the entire campaign history from day 1, allocating hundreds of thousands of candidate objects and evaluating coverage across all history every 15 minutes.
4. **`raw_gap_rows_cache` (P1)**:
   Cache-v2 materialized and serialized tens of thousands of raw gap rows `(start, end, type)` in JSON, causing cache file bloat (~6.88 MB in production), high serialization latency, and memory spikes.

### 4.2. Invariant & Structural Complexity Guarantees
1. **Zero Full-History Candidate Set**: Replaced global `bucket_candidates` set with incremental finalized partition `bucket_summary` reuse ($O(1)$ lookups per finalized day per interval).
2. **Zero Historical Finalized Reads on Warm Health**: Verified manifest SHA is bound to stat-fingerprint attestation (`st_mtime_ns`, `st_size`, `st_dev`, `st_ino`, `st_ctime_ns`). Warm health executes $0$ byte reads against finalized partitions.
3. **Zero Active Quick Check on Ordinary Health**: Active partition is validated via normal read queries and error handlers; deep `PRAGMA quick_check` is reserved for explicit audit commands (`quantctl microstructure audit`).
4. **Mandatory Finalization Checkpoint & Quick Check**: `finalize_partitions` truncates WAL checkpoints and requires `PRAGMA quick_check == "ok"` before computing SHA-256 and publishing to manifest.
5. **Exact Rolling Gap Counts**: 24h and 7d rolling raw gap counts are calculated using exact boundary SQL queries, active partition gap scans, and spill-gap tracking without expanding raw gap row arrays in cache.
