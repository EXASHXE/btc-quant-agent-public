# V0.5.1 H40-P1R4 Canonical Source Root Binding Repair Implementation Report

## 1. Executive Summary

This report documents the completed implementation of **Phase 1 Repair 4 (H40-P1R4)** of the H40 research pipeline, closing finding **P1RRR-F1 (HIGH)** identified during the Sol Independent Review (`reviews/v0.5/V0.5.1_H40_P1RRR_SOL_INDEPENDENT_REVIEW.md`):

- **Finding P1RRR-F1 (HIGH)**: Canonical H40 source root is caller-substitutable.
  In H40-P1RRR, `assert_authoritative` enforced mandatory cold verification against disk files and cold reconstruction of split partitions from source timestamp intersections. However, the locator itself remained caller-defined: a caller could construct a custom `H40SourceManifest` pointing `BTCUSDT_USD_M_1H` to an arbitrary path (e.g. `data/research/custom_btc.parquet`) containing valid schema and timestamps, generating a valid cold attestation and acquiring authoritative split status.
- **Remediation**:
  1. **Layer 1 Canonical Source Specifications**: Defined immutable canonical source specifications (`H40CanonicalSourceSpec`) derived directly and deterministically from `H40SourceManifest.build_preregistered_reference(protocol_identity_hash)` for canonical sources `BTCUSDT_USD_M_1H` and `ETHUSDT_USD_M_1H`.
  2. **Correspondence Enforcement**: Materialized source authority must prove correspondence to the canonical spec via `assert_canonical_source_record(record, protocol_identity_hash)`, verifying locator, product, cadence, archive checksum lineage (`archive_set_sha256`), and frozen reference file SHA (`reference_file_sha256`).
  3. **Caller Replacement Reference Neutralization**: Caller-supplied `reference_manifest` objects in `materialize_verified_manifest` cannot redefine canonical production H40 authority. Production split authority always verifies against the canonical spec independently derived from protocol identity.
  4. **Explicit Authority Policy Object**: Implemented `H40AuthorityPolicy` (`production_canonical()` vs `test_synthetic()`), cryptographically binding `is_production_canonical` into the split attestation preimage and hash. Default production policy strictly enforces canonical specifications; synthetic policy is permitted only in test scaffolding to exercise low-level validator mechanics.
  5. **Truthful Environment Accounting**: In the executing environment (`.`), `ETHUSDT_USD_M_1H` at `data/research/cross_asset_1h/ETHUSDT.parquet` matches the canonical spec and is `VERIFIED`. `BTCUSDT_USD_M_1H` at `data/research/BTCUSDT/data_manifest.json` is a legacy 1m manifest (`timeframe: "1m"`), yielding `NOT_TESTABLE` (`INTERVAL_MISMATCH`). Success was NOT fabricated, no substitute file was substituted, and production split materialization honestly fails closed with `SOURCE_UNVERIFIED`.
  6. **12 Mandatory Adversarial Tests**: Added 12 focused adversarial unit tests in `tests/test_v051_h40_p1_scaffold.py` proving that non-canonical locators, tampered products/cadences/checksums, unauthorized source IDs, and caller manifests cannot acquire production split authority.

Strict pre-outcome discipline was maintained throughout: ZERO directional labels, ZERO forward returns, ZERO MFE/MAE, ZERO feature calculations, ZERO candidate model searches, ZERO backtests, and ZERO confirmation holdout outcome evaluations.

## 3. Canonical Source Spec Design & Architecture

### 3.1 Immutable Canonical Source Specification (`H40CanonicalSourceSpec`)

Implemented in `src/btc_quant_agent/h40/source_manifest.py`:

```python
@dataclass(frozen=True)
class H40CanonicalSourceSpec:
    """Immutable canonical semantic specification for an authorized H40 data source."""

    source_id: str
    product: str
    cadence: str
    locator: str
    allowed_role: str
    origin_provenance: str
    reference_file_sha256: str | None
    archive_set_sha256: str | None
    protocol_identity_hash: str
```

### 3.2 Authority Policy (`H40AuthorityPolicy`)

Distinguishes production canonical split authority from test-only synthetic validator mechanics:

```python
@dataclass(frozen=True)
class H40AuthorityPolicy:
    """Controls canonical source spec enforcement for authoritative split materialization."""

    enforce_canonical_specs: bool = True
    policy_name: str = "PRODUCTION_CANONICAL"

    @classmethod
    def production_canonical(cls) -> H40AuthorityPolicy:
        return cls(enforce_canonical_specs=True, policy_name="PRODUCTION_CANONICAL")

    @classmethod
    def test_synthetic(cls) -> H40AuthorityPolicy:
        return cls(enforce_canonical_specs=False, policy_name="TEST_SYNTHETIC")
```

### 3.3 Cryptographic Attestation Binding (`is_production_canonical`)

`H40SplitAttestation` binds `is_production_canonical: bool`:
- Included in dataclass fields, `to_dict`, `from_dict`.
- Included in RFC-8259 canonical JSON preimage.
- Embedded into `attestation_hash`.
- `assert_authoritative` under production policy requires `attestation.is_production_canonical is True`.

### 3.4 Verification Functions

- `get_canonical_source_spec(protocol_identity_hash, source_id)`:
  Derives canonical spec directly from `H40SourceManifest.build_preregistered_reference(protocol_identity_hash)`. Fails closed (`SOURCE_UNVERIFIED`) if `source_id` is unknown or not an authorized primary split input (`BTCUSDT_USD_M_1H`, `ETHUSDT_USD_M_1H`).
- `assert_canonical_source_record(record, protocol_identity_hash)`:
  Validates that `record` strictly matches the canonical spec:
  - `record.product == spec.product` (fails with `PRODUCT_MISMATCH`)
  - `record.cadence == spec.cadence` (fails with `INTERVAL_MISMATCH`)
  - `record.locator == spec.locator` (fails with `SOURCE_UNVERIFIED`)
  - `record.archive_set_sha256 == spec.archive_set_sha256` (fails with `SOURCE_HASH_MISMATCH`)
  - `record.file_sha256 == spec.reference_file_sha256` where frozen by reference (fails with `SOURCE_HASH_MISMATCH`)
