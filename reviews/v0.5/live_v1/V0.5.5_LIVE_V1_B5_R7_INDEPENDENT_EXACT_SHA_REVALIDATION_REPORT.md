## Material finding: completion can be fabricated with SQLite REPLACE

V5 fails. The dispatch completion trigger guards `UPDATE OF analysis_completed`; an ordinary `INSERT OR REPLACE` against an existing dispatch does not execute that update guard. The shared SQLite connection leaves `PRAGMA recursive_triggers=0`, so the REPLACE implicit delete also bypasses the delete trigger.

On a fresh disposable database, after creating a normal event and dispatch, with all four dispatch triggers installed and no provider call, this statement succeeds:

```sql
INSERT OR REPLACE INTO live_position_case_dispatches
  (event_id,event_hash,symbol,state,analysis_completed,created_at_ms,updated_at_ms)
VALUES (?, ?, ?, 'DONE', 1, ?, ?);
```

Observed poststate: `state=DONE`, `analysis_completed=1`, and empty `analysis_admission_hash`, `dispatch_authority_hash`, `position_case_id`, `position_case_hash`, `position_case_json`, and `case_hash`; provider calls: 0. This violates the required atomic completion-marker authority fence and is sufficient for the FAIL decision. No implementation repair was made.
