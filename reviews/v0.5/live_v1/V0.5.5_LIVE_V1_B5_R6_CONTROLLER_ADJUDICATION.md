## Controller disposition

The independent FAIL is accepted.

One material F03 residual remains:

`R6-F03-RESIDUAL-TOCTOU`

The defect is not ordinary application DML bypass. With intact SQLite triggers, the normal UPDATE/
DELETE attempts are rejected. The validation deliberately bypassed the trigger layer in disposable
fixtures to test the *second* R6 requirement: durable transition binding and check/use safety.

That is a valid test of the frozen R6 contract because R6 required both:

1. schema-level authority immutability; and
2. independent durable-authority revalidation / transition binding.

The current implementation re-verifies event + dispatch authority, closes the read connection, then
later invokes external analysis or performs DONE. The terminal UPDATE binds dispatch event_hash,
symbol, lease and frozen-case identity, but it does not atomically prove that the canonical
`live_position_events` authority still matches the frozen dispatch authority at terminal use.

The result is a residual check -> use gap. Under the independent fixture, event authority can be
changed after the final re-read and before DONE, while the dispatch row remains unchanged, and DONE
can still succeed.

## Why this is a new material finding

This is not a repeat of the R5 F03 defect.

R5 F03:
- mutable event/outbox authority after claim;
- analysis and DONE could proceed without durable lifecycle checks.

R6 correctly added:
- event/dispatch immutability triggers;
- five lifecycle revalidation checkpoints;
- lease/case/event-hash predicates.

The remaining defect exists only at the final atomicity boundary between successful revalidation and
the external/terminal use. This is materially narrower new evidence and justifies one bounded repair.

## R7 semantic direction

Do not add more checkpoints. Additional read-then-use checks would recreate the same TOCTOU shape.

R7 must establish one explicit durable authority handoff for external analysis, preferably:

`IMMUTABLE_AUTHORITY_CAPSULE + ATOMIC_ANALYSIS_ADMISSION_RECEIPT`

or an equivalent mechanism with the same semantics.

The core rule:

> The provider call must consume a one-shot authority that was atomically minted from the exact
> event + dispatch + frozen-case authority. DONE must bind that same authority and must not be able
> to succeed against a divergent canonical event row.

This avoids trying to make an arbitrary Python gap between a SELECT and an await "small enough."

## Required R7 invariant

Before analysis admission:

- canonical PositionEvent hash/payload/authority must match;
- dispatch event_hash/symbol/full authority capsule must match;
- lease owner must still be current;
- frozen PositionCase hash/json/event linkage must match.

Mint exactly one immutable analysis-admission identity/hash in one SQLite transaction.

After admission:
- external analysis may consume only the frozen PositionCase + admission authority;
- any mutation of the dispatch authority/admission identity must invalidate completion;
- final DONE must bind the admission identity and atomically require canonical event authority
  consistency, e.g. through an EXISTS/join predicate or equivalent transactionally checked invariant.

Do not keep treating repeated re-reads as the authority boundary.

## Crash/retry requirement

R7 must explicitly define the crash state between durable analysis admission and external provider
completion.

It may use:
- an existing provider idempotency primitive if already authoritative; or
- fail-closed recovery/manual disposition when completion is uncertain.

It must not blindly duplicate an external analysis side effect merely because a lease expired.

Do not broaden this repair into a new generic workflow engine.
