## Controller-confirmed findings

### R5-F01 — HIGH / B5 blocker — typed alias ambiguity in protective contract

`protective_field()` compares aliases with ordinary Python equality:

```python
if primary in raw and alias in raw and raw[primary] != raw[alias]:
    ...
```

Python considers `1.0 == True`. Therefore a response containing, for example,
`quantity=1.0` and `origQty=true` is treated as alias-consistent. The helper then returns the
primary numeric value, so the later `isinstance(quantity, bool)` guard never sees the malformed alias.

This permits a malformed protective confirmation to become ACTIVE.

Classification:

`HIGH_PROTECTIVE_TYPED_ALIAS_AMBIGUITY`

### R5-F02 — HIGH / B5 blocker — runtime authority can change across async handoff

`LiveV1Runtime.execute_intent()` evaluates readiness, then awaits fresh-case preparation, then
hands off new-risk execution without re-reading current runtime/account authority.

A valid snapshot can therefore become invalid during the await. Independent validation reproduced
a transition to a validly hashed snapshot containing an unconfigured nonzero symbol; current
readiness correctly became invalid, yet execution handoff still occurred. The integrated fake backend
probe reached one fake entry POST.

The periodic REST path has the related stale-result pattern: after awaited work it can update the
internal `accepting_risk` flag using an earlier reconciliation result rather than the latest account
authority.

Classification:

`HIGH_RUNTIME_AUTHORITY_ASYNC_HANDOFF_STALE`

### R5-F03 — HIGH / B5 blocker — outbox authority not immutable through external side effects

PositionSupervisor verifies the event/dispatch-row relationship immediately after claim, but later
freeze, lease-renew, analysis and DONE transitions bind lease/case fields without re-establishing the
immutable event authority.

A concurrent writer can alter event/dispatch authority after the initial check. Independent
reproductions changed symbol/event hash and all stored PositionEvent identity/authority fields during
fresh-market materialization or analysis. The dispatch could still call analysis and reach DONE.

Classification:

`HIGH_POSITION_OUTBOX_AUTHORITY_MUTABLE_AFTER_CLAIM`
