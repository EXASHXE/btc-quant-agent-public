# B-line Initial Usable Release V1 RC1 — Controller Release Contract

Release ID: `B_LINE_INITIAL_USABLE_RELEASE_V1_RC1`

Base implementation SHA: `08e81bec003d645a0a0582db183a1b6916887eff`

Authority class: B-line operational/tactical engineering. This contract does not create A-line scientific authority.

## Objective

Produce one genuinely runnable end-to-end B-line release candidate using real public market data and DRY_RUN / TESTNET execution, with durable approval, reconciliation, restart/recovery, observability, and fail-closed behavior.

Canonical flow:

```text
real public market data
-> MarketWatch / Tactical assessment
-> immutable CasePackage
-> configured primary LLM analysis
-> optional bounded Codex secondary review
-> DecisionFusion
-> deterministic RiskCompiler
-> TradeProposal
-> Feishu notification / approval
-> approval-bound immutable intent
-> PreExecutionValidator
-> DRY_RUN or TESTNET execution
-> order/fill/protective state
-> position reconciliation
-> PositionSupervisor
-> material position event
-> new CasePackage / analysis / notification
```

## RC1 supported initialization contract

`SERIALIZED_SINGLE_RUNTIME_INITIALIZER`

For one durable Live V1 database path:
1. exactly one initializer may perform schema initialization/migration at a time;
2. no LiveV1Runtime may enter started/ready state before initialization succeeds;
3. concurrent cold-start contenders must be mechanically serialized or fail closed before yielding a usable runtime;
4. RC1 does not claim support for racing cold schema initialization by multiple independent workers;
5. restart after completed initialization must be deterministic and idempotent.

The implementation mechanism is not frozen. It may use a bounded SQLite-backed initializer boundary, process-safe file/DB lock, or equivalent repository-local primitive. Do not add distributed migration infrastructure for RC1.
