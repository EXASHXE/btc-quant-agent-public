## Controller-confirmed findings

### BLOCKER — PENDING recovery can promote protection without exact-ID confirmation

Recovery currently may use aggregate `open_protective_orders(symbol)` results to match the stored
clientAlgoId and then record the stop ACTIVE. For a `PENDING_CONFIRMATION` owner this can occur
without a successful retry of `query_protective_order(exchange_id)`.

Aggregate listing is not a substitute for exact-ID installation authority after an uncertain POST.

Classification:

`BLOCKER_PENDING_PROTECTION_RECOVERY_LACKS_EXACT_ID_CONFIRMATION`

### HIGH — confirmation omits submitted protective execution semantics

`_validate_protective_contract` verifies symbol, side, STOP_MARKET, positionSide, reduceOnly,
trigger, quantity and status, but does not verify the requested:

- algoType = CONDITIONAL;
- workingType = MARK_PRICE;
- priceProtect = TRUE;
- closePosition = false.

Classification:

`HIGH_PROTECTIVE_CONFIRMATION_CONTRACT_INCOMPLETE`

### HIGH — flat reconciliation can discard unresolved remote stop identity

When position quantity becomes flat, current reconciliation can call `release_flat()`, which clears
`exchange_id` and marks the owner RELEASED even when the owner is still
`PENDING_CONFIRMATION` and exact remote absence/cancellation has not been established.

Classification:

`HIGH_FLAT_RELEASE_CAN_DISCARD_UNRESOLVED_PROTECTION_AUTHORITY`

### HIGH — runtime admission does not uniformly validate configured account authority

Startup and periodic readiness primarily test reconciled/quality/stream/kill-switch state.
They do not consistently perform:

- snapshot.verify();
- environment equality;
- credential namespace equality;
- configured account_id equality

before setting `accepting_risk=true`.

`poll_positions()` has stronger checks, but startup/readiness/execute admission must share the same
authority gate.

Classification:

`HIGH_RUNTIME_READINESS_ACCOUNT_AUTHORITY_NOT_SINGLE_GATE`

### HIGH — outbox dispatch symbol not bound to event authority

PositionCase materialization calls:

`fresh_market_case(claimed_row["symbol"])`

without first proving the persisted dispatch-row symbol equals the verified PositionEvent symbol.

A corrupted row can therefore generate a case for a different symbol while retaining the original
event hash.

Classification:

`HIGH_POSITION_OUTBOX_SYMBOL_NOT_BOUND_TO_EVENT`
