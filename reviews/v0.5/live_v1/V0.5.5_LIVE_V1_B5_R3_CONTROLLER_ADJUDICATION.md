## Controller-confirmed BLOCKER — malformed protective confirmation accepted

The implementation currently performs:

```python
stop_id = str(raw_stop.get("algoId", raw_stop.get("orderId", "")))
```

A provider response containing `{"algoId": null}` therefore becomes the non-empty string
`"None"`.

`ProtectionStore.record_stop()` rejects only an empty exchange_id, so `"None"` is accepted,
stored as an installed protective stop, and can leave the kill switch permissive even though no
verifiable protective order identity exists.

Classification:

`BLOCKER_PROTECTIVE_CONFIRMATION_IDENTITY_NOT_FAIL_CLOSED`

Required invariant:

```text
protective placement response
-> validate canonical exchange ID type/value
-> verify exact protective contract / owner identity
-> only then persist INSTALLED/ACTIVE protection
```

Any malformed, null, missing, conflicting, or unverifiable protective confirmation must keep/trip
the kill switch and enter reconciliation. It must never be represented as installed protection.

## Controller-confirmed HIGH — cooldown/dedupe lacks account authority

`live_position_events` has no account_id column. Cooldown lookup is:

```text
WHERE symbol=? AND trigger=?
```

Therefore two accounts sharing a symbol/trigger share one cooldown namespace.

Classification:

`HIGH_POSITION_EVENT_COOLDOWN_NOT_ACCOUNT_SCOPED`

Required invariant:

```text
event/cooldown/dedupe authority
= account authority + symbol + position_side + trigger
```

Account A must never suppress account B's material event or case dispatch.

## Controller-confirmed conditional HIGH — lifecycle authority omits environment/credential namespace

`PositionObservationV1` carries account_id but no environment or credential namespace.
`live_position_lifecycle` keys only:

```text
account_id + symbol + position_side
```

LiveV1Config also defaults account_id to `DEFAULT_ACCOUNT`. Reusing one DB/account identifier
across DRY_RUN/TESTNET or credential namespace changes can therefore inherit stale lifecycle state.

Classification:

`HIGH_POSITION_LIFECYCLE_ENVIRONMENT_NAMESPACE_COLLISION`

This is conditional on incompatible DB/account reuse, but the repair should close it now rather than
leave mode-switch behavior implicit.
