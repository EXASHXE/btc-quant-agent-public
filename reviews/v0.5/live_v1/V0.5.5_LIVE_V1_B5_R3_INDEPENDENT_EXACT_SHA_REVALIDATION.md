## Confirmed findings and repair requirements

### BLOCKER B2-null-algo-id: malformed protection confirmation is accepted

At `src/btc_quant_agent/execution/backend.py:697`, a protective response `{"algoId": null}`
is converted to the nonempty string `"None"`. Through the public `submit_authorized` path, a
fake filled entry returned `ExecutionReport(status="FILLED", protective_stop_id="None")`.
SQLite recorded a NEW protective order and ACTIVE owner with exchange ID `"None"`, while
the kill switch continued to allow new risk. No authoritative confirmation query followed placement.

Repair must validate the protective response identity and expected owner contract before recording
installed protection. Malformed or uncertain confirmation must trip or retain the kill switch and
reconcile using exact ownership. Evidence: `b5_r3_authority_probe.py` and
`b5-r3-authority-reproduced.log` in the artifact directory below.

### HIGH B5-R3-H2-ACCOUNT-COOLDOWN: one account suppresses another account's event

At `src/btc_quant_agent/position_supervisor/supervisor.py:284`, cooldown queries use symbol
and trigger but no account identity. In temporary SQLite, account B was already open; account A
then emitted STOP_NEAR; B's independent STOP_NEAR observation one millisecond later emitted no
event or case dispatch. Repair must scope cooldown and deduplication to the complete account authority.
Evidence: `b5_r3_h2_account_probe.py` and `b5-r3-h2-reproduced.log`.

### Conditional HIGH: environment/namespace lifecycle collision

Position lifecycle identity omits environment and credential namespace. Reusing one database and
account ID across DRY_RUN and TESTNET can inherit earlier position state and suppress an opening
event. The model/supervisor fixture reproduced this collision; a full runtime mode switch was not
exercised. Repair should bind lifecycle state to environment/account authority, or reject incompatible
database reuse explicitly. This conditional finding is separate from the confirmed findings above.
