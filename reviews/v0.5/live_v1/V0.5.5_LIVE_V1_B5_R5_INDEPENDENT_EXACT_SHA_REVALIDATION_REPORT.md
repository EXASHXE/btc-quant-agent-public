## Findings that prevent PASS

### R5-F01 — malformed numeric alias confirms ACTIVE protection

For an approved intent with quantity 1.6472 and a current/filled position of 1.0, a complete exact protective response containing `quantity=1.0` and `origQty=true` was accepted. The owner became **ACTIVE**, quantity 1.0, after one POST. [protective_field at frozen source line 66](https://github.com/EXASHXE/btc-quant-agent-public/blob/a663921abf90504412d0d67b2b9c9f134f204d85/src/btc_quant_agent/execution/protection.py#L66) compares aliases with Python equality, under which `1.0 == True`. [The backend at line 693](https://github.com/EXASHXE/btc-quant-agent-public/blob/a663921abf90504412d0d67b2b9c9f134f204d85/src/btc_quant_agent/execution/backend.py#L693) validates only the returned primary numeric field. This fails R5-02's complete fail-closed quantity contract. Severity **HIGH**, validation blocker. The reproduction uses the normal claimed-intent recovery path and durable owner state, not only a direct helper call.

### R5-F02 — account authority can become invalid across awaited preparation

[execute_intent at lines 355–364](https://github.com/EXASHXE/btc-quant-agent-public/blob/a663921abf90504412d0d67b2b9c9f134f204d85/src/btc_quant_agent/live_runtime.py#L355) checks readiness before awaiting fresh-case loading and then unconditionally hands off new-risk execution. The coordinator changed the current snapshot during that await to a typed, validly hashed snapshot containing a nonzero unconfigured ETHUSDT position. Current readiness returned `UNCONFIGURED_POSITION_SYMBOL`, yet `execute_approved_intent` was awaited once. This fails R5-04's zero new-risk orchestration requirement. Severity **HIGH**, validation blocker. An additional [integrated probe](../../../evidence/v0.5.5/live_v1/B5_R5_INDEPENDENT_EXACT_SHA_REVALIDATION/runtime-real-service-probe.json) used the actual execution service and backend, forced fresh reads of that invalid-runtime-authority snapshot, and observed **one fake entry POST** with report `NEW`. The backend's validator does not enforce the runtime's configured-position-symbol restriction, so its later placement checks did not block this case. No real exchange write was attempted; all exchange methods remained mocked.

Periodic REST has the related stale-authority issue: after awaited preparation/recovery it may set the internal `accepting_risk=True` from an earlier valid REST result while latest-snapshot `status()` correctly says false. That narrower state-invariant failure is recorded as related evidence, not proof of a separate completed order.

### R5-F03 — outbox identity is not maintained through freeze, analysis and completion

[The initial event/dispatch comparison](https://github.com/EXASHXE/btc-quant-agent-public/blob/a663921abf90504412d0d67b2b9c9f134f204d85/src/btc_quant_agent/position_supervisor/supervisor.py#L575) uses a copied claimed row. [Subsequent freeze/lease/DONE writes](https://github.com/EXASHXE/btc-quant-agent-public/blob/a663921abf90504412d0d67b2b9c9f134f204d85/src/btc_quant_agent/position_supervisor/supervisor.py#L653) bind lease/case fields without revalidating immutable event/row authority. Deterministic concurrent SQLite changes during fresh-market materialization altered dispatch `event_hash` or `symbol`, or each of the eight stored PositionEvent identity/authority fields. All ten coordinator cases invoked analysis and reached **DONE**. This fails R5-05. Severity **HIGH**, validation blocker. The original dispatch schema contains event ID/hash/symbol; full authority fields are stored in the event table. Optional additional dispatch authority columns were tested separately in temporary test schemas, not added to implementation.

These attacks require a concurrent storage writer; callback writes reproduce that interleaving without timing luck. A mutation after a call has begun cannot retroactively make that earlier call count zero, but the observed invalid analysis admission and DONE transitions remain failures. Static corruption before claim is correctly rejected with zero market/analysis calls.
