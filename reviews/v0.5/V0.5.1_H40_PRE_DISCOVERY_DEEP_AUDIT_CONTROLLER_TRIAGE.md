## MED-01 Controller adjudication

### Finding

Current Parquet source extraction follows:

```text
file_path.read_bytes()
-> verify source_file_sha256
-> _extract_economic_rows(file_path, raw_bytes, ...)
-> pq.read_table(file_path)
-> canonical economic_rows_sha256 verification
```

JSON extraction consumes `raw_bytes` directly, while Parquet reopens the filesystem path.

### Severity

```text
MEDIUM
```

The Controller does not upgrade this to HIGH because an independently bound
`economic_rows_sha256` is recomputed after parsing and fails closed if the accepted H40 economic
rows differ. No demonstrated silent economic-value substitution survives that second digest.

### Governance decision

However, the issue **must close before P3 controller-authority publication**.

R2-F02 freezes the stronger invariant:

```text
Verifier re-extracts economic rows directly from sealed source bytes verified against file SHA-256.
```

For Parquet, reopening `file_path` does not literally satisfy that invariant even though the
second economic digest materially mitigates the integrity risk.

Therefore the required repair is mechanical:

```text
Parquet parser consumes raw_bytes via an in-memory Arrow/Parquet reader.
No filesystem reopen is permitted for economic parsing after source bytes are sealed/hashed.
```

This repair:

```text
scientific identity change = NO
Discovery provenance semantic change = NO
Lifecycle V5 semantic change = NO
```

It is an implementation-conformance repair to the already frozen F02 contract.

## MED-02 Controller ratification

### Ambiguity reviewed

R3R2 Section 3 states:

```text
TRAINING rows:
reference distribution at timestamp t uses ONLY observations strictly before t.

Minimum reference N = 60.

Warm-up:
no percentile value until N >= 60.
```

R2-F02 states:

```text
source support starts 2021-01-01T00:00:00Z
720-hour pre-2021-01-31 lookback reserve is non-evaluating
```

The split authority defines:

```text
BASE_ELIGIBLE_START_UTC = 2021-01-31T00:00:00Z
LOOKBACK_RESERVED = 720 hours
```

and explicitly excludes those reserve hours from partition/base-eligible membership.

### Controller interpretation

The Controller ratifies **Interpretation A** for First Discovery / WF1:

```text
H40_WF1_LOOKBACK_REFERENCE_INTERPRETATION_A
```

Exact meaning:

1. The interval

```text
[2021-01-01T00:00:00Z, 2021-01-31T00:00:00Z)
```

is non-evaluating source-history support.

2. Causally available raw feature observations reconstructed from that reserve **may contribute to
the expanding empirical percentile reference** for WF1_TRAIN, provided each reference observation:

```text
observation_time < decision_t
and
all source inputs satisfy close_time < observation_time
```

under the frozen feature formulas.

3. Reserve hours **must never** enter:

```text
base-eligible membership
WF1_TRAIN decision-row membership
evaluation denominator
labels/outcome rows
candidate counts
calibration-row membership
validation-row membership
candidate ranking population
```

4. The `N >= 60` percentile condition counts causally reconstructed reference scalars from the
reserve. Therefore the first WF1_TRAIN decision is not forced to NO_TRADE merely because fewer than
60 timestamps have elapsed since 2021-01-31.

5. This ratification applies to the **initial WF1 expanding reference only**. It does not alter the
R3R2 rule that later WF refits use that fold's chronologically past training partition only.

### Why this is a clarification, not new science

This interpretation preserves all already-frozen rules:

```text
strictly-prior PIT chronology
N >= 60
same percentile formula
same regime/opportunity thresholds
same 720-hour reserve
same base-eligible boundary
same source support interval
same current implementation behavior
```

It selects the meaning consistent with:

- R3R2's phrase `observations strictly before t`, which does not restrict the initial reference to
  evaluating decision rows;
- R2's designation `non-evaluating`, rather than `unusable for feature support`;
- the split manifest's treatment of reserve timestamps as source history excluded from eligible
  partition membership;
- the existing causal implementation, which uses reserve observations only as reference support.

Therefore:

