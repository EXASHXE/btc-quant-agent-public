## 3. Blocking finding

The current seal proves exact runtime **type**, but not exact runtime **behavior**.

The same commit modifies the lifecycle test fixture to construct the exact production verifier type without its constructor and then replace production verifier methods on the instance:

```python
verifier = object.__new__(H40ProductionDiscoveryEvidenceVerifier)
setattr(verifier, "verify_discovery_manifest", ...)
setattr(verifier, "verify_candidate", ...)
setattr(verifier, "verify_wf_fold", ...)
```

This object still satisfies:

```python
type(verifier) is H40ProductionDiscoveryEvidenceVerifier
```

and therefore passes the new production type guard.

Because `authorize_candidate_lock` subsequently dispatches through the instance:

```python
verifier.verify_discovery_manifest(...)
verifier.verify_candidate(...)
```

an exact-type instance can still shadow the reviewed class implementation.

The production verifier is a normal mutable Python class with an instance dictionary; no runtime mechanism in the reviewed change prevents these method shadows.

The same general issue applies to constructor-bound collaborators/state if they can be replaced on an exact-type object and are later trusted by the reviewed methods.

Therefore the current change does not yet establish the intended invariant:

```text
production candidate-lock scientific behavior
must come from the reviewed production verifier implementation
```

It establishes only:

```text
production verifier object's concrete Python type name/class identity
must match the reviewed class
```

Those are not equivalent in the current object model.

## 4. Why this is blocking

The project authority model is explicitly designed to prevent runtime objects or scripts from substituting scientific logic after preregistration.

A same-type object whose verification methods are instance-shadowed can return arbitrary hard-gate/LCB results while passing the current type check.

The repository already contains a concrete construction pattern proving that such an object can be materialized.

No real H40 outcomes need to be read to close this gap, so the correct action is fail-closed repair before P3B production acceptance.

## 5. Required repair property

The next repair must ensure that an exact-type verifier with instance-level behavior/dependency substitution cannot confer production candidate-lock authority.

Acceptable implementation directions include a narrow runtime implementation seal that:

- prevents instance shadowing of production scientific methods;
- prevents replacement of constructor-bound authoritative dependencies used by those methods;
- ensures production candidate-lock dispatches to the reviewed implementation;
- preserves synthetic test mode as a separate path.

Do not change P3B science, evidence schemas, frozen hashes, or lifecycle semantics merely to simplify tests.

If closing this gap requires changing a frozen governance contract, stop with a governance-amendment blocker rather than silently changing it.
