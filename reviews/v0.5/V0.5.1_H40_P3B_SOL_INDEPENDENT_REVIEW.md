## 3. Production authority blocker

The current production service constructor accepts:

```python

    implementation_authority=...,
    evidence_verifier=<any runtime object implementing H40LifecycleEvidenceVerifier>
)
```

and the only production-mode verifier restriction is effectively:

```text
implements the Protocol
AND
synthetic_only == False
```

The repository already contains test doubles such as `_ProductionEvidenceVerifier` that satisfy this condition.

There is no accepted verifier implementation hash/type/capability check in the production candidate-lock path.

Therefore a caller can construct a different object that:
- implements the three Protocol methods;
- reports `synthetic_only=False`;
- returns favorable `H40CandidateVerification` values;

and the lifecycle service has no implementation-identity check forcing use of the independently reviewed:

```text

```

This violates the intended lifecycle contract statement:

```text

```

and means the correct P3B verifier is materialized but not yet exclusive production authority.
