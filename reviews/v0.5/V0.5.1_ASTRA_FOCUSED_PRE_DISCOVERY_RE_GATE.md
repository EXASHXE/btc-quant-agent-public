### 5.2 RG-B02-01 — unverified links can incorrectly admit an orphan to committed lineage

**Classification: CURRENT_PRE_DISCOVERY_BLOCKER.** This is a remaining B-02 restoration-invariant defect, not a failure of SQLite's single-winner transaction.

**Exact file/symbol:** `src/btc_quant_agent/h40/lifecycle_authority.py:4598 :: H40LifecycleArtifactStore._get_committed_lineage`, called by `:4641 :: restore_authorization`; subsequent `:4462 :: _cold_restore_authorization` verifies only the requested receipt and its ancestors.

**Accepted invariant:** persistence/replay V2, canonical amendment §3: only the committed head or its unique verified ancestor lineage may restore as authority; fully published orphans confer no authority; malformed/hash-mismatched lineage fails closed. Final F01R3 acceptance §§3, 5 and 8 assert this closure.

**Concrete local current-code path:**

1. Through the exact issuing service and public `persist_authorization`, commit synthetic production-shaped Discovery `D`, then Candidate Lock `C`.
2. Issue valid termination `T` from `D`. Attempt to persist it after `C` won. The public store correctly rejects its stale predecessor, leaving fully published `T` as an orphan.
3. Control: `restore_authorization(run, T.hash, ...)` correctly rejects the orphan while committed receipt bytes are intact.
4. In the temporary fixture only, change `C`'s on-disk `receipt.upstream_receipt_hash` to `T.hash`. Do **not** change SQLite, `head_json`, `head_hash`, the content-addressed filename, `receipt_sha256`, or recompute any receipt hash.
5. Call the same public `restore_authorization(run, T.hash, ...)`.

Observed:

```text
head_unchanged: true
committed_head_state: H40_CANDIDATE_LOCKED
restored_orphan_state: H40_NO_GO
restored_is_original_orphan: true
```

The corrupted committed head receipt itself is rejected when requested directly. The asymmetry is the problem: `_get_committed_lineage` appends each advertised hash and follows raw `upstream_receipt_hash` without verifying the traversed envelope/receipt content against that hash. It therefore reports the false chain `C -> T -> D`. Cold restoration then verifies valid `T -> D`, never the corrupted `C` that supposedly established membership.

**Why it affects current research correctness:** a failed sibling commit is converted into a verified restored authorization by inconsistent local artifact lineage. No protected-data access, future execution authority, raw-head API or private commit helper is involved. A hash-integrity recovery boundary must reject this corrupted local state, not issue authority depending on which receipt the caller requests. The observed result does not mean the SQLite head changed or a real Discovery gate was crossed; it violates the accepted orphan/non-authority and reproducible-restoration contract of the lifecycle implementation being re-gated.

**Existing-test gap:** R49 and the publication/orphan tests keep the committed chain intact; head-integrity tests corrupt the SQLite row/JSON/hash; ordinary receipt-tamper tests restore the corrupted target. They do not corrupt a traversed descendant while requesting a valid orphan that the corrupted link names.

**Minimal required correction:** validate the complete chain from the trusted SQLite head before treating any link as membership authority. At each link verify exact envelope/schema, advertised and recomputed receipt hash against the expected content address, run/predecessor identity and accepted lineage; bind the head receipt's state/predecessor and chain sequence to the durable head. Only then allow restoration of a member. Add the paired local corrupted-link/orphan test, including a non-head traversed link. Do not weaken the canonical persistence contract or introduce another public commit API.

**Classification: CURRENT_PRE_DISCOVERY_HIGH.** This is the remaining H-01 crash/retry/concurrent-publication defect.

**Exact file/symbol:** `src/btc_quant_agent/h40/lifecycle_authority.py:4215 :: H40LifecycleArtifactStore.persist_authorization`, especially the existing-file branch at line 4237, required directory fsync at line 4273 inside only the new-file branch, and `_commit_run_head` call at line 4292.

**Concrete local current-code path B — concurrent identical publication:** publisher A links the complete receipt and pauses just before its required directory sync. Publisher B sees the identical final file and follows the existing-file branch. B commits sequence zero while A has not completed required directory durability. **Minimal required correction:** before every head commit referencing a receipt, ensure verified receipt bytes and its directory entry have satisfied the required durability step, including pre-existing/orphan and concurrently published receipts. At minimum the fail-closed receipt-directory synchronization cannot be confined to the new-file branch. Existing-byte verification must not substitute for durable publication evidence. No new scientific or lifecycle canonical amendment is needed to implement the already accepted ordering.
