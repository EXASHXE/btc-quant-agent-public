## 2. Repair 2 — Time-Lag HAC Autocovariance on Hourly Intervals (Closing R1-SOL-02)

### 2.1 Supersession of R1 Section 2 Trade-Sequence Lag Indexing
Section 2 of Amendment R1 constructed autocovariance across sequential trade indices $i, i+k$, setting $K = \min(24, N-1)$. Because accepted trades under low-frequency trading occur irregularly over time, trade-index adjacency does not equal hourly separation. R1 Section 2 is hereby **superseded** by the true calendar-time hourly lag formulation below.

### 2.2 Exact Hourly Time-Lag HAC Formulation
Let $\mathcal{P}$ be an evaluated partition containing $N$ accepted trades ($N \ge 1$).
Each accepted trade $i \in \{1, \dots, N\}$ has an exact UTC entry timestamp $t_i$ and value $z_i \in \mathbb{R}$.

Evaluations are performed on two series:
1. **Directional Correctness Series**: $y_i \in \{0, 1\}$.
2. **Net Return Series**: $x_i = r_{\text{net}, i} \in \mathbb{R}$ (under the frozen 12 bps friction proxy).

For any such series $z$:
1. **Sample Mean**:
   $$\bar{z} = \frac{1}{N} \sum_{i=1}^N z_i$$
2. **Sample Variance (Lag 0 Autocovariance)**:
   $$\hat{\gamma}_0 = \frac{1}{N} \sum_{i=1}^N (z_i - \bar{z})^2$$
3. **Hourly Time-Lag Autocovariance** $\hat{\gamma}_k$ for $k \in \{1, 2, \dots, 24\}$:
   Let $\mathcal{S}_k$ be the set of ordered trade pairs separated by exactly $k$ hours:
   $$\mathcal{S}_k = \left\{ (i, j) \mid 1 \le i < j \le N \text{ and } \frac{t_j - t_i}{3600\,\text{s}} = k \right\}$$
   The autocovariance at hourly lag $k$ is:
   $$\hat{\gamma}_k = \frac{1}{N} \sum_{(i, j) \in \mathcal{S}_k} (z_i - \bar{z})(z_j - \bar{z})$$
   If $\mathcal{S}_k = \emptyset$ (no trade pairs separated by exactly $k$ hours), then $\hat{\gamma}_k = 0.0$.
4. **Sample Autocorrelation** $\hat{\rho}_k$:
   $$\hat{\rho}_k = \begin{cases} \frac{\hat{\gamma}_k}{\hat{\gamma}_0}, & \text{if } \hat{\gamma}_0 > 0 \\ 0.0, & \text{if } \hat{\gamma}_0 = 0 \end{cases}$$
5. **Bartlett Kernel Weights** (for $K = 24$):
   $$w_k = 1 - \frac{k}{25}, \quad k \in \{1, 2, \dots, 24\}$$
6. **Variance Inflation Factor** $f(z)$:
   $$f(z) = 1 + 2 \sum_{k=1}^{24} w_k \hat{\rho}_k$$
7. **Raw Effective Sample Size**:
   $$n_{\text{HAC}}(z) = \begin{cases} \frac{N}{f(z)}, & \text{if } f(z) > 0 \text{ and } \hat{\gamma}_0 > 0 \text{ and } N \ge 2 \text{ and } f(z) < \infty \\ 1.0, & \text{otherwise (fail-closed)} \end{cases}$$
8. **Clipping**:
   $$n_{\text{HAC, clipped}}(z) = \operatorname{clip}\left(n_{\text{HAC}}(z), \, 1.0, \, N\right)$$

### 2.3 Simultaneous BTC and ETH Trades
When `BTCUSDT` and `ETHUSDT` both trigger an accepted trade at the identical hourly timestamp $t$, they are distinct observations with $t_j - t_i = 0$ hours. They do **not** contribute to $\mathcal{S}_k$ for any $k \ge 1$ and do not create artificial $k=1$ adjacency. Cross-asset contemporaneous dependence is captured by the joint UTC moving-block bootstrap and the occupied calendar-day floor.

### 2.4 Governing Integer Effective Sample Size
$$n_{\text{HAC}} = \min\left(n_{\text{HAC, clipped}}(y), \; n_{\text{HAC, clipped}}(x)\right)$$
$$n_{\text{eff}} = \min\left(N, \; N_{\text{24h\_blocks}}, \; \lfloor n_{\text{HAC}} \rfloor\right)$$
where $N_{\text{24h\_blocks}}$ is the count of distinct occupied UTC calendar days (`YYYY-MM-DD`) containing at least one accepted trade entry.

### 2.5 Persistence Requirements
All 24 values of $\hat{\gamma}_k, \hat{\rho}_k$, pair counts $|\mathcal{S}_k|$, weights $w_k$, $\hat{\gamma}_0(y), \hat{\gamma}_0(x), f(y), f(x)$, and final components must be recorded in evaluation artifacts for independent bitwise verification.

## 3. Repair 3 — Exact Bootstrap, Quantile, P-value, and Seed Specifications (Closing R1-SOL-03)

### 3.1 Exact Nearest-Rank Quantile Convention
For $M = 10000$ bootstrap replicates sorted in ascending order $v_{(1)} \le v_{(2)} \le \dots \le v_{(10000)}$:
The nearest-rank order statistic index for lower confidence bounds at level $\alpha$ is:
$$r(\alpha) = \max(1, \; \lceil \alpha \cdot M \rceil)$$
$$\text{quantile}_{\alpha} = v_{(r(\alpha))} \quad (1\text{-based order statistic})$$
$$\text{array\_index} = r(\alpha) - 1 \quad (0\text{-based implementation index})$$

Exact integer indices for governing confidence gates:
- **95% One-Sided LCB** ($\alpha = 0.05$):
  $$r(0.05) = 500 \implies v_{(500)} \equiv \text{sorted\_values}[499]$$
- **97.5% One-Sided LCB** ($\alpha = 0.025$, confirmation co-primary):
  $$r(0.025) = 250 \implies v_{(250)} \equiv \text{sorted\_values}[249]$$
- **90% One-Sided LCB** ($\alpha = 0.10$, secondary diagnostic):
  $$r(0.10) = 1000 \implies v_{(1000)} \equiv \text{sorted\_values}[999]$$

For upper critical values used in max-statistic thresholding:
$$r_{\text{upper}}(\alpha) = \lceil (1 - \alpha) \cdot M \rceil$$
For $\alpha = 0.05$:
$$r_{\text{upper}}(0.05) = 9500 \implies v_{(9500)} \equiv \text{sorted\_values}[9499]$$

Any conflicting phrasing in R1 referencing zero-indexed $\lfloor M \cdot \alpha \rfloor$ is hereby **superseded**.

### 3.2 Exact Marginal One-Sided Bootstrap P-Values Before Holm
For a tested metric point estimate $\hat{\theta}$ against preregistered null $\theta_0$, and $M = 10000$ bootstrap estimates $\hat{\theta}_1, \dots, \hat{\theta}_M$:
1. **Observed Test Statistic**:
   $$T_{\text{obs}} = \hat{\theta} - \theta_0$$
2. **Centered Bootstrap Statistics**:
   $$T_m = \hat{\theta}_m - \hat{\theta}, \quad m = 1, 2, \dots, M$$
3. **Exact Marginal One-Sided P-Value**:
   $$p = \frac{1 + \sum_{m=1}^M \mathbf{1}_{\{T_m \ge T_{\text{obs}}\}}}{M + 1}$$

Governing null values $\theta_0$:
- **Conditional Precision**: $\theta_0 = p_0$ (where $p_0$ is defined in Section 4).
- **Net Expectancy**: $\theta_0 = 0.0$.
- **Profit Factor** (if evaluated): $\theta_0 = 1.0$.

The $+1$ finite-sample correction and weak inequality $\ge$ are strictly mandatory. Holm step-down adjustment is then applied to these exact marginal p-values across family comparisons. Both raw and Holm-adjusted p-values must be persisted.

### 3.3 Exact Seed Preimage and PRNG Instantiation
To prevent cross-platform string-formatting discrepancies, the bootstrap seed preimage is defined strictly via Canonical JSON:

```python
import hashlib
from btc_quant_agent.research_contract.canonical import canonical_json

seed_preimage = canonical_json([
    protocol_id,
    candidate_id,
    partition_id,
    metric_id,
]).encode("utf-8")

digest = hashlib.sha256(seed_preimage).digest()
raw_u64 = int.from_bytes(digest[:8], byteorder="big", signed=False)
seed = raw_u64 % (2**63 - 1)
```

The pseudo-random number generator must be instantiated explicitly as:
```python
import numpy as np

rng = np.random.Generator(np.random.PCG64(seed))
```
The canonical preimage string, digest hex string, `raw_u64`, final integer `seed`, and NumPy library version must be recorded in evaluation metadata.

## 4. Repair 4 — Exact Confirmation Training Timestamp Boundary

### 4.1 Exact Half-Open Interval Definition
Natural-language descriptions of the confirmation training boundary are hereby superseded by the exact ISO 8601 half-open UTC timestamp interval:
```text
CONFIRMATION TRAINING PARTITION:
2021-01-31T00:00:00Z <= t < 2025-01-31T00:00:00Z

PURGE WINDOW (Pre-Confirmation):
2025-01-31T00:00:00Z <= t < 2025-02-01T00:00:00Z

CONFIRMATION EVALUATION HOLDOUT:
2025-02-01T00:00:00Z <= t < 2026-02-01T00:00:00Z
```

### 4.2 Calculation of Confirmation Null $p_0$
For the one-shot confirmation evaluation:
- $\pi_{\text{LONG}}^{\text{train}}$ and $\pi_{\text{SHORT}}^{\text{train}}$ are computed strictly over the confirmation training interval (`2021-01-31T00:00:00Z` to `2025-01-31T00:00:00Z`).
- $w_{\text{LONG}}$ and $w_{\text{SHORT}}$ are computed from the candidate's emitted actions on the confirmation holdout (`2025-02-01T00:00:00Z` to `2026-02-01T00:00:00Z`).
- The confirmation directional null is:
  $$p_0 = \max\left(0.50, \; w_{\text{LONG}} \cdot \pi_{\text{LONG}}^{\text{train}} + w_{\text{SHORT}} \cdot \pi_{\text{SHORT}}^{\text{train}}\right)$$
- Zero confirmation holdout labels may contribute to $\pi^{\text{train}}$.
