## Critical scientific interpretation

`NOT_TESTABLE` is not equivalent to `THRESHOLD_UNMET`.

Production lifecycle code explicitly chooses:

```text
NOT_TESTABLE
if no candidate passes and any candidate verification is scientific_unavailable;

THRESHOLD_UNMET
if no candidate passes and no scientific_unavailable condition exists.
```

Therefore this run does **not** establish that the 18 D1-D3 strategy configurations lack edge.

It establishes that the sealed Discovery population could not complete accepted scientific evaluation under the current fit/verification contracts.

## Why all 18 can become scientific_unavailable

Production verifier groups candidates by family and marks an entire family unavailable if any member of that family is missing from the `scientific` result set.

A candidate is omitted from the scientific result set when its accepted candidate result is `FIT_INVALID` and the verifier confirms the corresponding NOT_TESTABLE condition.

Thus:

```text
scientific_unavailable_count = 18
```

does not prove all 18 candidates directly experienced the same fit failure.

It can result from one or more direct FIT_INVALID candidates in each active D1/D2/D3 family, followed by family-level unavailability propagation.

The exact direct FIT_INVALID count and exact failure reasons are not present in the committed compact M3B report/evidence package.
