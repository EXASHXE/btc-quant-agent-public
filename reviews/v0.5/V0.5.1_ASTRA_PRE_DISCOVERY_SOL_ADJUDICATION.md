## 1. ASTRA-B-01 — ACCEPTED BLOCKER

`H40ExpectedSplitAuthority` accepts caller-supplied non-empty unique folds and a caller-supplied validation-contract map.

`authorize_wf_validation()` proves:

```text
evidence folds == supplied expected folds
evidence contracts == supplied expected contracts
```

but it does not prove that the supplied expected object was itself derived from the complete seal-bound runtime split and accepted P2 validation contract authority.

Therefore paired shrinkage:

```text
expected fold universe
+
evidence fold universe
```

can remain internally consistent while incomplete.

This is exactly the distinction:

```text
hash/self-consistency
!=
authority truth
```

The finding is accepted.

No scientific amendment is currently indicated because accepted P3R0R1 already requires complete fold derivation. The repair must make that accepted semantics executable.

---

## 2. ASTRA-B-02 — ACCEPTED BLOCKER

The current in-memory state machine is absorbing once it sees a terminal transition.

The persisted authority graph is not.

`H40LifecycleArtifactStore` stores independently named immutable files and resolves ancestry by predecessor receipt hash. It has no single durable authoritative run head and no atomic compare-and-advance relation.

Therefore two individually valid descendants of the same predecessor can coexist on disk, and a fresh process can restore a nonterminal sibling without learning that the run already terminated on another branch.

A correct predecessor chain proves ancestry, not uniqueness.

The finding is accepted.

A docs-first authority clarification/amendment is required because durable transition ownership, concurrent writer semantics, stale-head behavior and crash recovery must become normative rather than left to storage implementation choice.

---

## 3. ASTRA-B-03 — ACCEPTED BLOCKER

`revalidate_authorization()` reconstructs the immediate authorization step.

For Candidate Lock and later stages it consumes the cached prior authorization through `_require_prior()`, which verifies issuer/state/receipt lineage but does not recursively revalidate the root runtime seal/source truth.

Cold restoration does re-resolve and verify the seal.

In-memory reuse can therefore have weaker source-truth semantics than cold restore.

The finding is accepted.

The next authority closure must explicitly define verified-capability lifetime.

Permissible designs may include:

```text
A. transition-use always recursively revalidates the seal and active source truth

or

B. the run binds an independently protected immutable byte snapshot/content store
   whose continued identity is sufficient for later stages
```

A silently perpetual in-memory wrapper is not sufficient authority.

## 4. ASTRA-B-04 — ACCEPTED BLOCKER

This finding is outside H40 scientific semantics but is a real repository safety defect.

`ExecutionService.reconcile()`:

1. restores a persisted `ExecutionPlan`;
2. selects a signed client from the current config mode;
3. does not require `current_mode == plan.mode`;
4. does not revalidate the persisted plan hash before exchange interaction;
5. does not bind the plan/order to an exchange/account environment;
6. can issue cancellation, protective-order writes, or a reduce-only failsafe market order.

Thus a plan created under TESTNET can be reconciled while current config is LIVE.

The fact that defaults are disabled does not remove the capability-boundary defect.

This is accepted as BLOCKER for the full-system pre-Discovery gate.

It does not require an H40 science amendment. It requires a separate execution-boundary policy closure and repair.

---

## 5. ASTRA-H-01 — ACCEPTED HIGH

Current lifecycle publication creates the final immutable path with:

```text
O_CREAT | O_EXCL
```

before the full canonical artifact has been written/fsynced.

A crash after final-path creation can leave an empty or partial write-once artifact. Retry then fails closed against the corrupted final path.

This does not create false acceptance, but it breaks durable evidence recovery and can force unsafe manual intervention.

The finding is accepted.

It should be fixed together with B-02 because:

```text
artifact publication
+
durable run-head advance
```

must have one coherent crash/recovery protocol.

## 8. v0.6 architecture adjudication

Astra's architecture conclusion is accepted:

```text
C. hypothesis research beneath a validated-playbook registry
   and deterministic Trading Policy layer
```

This preserves:

- hypothesis-level falsifiability;
- bounded campaign budgets;
- finite preregistered universes;
- independent playbook validation;
- deterministic routing and NO_TRADE default.

It avoids treating the H-series as the final product architecture while also avoiding premature replacement of hypothesis science with a broad unconstrained regime/playbook search.

After H40 terminal state:

```text
hypothesis campaigns
-> accepted playbook records only when supported
-> validated playbook registry
-> deterministic policy/router
-> risk
-> execution
-> later LLM orchestration/explanation
```

No architecture choice is evidence of positive expectancy.
