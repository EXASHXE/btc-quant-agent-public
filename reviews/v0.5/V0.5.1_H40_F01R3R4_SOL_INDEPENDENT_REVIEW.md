## 3. Remaining blocker — legacy mirror fallback

Current code still contains this lineage behavior:

\`\`\`python
receipt_path = self._receipts_dir(run_authority_id) / f"{curr_hash}.json"
if not receipt_path.is_file():
    receipt_path = self._find_receipt_path(run_authority_id, curr_hash)
\`\`\`

But \`_find_receipt_path()\` can search legacy transition-key files under the run directory and return one whose envelope contains the requested \`receipt_sha256\`.

Therefore committed-lineage verification may still accept a missing authoritative content-addressed receipt when a matching legacy \`NN_name.json\` mirror remains present.

That violates the bounded repair contract:

\`\`\`text
Do not infer authority from legacy mirror files.
The content-addressed receipt chain is authoritative evidence for lineage only after verification.
\`\`\`

A legacy mirror is a compatibility artifact, not lifecycle authority.

### Concrete current path

\`\`\`text
1. Persist committed D/C normally, producing content-addressed receipts and legacy transition-key mirrors.
2. Remove the authoritative receipts/<hash>.json for a committed lineage node.
3. Leave the matching legacy NN_name.json intact.
4. Call restore_authorization().
5. _get_committed_lineage() falls back through _find_receipt_path().
6. The matching legacy receipt can supply lineage evidence.
\`\`\`

Expected accepted behavior:

\`\`\`text
authoritative content-addressed lineage receipt missing
=> fail closed
\`\`\`

regardless of legacy mirror presence.
