## P3R0-SOL-01 — HIGH — Lifecycle governance root does not bind lifecycle semantics

The published lifecycle_governance_authority_hash hashes only upstream P2 identities, artifact paths/commits, and the pre-F01 code HEAD.

It does not bind the newly authored lifecycle semantics: receipt schemas, transition matrix, lineage rules, persistence/write-once rules, replay rules, runtime snapshot sealing, candidate-lock evidence, WF evidence, or the F02 boundary.

Therefore materially different lifecycle protocols can produce the same lifecycle_governance_authority_hash.

### Required repair

Define a canonical lifecycle semantic hash tree, domain-separated from the scientific semantic root. At minimum content-bind canonical objects for:

~~~text
discovery_authorization_receipt_contract
candidate_lock_receipt_contract
wf_validation_receipt_contract
confirmation_ready_receipt_contract
termination_receipt_contract
transition_matrix_contract
persistence_replay_contract
runtime_snapshot_seal_contract
f02_boundary_contract
~~~

Publish a lifecycle_semantic_root_hash from those child content hashes.

The final lifecycle governance authority must bind the accepted scientific identities, P2 final acceptance identity, the committed P3R0/R1 lifecycle amendment identity, and lifecycle_semantic_root_hash.

Avoid self-reference by having the later independent acceptance publish the final governance authority hash after the repair commit exists.

~~~text

exact lifecycle implementation commit

~~~

The Discovery authorization receipt must bind that later accepted lifecycle implementation authority. Do not guess a future implementation SHA in this docs-only repair.

## P3R0-SOL-04 — HIGH — Receipt integrity is not yet equivalent to authoritative evidence

The receipt architecture proves content integrity, but privileged transitions can still be authorized by caller-authored claims.

Candidate lock currently carries a selected slot, selection_rank=1, and a summary artifact path/hash without freezing an authoritative discovery-result evidence object whose contents are verified under the accepted selection contract.

WF validation similarly carries validation_summary_artifact_hash and all_wf_gates_passed=True without requiring the verifier to recompute the gate result from canonical validation evidence.

A hash proves integrity of a claim, not truth of a claim.

### Required repair

For every privileged post-outcome transition, separate result evidence from transition authorization.

Define canonical result/evidence receipt schemas or canonical verifier inputs that are bound to the same run authority, exact candidate and split, and accepted scientific/statistical contract content hashes. The transition verifier must parse and verify/recompute the authoritative result evidence before issuing transition authority.

No real outcomes are to be computed during this repair.
