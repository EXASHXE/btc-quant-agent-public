# Blocker B03 — noncanonical regime_state collapse

Normative R3R2 Section 2.5 freezes the exact percentile states:

```text
REGIME_VOL_LOW  [0, 0.40)
REGIME_VOL_MID  [0.40, 0.60)
REGIME_VOL_HIGH [0.60, 1.0]

lower-bound owns equality
only REGIME_VOL_MID passes
```

Repair Contract R2 requires the production verifier to reconstruct the exact prefit output:

```text
regime_state
```

Current implementation instead emits:

```python
if 0.40 <= p_vol < 0.60:
    regime_state = "REGIME_VOL_MID"
else:
    regime_state = "REGIME_REJECT"
```

Therefore both accepted scientific states:

```text
REGIME_VOL_LOW
REGIME_VOL_HIGH
```

are collapsed into a new/noncanonical state string:

```text
REGIME_REJECT
```

The downstream pass/fail gate is numerically equivalent, but F03 is not merely a gate
reimplementation: it explicitly reconstructs the accepted prefit state. The exact state identity
must therefore be preserved.

## Required repair

When a valid percentile exists:

```text
p < 0.40            -> REGIME_VOL_LOW
0.40 <= p < 0.60    -> REGIME_VOL_MID
p >= 0.60           -> REGIME_VOL_HIGH
```

Only MID remains eligible.

For genuinely unavailable/undefined regime computation (missing scalar, reference N < 60), keep a
separate fail-closed internal/unavailable representation only if existing accepted evidence
semantics require one. Do not substitute that unavailable value for valid LOW/HIGH states.

Add boundary regressions for:

```text

0.40
0.599...
0.60
```

and prove lower-bound equality semantics.

# Blocker B04 — O_RANGE silently substitutes H-L when prior close is missing

Normative R3R2 Section 2.6 freezes standard true range:

```text
TR_k = max(
  H_k - L_k,
  |H_k - C_{k-1}|,
  |L_k - C_{k-1}|
)
```

and defines:

```text
E(t) =
TR_last /
mean(TR over the 24 reference bars strictly before t, excluding the last bar)
```

Current implementation builds 25 TR-bearing bars but obtains the previous close for the earliest
reference bar from the immediately preceding source bar.

If that prior-close carrier is missing, current code executes:

```python
tr = curr.high - curr.low
```

for the first reference TR.

That is a different formula. R3R2 defines standard true range and does not authorize an H-L
fallback/imputation.

The R1 test comments already recognize the dependency by constructing:

```text
25 TR-bearing bars
+
prior bar k=26 for C_{k-1}
```

but no regression currently proves that missing k=26 fails closed.

## Required repair

Preserve the frozen 25-bar TR-bearing population:

```text
24 reference bars
+
1 last bar
```

The immediately preceding close needed to compute the first reference bar's standard TR is an
input dependency, not an additional reference observation.

If the exact preceding close is unavailable or PIT-invalid:

```text
O_RANGE is undefined -> NO_TRADE / PIT_UNAVAILABLE
```

Do not fall back to H-L.

Add a regression where all 25 TR-bearing bars exist but the immediately preceding close is absent;
the scalar must be undefined.

Also test that a large gap between the earliest reference open and its preceding close affects its
TR exactly through the frozen standard-TR formula.
