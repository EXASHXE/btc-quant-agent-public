## 4. Blocker Root Cause Analysis

In Repair Contract Freeze R1, the provenance contract published:

```text

```

However, canonical serialization and SHA-256 computation of the represented provenance object (with the self-reported `contract_hash` excluded) deterministically yields:

```text
recomputed_hash = 31fc3930e44149e6b3af54ddd3b11c630f95cbbd3f152b3d0d5e614690dcf7ae
```

The controller independently checked multiple alternate interpretations (including self-reported hash inclusion, individual nested contracts, and contract projections), none of which matched `9a5a7110...`. The root cause was an identity representation defect in R1 where an unreproducible digest was published.

The R2 revision resolves this defect by explicitly separating the canonical preimage from the digest, freezing the exact preimage object without self-referential fields, and verifying deterministic recomputation.
