# Blocker B01 — source support interval is incorrectly applied to the whole sealed file

## Frozen contract

Repair Contract R2 freezes First-Discovery economic extraction support as:

```text
[2021-01-01T00:00:00Z, 2023-02-01T00:00:00Z)
```

The source file itself remains the exact accepted sealed source bytes. The support interval defines
which rows participate in H40 economic reconstruction; it does not redefine the accepted physical
source artifact or require that artifact to end at 2023-02-01.

The frozen canonical source authority for:

```text
ETHUSDT_USD_M_1H
```

is:

```text
locator   = data/research/cross_asset_1h/ETHUSDT.parquet
cadence   = 1h
product   = ETHUSDT
row_count = 44568
start_utc = 2021-01-01T00:00:00Z
end_utc   = 2026-01-31T23:00:00Z
```

The accepted F01 authority fixtures likewise materialize the verified ETH timestamp receipt across
the full 2021-01-01 -> 2026-02-01 source range.

## Current implementation defect

`_extract_economic_rows()` iterates every physical row in the sealed file and performs:

```python
if not (SUPPORT_START_UTC <= dt < SUPPORT_END_UTC_EXCLUSIVE):
    _fail("source timestamp ... outside support interval")
```

As a result, the accepted ETH source file necessarily fails as soon as the verifier reaches the
first physical source row at or after:

```text
2023-02-01T00:00:00Z
```

This means the implementation cannot consume the exact canonical production artifact it is
supposed to verify.

The new test:

```text
test_f02_12_source_timestamp_outside_support_interval_rejected
```

encodes the same incorrect interpretation and therefore cannot validate the real production
contract.

## Required minimal repair

Keep the authority chain separate from the economic support projection:

1. read/hash the **entire exact sealed source file** and require its full-file SHA-256 to match the
   accepted source record/receipt/runtime attestation;
2. parse using the receipt's verified timestamp field;
3. select only rows with timestamps in:
   `[2021-01-01T00:00:00Z, 2023-02-01T00:00:00Z)`
   for the H40 economic reconstruction/digest;
4. rows outside that support interval are not H40 economic rows and do not enter
   `economic_rows_sha256` / `economic_row_count`;
5. the presence of legitimate later rows in the exact sealed file must not itself fail H40;
6. malformed/duplicate/unordered rows **inside the selected H40 support projection** still fail
   closed, while the source receipt remains the authority for whole-file timestamp validation.

Add a regression using one exact source fixture containing both:

```text
valid H40-support rows
+
valid post-2023-02-01 rows
```

and prove:

```text
full file SHA binds all bytes
economic digest binds only the frozen H40 support projection
post-support rows do not enter the economic digest
```

Do not change the canonical source file identity or support interval.

# Blocker B02 — D2 reference window includes the forbidden left boundary

## Frozen R3R2 rule

Normative R3R2 Section 2.2 freezes D2 as:

```text
Reference bars:
complete hourly bars with close_time_ms < t
and open_time in (t - W, t)

the last closed signal bar is EXCLUDED from the prior range
```

The interval is explicitly open on the left.

For an hourly decision boundary `t`, the bar whose open time is exactly:

```text
t - W
```

is not a D2 reference bar.

## Current implementation defect

Current code:

```python
for k in range(2, range_hours + 1):
    b = bars.get((t - timedelta(hours=k), product))
```

For `W = 24`, this reads:

```text
t-2, t-3, ..., t-24
```

and therefore includes `t-W`.

The new test explicitly codifies the same mismatch:

```text
# 24h Donchian: reference bars t-2h through t-24h
for k in range(2, 25):
    ...
```

So the test is self-consistent with the implementation but not with the frozen R3R2 interval.

A sufficiently extreme high/low at exactly `t-W` can change the computed D2 break result even
though that row is outside the accepted reference interval.

## Required minimal repair

Implement the exact open-left R3R2 window.

For the current hourly indexing, construct the reference set by the semantic predicate, not by a
comment-derived range approximation:

```text
bar.close_time < t
bar.open_time > t-W
bar.open_time < t
bar is not the last closed signal bar
```

Then retain the already-frozen minimum complete-bar requirement:

```text
minimum complete bars = (W / 24) * 6
```

Add an adversarial boundary regression:

- put an extreme high/low on the bar at exactly `open_time == t-W`;
- keep all bars strictly inside the accepted interval unchanged;
- prove the D2 output is unchanged when that left-boundary bar is modified.

Also retain equality behavior:

```text
C == U or C == L => raw_score = 0
```

No threshold or formula redesign is authorized.
