## 1. Executive Summary

This repair report documents the complete closure of finding P1R5-F1 identified in the Sol Independent Review (`reviews/v0.5/V0.5.1_H40_P1R5_SOL_INDEPENDENT_REVIEW.md`).

1. **P1R5-F1 Remediation (Canonical File SHA Presence and Equality Required)**:
   - Defect: In `assert_canonical_source_record(...)`, when `spec.reference_file_sha256` was frozen, the condition `and record.file_sha256 is not None` allowed callers to omit `record.file_sha256` (`file_sha256 = None` or `file_sha256 = ""`), skipping equality validation against the protocol-frozen reference file SHA.
   - Fix: Updated `assert_canonical_source_record(...)` in `src/btc_quant_agent/h40/source_manifest.py` so that whenever `spec.reference_file_sha256 is not None`, the check requires `not record.file_sha256 or record.file_sha256 != spec.reference_file_sha256` to fail closed with `H40ReasonCode.SOURCE_HASH_MISMATCH`.
   - Symmetrically enforced the same fail-closed presence requirement on `spec.archive_set_sha256`: `not record.archive_set_sha256 or record.archive_set_sha256 != spec.archive_set_sha256`.
   - Consequently, all omitted (`None`), empty (`""`), whitespace-only, malformed, or unequal SHA values fail closed with `SOURCE_HASH_MISMATCH`.
   - The exact frozen canonical reference file SHA (`563a1a4d927ec2a007481783be9bd76896e1be57198af80c4b2a30608e124608` for ETH) passes without exception when all other canonical fields are valid.

2. **Retained Invariants & Closures**:
   - Production `materialize_authoritative(...)` and `assert_authoritative(...)` retain zero caller policy overrides.
   - Synthetic validator splits remain strictly non-authoritative (`is_authoritative = False`, `attestation.is_production_canonical = False`) and are rejected by `assert_authoritative(...)`.
   - BTC canonical production authority remains `NOT_TESTABLE`.
   - All tests remain 100% hermetic (no dependencies on untracked local market data).
   - Zero directional labels, zero forward returns, zero MFE/MAE.
   - Zero feature research, zero configuration search, zero backtests.
   - Confirmation holdout sealed, execution disabled, no alpha claims.
   - Protected H39 and Final Holdout surfaces unconditionally defended.

## 2. Technical Modifications

### 2.1 `src/btc_quant_agent/h40/source_manifest.py`
- In `assert_canonical_source_record(...)`:
  - Enforced that when `spec.archive_set_sha256 is not None`, `record.archive_set_sha256` must be non-empty and match `spec.archive_set_sha256`.
  - Enforced that when `spec.reference_file_sha256 is not None`, `record.file_sha256` must be non-empty and match `spec.reference_file_sha256`.
  - Any omission (`None`), empty string (`""`), whitespace, malformed hash, or hash mismatch fails closed with `H40ReasonCode.SOURCE_HASH_MISMATCH`.

### 2.2 `tests/test_v051_h40_p1_scaffold.py`
- In `test_mandatory_5_eth_canonical_checks_remain_enforced`:
  - Added adversarial cases testing that `file_sha256 = None` fails closed with `SOURCE_HASH_MISMATCH`.
  - Added adversarial cases testing that `file_sha256 = ""` fails closed with `SOURCE_HASH_MISMATCH`.
  - Added adversarial cases testing that whitespace `file_sha256 = "   "` fails closed with `SOURCE_HASH_MISMATCH`.
  - Added adversarial cases testing that malformed non-64-hex string fails closed with `SOURCE_HASH_MISMATCH`.
  - Added adversarial cases testing that wrong 64-hex hash fails closed with `SOURCE_HASH_MISMATCH`.
  - Added adversarial cases testing that `archive_set_sha256 = None` and `archive_set_sha256 = ""` fail closed with `SOURCE_HASH_MISMATCH`.
  - Verified that an exact matching canonical ETH record with frozen archive and file SHAs passes `assert_canonical_source_record(...)` without exception.
- In `test_tampered_archive_checksum_fails_canonical_spec`:
  - Added adversarial cases verifying that `file_sha256 = None` and `file_sha256 = ""` on unverified ETH records fail closed with `SOURCE_HASH_MISMATCH`.
