# V0.5.1 H40 P3B — Fit-Invalid Correction Fail-Closed Closure

## Status

```text
H40_P3B_FIT_INVALID_CORRECTION_FAIL_CLOSED_CLOSURE
PRE_OUTCOME
NO_REAL_H40_OUTCOMES_ACCESSED
```

This document closes one implementation ambiguity discovered while preparing the production Discovery scientific verifier.

It does not change any valid-candidate estimator, bootstrap method, null, alpha, hard-gate threshold, LCB formula, candidate order, source authority, search-space identity, or execution policy.

## 1. Existing accepted authority

R1 §3.6 requires, for each within-family candidate k, an observed point estimate and 10,000 centered bootstrap statistics before the family max statistic can be computed.

R3R4 §4.2 requires the correction universe to remain the sealed REGISTERED rows of that family, states that a fit-invalid candidate remains a failed member of the Discovery ledger, and forbids substitution.

R3R4 §4.4 separately allows a family to have NO_REPRESENTATIVE.

The accepted text did not uniquely specify how to evaluate the max statistic when a sealed REGISTERED candidate becomes fit-invalid and therefore has no valid metric estimate/bootstrap vector.

## 2. Fail-closed rule

The exact closure is:

```text
If any REGISTERED member of one Discovery correction family is fit-invalid,
or otherwise cannot produce the complete accepted metric/bootstrap inputs
required by R1/R2, then:

1. that candidate remains present in the sealed Discovery ledger;
2. it is recorded explicitly as FIT_INVALID / failed;
3. it is not replaced;
4. it is not removed from the preregistered family universe;
5. no artificial point estimate, bootstrap statistic, LCB, or marginal p-value
   is imputed for that candidate;
6. the family max-statistic is NOT recomputed on a reduced K;
7. the entire correction family is classified NO_REPRESENTATIVE for both
   PRECISION and NET_EXPECTANCY for this run.
```

This is a fail-closed availability rule. It does not redefine the accepted statistical procedure for a complete valid family.

## 3. Fixed six-family cross-family Holm universe

The cross-family multiplicity universe is fixed pre-outcome to exactly six family slots:

```text
D1_TREND_CONTINUATION
D2_BREAKOUT_CONTINUATION
D3_FAILED_MOVE_REVERSAL
D4_BTC_ETH_CONFIRM_DIVERGE
D5_FUNDING_DIRECTION_INTERACTION
PAIR_DEPTH_TWO
```

For each metric independently:

```text
PRECISION
NET_EXPECTANCY
```

a family classified NO_REPRESENTATIVE occupies its family slot with:

```text
raw marginal p-value = 1.0
```

for Holm step-down bookkeeping.

Therefore:

```text
cross-family K = 6 always
```

A fit-invalid family cannot reduce multiplicity by disappearing from the Holm universe.

The two Holm families remain separate exactly as accepted in R3R4.

## 4. Valid-family behavior unchanged

A correction family may run the accepted within-family max-stat procedure only when every sealed REGISTERED member required by that family has complete valid inputs under the accepted contracts.

For such a complete family, preserve exactly:

- R1/R2 moving-block bootstrap;
- M = 10,000;
- accepted deterministic seed semantics;
- accepted nulls;
- accepted nearest-rank quantiles;
- separate PRECISION and NET_EXPECTANCY max-stat corrections;
- accepted marginal one-sided bootstrap p-values;
- alpha = 0.05;
- existing hard gates;
- existing family representative rule.

No global M=18 correction is introduced.

## 5. Candidate eligibility and ranking

NO_REPRESENTATIVE families cannot supply a candidate to the final lock.

Among remaining valid family representatives, preserve exactly:

```text
1. pass every accepted hard gate
2. satisfy PRECISION cross-family Holm
3. satisfy NET_EXPECTANCY cross-family Holm
4. highest adjusted LCB net expectancy
5. highest adjusted LCB precision
6. lower complexity
7. ascending structural_configuration_hash / configuration ID
```

No runner-up promotion.

## 6. Terminal behavior

If zero eligible family representatives remain and at least one family is unavailable because its accepted scientific inputs are fit-invalid/undefined:

```text
target = NOT_TESTABLE
reason = NOT_TESTABLE
```

If complete scientific inputs exist but no candidate survives the accepted hard gates/corrections:

```text
target = H40_NO_GO
reason = THRESHOLD_UNMET
```

This distinction prevents unavailable scientific evidence from being misreported as negative economic evidence.
