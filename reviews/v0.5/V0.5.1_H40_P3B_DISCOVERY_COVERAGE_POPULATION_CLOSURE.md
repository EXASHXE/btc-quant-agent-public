# V0.5.1 H40 P3B — Discovery Coverage Population Closure

## Status

```text
H40_P3B_DISCOVERY_COVERAGE_POPULATION_CLOSURE
PRE_OUTCOME
NO_REAL_H40_OUTCOMES_ACCESSED
```

This document closes the remaining ambiguity in the candidate-lock scientific coverage hard gate.

It does not change the accepted coverage interval, candidate action thresholds, training sample-support rule, calibration floors, bootstrap science, family correction, or final ranking.

---

## 1. Existing accepted authority

BASE §10.1 defines:

```text
coverage =
accepted LONG or SHORT decisions
/
all base-eligible decisions
```

BASE §11 freezes scientific coverage:

```text
0.25% <= coverage <= 10.0%
```

R3R3 separately freezes:

```text
training_fit_population =
WF1 TRAINING rows passing candidate eligibility A..F
with proposed_side != 0
BEFORE probability calibration / confidence threshold
```

and states this population exists for:

```text
training n_eff >= 120
```

R3R3 also states calibration sample floors use actual final calibrated actions on WF1 Calibration.

R3R4 freezes WF1 Calibration as the only Discovery outcome partition used for candidate-ranking precision/net-expectancy statistics.

The remaining ambiguity was whether the scientific coverage interval applies to:
- WF1 Training proposed-side population;
- WF1 Calibration final actions;
- or both.

---

## 2. Candidate-lock coverage population

The accepted candidate-lock scientific coverage gate applies ONLY to:

```text
WF1_CALIBRATION final emitted actions
```

after:
- source/runtime/PIT eligibility;
- regime;
- opportunity;
- direction;
- geometry;
- calibration;
- confidence threshold;

have produced the final action:

```text
LONG
SHORT
NO_TRADE
```

The numerator is:

```text
N_accept =
count of final LONG or SHORT actions on WF1_CALIBRATION
```

The denominator is:

```text
N_base =
count of all base-eligible decision rows on WF1_CALIBRATION
within the candidate's active asset scope
```

Therefore:

```text
coverage_discovery =
N_accept / N_base
```

---

## 3. Base-eligible denominator semantics

`N_base` is determined before candidate-specific selection gates.

A base-eligible row is counted in the denominator if it belongs to:
- the accepted WF1_CALIBRATION split;
- the candidate's active product scope;
- the accepted base timestamp/product decision universe;
- authoritative source/runtime/PIT eligibility required for that base decision row.

Candidate-specific failure or abstention at any later stage does NOT remove that row from the denominator.

In particular, rows producing:
- regime rejection;
- opportunity rejection;
- no direction;
- insufficient geometry cell;
- calibration abstention;
- confidence-threshold abstention;
- final NO_TRADE

remain denominator rows when they are otherwise base-eligible.

This preserves BASE's meaning of coverage as selectivity over available decision opportunities rather than selectivity conditional on already passing candidate gates.

---

## 4. Active asset-scope counting

For a single-product candidate:

```text
N_base =
base-eligible rows for that product only
```

For a pooled BTC+ETH candidate:

```text
each (timestamp, product) decision row counts separately
```

and:

```text
N_accept =
accepted BTC actions + accepted ETH actions

N_base =
base-eligible BTC rows + base-eligible ETH rows
```

Coverage is the ratio of pooled counts.

Do NOT:
- average per-asset percentages;
- weight assets equally regardless of row count;
- impose an additional per-asset coverage gate unless separately authorized.

Existing later per-asset concentration/gate rules remain separate.

---

## 5. Training proposed-side population is NOT a coverage gate

The WF1 Training proposed-side population defined by R3R3 is used for:

```text
training fit-support / sample-support
training n_eff >= 120
```

It is NOT subject to the scientific coverage interval:

```text
[0.25%, 10%]
```

No second training coverage hard gate is created.

Do not retroactively apply the WF1 Calibration calibrator/confidence threshold to WF1 Training to manufacture a comparable final-action coverage number.

Training proposed-side rate may be persisted as a diagnostic, but it has zero candidate-lock hard-gate authority.

---

## 6. Exact inclusive comparison

The accepted interval is inclusive:

```text
0.0025 <= N_accept / N_base <= 0.10
```

Do not rely on binary floating-point threshold comparison.

Use exact integer inequalities:

```text
lower gate:
400 * N_accept >= N_base

upper gate:
10 * N_accept <= N_base
```

Both must pass.

Equivalent exact-rational arithmetic is allowed only if it produces the same result.

---

## 7. Edge cases

### Zero denominator

If:

```text
N_base == 0
```

then:

```text
NOT_TESTABLE
```

No coverage value is imputed.

### Zero accepted actions

If:

```text
N_base > 0
N_accept == 0
```

then coverage is exactly zero and the lower hard gate fails.

This is a complete hard-gate failure, not missing evidence.

### Invalid accepted action outside denominator

If an accepted LONG/SHORT action is bound to a decision row not in the authoritative base-eligible denominator universe:

```text
FAIL CLOSED
```

The row cannot be added to numerator or denominator ad hoc.

---

## 8. Candidate-level and family-level consequence

For a complete candidate:

```text
coverage < 0.25%
or
coverage > 10%
```

means:

```text
candidate hard gate = FAIL
```

It cannot become a family representative.

This does not by itself mean all H40 is NO_GO; other preregistered candidates/families continue under the frozen correction universe.

Existing no-runner-up / family / final-lock semantics remain authoritative.

---

## 9. Later stage coverage consistency

When later separately authorized:

### Walk-forward

Coverage uses:

```text
final emitted LONG/SHORT actions on the authorized validation population
/
all base-eligible decision rows in the corresponding validation population
and candidate active asset scope
```

For the pooled Section 11 / Section 13.1 gate, counts are pooled across the four authorized validation folds rather than averaging fold percentages.

### Confirmation

Coverage uses:

```text
final emitted LONG/SHORT actions on the confirmation holdout
/
all base-eligible confirmation decision rows in candidate active asset scope
```

These statements preserve the same BASE metric definition across evaluation stages.

They do not authorize WF or Confirmation access.

## 12. Mandatory implementation invariants

Tests must prove:

1. Candidate-lock coverage uses WF1_CALIBRATION final actions.
2. Training proposed-side rate cannot pass/fail the coverage hard gate.
3. Final NO_TRADE rows remain in the denominator when base-eligible.
4. Candidate-specific missing/failed downstream gate does not shrink denominator.
5. Single-product scope counts only that product's base rows.
6. Pooled scope uses sum of product-row counts, not average of percentages.
7. Exact lower boundary 0.25% passes.
8. Value immediately below 0.25% fails.
9. Exact upper boundary 10% passes.
10. Value immediately above 10% fails.
11. Integer cross-multiplication is used or proven equivalent.
12. Zero denominator is NOT_TESTABLE.
13. Zero numerator with positive denominator is a hard-gate fail.
14. Accepted action outside base-eligible universe fails closed.
15. Wrong/missing policy ID/hash fails closed.
