## 1. Close H40-FSA-01: Exact Direction-Score and Calibration Pipeline

### 1.1 The raw_score contract (single, deterministic, one-dimensional)

For **every active single-family variant and every active pair**, the raw score passed into calibration is exactly the **signed raw scalar of the base direction owner's feature**, defined in Section 2. There is exactly one raw-score definition per variant/pair; no multi-feature ML model, feature-selection procedure, regularization grid, optimizer grid, hidden model family, or new search degree of freedom exists.

```text
D1_V1_RETURN_4H      raw_score = s_D1_4H(t)          (Section 2.1)
D1_V2_RETURN_12H     raw_score = s_D1_12H(t)         (Section 2.1)
D2_V1_BREAKOUT_24H   raw_score = s_D2_24H(t)         (Section 2.2)
D2_V2_BREAKOUT_72H   raw_score = s_D2_72H(t)         (Section 2.2)

D4_V1_CONFIRMATION_4H raw_score = s_D4_conf(t)       (Section 2.4)

D5_V2_CROWDING_Q20_D2 raw_score = s_D2_24H(t)        (base owner D2; D5 vetoes, never a predictor)
```

Orientation is frozen: **larger raw_score = more bullish; smaller raw_score = more bearish; zero = neutral/no directional evidence**.

For pairs and D5 single-family variants, the secondary D4/D5 components are **confirm/veto filters only** — they never become additional learned predictors, and they never modify the base raw score. If the secondary filter fails, the row is `NO_TRADE` (Section 1.5); if it passes, the retained raw score is exactly the base owner's raw score.

### 1.2 Calibration target encoding (resolving the ternary/binary mismatch)

The economic label is ternary (BASE 3.2): `LONG_LABEL`, `SHORT_LABEL`, `NEUTRAL_LABEL`. Calibration fits a binary `p_up`.

```text
Calibration population (per fold):
  included: every base-eligible decision at timestamp t on the calibration partition
            where the configuration emits a NON-ZERO raw score (directional evidence exists)
            AND the row passes regime + opportunity gates.
  excluded: NEUTRAL_LABEL outcomes and any decision with zero raw score.

Target y for a calibration observation:
  y = 1  if r_h(t) >  +c_rt        (LONG_LABEL)
  y = 0  if r_h(t) <  -c_rt        (SHORT_LABEL)
  (NEUTRAL_LABEL rows are NOT in the calibration population; see below)

p_up interpretation: p_up = P(y = 1 | x = raw_score) = calibrated probability the horizon
  return exceeds +c_rt, conditional on the row being in the calibration population.
```

**Population distinction (mandatory).** Calibration is conditional on non-neutral, non-zero-raw-score directional evidence. This is distinct from the later accepted-trade precision population: BASE 3.2 requires that **neutral outcomes are not silently dropped from accepted-trade precision** — i.e., an accepted LONG/SHORT trade whose realized outcome is `NEUTRAL_LABEL` counts as incorrect in precision. The two populations are defined exactly:

```text
calibration population     = directional rows on the calibration partition (nonzero raw score,
                             gates passed, label != NEUTRAL_LABEL); used to fit p_up only.
accepted-trade precision population = ALL accepted trades on the evaluation partition
                             (LONG or SHORT emitted), INCLUDING those whose outcome is
                             NEUTRAL_LABEL; used to compute Section 3.2 precision.
```

### 1.3 Platt logistic form, fit, and degeneracy

```text
Form:        p_up = 1 / (1 + exp(-(a * raw_score + b)))
Parameters:  (a, b) fitted by maximum likelihood on the calibration population.
Intercept:   b is fitted (no intercept-policy omission).
Regularization: NONE. If the optimizer fails to converge to finite (a, b), the row fails
             closed to NO_TRADE (calibration undefined = failure, never a pass).
Solver:      deterministic — binary logistic regression via Newton-Raphson on the exact
             calibration population, iterated to relative log-likelihood change < 1e-9,
             max 100 iterations; identical inputs => identical (a, b).
Degenerate one-class/constant-score: if the calibration population has zero LONG_LABEL or
             zero SHORT_LABEL rows, or raw_score is constant, calibration is undefined
             -> the configuration fails closed (NOT_TESTABLE for that fold).
Standardization: none (raw_score enters the linear form directly; no z-scoring).
```

### 1.4 Isotonic, tie convention, and R3 fallback

```text
ISOTONIC_IF_ELIGIBLE_V1 eligible iff calibration population has >= 200 total observations
             AND >= 40 per predicted side (y=1 and y=0).
Isotonic input/output: pool-adjacent-violators algorithm over (raw_score, y) pairs;
             input sorted ascending by raw_score; output monotone nondecreasing p_up.
Tie convention: identical raw_score values with mixed y are pooled together into one
             output value (PAVA natural pooling; no tie-breaking reordering).
If isotonic is ineligible, deterministic fallback to PLATT_LOGISTIC_V1 on the same
             calibration population (R3 Section 7, preserved). The fallback is
             identity-preserving: the row's calibration contract id remains
             CALIBRATION_ISOTONIC_IF_ELIGIBLE_V1; the fallback is part of the contract
             semantics and is bound into the calibration contract content hash.
```

### 1.5 Threshold rule and filter gate order

```text
Funnel order per row:
  1. regime gate      (R_VOL_RANGE: only REGIME_VOL_MID passes; else NO_TRADE)
  2. opportunity gate (O_RANGE_EXPANSION: only O_ELIGIBLE proceeds; else NO_TRADE)
  3. direction evidence (raw_score != 0; else NO_TRADE)
  4. secondary filter (pairs/D5: confirm/veto; veto => NO_TRADE)
  5. calibration      (p_up from fitted mapping)
  6. threshold: LONG if p_up >= q; SHORT if p_up <= 1 - q; else NO_TRADE,
     with q in {0.55, 0.60, 0.65} frozen per row template (R3 Section 8.2).

No learned cutoff exists. Thresholds are exactly {0.55, 0.60, 0.65}.
```

No new configuration slot is created. Calibration method/threshold remain exactly those frozen by R3/R3R1.

## 2. Close H40-FSA-02: Every Active Feature Is Executable

### 2.0 Canonical bar-indexing convention (used everywhere)

Let `t` be a decision boundary (an hourly UTC boundary). Define the hourly bar `B_k` whose open time is `k` and close time is `k+1h`. A bar is usable in a feature claimed at `t` iff `close_time_ms(B_k) < t` (strictly) and `closed == true`.

For any product `X` and window `W` hours:

```text
C_X(t)     = close of the last hourly bar strictly before t
C_X(t - W) = close of the hourly bar with open time (t - W), if that bar is complete
             and its close_time_ms < t
r_X(t, W)  = log(C_X(t) / C_X(t - W))
```

If either endpoint bar is missing, duplicated, not closed, or has untrustworthy timestamps, `r_X(t, W)` is undefined → the row is `NO_TRADE` (`PIT_UNAVAILABLE`). No imputation.

### 2.1 D1_V1_RETURN_4H / D1_V2_RETURN_12H

```text
s_D1_4H(t)  = r_X(t, 4h)
s_D1_12H(t) = r_X(t, 12h)

Equality: s == 0 -> raw_score = 0 -> NO_TRADE (neutral/no directional evidence).
Missing endpoint -> NO_TRADE (PIT_UNAVAILABLE).
Product X = per-scope projection (BTC_ONLY -> BTCUSDT; ETH_ONLY -> ETHUSDT;
           POOLED_BTC_ETH -> the row's own product).
```

### 2.2 D2_V1_BREAKOUT_24H / D2_V2_BREAKOUT_72H (Donchian continuation)

```text
Prior range window W in {24h, 72h} of closed bars strictly before t.
Reference bars: the set of complete hourly bars with close_time_ms < t and
                open_time in (t - W, t).  [the last closed signal bar is EXCLUDED
                from the prior range]

Upper bound U(t) = max(high of reference bars)
Lower bound L(t) = min(low  of reference bars)
Test bar: the last closed bar strictly before t (close C_X(t), high H(t), low Lo(t)).

Break condition (close-based):   C_X(t) > U(t)  -> LONG   (s = +1)
                                 C_X(t) < L(t)  -> SHORT  (s = -1)
No break:                         L(t) <= C_X(t) <= U(t) -> s = 0 -> NO_TRADE
Equality:                         C_X(t) == U(t) or C_X(t) == L(t) -> s = 0 -> NO_TRADE
                                  (break requires STRICTLY beyond the boundary)
Dual-touch (both bounds equal/touched): s = 0 -> NO_TRADE (ambiguous, fail closed)
Break tested by CLOSE ONLY (not high/low touch). raw_score = s (sign only,
                                  magnitude not used in score; sign is the score).

Missing/gapped window: if the reference window contains fewer than (W/24) * 6 complete
                                  bars, the feature is undefined -> NO_TRADE (PIT_UNAVAILABLE).
```

### 2.3 D3_V1_FAILED_BREAK_24H / D3_V2_FAILED_BREAK_72H (failed-move reversal)

Chosen interpretation: **two-bar sequence** (break bar, then close-back bar) — the simplest pre-outcome interpretation consistent with BASE's "completed break-and-close-back".

```text
Prior range window W in {24h, 72h} of closed bars strictly before the break bar.
U(t) / L(t) as in Section 2.2 over that window.
Break bar b1: the last closed bar strictly before t with close strictly outside [L, U]:
                C(b1) > U -> upward break; C(b1) < L -> downward break.
Close-back bar b2: the bar immediately following b1 (open time = b1.close_time).
                A close-back occurs iff the break is upward and C(b2) < U, or
                the break is downward and C(b2) > L.  (close strictly back inside)

Side/raw score:
  upward break then close-back  -> s = -1 (reversal: SHORT)  raw_score = s_D3 = -1
  downward break then close-back -> s = +1 (reversal: LONG)  raw_score = s_D3 = +1
  no break, no close-back, or equality at a boundary -> s = 0 -> NO_TRADE
  (close-back requires STRICT re-entry: C(b2) == U after upward break is NOT a close-back)

Multi-bar: the close-back is tested ONLY on the immediately next bar (b2). If b2 does
  not close back, the pattern is closed (state reset): no later bar revives it. This
  freezes the state machine without adding a search parameter.

Missing behavior: missing b1 or b2 or insufficient window -> NO_TRADE (PIT_UNAVAILABLE).
raw_score = s (sign only).
```

### 2.5 Regime R_VOL_RANGE_V1_24H — exact raw scalar (no slash, no composite choice)

```text
Raw scalar (chosen, pre-outcome, no outcome access): realized volatility of log returns.

Inputs: close prices of the 24 complete hourly bars strictly before t, i.e. bars with
        open_time in (t - 24h, t), close_time_ms < t.
Let closes c_1..c_n (n = 24, ordered by time), log returns
        z_i = log(c_{i+1}/c_i) for i = 1..n-1  (n-1 = 23 returns).
Raw scalar RV(t) = sqrt( (1/(n-2)) * sum_i (z_i - mean(z))^2 )     [sample std, ddof=1]

Minimum complete bars: exactly 24 required; fewer -> NO_TRADE (PIT_UNAVAILABLE).
Units: dimensionless log-return volatility per hour, expressed as a float.
NaN/Infinity in any input -> NO_TRADE (PIT_UNAVAILABLE).

Percentile (PIT-safe) and state boundaries: R3R1 Section 1.1 preserved exactly:
  REGIME_VOL_LOW [0,0.40), REGIME_VOL_MID [0.40,0.60), REGIME_VOL_HIGH [0.60,1.0],
  lower-bound-owns-equality, only MID passes (reason THRESHOLD_UNMET otherwise).
```

### 2.6 Opportunity O_RANGE_EXPANSION_V1_24H — exact raw scalar

```text
Raw scalar (chosen, pre-outcome): true-range expansion over the trailing 24h.

TR_k = max(H_k - L_k, |H_k - C_{k-1}|, |L_k - C_{k-1}|)   (standard true range of bar k)
Raw scalar E(t) = TR_last / mean(TR over the 24 reference bars strictly before t,
              excluding the last bar), where TR_last is the true range of the last
              closed bar strictly before t.

Minimum complete bars: exactly 25 (24 reference + 1 last) required; fewer -> NO_TRADE.
Reference mean: simple arithmetic mean of the 24 TR values.
Equality: denominator > 0 required; denominator == 0 -> NO_TRADE (PIT_UNAVAILABLE).
Units: dimensionless ratio (float >= 0).

Percentile (PIT-safe) and state boundaries: R3R1 Section 1.2 preserved exactly:
  O_NONE [0,0.60), O_WATCH [0.60,0.80), O_ELIGIBLE [0.80,1.0], lower-bound-owns-equality,
```

## 3. Close H40-FSA-02/H40-FSA-03: Single PIT-Safe Percentile/Quantile Contract

One reusable normative percentile algorithm serves every active percentile/crowding feature (`R_VOL_RANGE`, `O_RANGE_EXPANSION`, and the D5 crowding quantile).

```text
Empirical CDF / rank:  for a reference sample S = {x_1..x_N} of raw scalars and a query x:
   rank(x) = (1/N) * |{s in S : s < x}|                       (strictly-lesser fraction)
   p(x)    = rank(x) + (1/N) * (0.5 if any s == x else 0.0)   (mid-rank tie rule)

Quantile Q(p) (used for D5 thresholds), exact nearest-rank method:
   sort S ascending; Q(p) = S[ceil(p*N) - 1]  (1-based order statistic, 0-based index
   ceil(p*N)-1); p in [0,1].

Tie handling: ties share the mid-rank empirical probability (above) and the
   order-statistic quantile is the value at the computed rank; no interpolation.
Equality handling: a query equal to a reference value gets p via the mid-rank rule.
Minimum reference N: 60. If N < 60 the percentile/quantile is undefined -> NO_TRADE.
NaN/Infinity: rejected from the reference and from the query -> NO_TRADE.
Sample ordering: reference ordering is irrelevant for the CDF/quantile (set semantics).

PIT safety (mandatory):
  - TRAINING rows: the reference distribution for a feature value at training
    timestamp t uses ONLY observations strictly before t (expanding lagged empirical
    reference). A feature value claimed available at t NEVER uses future observations,
    even inside the same offline training partition.
  - CALIBRATION/VALIDATION rows: the reference is the FROZEN training-time fitted
    distribution (the empirical reference fixed at the end of training, lagged one
    decision), not a per-row refit.  [for validation rows, the training reference is
    applied without recomputation]
  - WF refits: later WF refits re-estimate the reference on that fold's chronologically
    past training partition only (R1 Section 1.2, preserved).
  - Warm-up: no percentile value is emitted until the training reference has N >= 60;
    before that, the feature is undefined -> NO_TRADE.
```

The same algorithm is used for `R_VOL_RANGE` percentile (Section 2.5), `O_RANGE_EXPANSION` percentile (Section 2.6), and the D5 crowding quantile (Section 4).

## 4. Close H40-FSA-03 / R3R1-SOL-01: Finish D5 Funding Interaction Semantics

### 4.1 The crowding scalar (exact)

```text
Source field: the funding rate of the own-product perpetual at its last settlement
             strictly before t.
Last-settled record selection: among funding settlement timestamps with
             settlement_time_ms < t, take the one with the maximal settlement_time_ms.
             Funding after t is never used (PIT). If no settlement exists before t,
             the D5 feature is undefined -> NO_TRADE (SOURCE_MISSING / PIT_UNAVAILABLE).

Signed vs absolute: the raw funding rate is used SIGNED: f(t) in (-inf, +inf).
Side-aware vs side-independent: SIDE-AWARE.
Aligned crowding magnitude:  a(t) = f(t) * base_side(t)
  where base_side(t) = sign of the base owner's raw score (Section 1.1).
  a(t) > 0 means funding is aligned with (crowded in the direction of) the base side.

Tail/quantile meaning of q in {0.10, 0.20}:
  Q_train(q) = quantile of the training |a| distribution (absolute aligned crowding)
               at probability q, computed with the Section 3 algorithm on the PIT-safe
               training reference (chronologically past observations only).
  q is the UPPER-tail mass: extreme aligned crowding is defined by
  a(t) >= Q_train(1 - q)   (i.e., top 10% / top 20% of |a|).

Hypothesis (frozen, pre-outcome): CROWDING-REVERSAL for all three D5 components
  (D5_V1, D5_V2, D5_PAIR). Extreme aligned funding crowding predicts reversal,
  so it VETOES the base side.

Veto/confirm rule:
  if base_side != 0 and a(t) >= Q_train(1 - q):   VETO -> NO_TRADE
  if base_side != 0 and a(t) <  Q_train(1 - q):   PASS -> retain base raw_score
  if base_side == 0:                               NO_TRADE (no directional evidence)

Equality/tie behavior: at the threshold, a(t) == Q_train(1-q) IS a veto (>=).
  Ties in the quantile computation follow Section 3.
Missing source behavior: no settled funding before t, NaN/Infinity funding, or N < 60
  training reference -> NO_TRADE.
Training reference distribution: |a| over the PIT-safe training reference; frozen for
  calibration/validation (Section 3).
Raw score after filter: exactly the base owner's raw score if the filter passes
  (Section 1.1). Funding NEVER emits side by itself.
```

## 5. Close H40-FSA-04: Geometry Population and Fallback Determinism

### 5.1 Supersession of the BASE "N<30 => NO_TRADE" sentence

BASE Section 3.3's sentence "Fewer than 30 training observations in the applicable estimation cell causes `NO_TRADE`" is **superseded** by the R3/R3R2 pooling hierarchy below: `N < 30` triggers the next fallback level first; only when **every** fallback level has `N < 30` does the row fail to `NO_TRADE` with `INSUFFICIENT_CELL_N`.

### 5.2 Estimator population and cells

```text
Training-observation eligibility for geometry cells:
  observations = training-partition decisions at timestamp t that:
      (a) pass the regime gate (REGIME_VOL_MID),
      (b) pass the opportunity gate (O_ELIGIBLE),
      (c) have a non-zero raw score (directional evidence),
      (d) are on the training partition only (no calibration/validation rows).
Proposed-side mapping (per observation, using the configuration's proposed side s = +1/-1):
      s = +1 (LONG)  -> use MFE_LONG,  MAE_LONG
      s = -1 (SHORT) -> use MFE_SHORT, MAE_SHORT
  (BASE 3.3 definitions; MFE/MAE are training-realization values used ONLY inside the
   geometry estimator, never as protocol-authoring inputs.)

Exact cell keys: (scope, primary_horizon, direction_side)
  scope in {BTC_ONLY, ETH_ONLY, POOLED_BTC_ETH}; pooled cells pool BTC and ETH
  observations together (one joint cell per (scope, horizon, side)).

Fallback order (R3 Section 6, made exact):
  level 1: (scope, primary_horizon, direction_side)       [exact cell]
  level 2: (scope, primary_horizon)                        [pool over side]
  level 3: (scope)                                         [pool over horizon and side]
  level 4: global                                           [pool over everything]

Decision algorithm:
  for each level in order 1..4:
      if cell N >= 30: compute medians on this level; stop.
  if every level has N < 30: -> NO_TRADE (INSUFFICIENT_CELL_N).

Median convention (odd/even N): odd N -> middle order statistic; even N -> arithmetic
  mean of the two middle order statistics.

Gates applied at the winning level:
  estimated median MFE >= 1.5 * c_rt            (c_rt = 0.0012)
  estimated median MFE / max(estimated median MAE, c_rt) >= 1.25
  else -> FAIL -> NO_TRADE (THRESHOLD_UNMET).

Final fail-closed state if every level is thin: NO_TRADE (INSUFFICIENT_CELL_N), never a
  relaxed pass.
No fold uses calibration/validation future realizations in a geometry fit.
```

No MFE/MAE values are computed by this amendment.
