## 3. Defect and Repair Shape

**Before.** `ComparisonContract` preregistered the funding *model*, but every formal consumer took the funding settlement event set from the caller (`funding_events`). A candidate could supply any event list — including a sign-flipped rate or an empty list — and the run would hash cleanly, replay cold, and remain internally consistent, because no persisted artifact constrained the settlements.

**After.** The settlement event set is **reconstructed**, never chosen, from an independent, preregistered, content-bound funding evidence root:

- The protocol creation binds a required, deeply immutable `FundingIntervalIdentity` into `ComparisonContract.funding_interval` (`economic/qualification.py:237`, required — `:290-291` raises `TypeError` when absent). The identity is carried in the qualification `semantic_payload` (`:333`), so the preregistered comparison authority references the concrete funding evidence artifact.
- The concrete artifact is a strict canonical funding evidence file (schema v1.0.0, `evidence_type = FORMAL_FUNDING_SETTLEMENT_DATASET`, `ResultCompleteness.COMPLETE`, strict local validation, no network).
- Every formal consumer independently reconstructs the settlement tuples through one shared loader — `load_and_validate_funding_evidence(...)` (`economic/funding_evidence.py:105`) — and compares caller/persisted event lists as **assertions only**.
- `EconomicRunIdentity` gains `funding_evidence_id` and `funding_evidence_content_sha256` (`qualification.py:434-435`), binding each run identity to the exact evidence artifact.

New authority graph:

```text
preregistered ComparisonContract
  → funding model identity
  → FundingIntervalIdentity in ComparisonContract.funding_interval (required, in semantic_payload)
  → COMPLETE EvidenceReference → strict canonical funding evidence file
  → independently reconstructed FundingSettlement tuple
      → candidate simulation
      → benchmarks (PASSIVE + RANDOM share the same root)
      → cold execution replay
```

## 5. Proof That Caller/Persisted Event Lists Are Assertions Only

Four formal consumers reconstruct independently; none trusts a caller list:

1. **Candidate run** — `execute_bound_run(..., funding_evidence, funding_events=None)` (`qualification.py:979`): when `funding_evidence is None` the run is rejected outright (`:984` "funding-required"); `funding_events` is compared against the reconstruction as an assertion. `_random_matched_benchmark` (new required `funding_evidence` parameter, `qualification.py:~1665`) forwards the authority to its internal trial `execute_bound_run` (`funding_evidence=funding_evidence, funding_events=funding_events`).
2. **Cold execution replay** — `verify_execution_replay` (`execution_replay.py:59`): cross-checks the persisted run identity against the recorded reference (`:101-105`), then performs an **independent authoritative reload** from the persisted `formal_execution_replay_inputs.funding_evidence` (`:108-112` comment + `load_and_validate_funding_evidence` call), and rejects diverging persisted events (`:122` "persisted funding events differ from preregistered funding evidence"). A candidate that re-hashes every outer artifact still fails the independent reload (T15).
3. **Benchmark replay** — `verify_benchmark_replay` (`execution_replay.py:145`) rebuilds the suite through the same `_random_matched_benchmark` path with the independently reloaded funding evidence (`:176`).
4. **Formal research job** — `execute_formal_research_job` (`formal_research.py:258-264`) preloads `authoritative_funding = load_and_validate_funding_evidence(spec.funding_evidence, ...)`, forwards it to both the simulation and the replay bundle builds (`:268/:273/:280`), and records the result reference chain `[spec.dataset_evidence, spec.funding_evidence]` (`:283`).

Runtime/job `funding_events` is documented as an optional compatibility assertion only (`formal_research.py:106`); the caller's empty list never means "no settlements" (T7), because the loader's reconstruction always wins.
