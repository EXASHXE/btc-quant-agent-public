## 3. Root Cause Analysis

In previous versions, `MicrostructureStore.status()` keyed cached partition statistics with:
```python
cache_key = f"{path.name}:{st.st_mtime_ns}:{st.st_size}"
```
and assigned:
```python
stats_cache[cache_key] = {...}
```
without evicting older revisions for the same partition filename. Because the active day's partition is continually appended to during live capture, every inspection added a new entry while retaining all historic revisions. Furthermore, each entry persisted large arrays (`latencies`, `clocks`, `segments`), multiplying serialization payload size and causing the file to balloon to ~693 MB.

## 4. Cache-v2 Architecture & Implementation

### 4.1. Schema v2.0.0
Replaced revision-in-key storage with exactly one top-level cache entry per partition filename:
```json
{
  "schema_version": "2.0.0",
  "partitions": {
    "microstructure-YYYY-MM-DD.sqlite3": {
      "mtime_ns": 123456789,
      "size": 123456,
      "stats": {
        "depth": 0,
        "trades": 0,
        "gap_rows": [],
        "book_samples": 0,
        "aggregate_buckets": 0,
        "duplicate_count": 0,
        "conflict_count": 0,
        "segments": {},
        "depth_valid_segments": [],
        "orphan_count": 0,
        "latest_heartbeat_ms": null,
        "latest_clock": null,
        "integrity": true,
        "latencies": []
      }
    }
  }
}
```

### 4.2. Invariants Enforced
1. **One Entry Per Partition**: The dictionary key in `partitions` is strictly `path.name`.
2. **Freshness Identity**: Freshness is determined by `mtime_ns` and `size` stored inside the entry. Mutating a partition replaces the entry under the identical key.
3. **Mandatory Stale-Entry Pruning**: Before every save, the store determines `current_names = {p.name for p in self.root.glob("microstructure-*.sqlite3")}`. Any partition entry not in `current_names` is pruned immediately.
4. **Defensive Size Guard**: `MAX_PARTITION_STATS_CACHE_BYTES = 128 * 1024 * 1024` (128 MiB). If the cache exceeds this threshold, `_load_stats_cache()` unlinks the file and treats it as a miss without calling `read_text()`.
5. **Fail-Safe Miss Handling**: Malformed JSON, version mismatch, or corrupted stats schemas are treated as misses and cleanly rebuilt from SQLite.
6. **Safe Clock Optimization**: Clock queries fetch only the latest measurement per partition (`ORDER BY measured_at_ms DESC LIMIT 1`) and derive the globally latest clock via `max()`, avoiding storage of complete clock histories while preserving status equivalence.
7. **Atomic Publication**: Cache files are written via `publish_bytes` using compact JSON (`separators=(",", ":")`).
