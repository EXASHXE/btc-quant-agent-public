This document closes the remaining ambiguity between the accepted bootstrap seed/PCG64 contract and the exact mapping from PRNG output to moving-block start indices.

It does not alter the seed, block length, start universe, replacement rule, replicate count, block-boundary semantics, proxy-return formula, max-statistic, Holm control, hard gates, or candidate ranking.

## 1. Existing accepted authority

R1 §3.1 requires:

```text
L = 168
M = 10000
U_start = {0,1,...,H-168}
B = ceil(H/168)
```

and requires B start indices per replicate, sampled independently and uniformly with replacement.

R2 §3.3 requires:

```python
rng = np.random.Generator(np.random.PCG64(seed))
```

with the already accepted deterministic seed derivation.

The authority did not specify the discrete integer-sampling method.

Multiple mathematically uniform mappings from PCG64 output to `U_start` produce different deterministic sequences and therefore different bootstrap vectors.

---

## 2. Exact start-index mapping

Let:

```text
L = 168
M = 10000
S = H - L + 1
B = ceil(H / L)
```

Require:

```text
H >= 168
S >= 1
```

If:

```text
H < 168
```

the bootstrap evaluation is:

```text
NOT_TESTABLE
```

and no start-index RNG draw is permitted.

For `H >= 168`, instantiate exactly:

```python
rng = np.random.Generator(np.random.PCG64(seed))
```

Then, with zero prior RNG consumption from that generator, execute exactly one call:

```python
starts = rng.integers(
    low=0,
    high=S,
    size=(10000, B),
    dtype=np.int64,
    endpoint=False,
)
```

This single call is the complete accepted start-index sampling algorithm.

---

## 3. Matrix interpretation

The returned array shape is exactly:

```text
(10000, B)
```

Interpret:

```text
starts[m, b]
```

as:

```text
replicate index m = 0..9999
block draw index b = 0..B-1
source start index in U_start
```

Rows are consumed in ascending replicate order.

Columns are consumed in ascending block-draw order.

No transpose, flatten/rechunk, alternate reshape, or other reordering is authorized.

The sampled start index directly denotes the source-hour index:

```text
0 <= starts[m,b] <= H-168
```

---

## 4. Exactly one integer draw call

Per:

```text
candidate_id
partition_id
metric_id
seed
```

bootstrap evaluation, the accepted implementation uses exactly one `Generator.integers` call for the entire `(10000,B)` matrix.

Do NOT replace the single call with:
- one call per replicate;
- one call per block;
- `Generator.choice`;
- `Generator.random` plus float scaling;
- modulo reduction of raw uint64;
- custom rejection sampling;
- `random_raw`;
- Python `random`;
- `RandomState`;
- `default_rng` as a shorthand constructor;
- a new seed per replicate.

Even if another method is mathematically uniform, it is not the accepted deterministic mapping.

---

## 5. RNG consumption isolation

Immediately after:

```python
rng = np.random.Generator(np.random.PCG64(seed))
```

the next RNG operation MUST be the single accepted `rng.integers(...)` matrix draw.

No other random draw may consume generator state first.

After the matrix has been generated, metric recomputation must not use that same generator for any additional stochastic choice unless separately authorized by an accepted contract.

The start matrix is therefore a pure deterministic function of:

```text
seed
H
B
NumPy implementation/version
this sampler contract
```

## 12. Mandatory implementation invariants

Tests must prove:

1. `high == H-168+1`, endpoint excluded.
2. `size == (10000,B)`.
3. dtype is `np.int64`.
4. exactly one `Generator.integers` call is used.
5. no RNG call occurs before the matrix draw.
6. row m / column b mapping is exact.
7. repeated start indices are retained.
8. `Generator.choice` implementation is rejected.
9. custom `random_raw` rejection sampler is rejected even if uniform.
10. float scaling / modulo mapping is rejected.
11. wrong NumPy version fails replay closed.
12. regenerated canonical start-matrix hash must equal evidence hash.
13. `H < 168` is NOT_TESTABLE and draws nothing.
14. two exact replays with same version/inputs produce the exact same matrix hash.
15. different metric seed produces a different matrix except for astronomically accidental full equality, which test fixtures must avoid.
