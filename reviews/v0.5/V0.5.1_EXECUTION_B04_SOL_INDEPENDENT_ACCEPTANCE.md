## 1. Accepted Astra defect

ASTRA-B-04 is accepted:

```text
ExecutionService.reconcile()
loads a persisted plan/order
but selects the signed client from current config mode
without first proving persisted environment/account equality.
```

Therefore a persisted TESTNET plan can be routed through a LIVE client if configuration drifts.

The same class of authority must be checked for:

```text
submit_entry
reconcile
reconcile_open_plans
prepare_close where signed reads are involved
submit_close
cancel_entry
protective orders
failsafe close
```

## 2. Current deployment policy

For v0.5.1 the sole accepted deployment policy is:

```text
RESEARCH_DISABLED_V1
```

Normative rule:

```text
No signed Binance network capability is authorized in the current research branch.
```

This includes both writes and signed user/account/order reads.

There is no accepted production/testnet execution-write authority object.

Configuration values alone such as:

```text
execution.mode=testnet
execution.mode=live
allow_live=true
confirmation environment variables
credentials present
```

must not create execution authority.

Policy B from the Gemini document is retained only as future design input.

It is not implemented or authorized by this closure.

A later operational/testnet/live phase must receive separate explicit authority before signed capability becomes reachable.

## 3. Offline execution-environment authority

The implementation may introduce:

```text
EXECUTION_ENVIRONMENT_AUTHORITY_V1
```

with non-secret offline-verifiable fields:

```text
schema_id
mode
exchange_family
environment_id
normalized_rest_base_url
credential_namespace_id
account_authority_id
position_mode_assumption
margin_mode_assumption
```

### Requirements

`mode`:

```text
paper | testnet | live
```

`environment_id` must distinguish at minimum:

```text
local_paper
binance_usdm_testnet
binance_usdm_live
```

`credential_namespace_id` identifies which configured credential namespace the plan was created for, e.g.:

```text
NONE
BINANCE_TESTNET
BINANCE_LIVE
```

It contains no credential value.

`account_authority_id` is an explicitly configured non-secret stable account/subaccount authority label or opaque identifier.

It MUST NOT be derived by persisting:

- API secret;
- raw API key;
- a reversible credential representation.

The current closure does not require hashing an API key into long-lived artifacts.

TESTNET and LIVE can never share one environment identity.

## 4. Remote account attestation correction

The Gemini proposal attempted to use a signed account query as part of a preflight that was also required to finish before any signed request.

That ordering is inconsistent.

The accepted architecture separates:

### Stage A — offline authority preflight

Must complete before constructing/using a signed client:

```text
plan integrity
plan mode
persisted environment identity
current configured environment identity
credential namespace identity
configured account authority identity
order receipt binding
symbol
action classification
accepted execution-write authority
```

### Stage B — optional future remote attestation

Only after Stage A succeeds and a future execution-write authority exists may an operational deployment perform a signed read to attest remote account/position state.

Stage B is not authorized in current v0.5.1.

No concrete remote account endpoint is frozen into this authority closure.

## 5. Plan authority binding

Both `ExecutionPlan` and `ClosePlan` must bind:

```text
mode
execution_environment_id
credential_namespace_id
account_authority_id
```

inside their canonical plan hash.

All current risk/geometry fields already part of the plan hash remain bound.

Required invariant:

```text
mutated persisted plan + old plan_hash
-> fail before any signed capability
```

No environment value may be inferred at reconciliation time from current config alone.

## 6. Order receipt binding

A persisted exchange/order receipt must bind at minimum:

```text
plan_id
plan_hash
role
mode
execution_environment_id
credential_namespace_id
account_authority_id
symbol
exchange_order_id/client_order_id as applicable
status
submitted_at
```

A numeric/string order ID is never globally authoritative by itself.

Required compound identity:

```text
plan_hash
+
execution_environment_id
+
account_authority_id
+
symbol
+
exchange/client order identity
```

## 7. Required offline preflight order

Before any signed client construction or signed network interaction:

```text
P01 load persisted plan
P02 parse exact typed plan
P03 recompute plan hash
P04 require stored plan_hash equality
P05 verify plan kind/status
P06 resolve persisted mode/environment/account/credential namespace
P07 resolve current configured offline environment/account/credential namespace
P08 require exact persisted/current equality
P09 load relevant persisted order receipt
P10 require receipt plan_hash equality
P11 require receipt environment/account/credential namespace equality
P12 require symbol equality
P13 classify requested action
P14 require current accepted execution capability authority
P15 under RESEARCH_DISABLED_V1 -> fail closed
P16 signed client/network interaction is therefore unreachable
```

No injected/configured production signed client may bypass P01-P15.

Tests may use explicit test-only fake transports; those are not production authority.

## 9. Failsafe correction

The current repository's automatic reduce-only MARKET fallback is not authorized under `RESEARCH_DISABLED_V1`.

The repair must not merely make that path safer.

It must make the production path unreachable without a future accepted execution-write authority.

Any future reintroduction must separately prove:

```text
same environment
same account
current position
direction
bounded reducible quantity
reduce-only semantics
no increase in absolute exposure
auditable provenance
```

That future policy is outside this repair.
