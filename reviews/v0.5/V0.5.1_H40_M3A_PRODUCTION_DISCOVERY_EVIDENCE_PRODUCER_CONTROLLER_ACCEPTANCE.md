## Runtime scaling blocker discovered by Controller

M3A correctness tests use a compact synthetic source and record:

```text
exact synthetic decision rows = 9504
producer + verifier round-trip test call ~= 47.41 seconds
```

The real frozen WF1 split is approximately:

```text
WF1_TRAIN = 15312 hours
WF1_CALIBRATION = 2184 hours
18 registered candidates

raw candidate/partition decision rows =
18 * (15312 + 2184) = 314928
```

Raw row count alone is ~33x the synthetic equivalence fixture.

More importantly, current production reconstruction contains super-linear paths.

### Hotspot RUNTIME-01 — training percentile reconstruction

`_reconstruct_prefit_cached()` performs for every WF1_TRAIN decision:

```python
rv_sample = [v for dt, v in rv_series if dt < t]
exp_sample = [v for dt, v in exp_series if dt < t]
```

followed by `_empirical_percentile()`, which scans the sample again for strict-less and tie detection.

Therefore expanding-reference percentile reconstruction is O(N^2) in the training length for each candidate cache identity.

The cache key includes candidate ID, so three configurations sharing one direction contract do not share the same reconstructed regime/opportunity state.

### Hotspot RUNTIME-02 — geometry lookup

`_geometry_pass()` scans the full owner geometry record set at each fallback level for every calibration decision, rebuilding subsets before median calculation.

This is O(calibration_rows * training_geometry_rows) per candidate in the current implementation.
