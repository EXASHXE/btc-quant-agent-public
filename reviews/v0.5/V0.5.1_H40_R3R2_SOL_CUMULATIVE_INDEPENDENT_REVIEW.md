## 3. Detailed findings

### R3R2-SOL-01 — Hourly bar indexing is not a single coherent clock

R3R2 Section 2.0 defines:

```text
C_X(t)     = close of the last hourly bar strictly before t
C_X(t-W)   = close of the hourly bar with open time (t-W)
r_X(t,W)   = log(C_X(t)/C_X(t-W))
```

This mixes a close-boundary endpoint for `C_X(t)` with an open-time endpoint for `C_X(t-W)`. With canonical hourly bars, a W-hour return should compare closes separated by exactly W hourly intervals. The current formula can span W-1 intervals depending on how the exchange close timestamp is represented.

The same ambiguity propagates into D4 and any return-derived raw score.

The repair must define relative closed-bar indices once, e.g. `B_0(t)=[t-1h,t)`, `B_j(t)=[t-(j+1)h,t-jh)`, then define all formulas from those indices.

### R3R2-SOL-02 — D2 and D3 remain semantically defective

D2 states that the last closed signal bar is excluded from the prior range, but its formal reference set is:

```text
complete bars with close_time<t and open_time in (t-W,t)
```

while the test bar is also “the last closed bar strictly before t”. Under the literal set expression the test bar participates in `U(t)`/`L(t)`. Since a close cannot exceed its own bar high or be below its own bar low, a close-based breakout against a range containing the test bar is mechanically suppressed. The additional minimum-window rule `(W/24)*6` is also incompatible with a 24h/72h hourly Donchian range.

D3 has two further issues:

1. “the last closed bar strictly before t with close outside [L,U]” does not uniquely mean the immediately preceding break bar; an implementation may search arbitrarily far backward;
2. close-back after an upward break is only constrained by `C(b2)<U`, and after a downward break only by `C(b2)>L`. That does not guarantee that `b2` closed strictly *inside* the prior range; an overshoot through the opposite boundary would still qualify.

The simplest unique repair is:

```text
B0 = last usable closed bar at t
B1 = immediately preceding bar
D2 prior range = B1..BW; test bar = B0
D3 prior range = B2..B(W+1); break bar = B1; close-back bar = B0
close-back requires L < C(B0) < U
```

with exact consecutive-bar requirements and no stale-pattern search.

### R3R2-SOL-03 — Platt calibration may reverse the hypothesis

R3R2 freezes the orientation:

```text
larger raw_score = more bullish
smaller raw_score = more bearish
```

but then fits an unconstrained Platt form:

```text
p_up = sigmoid(a*raw_score+b)
```

If `a < 0`, a positive D1/D2 continuation score becomes *less* bullish than a negative score. The calibrator then silently converts an authorized continuation/reversal family into the opposite directional hypothesis. That is not calibration; it is an unregistered sign inversion.

Isotonic is nondecreasing and therefore preserves orientation, so Platt must do the same. The repair should define a monotone Platt contract, preferably a unique finite constrained MLE with `a >= 0`, and fail closed when no unique finite orientation-preserving fit exists. `a == 0` should not be allowed to create one-sided trades from a directionless constant mapping.

The current Newton-Raphson description also omits enough initialization/singularity/separation detail that two implementations need not terminate identically. A mathematically unique constrained optimum + explicit degeneracy/fail-closed rule is preferable to over-specifying an implementation-specific optimizer.

### R3R2-SOL-04 — Fit populations do not consistently follow the funnel

The action funnel places secondary D4/D5 confirm-veto filtering before calibration. Yet the calibration-population text explicitly mentions regime, opportunity, nonzero raw score, and non-neutral label without clearly requiring the secondary filter to pass.

The same issue appears in geometry eligibility and D5 crowding-reference construction.

For a pair/D5 candidate, fitting on rows that the candidate itself would veto changes `p_up`, geometry medians, and the D5 threshold distribution. The repair must freeze a single candidate-pre-fit eligibility sequence:

```text
valid sources/PIT
-> regime passes
-> opportunity passes
-> base raw_score != 0
-> secondary confirm/veto passes (when present)
```

Calibration then additionally requires a non-neutral binary target. Geometry uses the pre-fit population with realized training-only MFE/MAE. D5's own quantile reference must state exactly whether it is fit on the pre-D5 base-eligible population or after the D5 filter; it cannot be circular.

Recommended non-circular D5 rule: build the crowding reference from rows that pass source/PIT + regime + opportunity + nonzero base side, before applying the D5 tail veto itself.

### R3R2-SOL-05 — Geometry ownership and fallback deduplication remain ambiguous

R3/R3R2 specify fallback:

```text
(scope,horizon,side)
-> (scope,horizon)
-> scope
-> global
```

but geometry eligibility depends on the candidate's raw directional score. A full configuration itself has one scope and one primary horizon, so levels 3/4 cannot expand unless the estimator pools across sibling configurations. The protocol does not state which sibling configurations share one estimator, whether threshold/calibration refinements duplicate the same observation, or whether the same BTC/ETH market observation appearing under single-asset and pooled scopes is counted multiple times.

Repair this by defining one geometry-fit owner and one unique observation key. A minimal construction that preserves the R3 hierarchy is:

```text
geometry_fit_owner = direction_contract_id (single variant or pair variant)
unique geometry row key = (direction_contract_id, scope, primary_horizon,
                           decision_t, product, proposed_side)
```

Threshold/calibration refinements must not duplicate geometry rows. Fallback levels operate only within the same `direction_contract_id`; pooled rows preserve the already-frozen equal BTC/ETH weighting.

### R3R2-SOL-06 — Active gate lookbacks still have counting defects

`R_VOL_RANGE_V1_24H` describes 24 closes but only 23 one-hour returns. If the intended quantity is trailing 24h hourly realized volatility, the protocol should define 24 one-hour returns with 25 close endpoints, or explicitly rename/retain a 23-return estimator.

`O_RANGE_EXPANSION_V1_24H` requires 24 reference TR values plus `TR_last`, but standard true range for the earliest reference bar needs the previous close. Therefore the exact predecessor requirement must be part of the minimum complete-bar contract. The clean indexed definition is:

```text
TR_j = max(H_j-L_j, abs(H_j-C_{j+1}), abs(L_j-C_{j+1}))
E(t) = TR_0 / mean(TR_1..TR_24)
```

which requires bars `B_0..B_25` to be complete and consecutive.

### R3R2-SOL-07 — Percentile tie rule is mislabeled and boundary-incomplete

Published formula:

```text
p(x)=#(s<x)/N + 0.5/N if any tie exists
```

is not a mid-rank when `m>1` observations equal `x`. The actual mid-rank empirical CDF is:

```text
p(x) = ( #(s<x) + 0.5 * #(s==x) ) / N
```

The repair should use that exact formula. Also either constrain nearest-rank `Q(p)` to `0 < p <= 1` or explicitly define `Q(0)=min(S)`; the current `ceil(0*N)-1` produces an invalid negative rank under the stated contract.

### R3R2-SOL-08 — Calibration semantics are not transitively content-bound

The semantic-root tree labels a field `calibration_contract_hashes` but fills it with textual IDs:

```text
[CALIBRATION_PLATT_LOGISTIC_V1,
 CALIBRATION_ISOTONIC_IF_ELIGIBLE_V1]
```

A material change in the calibration target, slope constraint, degeneracy rule, or isotonic semantics under the same textual ID would therefore not necessarily alter `semantic_root_hash`. This violates the cumulative R3 principle that material semantic changes must change structural identity.

The repair must hash the full canonical calibration contract objects and place those actual content hashes in the semantic root. The same transitive-content rule must hold for every child registry/root.

### R3R2-SOL-09 — ECE/Brier population is now under-specified

R3R2 defines `p_up` as conditional on non-neutral directional outcomes. BASE separately requires ECE and positive Brier skill for probabilistic candidates. After the ternary-to-binary repair, the protocol must state the exact population and target used by ECE/Brier/Brier-skill, and the frozen constant base-rate predictor against which Brier skill is measured.

The coherent minimal rule is to evaluate probability diagnostics on the same non-neutral binary target population used to define `p_up`, while keeping accepted-trade precision on all accepted trades including neutral outcomes. The base-rate probability must be estimated only from the calibrator's allowed calibration population and then frozen for any later evaluation partition.
