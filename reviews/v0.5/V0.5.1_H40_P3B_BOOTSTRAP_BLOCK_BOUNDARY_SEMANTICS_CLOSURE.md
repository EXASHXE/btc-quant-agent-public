# V0.5.1 H40 P3B — Bootstrap Block-Boundary Semantics Closure

## Status

```text
H40_P3B_BOOTSTRAP_BLOCK_BOUNDARY_SEMANTICS_CLOSURE
PRE_OUTCOME
NO_REAL_H40_OUTCOMES_ACCESSED
```

This document closes an ambiguity in R1 §3.1–3.4 concerning fixed-horizon outcomes near moving-block boundaries and the final trimmed bootstrap tail.

It does not alter the accepted block length, replicate count, seed, null, quantile, max-statistic, Holm control, proxy-return formula, hard gates, or selection order.

---

## 1. Existing accepted authority

R1 freezes:

- 168-hour non-circular source blocks;
- joint BTC/ETH UTC-hour sampling;
- concatenation of B sampled blocks;
- trimming to exactly H sampled hourly positions;
- extraction of accepted trades from the replicate;
- recomputation of replicate precision, net expectancy, and profit factor.

BASE separately freezes each candidate decision's fixed primary horizon and the source-timeline endpoint used to define its label and proxy economic return.

The accepted text did not specify whether a decision near the end of a sampled block should:
1. use its original source-timeline endpoint, or
2. use the synthetic next block after concatenation.

Those choices produce different outcomes and therefore require pre-outcome closure.

---

## 2. Fundamental rule: bootstrap resamples observation bundles, not a synthetic market path

The accepted interpretation is:

```text
A bootstrap replicate resamples source-anchored decision/outcome observation bundles
in 168-hour source blocks.

The concatenated bootstrap timeline defines only:
- which source decision hours are sampled,
- their multiplicity,
- and their replicate order.

It does NOT define a new price path, feature path, or holding-period endpoint path.
```

For every retained sampled decision hour, all fixed-horizon scientific outcomes remain anchored to that decision's original source timestamp and accepted source evidence.

---

## 3. Exact 168-hour block semantics

Each sampled block contains exactly 168 consecutive **source decision-hour identities**.

For each source hour, the block carries the candidate's already-bound decision state for that source hour, including the aligned BTC/ETH rows where applicable.

The block core is:

```text
source hour j
through
source hour j + 167
```

The existing non-circular start universe is unchanged.

Repeated or overlapping source blocks are allowed exactly as ordinary bootstrap multiplicity.

If one source hour appears multiple times in a replicate, each occurrence is a distinct bootstrap occurrence carrying the same source-bound decision/outcome evidence.

---

## 4. Candidate decision semantics

The candidate is NOT re-executed on the synthetic concatenated sequence.

For a retained sampled source hour:

```text
action =
the candidate action already bound to that original source decision hour
```

No feature, calibration, signal, gate, or action is recomputed using a previous/next bootstrap block.

Therefore artificial cross-block feature states cannot be created.

---

## 5. Fixed-horizon endpoint semantics

For a sampled accepted trade with:

```text
source decision timestamp = t
candidate primary horizon = h
```

the endpoint is always the original accepted source-timeline endpoint:

```text
C_h(t)
```

defined by BASE for that source timestamp and horizon.

Thus:

```text
r_h(t) = log(C_h(t) / P0(t))
```

and proxy return remains computed from that source-bound endpoint using the accepted:

```text
H40_P3B_PROXY_NET_RETURN_FORMULA_V1
```

No endpoint is obtained from the next synthetic bootstrap block.

---

## 6. Cross-block prohibition

The following is explicitly forbidden:

```text
sample block A
then sample unrelated block B
then use a price from block B as the fixed-horizon exit for a decision in block A
```

No label, proxy return, MFE/MAE path, feature, or action may be formed by crossing a bootstrap concatenation boundary.

The bootstrap concatenation boundary has no market-time meaning.

---

## 7. Source-local outcome support / halo

A retained source decision may require source evidence after the end of its 168-hour sampled core.

That is allowed only through the original source-timeline outcome support already authorized by the split/purge contract.

For example, a 12-hour trade emitted during the final hours of a 168-hour sampled core may use its original source-local +12h endpoint even though that endpoint lies outside the 168-hour block core.

This is NOT a 180-hour block.

The extra source rows are outcome-support evidence only; they:
- do not become sampled decision hours,
- do not add bootstrap multiplicity,
- do not alter block length,
- do not create additional candidate decisions.

If the required source-local endpoint is not authorized/available under the original split/purge/source authority, the scientific input fails closed.

No cross-boundary substitution is permitted.

---

## 8. Final trimming semantics

R1's rule remains:

```text
draw B blocks
concatenate 168 * B sampled core-hour positions
retain only the first H sampled core-hour positions
```

The exact closure is:

### Retained core position

If a sampled decision-hour position is within the first H retained positions:
- its candidate decision is retained;
- if it is an accepted trade, its original source-anchored fixed-horizon outcome is retained;
- its outcome may extend beyond the retained synthetic tail because synthetic position is not market time.

### Discarded core position

If a sampled decision-hour position lies after the first H retained positions:
- that decision occurrence is discarded entirely;
- it contributes no action, trade, label, return, or metric.

There is no partially retained trade.

Do NOT remove the last h hours of the retained synthetic sequence merely because their source-anchored outcomes extend beyond synthetic position H.

---

## 9. Missing outcome behavior

For every retained accepted trade, complete authorized source-bound scientific outcome evidence is mandatory.

If it is missing, malformed, outside source/split authority, or inconsistent with the candidate horizon:

```text
FAIL CLOSED
```

Do not:
- drop only that trade from the replicate;
- shorten its horizon;
- use the next bootstrap block;
- impute zero/neutral;
- use the nearest available close.

Any existing candidate/family NOT_TESTABLE or fit-invalid handling remains authoritative.

---

## 10. Replicate ordering

Replicate order is deterministic:

```text
sampled block draw order
-> source hour ascending within each block
-> existing same-hour product ordering
```

The existing BTC-before-ETH same-hour ordering remains unchanged where applicable.

Replicate ordering may be used for deterministic output ordering only.

It does not redefine source timestamps for outcome calculation.

---

## 11. Statistical consequence

For each replicate, precision and net expectancy are recomputed from the multiset of retained sampled decision/outcome bundles.

Thus the bootstrap changes:
- which source observations appear;
- how many times each appears;
- their replicate sequence.

It does NOT change the realized source-local outcome attached to a sampled decision.

This preserves the original fixed-horizon estimand while using 168-hour blocks to resample dependence structure.

## 13. Mandatory implementation invariants

Production verifier/tests must prove:

1. a trade in source hour 167 of a sampled block uses its original source endpoint, never block 2;
2. changing the next sampled block cannot change block 1 retained trade outcomes;
3. the same source hour sampled twice yields two replicate occurrences with identical source-bound outcome;
4. retained final-tail trades are included when their authorized source outcome exists;
5. discarded post-H synthetic positions contribute nothing;
6. source outcome support beyond the 168-hour core never creates extra sampled decisions;
7. missing source endpoint fails closed rather than dropping only one replicate trade;
8. candidate actions are copied from source-hour evidence, not re-run across synthetic boundaries;
9. BTC/ETH joint source-hour sampling remains inseparable;
10. no synthetic concatenation timestamp is used to look up P0 or C_h.
