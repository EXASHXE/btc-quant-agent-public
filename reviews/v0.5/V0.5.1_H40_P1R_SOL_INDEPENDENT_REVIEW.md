## Accepted closures

### P1-F1 HIGH — caller-forgeable confirmation readiness: CLOSED

The public `H40ConfirmationGuard` no longer accepts a readiness boolean or any other caller-controlled capability. During P1/P1R, `is_ready` is fixed false and `assert_outcomes_accessible()` always fails closed. `H40LifecycleStateMachine` construction is restricted to preregistered/P1-scaffold states, so direct construction at discovery/candidate/validation/confirmation states is rejected.

This is sufficient for P1/P1R. Future confirmation readiness must still be introduced only by a separately authorized, content-addressed authority task; P1R correctly does not invent that capability.

### P1-F2 HIGH — protected-source relabel/open bypass: CLOSED

Protected-path authority is now enforced independently of caller source status before source filesystem content operations. Raw locator, source ID, normalized path, and resolved path are checked. `validate_source_artifact()` performs the protected-surface check before local byte/timestamp inspection. The synthetic relative-path/symlink/relabel attacks cover the intended bypass family without opening H39 or Final Holdout data.

### P1-F3 MEDIUM — source/timestamp reconstruction: CORE LOGIC VALID

The implementation correctly separates preregistered reference metadata from local validation receipts, hashes local bytes, extracts timestamp-only evidence, records gaps/duplicates/membership hashes, and provides a materialized BTC/ETH common-intersection split builder. Static schedule construction is marked non-authoritative.

However, one remaining authority bypass prevents final acceptance.

## Blocking finding

### P1R-F1 HIGH — authoritative split status is still caller-forgeable

The current `H40SplitManifest.build_materialized()` API accepts:

```text
btc_timestamps: Sequence[str]
eth_timestamps: Sequence[str]
btc_receipt: optional
eth_receipt: optional
```

Both receipts are optional. Any caller can pass arbitrary non-empty timestamp arrays and receive a split with:

```text
is_authoritative = True
```

without proving that either timestamp sequence came from `validate_source_artifact()` or from a materialized VERIFIED H40 source manifest.

The focused tests explicitly use this bypass as a positive path: synthetic `generate_hourly_range(...)` arrays are passed with no receipts, and the result is asserted authoritative.

There is a second equivalent construction path: `H40SplitManifest` exposes `is_authoritative` as caller-controlled serialized dataclass state, and `from_dict()` accepts it. A caller can therefore construct/deserialise a manifest with `is_authoritative=True`; `assert_authoritative()` currently checks only that boolean.

This contradicts the P1/P1R authority requirement that materialized authority be derived from verified local source bytes/timestamps rather than metadata or caller assertions. It also makes the source-manifest hash only a string field rather than proof that the timestamp membership was reconstructed from that manifest.

Impact is latent because labels/search remain unauthorized, but this object is intended to become the split authority used by later H40 phases. Allowing caller-chosen membership to acquire `authoritative` status could later alter train/calibration/validation membership, hide gaps, or admit future/foreign timestamps.

Severity: **HIGH authority-boundary blocker**.

## Required repair semantics

A final narrow P1 authority repair should ensure all of the following:

1. No public constructor/deserializer boolean alone can make a split authoritative.
2. The public authoritative materializer must consume verified source authority, not caller timestamp lists alone.
3. Required BTC/ETH candle authorities must be locally revalidated or cold-verified against exact local bytes before authoritative split construction.
4. Timestamp membership used by the split must be independently extracted/reconstructed from those verified artifacts or strictly verified against their validation receipts.
5. Receipt fields must be bound to the exact source record/artifact: source ID, locator, byte SHA, product, cadence, timestamp count, first/last timestamp, duplicate/gap state, and timestamp-membership hash.
6. `source_manifest_hash` in the resulting split must equal the exact verified manifest consumed by materialization; an arbitrary caller string cannot substitute another source root.
7. Serialized/rehashed `is_authoritative=true`, forged receipt content, omitted receipts, mismatching membership hashes, and arbitrary timestamp arrays must all fail closed.
8. Synthetic timestamp-only fixtures remain allowed for unit testing only through a verifier-owned test source artifact/receipt path, not by bypassing source authority.

An implementation may keep a low-level pure split function for internal testing/calculation, but it must be explicitly non-authoritative/private and unable to produce an authority object accepted by downstream H40 gates.
