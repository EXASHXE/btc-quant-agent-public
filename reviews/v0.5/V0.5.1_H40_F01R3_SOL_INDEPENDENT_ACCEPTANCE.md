## 3. Accepted B-01 semantics

The production WF universe is exactly four folds:

```text
WF1 -> WF1_VALIDATION
WF2 -> WF2_VALIDATION
WF3 -> WF3_VALIDATION
WF4 -> WF4_VALIDATION
```

Confirmation is not a fifth WF fold.

Production expected WF authority must be derived from the seal-bound runtime split and accepted validation-contract authority.

Caller construction of a self-consistent reduced expected authority cannot grant production WF authority.

No change is made to:

```text
wf_validation_receipt_contract_hash =
bb5698a85daec1a5b9dcd169bde3d575befe8c0a1d73c2e87136cf35afb4001b
```

because that child already requires complete derivation/no subset.

## 4. Accepted B-02/H-01 semantics

Per `run_authority_id` there is exactly one committed authoritative durable head.

The head schema is:

```text
H40_DURABLE_RUN_HEAD_V1
```

The committed head binds:

```text
run_authority_id
head_receipt_hash
head_state
head_predecessor_receipt_hash
transition_sequence
terminal
```

The lifecycle history commit point is durable-head advancement, not receipt-file existence.

Receipt publication happens first.

A fully durable receipt that is not referenced by the committed head is an uncommitted orphan and grants no lifecycle authority.

Head advancement must be a **linearizable transactional compare-and-advance**, not a read/check followed by an unconditional atomic rename.

Recommended implementation:

```text
SQLite transaction
BEGIN IMMEDIATE
conditional head advance
COMMIT
```

Terminal committed heads are absorbing across restarts and processes.

Restore may only issue authority for the committed head or its unique ancestor lineage.

## 5. Accepted B-03 semantics

Capability model:

```text
MODEL A
```

Before any production transition issuance, revalidation or consumption of a cached prior authorization:

```text
recursively resolve root runtime authority
reverify runtime snapshot seal
cold revalidate current active-source truth
then consume prior authorization
```

Cached and cold-restored semantics must be identical.

If an active source disappears or mutates, cached descendants do not remain valid transition capabilities.

## 6. M-01 disposition

Gemini's M-01 rule is not accepted because it referenced a nonexistent generic `receipt.row_count` field and fixed data-specific counts/gap values.

M-01 remains:

```text
OPEN MEDIUM / PRE-P3 OBLIGATION
```

If implemented during F01R3, only generic equality may be used:

```text
record.row_count == cold_receipt.timestamp_count
record.gap_count == cold_receipt.gap_count
record.start_utc == cold_receipt.first_timestamp_utc
record.end_utc == cold_receipt.last_timestamp_utc
```

No fixed runtime count or zero-gap assumption becomes authority.
