## What P1R5 correctly closes

P1R5 correctly repairs both findings from the previous review.

### Production/test authority boundary

The public production APIs no longer accept a caller-controlled authority policy. `H40AuthorityPolicy` is removed from the public surface and production `materialize_authoritative(...)` / `assert_authoritative(...)` unconditionally apply canonical source checks.

Synthetic validator mechanics are separated into dedicated non-authoritative APIs. Synthetic outputs have `is_authoritative=False` and `attestation.is_production_canonical=False`, and production assertion rejects them.

The canonical source specification now explicitly records production authority availability. Under the currently accepted protocol:

```text
BTCUSDT_USD_M_1H = NOT_TESTABLE
ETHUSDT_USD_M_1H = VERIFIED
```

Therefore a synthetic 1h BTC artifact placed at the canonical locator cannot create production split authority. The implementation correctly accepts the safe result that the production split is currently unavailable.

### Hermetic CI

The previous tests depended on repository-local untracked market artifacts. P1R5 removes that assumption and separates hermetic synthetic validator tests from environment-dependent canonical source availability.

## Remaining finding

### P1R5-F1 MEDIUM — frozen canonical file SHA may be omitted as `None`

`assert_canonical_source_record(...)` currently validates the frozen reference file identity with this condition:

```python
if (
    spec.reference_file_sha256 is not None
    and record.file_sha256 is not None
    and record.file_sha256 != spec.reference_file_sha256
):
    raise ...
```

This rejects a wrong SHA but accepts a missing SHA (`record.file_sha256 is None`) even when the canonical source spec has a frozen `reference_file_sha256`.

For ETH, the accepted canonical spec has a frozen file SHA and production authority state `VERIFIED`. A caller can therefore construct a VERIFIED ETH source record with:

```text
canonical source_id
canonical product
canonical cadence
canonical locator
canonical archive_set_sha256
file_sha256 = None
```

and bypass the canonical file-SHA equality check. Subsequent cold validation hashes the actual file, but because the record itself contains no expected file SHA, `validate_source_artifact(...)` does not compare those bytes to the protocol-frozen canonical file SHA. The receipt/attestation can then bind the caller's actual bytes instead of the frozen canonical bytes.

Today this cannot by itself create a production authoritative H40 split because BTC production authority is explicitly `NOT_TESTABLE`, so the production builder fails before a BTC+ETH pair can be authorized. That is why this finding is classified MEDIUM rather than HIGH.

However, it is an incomplete source-authority scaffold and would become exploitable immediately when a future protocol amendment establishes BTC canonical production authority. P1 should close this now, before downstream stages depend on this boundary.

Existing tests cover an incorrect ETH `file_sha256`, but not omission/null of the canonical SHA.

## Required closure

When a canonical source spec freezes `reference_file_sha256`, canonical production authority must require exact presence and equality:

```text
spec.reference_file_sha256 is not None
=> record.file_sha256 must be non-null
=> record.file_sha256 == spec.reference_file_sha256
```

`None`, empty string, malformed value, or any unequal value must fail closed with `SOURCE_HASH_MISMATCH` (or an equivalently precise source-authority failure).

Add adversarial tests for at least:

1. ETH canonical record with `file_sha256=None` fails;
2. ETH canonical record with `file_sha256=""` fails;
3. exact frozen ETH SHA remains accepted by `assert_canonical_source_record` when all other canonical fields are correct;
4. synthetic validator APIs remain non-authoritative;
5. BTC remains `NOT_TESTABLE` and cannot obtain production authority;
6. exact-head ordinary push CI is green.

Do not change source locators, split math, confirmation/lifecycle semantics, protocol identity, H39/Final Holdout protections, execution state, or the frozen kernel.
