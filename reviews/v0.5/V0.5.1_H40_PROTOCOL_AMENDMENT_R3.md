Common rules for all ten variants:

- **Availability rule**: `AVAILABILITY_CLOSED_BAR_STRICT_V1` — every feature row has `available_at_ms <= t`; candle-derived features use only candles with `close_time_ms < t` and `closed == true`; the decision is made at hourly boundary `t`; the reference price `P0(t)` is the linear-perpetual 1h candle open at `t` used only as an event observable.

- **Missing-data behavior**: `FAIL_CLOSED_NO_TRADE` — missing/ambiguous/mismatched inputs make the row `NO_TRADE`; nothing is imputed or interpolated.
- **Mechanical refit identity**: `REFIT_CHRONOLOGICAL_PAST_ONLY_V1` — parameters re-estimated only on chronologically past observations at locked fold boundaries; zero parameter-grid expansion, zero family substitution, zero configuration mutation.
- **Normalization/train-fit rule**: percentile-style statistics (regime/opportunity/crowding) are fitted on the current training partition only, lagged one decision, and frozen for the following calibration/validation interval; raw directional measures (closed-bar log returns, range breaks) are used sign-wise without cross-sectional scaling (Section 4).

## 10. Canonical Serialization and Immutability Contract

- **Canonical JSON**: RFC-8259 deterministic serialization, sorted object keys, no insignificant whitespace, UTF-8, no duplicate keys; numeric rounding rules as defined by the repository's `canonical_json` (floats rounded to the same precision as the source field; thresholds stored exactly as `0.55`/`0.60`/`0.65`).
- **Ordering rules**:
  - `family_combination` order is **semantic**: base owner first, then the filter/confirming family (Section 3). 
  - `required_feature_ids` order is **semantic** where it encodes the pipeline (base direction feature first); otherwise it is frozen per contract and preserved verbatim.
  - `assets`/`product_scope` are **set-ordered**: sorted ascending (`BTCUSDT`, `ETHUSDT`).
  - `contract_references` are **set-ordered**: sorted by contract id.
  - `source sets` are sorted ascending by source id.
- **Duplicate semantic rows**: duplicate `configuration_hash` values are rejected (`CONFIG_IDENTITY_CONFLICT`); duplicate semantic rows cannot be distinguished only by slot number.
- **Immutability**: nested semantic data is immutable after construction; mutation of any material semantic field requires a new hash. Round-trip serialization (`to_dict`/`from_dict`) must preserve every hash bit-for-bit.
