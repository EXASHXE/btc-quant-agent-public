# B04 — BTC/D4 expansion is materially understated

Baseline R2 describes BTC/D4 expansion as approximately one configuration step / adding BTCUSDT_USD_M_1H to the P1 snapshot.

Current code explicitly has:

```text
P1_SOURCE_AUTHORITY_STATES[BTCUSDT_USD_M_1H] = NOT_TESTABLE
```

and the canonical source spec also marks BTC production authority NOT_TESTABLE.

Source promotion requires formal source validation/evidence and changes the runtime authority snapshot identity.

Additionally, the frozen BTC locator is:

```text
data/research/BTCUSDT/data_manifest.json
```

but the F02 production JSON economic adapter requires the active source bytes themselves to expose hourly timestamp/open/high/low/close rows (or bars[]). The current Binance archive builder's data_manifest.json is metadata/checksum inventory, not economic OHLC rows.

Therefore BTC expansion must be reclassified from READY_AFTER_SMALL_EXTENSION / 1 config step to something like:

```text
READY_AFTER_SOURCE_AUTHORITY_AND_ECONOMIC_ADAPTER_CLOSURE
```

Future closure must include canonical BTC 1h economic artifact/adapter binding, source validation receipt, runtime source-authority promotion, new runtime snapshot identity/evidence, and production verification.
