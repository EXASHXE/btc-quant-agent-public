## 3. Re-gate of the four original findings

### AG-01 — funding source substitution

**Result: CLOSED.**

Current formal jobs require an explicit local `funding_evidence` reference. `ComparisonContract.funding_interval` is part of the comparison semantic payload and therefore its hash/identity. The funding interval binds:

```text
evidence_id
content_sha256
coverage_start_ms
coverage_end_ms
event_count
event_set_sha256
```

`load_and_validate_funding_evidence()` independently checks exact evidence identity/content hash, exact comparison coverage, COMPLETE evidence, product, schema, strict timestamp ordering, finite rates/prices, event count and canonical event-set hash. COMPLETE zero-event evidence is therefore distinguishable from caller omission.

`FormalResearchJobSpec.funding_events` is now only a compatibility assertion. `run_formal_job()` reconstructs authoritative funding from preregistered evidence before candidate/benchmark execution. `verify_execution_replay()` reloads evidence bytes again during cold replay, compares persisted funding events only as an assertion, and requires the reconstructed event hash to equal the run identity.

The R05CR closure additionally requires the run-bound funding evidence ID in qualification `required_evidence_ids`; the persisted validator independently enforces the same invariant. Existing registry logic then requires the exact content-addressed funding `EvidenceReference` to be present and locally hash-valid.

The original `+rate / -rate / empty list` self-consistency family can no longer share unchanged comparison/protocol authority. Sign swap, event deletion/addition, timestamp/mark/rate substitution, evidence replacement or persisted full rehash necessarily changes/fails an independently preregistered root.

### AG-02 — candidate-controlled material-input selection

**Result: CLOSED.**

Current candidate replay resolves a `MaterialInputSelectorPolicy` from the authoritative producer contract and independently selects the exact latest-N eligible closed/available candles from the full frozen candle dataset and signal decision time.

The selector fails closed on ambiguous momentum floors, insufficient history, duplicate/non-increasing rows, cadence gaps, and symbol/interval crossing. Builder-side caller references are assertions only.

Most importantly, cold `validate_formal_replay_input_bundle()` recomputes the expected candle window and exact `InputReference` set from:

```text
registered immutable producer contract
+ complete frozen candle sequence
+ signal timestamp
+ dataset evidence identity
```

and then requires exact equality with persisted refs, material open-times, preimage hash, selector type, exact required bar count and selector hash.

Therefore the original `[2,3]`, `[0,3]`, `[0,1,3]` synchronized-rehash attack cannot retain one authority identity: omitted/substituted/extra rows fail against independently reconstructed expected refs.

### AG-03 — producer parameters mutable under cached identity

**Result: CLOSED.**

`SignalProducerContract.__post_init__()` recursively freezes/detaches parameters using the existing canonical `freeze_json` machinery before computing/validating `contract_hash`. Serialization thaws detached ordinary JSON values rather than exposing the authority object.

`SignalProducerRegistry.register_contract()` recomputes semantic content hash before registration, allows exact duplicate semantics idempotently, and rejects conflicting same-ID authority. `get_contract()` recomputes the semantic hash every lookup and fails closed if stored semantic content no longer matches the cached hash.

Thus normal alias mutation and nested dict/list mutation cannot change authority. Even hostile `object.__setattr__` replacement that bypasses frozen-dataclass ergonomics leaves a stale hash and is rejected at the registry authority boundary before formal replay.

Default producer contract hashes remain unchanged; this repair hardened authority representation rather than silently migrating built-in semantic identities.

### AG-04 — GET `/health` mutates forward SQLite

**Result: CLOSED for the original write-side-effect defect.**

`QuantService.health()` now uses `ForwardDerivativeStore.read_status()` instead of constructing writer-mode storage.

Read-only inspection bypasses writer `__init__`, returns a degraded missing-store response without creating directories/files, and opens existing stable stores with `immutable=1` + `PRAGMA query_only=ON`. A non-empty WAL causes `ForwardStoreWalRecoveryRequired` before SQLite connect; the endpoint degrades rather than allowing SQLite to create recovery SHM or ignoring live WAL state.

Writer initialization/migration semantics remain on the normal constructor and are not invoked by GET health.

Nonblocking residual: there is an extremely narrow check/open TOCTOU if a writer starts after the WAL precheck and before immutable open. This can transiently affect observational freshness, but does not create files, mutate storage, promote research, access protected outcomes, or enable execution. Classification: `LOW_OPERATIONAL_HEALTH_FRESHNESS_RACE`, not a kernel-freeze blocker.

## 4. Fresh P5 evidence-chain attack

A new re-gate question was tested by code inspection: can a direct qualification caller shrink `required_evidence_ids` and preserve a promotable result even after funding closure?

**Result: rejected by the composed registry invariants.**

The registry independently:

1. loads and content-hash verifies the result evidence itself;
2. requires the semantic `required_evidence_ids` to equal the attestation;
3. requires every declared required evidence ID to exist and be COMPLETE/hash-valid;
4. requires exactly one P6 run evidence and exactly one P6 benchmark evidence;
5. loads those files and requires byte/semantic equality with the nested bound run/suite;
6. derives the dataset evidence ID from the bound run identity and requires it in the required set;
7. validates dataset hash/identity against both run identity and comparison interval;
8. invokes independent cold P6 semantic replay;
9. R05CR separately makes the bound funding evidence ID mandatory in the qualification required set.

Therefore direct construction cannot omit run, benchmark, dataset or funding roots and still reach an economic qualification decision. Result evidence is independently required by `result_evidence_id` and loaded before these checks.
