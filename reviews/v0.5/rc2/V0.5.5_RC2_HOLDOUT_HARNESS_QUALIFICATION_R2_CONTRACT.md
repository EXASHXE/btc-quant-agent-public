## Required harness repairs

### 1. Event-time normalization

For every Binance metrics archive:
- parse source event timestamp explicitly;
- sort by event timestamp before period sampling;
- deduplicate deterministic duplicate timestamps;
- select latest event-time observation per frozen period;
- never use archive row order as temporal authority.

Add a permutation-invariance test:
same source rows in multiple archive orders -> identical normalized OI / taker / GLS / top-position / top-account series hashes.

Include the known FILUSDT 2026-09-06 archive as a regression fixture/reference:
the 17h bucket must select the actual latest event-time row, not the archive-order tail.

### 2. Cache authority

Any raw/source cache must be content-addressed or bound by:
- source URL list;
- per-source SHA256;
- parser/normalizer version;
- role set;
- time window;
- harness code identity.

A cache created under a different harness/parser identity must fail closed or rebuild. No anonymous mutable `/tmp/<name>` cache may silently survive a parser change.

### 3. Exact runner identity

Before any replay:
- require clean worktree;
- compute validation harness file SHA256;
- record exact git HEAD;
- record all validation-script hashes;
- bind them in an execution manifest.

After replay:
- recompute and assert identical script hashes and git HEAD;
- evidence must contain those identities;
- a mismatch invalidates the run.

### 4. Evidence generation

The committed runner itself must generate all authority findings. No manual/post-hoc evidence edit may create a result absent from the committed code path.

Tests must prove a source-order mismatch or script identity mismatch produces fail-closed terminal state.

### 5. Production-equivalent context

Retain the R1.1 fixes:
- TARGET-only outcome aggregation;
- context-only BTC/ETH/reference snapshots;
- >=300 closed 15m/1h/4h bars before first decision;
- no normal warm-up OOS drop;
- authentic 1m where target outcomes are exercised for harness diagnostics;
- PIT violations = 0.

### 6. Qualification replay

Use burned/non-protected symbols only.

Run at least:
- a parser normalization unit suite;

Outcome profitability is irrelevant to qualification.
