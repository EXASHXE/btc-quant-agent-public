## BLOCKER F01-SOL-01 — caller-invented source/split hashes can enter a production-looking seal

Current production factory accepts three caller strings:

~~~text
source_manifest_hash
split_manifest_hash
split_attestation_hash
~~~

H40RuntimeSnapshotSeal.from_current_production_authority(...) does not load and verify the typed H40SourceManifest / H40SplitManifest / H40SplitAttestation objects that own those identities.

The test helper demonstrates this directly by passing arbitrary SHA-256 values derived from strings such as source-base, split and attestation, while the resulting seal is not marked synthetic.

This violates the accepted rule:

~~~text
hash integrity != evidence truth
~~~

The repository already has the authoritative verification path:

~~~text
H40SourceManifest
H40SplitManifest
H40SplitAttestation
H40SplitManifest.assert_authoritative(source_manifest, repo_root)
~~~

That path cold-verifies source receipts, file hashes, timestamp membership, split reconstruction and attestation self-hash.

### Required repair

Production seal creation must accept typed verified authority, not independent hash strings.

Preferred shape:

~~~text
H40RuntimeSnapshotSeal.from_verified_authority(
    source_manifest=...,
    split_manifest=...,
    repo_root=...
)
~~~

It must call the existing authoritative split/source verification path and derive:

~~~text
source_manifest.manifest_hash
split_manifest.split_hash
split_manifest.attestation.attestation_hash
~~~

Synthetic hash-only construction must remain explicitly synthetic-only.

## BLOCKER F01-SOL-02 — complete REGISTERED roster and runtime snapshot identity are not proven

H40RuntimeSnapshotSeal is publicly constructible with synthetic_only=False by default.

verify_against_accepted_ledger() checks that each supplied entry corresponds to a REGISTERED slot, but does not prove:

~~~text
supplied roster == complete accepted REGISTERED roster
~~~

It also does not recompute the supplied runtime_authority_snapshot_hash from the actual accepted runtime authority snapshot.

Therefore a caller can construct a production-looking seal with:

- one REGISTERED row omitted;
- matching caller-chosen counts;
- arbitrary runtime snapshot hash;
- otherwise individually valid roster entries.

That changes the active Discovery universe before outcomes.

### Required repair

For production authority:

1. derive the complete accepted materialized search-space ledger;
2. derive the exact complete REGISTERED roster;
3. require exact equality with the seal roster;
4. derive registered/not-testable counts rather than accept caller counts;
5. recompute current accepted runtime-authority snapshot hash;
6. require exact equality;
7. prevent public direct construction from manufacturing production authority.

Add adversarial coverage for 17/151 vs authoritative 18/150, omitted REGISTERED row, substituted roster row, arbitrary snapshot hash, and direct-constructor production forgery.

## HIGH F01-SOL-03 — persistence restore is not a cold independent restore

H40LifecycleArtifactStore.restore_authorization(...) requires an already-existing process-local expected_authorization.

The persisted envelope contains only:

~~~text
receipt
receipt_sha256
bound_evidence
bound_evidence_sha256
~~~

The restore path parses disk bytes, compares them with the caller-provided in-memory authorization, revalidates that in-memory object, and returns it.

This detects tampering against an already-held object, but cannot reconstruct lifecycle authority after a cold process restart.

The persisted state does not independently reconstruct:

- run authority;
- runtime seal;
- implementation authority;
- predecessor receipt chain;
- split authority;
- verifier context.

### Required repair

Implement an actual cold restore model.

Either persist sufficient canonical authority context/references, or define an explicit content-addressed authoritative resolver.

A valid test must discard the original in-memory VerifiedLifecycleAuthorization objects, then reconstruct and reverify the persisted chain.

A caller-supplied expected_authorization is not sufficient as the restore authority.

## HIGH F01-SOL-04 — no production scientific-verifier integration seam

H40LifecycleAuthorityService is currently typed specifically around H40SyntheticEvidenceVerifier | None.

Production construction forces evidence_verifier=None and explicitly rejects a verifier in non-synthetic mode.

Therefore, even after lifecycle implementation authority is accepted:

~~~text
Discovery entry: potentially possible
Candidate Lock: always fail-closed
WF validation: always fail-closed
~~~

Fail-closed is correct today, but F01 should expose a narrow typed seam for the future separately accepted P3 scientific verifier so P3 does not need to rewrite the trusted lifecycle core.

### Required repair

Define a verifier protocol/ABC conceptually equivalent to:

~~~text
verify_discovery_manifest(...)
verify_candidate(...)
verify_wf_fold(...)
~~~

The synthetic verifier implements it with synthetic_only=True.

A future P3 production verifier can implement it with synthetic_only=False.

Production service must still default to no verifier and remain fail-closed before P3, but it must have a typed non-synthetic integration path.

F01 must not implement the real statistical engine.

## MEDIUM F01-SOL-05 — T15 overstates R3R4 verification

test_t15_exact_r3r4_selection_order verifies the final ordering mechanics:

~~~text
hard gate
-> adjusted LCB net expectancy
-> adjusted LCB precision
-> lower complexity
-> structural hash
~~~

It does not recompute:

- within-family REGISTERED correction universe;
- separate PRECISION max-stat correction;
- separate NET_EXPECTANCY max-stat correction;
- family representatives;
- cross-family Holm.

The synthetic verifier consumes adjusted LCB values and synthetic hard-gate booleans.

### Required repair

Do not claim this synthetic test proves full R3R4 science.

Rename/reframe it as final selection-order mechanics and explicitly defer statistical correction recomputation to the future P3 verifier, or model only the abstract correction bindings without implementing the real statistical engine.
