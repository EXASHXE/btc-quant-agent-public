## Historical economic PIT versus operational PIT

**Historical economic PIT is source-capable for a pinned reference-return claim.** The row opening at `t-1h`, closing at `t-1ms`, represents `B[t]`. Features at `t` may use completed bars through `B[t]`, never the row opening at `t`, entry/exit Opens or future fields. The reference endpoint may later use native economic Opens at `t+1h` and `t+5h` under the frozen four-hour horizon. No reference values or returns are calculated here.

A masked, precommitted one-shot historical test can support that reference-return claim if exposure credibility, source identity, causal implementation, accepted inference/power, immutable selection and independent lock-audit gates are established. It cannot claim actual executable PnL or latency. Revised current archives describe the pinned final economic snapshot, not necessarily first-observed inputs.

**R1.1's actual paired receipt/on-time gate cannot be reconstructed from archives.** R1.2 must explicitly define historical eligibility from economic completeness and delayed reference timing and distinguish that estimand from forward as-observed eligibility. Missing receive times cannot be fabricated or treated as proof of on-time availability. This task does not authorize that design change.

**Forward operational PIT remains mandatory.** Retain raw received bytes, exchange close identifiers, actual local receive/ingest/finalization timestamps, versions/revisions, raw/canonical hashes and all expected paired-hour dispositions. Preserve R1.1's `max(receive_BTC,receive_ETH) < t+1h`, no-backfill/no-silent-revision semantics and independent source closure: at least 720 expected paired hours, paired on-time point estimate >=99.5%, Wilson 95% lower bound >=99.0%, exact replay and zero unresolved semantic mismatch. Short forward confirmation needs a separately frozen operational contract; no arbitrary new duration or performance pass threshold is selected here.

## Protected-partition governance proposal

The lifecycle is `HISTORICAL_DEVELOPMENT -> MASKED_HISTORICAL_DISCOVERY -> Candidate Lock -> independent audit -> MASKED_HISTORICAL_VALIDATION -> FORWARD_CONFIRMATION`.

Before freezing, bind source/exposure/partition/fit/candidate/endpoint/inference/power identities, exact implementation and the selected duration pair into one immutable semantic authority. Separate source-operator raw custody and credentials from scientific change rights. Normal feature, label, replay, cache, notebook, CLI and export APIs must deny masked access by default, including indirect warmup, label-tail, cooldown, bootstrap and TRAIN-fit paths.

Before explicit unseal, non-source roles may receive **only bounds, source hashes, raw source row counts, gap status and exposure class**. Deny raw paths, event masks/support/counts, candidate returns/PnL/rankings/moments/LCBs/charts and identifying event telemetry through outputs, logs, errors and caches. Masked computation, where later authorized, writes only to an isolated sealed store.

Controller authority uses two distinct signed, one-use capability types:

1. `H41_SUCCESSOR_HISTORICAL_DISCOVERY_UNSEAL_V1`: issued only after source/exposure closure, accepted hybrid design, synthetic power/method acceptance, authority freeze and independently accepted exact-SHA mask enforcement. Scope is exactly one frozen Discovery computation/disclosure; Validation remains sealed.
2. `H41_SUCCESSOR_HISTORICAL_VALIDATION_UNSEAL_V1`: issued only after the consumed Discovery gate, immutable Candidate Lock, accepted independent lock audit and explicit Controller GO. Scope is exactly one precommitted Validation evaluation of the locked candidate; no runner-up substitution.

Each token binds Controller issuer, authority root, implementation, dataset/partition/exposure hashes, roster or lock, operation, recipient role, single-use nonce and issue/expiry times with a Controller signature. Verify every binding and lifecycle state at use and cold restore; atomically consume the nonce before outcome access. No usable token is issued here.

Append-only hash-chained signed access logs record allow/deny, principal/role/change rights, operation, partition/root/source identity, capability/request/artifact hashes, timestamp and nonce consumption. Maintain immutable checkpoints in independent auditor custody; logs visible before unseal contain no protected outcomes or event support. Separate source-integrity receipts from scientific evidence. Preserve old H39, H41 WF1 Validation and Final Holdout seals; a new partition label never silently supersedes them.

Unauthorized candidate-aligned disclosure to scientific change-rights holders stops the affected campaign, preserves incident evidence and requires Controller disposition/new authority and fresh authorized data. No favorable-month salvage, duration extension, alternate methods/seeds or parameter repair on the compromised sample. Public price awareness alone is not an incident. These controls are a proposal; enforcement is not implemented or claimed accepted.
