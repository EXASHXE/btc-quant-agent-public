**Explicit statement:** in every case, GET created **no directory, no DB file, no WAL, no SHM, no schema, no rows**. The main runtime repository was unchanged during GET (A04-T5).

### Read-only connection design

- `open_read_only(path)` classmethod creates an instance via `__new__` bypassing writer `__init__` entirely; `_read_only=True`.
- `_connect()` read-only branch: requires `self.path.is_file()`; selects a sidecar-free SQLite URI from `self.path.resolve().as_uri()`:
  - non-empty `-wal` sidecar present (active writer) → `?mode=ro` (joins the writer's existing `-shm`, creates no new files, reads a consistent WAL snapshot);
  - otherwise → `?immutable=1` (single-writer store fully checkpointed whenever no WAL sidecar remains, since SQLite checkpoints and removes WAL on the writer's last close — `immutable=1` reads exactly and creates no side files);
  - `PRAGMA busy_timeout=10000` + `PRAGMA query_only=ON` (defense-in-depth; INSERT/UPDATE/DELETE/DDL denied with "attempt to write a readonly database");
  - no `prepare_schema`/`finish_schema`, no CREATE/ALTER/journal-mode mutation, no commit; connection closed in `finally`.
- `read_status(...)` never raises: missing store → explicit degraded dict; existing store → full `status()` reused (no forked second status implementation); any store-inspection exception → degraded dict with a stable error classification (`sqlite3.OperationalError: ...`).
