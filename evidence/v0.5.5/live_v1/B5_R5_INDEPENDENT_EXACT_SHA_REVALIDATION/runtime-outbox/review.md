1. **New-risk orchestration can start after account authority becomes invalid during case refresh.** `LiveV1Runtime.execute_intent` checks readiness at `live_runtime.py:355-357`, then awaits `_refresh_case` at `:363` and unconditionally invokes `execution_service.execute_approved_intent` at `:364`. This is a route past the runtime's configured-symbol rule. The attack uses a fake execution service, so it proves unsafe handoff, not a completed exchange order. The backend's later placement gate may still reject particular submissions.

2. **Periodic REST can set `accepting_risk=True` using a snapshot that is no longer current.** `_rest_loop` stores the REST result at `live_runtime.py:259`, awaits `_refresh_case` and recovery at `:265-267`, then validates that earlier local snapshot at `:276` and sets `accepting_risk` at `:281`. `runtime/rest-result-stale` changes `account_watch.latest_snapshot()` to a foreign account during the await. This violates the runtime state invariant and allows callers that trust the flag to observe authorization the current snapshot does not grant. A direct `execute_intent` call still rechecks readiness and blocks, which limits immediate order impact.
