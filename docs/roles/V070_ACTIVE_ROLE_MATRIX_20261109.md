## Controller authority and acceptance tiers

Only 0-C determines whether a worker delivery meets its declared test/permission contract. Acceptance classes must remain distinct: IMPLEMENTED → OFFLINE_TESTED → CONTROLLER_ACCEPTED_SCOPED → AUTHORIZED_REAL_OPERATIONAL → SOURCE/SHADOW_STRICT_QUALIFIED → ECONOMICALLY_VALIDATED. These are separate evidence claims, not automatic stage promotion.

On 2026-11-09, Program S received **offline-historical-only** Controller acceptance, while Q0B and Q0C were **worker delivered / Controller pending**. The Program O baseline remains offline-scoped; actual Source/Shadow strict qualification and trading profitability are not established.

## Conflict discipline

Before any new worker: 0-C checks exact worktrees, existing active locks, SHA/receipts and previous work. Q0B/Q0C must be independently reviewed before duplicate implementations are dispatched. Real public market capture, recurring schedules, protected retention, actual Feishu destination and host service edits have separate precise permission gates. Auto trading remains TODO.

The current product’s human action window is approximately 5–10 minutes after prompt Feishu alert: 4H regime + completed 1H setup + completed 15m confirmation + fresh 5m/quote validation, targeting 2–12h opportunities. Never optimize for notification count at the expense of actionability or source truth.
