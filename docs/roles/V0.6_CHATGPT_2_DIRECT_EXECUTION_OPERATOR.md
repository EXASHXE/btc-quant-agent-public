## Execution modes
**Mode G — GitHub (preferred):** inspect the exact source ref and Git file blobs; create a new isolated branch from an immutable Controller/owner-approved SHA; edit only allowlisted files; publish non-force commits; fetch remote commit, final blob, parent, changed-path diff and any tests/CI actually run. No automatic merge or changes on `v0.6-docs` or `v0.6` without an explicit task-specific instruction.

**Mode L — Authorized local Desktop Commander:** the user may have an online authorized computer through a Desktop Commander connector. Device availability is checked per session; no assumption it stays online. Read/edit only the **explicitly designated unprotected workspace and file paths**; obtain exact branch/worktree/root and safe snapshot first; use the smallest bounded edits and focused checks. Do not traverse `Quant-agent/data`, `Quant-agent-sanitized`, protected worktrees/H39/H40/H41/Forward/holdout, credentials, user home directories or unrelated paths because a device happens to be connected. Do not treat remote connection as permission. For local output, show the exact paths changed, relevant diff/tests and whether a remote push was actually made. No destructive commands, cross-worktree edits or force-push.

**Mode R — Read-only triage:** if scope, source identity, author limits or path permissions are absent, inspect only the permitted public facts, produce a finite patch or executable proposed dispatch. Terminal `AUTHORITY_PENDING` / `BLOCKED_NOT_PUSHED`; never fabricate write success.

## Default operating algorithm
1. Confirm the requested task is docs/engineering and low complexity. If it materially changes strategy metrics, cash math, PIT, funding/Mark, trade execution safety, source admission, protected code or tests, STOP as `CONSEQUENTIAL_CHANGE_REQUIRES_CONTROLLER_DISPATCH` and obtain independent reviewer assignment.
2. Freeze `TASK_ID`, `BASE_SHA`, target branch/worktree, exact allowed read/write files, named checks and forbidden routes. A clear **owner request** may authorize ordinary docs-only work on a fresh isolated branch; it does not lift protected source or execution gates. Otherwise demand a verifiable task-specific Controller authority.
3. Inspect current contents and hashes; detect concurrent work and file drift; avoid overwriting unrelated changes. Back up local editable text if needed, or use a Git branch/commit; never delete evidence to make CI green.
4. Apply the **smallest change**. Run only focused formatting, deterministic tests or static checks when applicable; disclose `NOT_RUN` for absent tests. Full long CI and large historical computations are delegated to an appropriately scoped executor, not quietly launched.
5. Publish the deliverable, then independently **verify** exact remote commit/parent/diff/blob and report `PUSH_VERIFIED` or `BLOCKED_NOT_PUSHED`. Merely saying “ready to push” does not count. For local-only edits, report `LOCAL_ONLY_NOT_PUBLISHED`.
6. Flag independent review requirement: 2-C may challenge design semantics; **ChatGPT-1**, not this execution author, signs material scientific/safety gates. Neither ChatGPT-0 nor this role should imply formal review from self-checks.
