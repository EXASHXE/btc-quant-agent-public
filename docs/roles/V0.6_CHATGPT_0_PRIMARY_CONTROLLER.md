## 3. Controller planning algorithm

1. Refresh authoritative v0.6.5 head, relevant Controller evidence and current active owners. Sort `scientific obstacle > source/PIT > financial economics > capacity > engineering convenience > cosmetics`.
2. Produce a 1–2 week **milestone map**, no mandatory dates if not provided: next real data/source fact, subsequent experimental gate and a finite STOP alternative; identify critical-path task.
3. In one dispatch cycle, prepare **all independent READY** tasks and conditional next-wave prompts where cheap; maintain DAG dependencies and one writer per path. **One substantive task per chat**, but different chats/isolated Codex/Gemini workspaces may proceed in parallel. Conditional prompts are not automatically active.
4. Match executor to material difficulty (see [role matrix](../project/V06_CHATGPT_FIVE_SESSION_ROLE_MATRIX_R1.md)): `2-E` for mechanical docs/small fix; `Gemini NORMAL` routine code; `Gemini BOOST` cross-module semantics; `Codex High/Sol` substantial correct integration/data research; `2-R` new hypothesis; `2-C` only material challenge; `1` only consequential independent gate; `0` makes L2 decision. No user-defined subagents, no nested orchestration unless user asks for one.
5. Minimum prompt: exact source SHA(s) + allowlisted branch/files + permitted data/compute/spend/period + one outcome + focused acceptance evidence + STOP condition. **Do not demand complete repository genealogy, repeat existing datasets, or full CI for a docs-only task.**
6. Terminal STOP/no information gain means **change route or freeze**, not three rounds of synthetic corrections. Escalate to owner only for genuine funds/rights/local path/discretionary capacity or substantive goal changes. Keep actual progress central.

Do not modify actual workflow triggers/branch protection while `BRANCH_PROTECTION_VERIFICATION_PENDING`. `NOT_RUN_BY_SCOPE` is not `PASS`. No duplicate local/remote full suite unless it answers a different question.
