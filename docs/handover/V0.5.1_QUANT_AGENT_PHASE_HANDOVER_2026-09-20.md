# 0. 如何使用本文档

本文档是当前阶段的**综合交接快照与工作章程**，用于减少新会话重新梳理仓库的成本。

但本文档本身不是最高 authority。后续任何主控大模型启动时，必须先重新读取 GitHub 当前状态。

## 0.1 证据优先级

发生冲突时，优先级从高到低为：

```text
1. 当前远端 exact branch / exact commit / actual diff
2. 已接受的 protocol / amendment / independent acceptance artifact
3. 当前生产代码、测试、canonical hash 与 exact-SHA CI
4. 最新 implementation report / review artifact
5. 本阶段性交接文档
6. 历史 handoff / 历史 prompt / 历史聊天总结
```

禁止仅凭本文档中的 SHA、状态或路线继续开发而不核对远端。

## 0.2 主控 Agent 启动规则

每次接手项目，至少完成：

```text
- 获取 v0.5-refactor HEAD
- 获取 v0.5-refactor-docs HEAD
- 查看最近相关 commits
- 找到当前阶段最新 authoritative prompt
- 找到最新 independent review / acceptance
- 比较 implementation commit -> current HEAD 的真实 diff
- 检查当前 blocker 是否已经被后续 commit 关闭
- 检查 exact reviewed SHA 的 CI，而不是泛化为“CI 绿”
```

如果仓库已推进到本文档之后，以仓库实际状态为准，并更新路线。


# 24. Review checklist

主控模型 review 时至少过以下清单。

## Git / lineage

- exact SHA；
- expected parent；
- docs/code branch discipline；
- preregistration before outcomes；
- implementation after protocol acceptance；
- no silent force/rebase；
- tested SHA == reviewed SHA。

## Scientific

- no look-ahead；
- no hidden threshold tuning；
- no new hypothesis after outcomes；
- exact multiple-testing universe；
- no runner-up promotion；
- split/purge/embargo；
- cost semantics；
- sample floor；
- outcome only in authorized stage。

## Authority

- caller cannot self-authorize；
- independent source authority；
- exact content preimage；
- no cached identity with mutable semantics；
- receipts prove evidence, not only caller claim；
- replay protected by run/candidate/split binding；
- historical baseline identity separated from current executable identity。

## Data

- event / available / observed / decision times；
- no forward backfill；
- no synthetic historical L2；
- source role not confused；
- WAL/read-only semantics；
- missing data fails closed。

## Engineering

- direct adversarial tests；
- full tests；
- mypy；
- Ruff；
- compileall；
- CI；
- resource/runtime impact；
- API/CLI side effects。

## Safety

- execution disabled；
- H39 unchanged；
- Final Holdout sealed；
- secrets absent；
- no unauthorized order path。

# 25. Prompt authoring quality bar

一个合格的 Prompt 应做到：

```text
two independent competent implementers
should make materially equivalent changes
```

如果 Prompt 仍允许：

- 自选算法；
- 自选字段；
- 自选 hash preimage；
- 自选 tie-break；
- 自选 fallback；
- 自选 source；
- 自选 pass/fail；

那么说明 protocol 尚未冻结充分。

此时应继续 docs/protocol repair，而不是进入 implementation。

# 26. 当前最重要的工程/研究教训

## 26.1 自洽不是 authority

```text
candidate supplies data
candidate hashes data
replay reads same data
hash matches
```

仍然不证明数据 authoritative。

---

## 26.2 Hash 不证明 claim 为真

```text
hash("PASSED=true")
```

只能证明 string 未变。

必须：

```text
evidence
-> verifier
-> derived result
-> authorization
```

---

## 26.3 Freeze first, observe later

所有会影响 candidate：

- search space；
- formula；
- statistic；
- tie break；
- calibration；
- source authority；
- split；
- sample floor；

必须在 outcomes 前冻结。

---

## 26.4 Failed family means stop

不能：

```text
失败
-> 扩 budget
-> 换阈值
-> reverse
-> 继续直到赢
```

---

## 26.5 Operational health 不等于 research validity

Forward collector：

```text
HEALTHY
```

只代表 collector/chain 状态。

它不代表：

```text
ALPHA
PROFITABILITY
VALIDATED STRATEGY
```

---

## 26.6 CI 不等于真实 runtime acceptance

特别是 Forward health：

```text
synthetic CI
!=
35 GB production-data runtime
```

因此需要独立真实环境 acceptance。

# 34. 最后原则

本项目未来最重要的不是“尽快找到一个看起来盈利的策略”，而是：

```text
如果最终得到一个 candidate，
必须能够解释：
它为什么不是未来函数、
为什么不是搜索偏差、
为什么不是 caller 自证、
为什么不是 benchmark substitution、
为什么不是数据 provenance 错误、
为什么不是 holdout leakage、
为什么另一个独立实现者会得到相同结果。
```

只有在这套 evidence chain 上成立的结果，才值得继续进入 Forward / Shadow / 更高等级验证。
