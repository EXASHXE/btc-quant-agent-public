# V0.5.1 — Tactical Policy B-Line Implementation Handover

## 0. Document role

This is the dedicated handover for the **B-line / Personal Tactical Policy** track.

It is intentionally separate from the H40/H41 scientific mainline handover.

The B-line goal is:

```text
real-time market observation
→ deterministic tactical setup detection
→ forward/shadow evidence
→ rolling calibration
→ uncertainty-aware tactical policy
→ human decision support
```

It is **not**:

```text
scientific alpha authority
automatic execution
live/private exchange trading
replacement for H41
```

The B-line is allowed to move faster and use provisional evidence, but it must retain PIT discipline, cost realism, auditability, and strict separation from H40/H41 protected outcomes.

# 5. Critical gaps found by Controller review

## GAP-B01 — timeframe ROC semantic ambiguity

The current timeframe snapshot uses a 12-bar ROC calculation.

That means the same field has different elapsed-time semantics:

```text
15m × 12 = 3h
1h  × 12 = 12h
4h  × 12 = 48h
```

However parts of code/docs use phrases such as “1h return/shock” around the 1h snapshot ROC.

This must be corrected before Tactical Policy R2 so feature names correspond to actual elapsed time.

## GAP-B02 — configured EMA200 is not an active semantic feature

Config declares:

```text
ema_slow = 200
```

but current operational snapshot logic primarily computes/uses EMA20/EMA50 and the current data-fetch depth is not designed around a formally supported EMA200 semantic contract.

B0 must not leave a configured-but-semantic-no-op feature.

## GAP-B03 — Range Mean Reversion docs/code drift

Documentation advertises:

```text
RANGE_MEAN_REVERSION
```

but no corresponding active production evaluator exists.

Do not silently implement a new strategy in B0.

The correct B0 action is to mark it:

```text
RESERVED / NOT_ACTIVE
```

and align docs/tests.

## GAP-B04 — playbook selection is implicit precedence

Current directional playbook composition uses first-match behavior equivalent to:

```text
TREND_PULLBACK
OR BREAKOUT_RETEST
OR FAILED_BREAKOUT
OR VOLATILITY_EXPANSION
```

This creates an implicit priority order without statistical authority.

B0 should preserve current output behavior but make this precedence explicit and auditable.

Future B4 must replace static precedence with calibrated policy resolution.

## GAP-B05 — cross-sectional relative-strength denominator can depend on scan scope

Relative-strength ranking incorporates universe/median context.

The effective reference set must not silently depend on whether a user scans:

```text
--symbols LINKUSDT
```

versus:

```text
--all
```

B0 must introduce a fixed ranking/reference universe identity.

## GAP-B06 — heuristic score is not probability

Current 0–100 Opportunity Score uses hand-authored weights such as:

```text
trend
structure
entry quality
derivatives confirmation
participation
relative strength
net RR
penalties
```

It is useful as a deterministic rule score.

It must not be interpreted as:

```text
P(win)
confidence probability
expected return
validated edge
```

Until calibrated, name/describe it as:

```text
RULE_SCORE
```

or an equivalently explicit non-probabilistic label.

## GAP-B07 — thresholds remain heuristic

Examples include:

```text
ADX threshold
ATR overextension multiples
funding crowding thresholds
OI change thresholds
BTC shock threshold
top-trader crowding threshold
net RR threshold
relative-strength exemption threshold
```

These are operational heuristics, not validated scientific parameters.

They remain allowed for B-line EXPERIMENTAL/SHADOW operation, but promotion must depend on forward/OOS evidence.

## GAP-B08 — full decision-time feature evidence is not yet a first-class immutable object

Current audit/shadow rows persist many decisions and identities, but B-line V2 needs one immutable feature/evidence object per decision containing the complete signal-time feature vector.

Without this, later attribution cannot reliably answer:

```text
Did OI improve breakout expectancy?
Did funding crowding hurt trend continuation?
Which regime makes a playbook useful?
```

This is B1, not B0.

## GAP-B09 — no calibrated policy layer

Current system does not yet estimate:

```text
P(fill)
P(TP1 before SL | fill)
Expected Net R | fill
Expected Net R | signal
uncertainty / credible interval
effective sample size
```

This is the core B3/B4 upgrade.

## GAP-B10 — grid lacks equivalent forward evaluator

Grid recommendation is currently operational/advisory.

A future Grid Shadow evaluator must measure:

```text
paired profit
inventory excursion
maximum underwater
capital utilization
funding drag
boundary breach
trend transition loss
grid shift frequency
net fee-adjusted P&L
```

## GAP-B11 — derivatives need normalized state, not only absolute thresholds

Future Tactical Policy should add rolling:

```text
OI z-score / percentile
funding percentile
basis percentile
long-short percentile
taker-flow z-score
```

by:

```text
symbol × timeframe × regime
```

rather than assuming one absolute number means the same thing for BTC and DOGE.

# 7. Tactical strategy status taxonomy

The B-line must never use only VALID/INVALID.

Use:

```text
EXPERIMENTAL
  rule logic exists; observation only

SHADOW_PROVISIONAL
  forward evidence exists but is insufficient for tactical use

TACTICAL_PROVISIONAL
  rolling OOS + forward shadow evidence supports limited-risk human use

VALIDATED_FORWARD
  multi-window / multi-regime forward performance remains stable
```

No B-line state is equivalent to H41 scientific authority unless separately promoted through the scientific mainline.

```text

```

## B2 — ShadowEvaluationV2

Add:

```text
playbook-specific outcome windows
playbook attribution
realized funding/friction
signal cohort metrics
grid shadow evaluator
```

## B3 — Historical Replay + Rolling OOS

One policy implementation must run in:

```text
historical causal replay
live forward shadow
```

## B4 — Calibration + Tactical Policy Resolver

Estimate:

```text
P(fill)
conditional win probability
Expected Net R
uncertainty
effective sample size
regime-conditional evidence
```

Static playbook precedence is replaced by evidence-aware policy resolution.

## B5 — Forward Promotion

Promotion gates move candidates through:

```text
EXPERIMENTAL
→ SHADOW_PROVISIONAL
→ TACTICAL_PROVISIONAL
→ VALIDATED_FORWARD
```

## B6 — Policy Agent / TradingAgents-style orchestration

Only after multiple playbooks have evidence.

Agent roles may explain or route among accepted Tactical Playbooks.

The Agent must not become the source of strategy truth.
