## Distinguish two forms of “real-money testing”

**Project-managed strategy execution with real funds:** Requires G1–G5, including a justified strategy-quality basis and **separate explicitly bounded LIVE_APPROVAL_ONLY authorization**. An LLM response or Feishu click cannot generate trading authority. For high-leverage/perpetual positions, liquidation/funding/liquidity/fees add substantially more failure modes; apply stricter limits and independent pre-live risk review.

**User's manually operated tiny discretionary trades:** The user can choose to trade in an exchange UI under personal responsibility without connecting the project's trading API keys. Such discretionary observations are **not** a v0.6 system release, not a valid protected alpha proof and must never be relabeled `LIVE_V1_PASS`. A read-only monitor and manually copied suggestion can be evaluated independently, with risk budget and a contemporaneous receipt; this route does not grant software any order API permission.
