## 6. Strategy Composer — proposed gated architecture

**Architecture:** `Regime(4H+1D context) -> Setup(completed 1H) -> Entry(new completed 15m) -> Risk/Cost/Quote(5m/latest) -> WATCH/READY/NO_SETUP/SOURCE_BLOCKED -> Q0BC/Q0C permitted outbox -> Shadow`.

Composition rules:

1. Use a single deterministic venue-source as-of join; each record must carry `event_time`, `closed_at`, `available_at`, `decision_at` and source receipt/revision. A 1H setup cannot use the 15m trigger to revise its past setup facts.
2. Freeze the 1H plan/geometry and setup identity at discovery, then independently evaluate fresh 15m confirmation and 5/10-minute executable price/entry-zone/no-chase/stop/TP/cost policy. Old confirmation cannot become new READY after restart.
3. Reuse `FactorPipeline` and one versioned registry/cache rather than duplicating indicators in Q0B or introducing another authoritative strategy registry.
4. Preserve the **Q0B/B-01 native setup identity** and Q0BC R1.1 design principles: episode identity independent of adapter policy drift; deterministic causes; distinct immutable evaluation observation, notification eligibility and provider-delivery state; cold-start/restart fences; no automatic UNKNOWN retry.
5. Never promote routine `NO_NEW_MATCHING_15M_CONFIRMATION` WATCH into a new transition or automatic withdrawal of a still-valid READY. Separate genuine invalidation, event expiry, source/account veto, quote delay and provider UNKNOWN.
6. Missing cost inputs, stale quotes, unavailable legal source coverage or conflicting confirmed 4H regimes **fail closed** for actionable dispatch. `SOURCE_BLOCKED` is not `NO_SETUP`.
7. Three-arm Strategy Lab has strict experiment IDs, fixed eligibility and preregistration records. Parameter search is bounded and documented; exploratory thresholds cannot be recast as prospective confirmatory results.
8. Strategy output must distinguish plan `TP1/TP2/TP3` from shadow-recorded actual/fill-simulated partial exits; missing structural TP2/TP3 remains `UNKNOWN`, never fabricated.
9. Signals are read-only candidate advisory; no account/order APIs and no actual position management. All exit policy experiments run on **hypothetical Shadow fills** only.

### 6.1 Entry actionability (avoid expired price-zone cards)

Use explicit `WATCH -> ARMED -> ENTRY_READY -> MISSED_ENTRY/INVALIDATED/EXPIRED` only as a proposed domain-layer vocabulary; reconcile actual Q0B/Q0BC state names rather than unilaterally migrating existing stored values.

- On closed-bar confirmation, recompute currently executable entry zone from the *frozen* plan and fresh qualified quote, not from a price available before confirmation.
- Reject if the projected 5- and 10-minute response envelope leaves the no-chase limit or if post-confirmation fee/spread/slippage-adjusted R falls below the frozen policy.
- If a pullback was missed but a genuine continuation setup appears, create a **new family/setup hypothesis** rather than reusing or rekeying the expired episode.
- Log all WATCH→READY, missed-entry and no-fill denominators (including no plan) without converting prior unknown cases to false losses/wins.

### 6.2 Exit Policy Lab, separate from entry-alpha claims

Initial stops: `SL_long = last_confirmed_structural_low - k*ATR`; `SL_short = last_confirmed_structural_high + k*ATR`. The initial downside budget must not be loosened because the position loses. Test, as **separate preregistered policies**, fixed structural TP, fixed horizon/time stop, partial TP and ATR/confirmed-structure trailing stop. Do not confuse a displayed second price target with actually simulated scale-out. Use conservative intrabar ordering, explicit no-fill/censoring and after-cost realized R.

The Exit Lab requires new hypotheses after A/B/C, not a post-hoc search across all entry arms and exit variants.
