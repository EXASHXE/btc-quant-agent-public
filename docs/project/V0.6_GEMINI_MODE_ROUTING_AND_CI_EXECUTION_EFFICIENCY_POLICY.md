## 3. New default execution plan

- First determine and label task tier + model mode (NORMAL or BOOST) in the task header, plus write allowlist, exact start SHA, output definitions, bounded goal.
- NORMAL: one independent worktree; typically <=2 commits; local task tests + Ruff/compile first; single final remote push; avoid full run unless release/unknown risk; no nested workers by default.
- BOOST: one full architecture or method plan; stage at most 3 coherent independent waves; typically <=4 commits and one final push; at most 2 short read-only helpers if justified, no recursive Goal subagents, no repeated baseline research from scratch, resolve blocked cases with finite terminal evidence.
- Code quality: each wave uses tests selected by trusted risk map, failure replay, exact source SHA, and deterministic fixture. Only final release/safety-science exact SHA uses authoritative full suite, still including H40/H41.
- CI: preserve unknown executable / unknown source / deletion / renaming / critical config = FULL; known A feed and R2/R3 bridge code select dependency-complete owned suites; docs/evidence = none; CI planner = CI self-tests. Scheduled weekly and explicitly requested manual FULL remain unchanged.
- Avoid duplicate full runs on local and remote for the same SHA without clear distinct purpose. When goal claims final full CI, inspect real pytest step, non-skipped count, run conclusion and head SHA.
- Cost claims must distinguish target runtime / full pytest runtime / installs / CI queuing / worker orchestration / data collection. Do not claim Boost model itself has specific speed multiplier absent controlled comparison.
