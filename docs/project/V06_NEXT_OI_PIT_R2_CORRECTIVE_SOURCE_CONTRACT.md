## 3. Persistent causal receiver/PIT, correction and clock contract (F03)

**Provider time is not known-at.** `openInterest.time` is provider *transaction time*, not a recognized gateway publication instant. `openInterestHist.timestamp` is aggregate *period end*, not publication or receiver time. For a record version `v`:

- `period_start_ms` (if independently derived with reliable alignment) and `provider_period_end_ms` = provider OI statistics timestamp; for snapshots, `provider_transaction_at_ms` instead. Do not force snapshot times onto a statistical bucket grid.
- `request_started_mono_ns` / `request_finished_mono_ns` and `receiver_complete_mono_ns`; simultaneously captured local wall UTC time and uncertainty/offset-bracketing, new `receiver_epoch_id` after process restart or wall/monotonic discontinuity. Only compare monotonic clocks **within** one verified epoch.
- `receiver_first_complete_utc_interval=[lo,hi]` from a trusted clock-discipline witness plus receiver capture, with `receiver_wall_utc_ms` and `utc_uncertainty_ms`. An application `time.time()` read alone is **not** a calibrated trusted UTC; uncertainty includes jitter/offset and clock-step checks. A response is usable at earliest **safe upper bound** `hi`, not nominal timestamp `lo`.
- `raw_body_sha256` over unmodified response bytes; separately `canonical_field_hash` over stable, versioned parsed fields; `source_endpoint`, request params (no secrets), HTTP status, response-header quota receipt, response body length, client/build source SHA, retrieval attempt identity; `first_seen_version_id` and append-only version sequence. A raw JSON hash is not invented by a worked example.
- `provider_publish_at` is `UNKNOWN` unless independently exposed with signed/source-specific proof. Earliest observed first receipt **does not estimate** exact publication; polling places only a bounded observation interval if a previous fresh poll definitely showed absence.
- Per-version source-known rule:
  `known_at_safe(v) = max(provider_period_end_safe(v), first_complete_receiver_UTC_hi(v), independently_proven_publish_hi_if_present)`.
  For a snapshot, replace period end by provider transaction time mapped with clock uncertainty. Any missing trusted interval, period misalignment, inconsistent UTC domain, impossible temporal ordering or ambiguous revision => `PIT_UNKNOWN / BLOCK_DECISION`.
- Joint feature decision `t_decision_safe >= max(known_at_safe(each included feature), confirmation_bar_complete_at_safe)` **and** meets precommitted staleness, period contiguity, instrument/unit identity, receiver coverage and revision rules. Treat conditional clock bounds, not provider timestamps, as the real decision admissibility test. Decision at exactly an uncertain boundary is rejected or delayed until the upper bound.
- Clock QC **single binding draft example**: require `abs(estimated_server_UTC_offset_ms) + worst_case_clock_uncertainty_ms <= 5000 ms` and abort on an unexplained clock step greater than **1000 ms** between valid receiver samples. The former tests gross relative skew, the latter continuity; no contradictory “30s allowed vs 5s abort” gate. Both numbers are **proposed pilot criteria only** and need separate Controller/source calibration; remote `/time` checks by themselves cannot certify reliable UTC.

**Append-only version transition:** Logical aggregate key `(venue, symbol, contract_spec_version, endpoint, period, provider_period_end_ms)`; retain **all** complete raw response receipts with their first-read clocks. Identical canonical payload seen again is a repeat with a new observation receipt but retains **original version first_seen**; changed canonical contents with same logical key create version `v+1` and immutable correction link `corrects(v)`, never mutate `v` or retroactively let a 12:45 revision affect a 12:20 decision. Until decision-time version choice and revision policy are provable, future decisions touching that logical key fail closed. Before a revision is known, older decisions must preserve the actual previously known version; an unexpected conflict triggers audit, not hindsight recomputation. Competing responses in simultaneous epochs with indeterminate ordering are `REVISION_ORDER_UNKNOWN`. Snapshots can conflict across receipt versions; do **not** assert universal provider irrevisability without proof.

**Observed-nonobserved distinction:** A historical REST download at 13:00 containing period end 12:00 becomes observable to **our** receiver no earlier than 13:00; earlier exchange publication is still unknown. A duplicate query at 13:05 returning a corrected 12:00 value is a later-version observation, not an invisible change to the 12:00 signal. On gaps, nonconsecutive bucket ends, truncated initial responses, missing clock epochs, schema change, stale inputs or incomplete coverage: emit typed `OI_UNKNOWN` and exclude from any new OI admission; never interpolate/synthesize missing OI or infer source continuity from later backfill.

2. `t_confirmation_close`: first **fully completed** acceptable post-shock confirmation bar, not contemporaneous “t” when confirmation occurs at t+1/t+2.
