## 1. Explicit V3 object model and deterministic identity protocol

Five distinct, typed objects are required to prevent conflation:

1. `SourceOriginWitness`: a validated, causal **upstream** anchor identifying one shock discovery instance using a source-lineage identity and precommitted structure discovery contract; NOT a later confirmation, not OI/Last future outcome, not an unverifiable opaque hash. In synthetic-only reasoning the origin is a declared invented seed and must never receive the `SOURCE_ADMITTED` grade.
2. `EconomicShockV3`: one immutable `shock_id_v3` for the one upstream economic impulse/event, independent of downstream LONG/SHORT, 5/15/30m, strategy arms, execution and data-health choices. Stores the initial source-neutral structure candidate and its first-known-at upper bound.
3. `DirectionClaimV3`: zero or more `(shock_id_v3, claimant_rule_id, side, confirmation_clock, evidence_version, decision_known_at)` records. LONG and SHORT claims may conflict within **one** shock; each claim is *not* another economic event. A shock can be source-observed with no valid confirmation.
4. `FeatureReceiptV3`: X/OI/quote evidence with first durable receiver-known-at, source version, reason/status and the decision-as-known view. Later revisions belong to the same shock by reference, never update its immutable core identity.
5. `PolicyDecisionV3`: policy-specific action/NO_ACTION, execution/quote guard, risk state, planned occupancy and hypothetical outcomes, keyed by `(shock_id_v3, policy_contract_id, decision_tick, policy_version)`. Distinct policies and clocks may produce different **candidate opportunities** or portfolio actions but never multiply the upstream shock count.

**Canonical collision-resistant domain-separated ID proposal:**

`shock_id_v3 = SHA256(UTF8("V06.ECON_SHOCK.V3\u0000") || canonical_bytes(core))`, where `core` is a length-delimited, strictly typed, versioned record containing:
- `schema="ECONOMIC_SHOCK_V3"`, `venue="BINANCE"`, `market="USDM_PERP"`, full `instrument_contract_identity` including contract/spec version and event clock units, and `discovery_rule_id` + immutable rule version / prereg identity;
- `source_origin_ref`: unique original observation *lineage* anchored in independently verified venue transport/source, provider-native stable IDs/sequence interval **if actually furnished**, or separately warranted upstream derived-event anchor with full deterministic raw-source trace. Must include an immutable `origin_instance_discriminator` fixed using available **at-first-discovery**, pre-registered features (e.g., distinct native sequence ranges), not a random receiver-assigned ordinal or timestamp-only surrogate;
- `shock_structural_anchor`: predeclared source-neutral structural setup identifier and upstream start/first discovery boundaries of the shock *known when minted*, with a stable serialization of quantities / ticks; frozen origin setup zone/window and causal parent lineage if this is a legitimate rearm;
- `original_first_safe_known_at_bound` and its trust-domain clock/epoch interpretation **as an asserted witnessed core field only if source admitted**. Once minted this bound never changes on later reconnect or revision; if no trustworthy receiver clock, mark `UNMAPPABLE_SOURCE_UNKNOWN` and use a **synthetic-only** namespace instead of minting a falsely authenticated ID.

**Never include** side, shock trading direction, later confirmation 5m/15m/30m, OI/quote/funding, future state, return, PnL, source receiver connection epoch at *replay*, model decision score, quote price, postconfirmation end time, policy occupation or stop/fill. Distinguish *precommitted source structural anchor* from later `confirmation_end` and avoid any timestamp obtained only after the event. The event's raw payload hash is a **versioned evidence pointer**, not a mutable component of the core ID: revised payload bytes do not re-key the already discovered shock.

**Canonical encoding guard:** freeze the exact serialization version (e.g., canonical UTF-8 JSON with sorted keys, fixed units and integer clocks, no floats/NaN, normalized Unicode, deterministic decimal-string tick quantization, explicit null semantics), stable hash domain and bytes; enforce source-contract identity and collision consistency before comparing hashes. Two records with the same `shock_id_v3` but conflicting immutable core precommitments are `CORE_ID_COLLISION/QUARANTINE`, not duplicate independent events. Hash strength does not authenticate input provenance or data rights.

**Same timestamp can mean different shocks:** two genuinely independent original structural impulses can share provider/event time. They are distinct ONLY if a **predecision**, source-attested origin discriminator (different native sequence/order interval, pre-frozen structure-formation witness or independently unique upstream origin instance) proves distinct provenance. If all precommitted fields and witnesses are indistinguishable, do not arbitrarily split them by side, later zone/confirmation, arrival order or sequential allocator; emit `ORIGIN_AMBIGUOUS / UNMAPPABLE`. Conversely, a later-discovered new shock cannot reuse an older origin merely because it shares a clock second.

### Source grade split (non-negotiable)

`SYNTHETIC_ORIGIN_V3` is permitted **only as design/test object**, e.g. invented `source_identity_hash="synthetic-source-hash"`, fabricated upstream fixture `original_seed` and `first_known_at`. No synthetic source ID, even 64 hex characters, can make `SOURCE_ADMITTED` true. For authentic source-grade V3, separately verify source rights, TLS/peer origin, raw unchanged payload bytes and source chain, clock UTC/monotonic bounds and append-only durable first-seen, instrument multiplier/units, parser version, and independently reviewed ledger. R3 OI first-known rule and current synthetic receiver contracts are documentary; `SOURCE_NOT_ADMITTED` is unchanged.

### Legacy mapping receipt, never blind equivalence

Store `MappingReceiptV3 = (from_contract, from_exact_blob, old_id, to_v3_id?, mapping_kind, proof_refs, reason, first_witness_at, mapping_record_version)`, append only. Accepted mapping categories:
- `MANY_TO_ONE_PROVEN`: two R3 opposite-side IDs map to **one** V3 shock **only when** independently verified common upstream original anchor, matching pre-identity structural source and no evidence of distinct original impulses. Map both side claims as typed child records.
- `ONE_TO_ONE_PROVEN`: R2 Seed (or an R3 old ID) has a uniquely matched independently witnessed upstream origin and a complete unchanged original seed. Requires authenticated source for live-grade; only `SYNTHETIC_ONE_TO_ONE_FIXTURE` grade for invented R2 records.
- `ONE_TO_MANY_UNRESOLVED`: older ID used broad time/structure and may collapse separate original impulses; **do not invent** splits or assign downstream direction as discriminant. Requires genuine original/source precommitted independent anchors; otherwise `UNMAPPABLE`.
- `MANY_TO_ONE_UNRESOLVED`: apparent common timestamp without authenticated shared upstream anchor; **do not** merge merely by clock/price.
- `UNMAPPABLE_SOURCE_UNKNOWN`: R2 opaque `source_identity_hash`/first-known was invented or absent, original R3 data has no proven causal lineage or trusted clock, historical private/protected source inaccessible. Retain original ID and `UNKNOWN`, do not import old historical rows into a fresh v3 trial. 
- `UNMAPPABLE_SCOPE_OR_VERSION`: old R1/R2 replay/schema bytes changed, original serialized seed/clock/meaning unavailable or source units/contract changed. Fail closed; no silent contract widening.

**Versioned replay contract:** 
- `shock_key_v3` immutable upstream ID; `claim_semantic_key_v3=hash(V3_CLAIM,shock_id,predeclared_claim_rule,side,confirmation_frame_id,confirmation_version)` separates genuinely different claimed evidence while keeping economic count = 1.
- `delivery_attempt_key_v3=hash(V3_DELIVERY,transport_identity,receiver_epoch,attempt_uuid,raw_payload_sha,stable_sequence_index)` records each physical receipt (synthetic-only when unauthenticated). Reconnect can produce a new attempt, NEVER a new shock; identical semantic claim with the same original source version is `DUPLICATE_CLAIM`, even if its delivery key differs.
- `decision_as_known_key_v3=hash(V3_DECISION,shock_id,policy_id,policy_schema_version,precommitted_decision_tick,source_evidence_view_version)` freezes a decision's source snapshot and outcome-blind policy branch. When a later revision arrives, append a **different evidence-version receipt**, keep prior decision unchanged. An attempt version change cannot retrofit the earlier `source_evidence_view_version` or change the historical set of timely OI observations.
- Only replay source versions **whose durable witnessed upper-known-at precedes their original decision tick**; retroactive backfill is blocked. A late duplicate with an earlier-looking provider time is not earlier known-at.

**Crosswalk fail-closed criteria:** old ID impossible to invert into unique original anchor; matching source only by SHA-shaped string; missing exact scheme/contract version; first-known-at inferred from later confirmation/REST OI bucket label; conflicting R2 seed precommitments; no distinguishable source sequence for simultaneous distinct shocks; duplicated epoch response that changes precommit fields; no authenticated clock/rights. None of these become a new source-qualified E_X event. Do not patch R2 code with this document; Controller must separately grant versioned adapter implementation/tests if desired.

## 3. Typed state machines: side, invalidation, rearm, confirmation and portfolio

### 3.1 Sides attach to one shock

Record `claim_side_state` per economic shock **as a time-indexed append-only sequence**, not a mutable final label:
- `NO_DIRECTION`: original shock seed exists but no qualified directional confirmation; enters parent structural-shock ledger but not an action.
- `PROVISIONAL(LONG|SHORT)`: a causal tentative claim first received within precommitted setup.
- `CONFIRMED(LONG|SHORT)`: bar fully closed and first-complete receiver-known **by its own decision time**. A later confirmation on another timeframe of the same side is an additional *claim evidence*, not another shock.
- `SIDE_CONFLICT_SIMULTANEOUS`: admissible opposing LONG/SHORT claims for same `shock_id` and identical decision tick; **both** candidate confirmations quarantined for that tick, no deterministic sorting by side, no new episode.
- `SIDE_FLIP_AFTER_CONFIRMATION`: opposite claim at a later tick for already directed original shock; preserve earlier original as-known decision/position/ledger and **reject later opposite new opportunity** from that same shock. Do not cancel or rewrite an earlier hypothetical fill; risk/position closure belongs to a separate future authorized policy contract.
- `INVALIDATED`: only from independently witnessed precommitted invalidation predicate `known_at <= invalidation_at_safe`. Once invalidated, latch, prevent reactivation of same shock by confirming another timeframe or swapping side.
- `CONFLICT_UNKNOWN`: causal ordering of opposite claims unresolved due to receipt clock epoch or revision, ⇒ **NO_ACTION** and no certified direction.

Policy can be strictly more conservative, e.g. declare NO_ACTION on all unresolved prior side conflicts, but cannot selectively resolve side using future price, first profitable confirmation, return or PnL. The *parent event count* remains one for known original shocks even when no direction is selected; separately count eligible **directional** decisions.

### 3.2 Legitimate rearm

A new shock v3 ID requires `new_original_origin_ref` (independently distinct from old) and `parent_shock_id_v3`, **authentic causally recorded parent invalidation known before the rearm first-seen**, and `t_new_original_first_known >= t_parent_invalidated_safe + max(frozen_parent_cooldown, frozen_policy_min_cooldown)`. Parent cooldown must be fixed before the parent setup—cannot choose a shorter child cooldown to bypass it. Apply half-open window/zone structural equivalence precommitment; a duplicate late confirmation inside old equivalence zone is old shock and cannot mint a new ID.

If parent was provisional but not genuinely invalidated, a later “new seed” on the same causal lineage is `REARM_NOT_CAUSAL`; new origin presence alone does not waive parent latch and cooldown. A supposedly new opposing-direction claim using the **same** original anchor is `SIDE_FLIP_AFTER_CONFIRMATION`, not rearm. If parent invalidation source is missing, timestamp ambiguous, or independent original differentiator absent: `REARM_UNVERIFIED / UNMAPPABLE`. Accept the R2 synthetic rearm only as a fixture until source/witness proof exists.

### 3.3 No hindsight on occupancy

Two separate policy streams `π_E` early X-only and `π_W` wait-OI, plus later optional separately preregistered fallback, receive the **same exogenous shock IDs** in ascending first-known-at and precommitted tie-order. Maintain separate position/collateral/risk/hold calendars and policy-specific NO_ACTION; 4–24h holding budgets are *prospective assumptions*, not fills. One active aggregate BTC slot per policy by default, half-open `[start,end)` planned occupancy; overlapping entry intents from distinct shocks are `PORTFOLIO_OCCUPIED` in that policy, not erased from the common source-neutral ledger. Equal-time distinct shocks use precommitted source-sequence/contract-rule tie-break; if indistinguishable and would compete for one position, `AMBIGUOUS_PRIORITY / NO_ACTION`, not arbitrary list iteration.

**Ordering guard:** side-conflict recognition for a tick must be a set operation over all causally known same-tick claims **before** portfolio selection, independent of input permutation. A later flip must not retroactively remove a prior PIT-qualified event. Invalidation and record versions only apply if receiver-known by the original decision tick. Dynamic hypothetical holds cannot retroactively shrink predeclared eligible **calendar** exposure.

## 4. C01–C03 source-neutral cohorts and honest opportunity denominators

**Versioned population definitions (new identity owner):**
- `E_S` = **economically discoverable V3 shock origins** within X-source-valid scheduled observations, independent of side, OI, quote, 5/15/30m confirmation and occupancy. This structural seed universe includes no-direction/invalidated/side-conflict origins and counts each physical impulse once.
- `E_X⊆E_S` = V3 shock IDs with precommitted, **source-qualified X-only** structural/confirmation/side eligibility by the X decision clock, all statuses counted under one shock; no OI/quote/portfolio filtering. `E_X` is the common cause/source-neutral **parent** for C01/C02 scientific analyses.
